# Feature Specification: 他のアプリとのドラッグ&ドロップ

**Feature Branch**: `claude/affectionate-carson-yaiayj`

**Created**: 2026-11-07

**Status**: Draft

**Input**: TAK-74 https://linear.app/takyoshida/issue/TAK-74 — Finder のように、Folzio から他のアプリへ、他のアプリから Folzio へ、
ファイルやフォルダをドラッグ&ドロップで受け渡せるようにする（ブラウザのアップロード欄への画像のドラッグ、Finder との移動・コピー、
ブラウザに表示中の画像の取り込み）。

## Clarifications

### Session 2026-11-07

- Q: Folzio からアプリ外へドラッグするとき、許可する操作は？ → A: コピーと移動。どちらにするかは Finder と同じく
  ドロップ先のアプリが決める（FR-344）
- Q: アプリ外から file URL をドロップしたとき、移動とコピーをどう決めるか？ → A: Finder と同じ。同じボリュームなら移動、
  別のボリュームならコピー、Option でコピー、⌘ で移動（FR-346）
- Q: アプリ外からのドロップを受け付ける場所は？ → A: アプリ内のドラッグの宛先（FR-163（file-operations.md））と同じ範囲（FR-345）
- Q: アプリ外への移動を許可すると Dock のゴミ箱へドラッグできるが、どう扱うか？ → A: Finder と同じく許可する。
  ゴミ箱から戻せるため（FR-344・A-129（変更））。T005 の確認で Dock がドラッグ元に削除を任せると分かり、後に取り下げた（下の Session を参照）
- Q: ブラウザの画像の取り込みに、キーボードで行う手段がない（憲章 原則 III の MUST）。どうするか？ → A: この feature から外し、
  キーボードの手段と合わせて別の Issue で扱う（A-204）。
  - 外す前に決めていた内容は、別の Issue へ引き継ぐ: 画像はファイルの書き出しの約束（file promise）を優先し、なければ画像データを PNG で保存する。
    URL だけのドラッグは受け付けない。画像データの名前は画像の URL の末尾の名前（拡張子は `.png`）、なければドロップした日時
- Q: Option と ⌘ を同時に押してドロップしたら？ → A: Finder の表示に合わせて Option を優先し、コピーとする（分析の A1。設計レビューで、OS の許可に従うよう改めた。下の Session を参照）
- Q: 検索結果からアプリ外へ移動した項目は？ → A: アプリ内の移動と同じく、検索結果から外す（EC-236。分析の U2）

### Session 2026-11-07（設計レビュー）

- Q: アプリ外への移動と Dock のゴミ箱は Folzio の確認モーダルを出さず、FR-024（移動は常に確認）と FR-079（ツリーのフォルダのゴミ箱は必ず確認）に反する。
  どう整理するか？ → A: 例外として明記する。アプリ外のドロップ先が実行する操作は、両方の確認の対象外とする（FR-024（変更）・FR-079（変更））。
  Dock のゴミ箱に対応しないことになったため、FR-079 の変更は取り下げ、FR-024 の移動の例外だけを残した（T005）
- Q: Dock のゴミ箱がファイルを移さず、ドラッグ元に削除を任せる仕組みだった場合は？ → A: Dock のゴミ箱には対応しない。削除の操作を許可から外し、
  ゴミ箱へは ⌘⌫ と「ゴミ箱に入れる」で入れる（FR-344）
- Q: マスクの変更だけで Finder・Dock が期待どおりに動くかは未実証。いつ確かめるか？ → A: 実装の最初に、マスクだけを変えた版で保守者が macOS で確かめ、
  その結果で仕様を確定してから残りを実装する（tasks.md の Phase 2）
- Option と ⌘ を同時に押すと、Finder ではエイリアスの操作になり、OS がドラッグ元の許可をリンクだけに絞ると考えられる。
  先の決定（Option を優先してコピー）を改め、OS が絞った許可に従う（FR-346）
- 衝突の「中止」は、既存の動作どおり、それまでに完了した項目を残して残りを行わない（SC-182。`Tests/FolzioAppTests/FileTransferCancellationTests.swift`）
- 検索結果から外へ移動した項目は、FSEvents による除外に加えて、アプリ内の移動と同じく記録し、検索中に遅れて届く古い結果を出さない（EC-236）
- Q: 遅れて届く古い結果を防ぐ記録は、いつ行うか？（Finder は移動を非同期で行うと考えられ、ドラッグの終了の時点では項目がまだ元の場所にある恐れがある）
  → A: FSEvents の報告で、消えた項目を検索結果から外すときに記録する。記録するのは、消えた結果の行そのものではなく、その祖先のうち消えている一番上のフォルダ
  （検索のルートまで）とする（フォルダごと移動されたとき、まだ届いていない同じフォルダの別のファイルも防ぐため。3回目の設計レビュー）。
  ドラッグ以外のアプリ外の移動・削除にも同じく効く。

### Session 2026-11-07（先に行う確認の結果、T005）

保守者が、マスクだけを変えた版（`6e8f2a3`）を macOS で確かめた（`checklists/validation.md`）。

- Finder（同じボリューム）: 修飾キーなしで移動、Option でコピー、⌘ で移動になった。Finder（別のボリューム）: 修飾キーなしでコピー、⌘ で移動になった
- Dock のゴミ箱: ファイルは元の場所に残った（Dock はドラッグ元に削除を任せる）。保守者の先の決定どおり、Dock のゴミ箱には対応しない。
  削除の操作をマスクから外し、FR-079 の変更を取り下げる（FR-344・US75-AS5・A-129（変更））
- Option と ⌘ を同時に押して Finder へドラッグ: 何も起きなかった（受け付けないカーソル）。エイリアスを対象外とする A-206 と合う
- Finder から Option と ⌘ を同時に押して Folzio のツリーへドラッグ: 宛先が強調された。今のツリーはドラッグ元がコピーを許可するときだけ受け付けるので
  （`DirectoryTreeViewController.swift:1806-1813`）、Finder はこのときもコピーを許可している。FR-346 の規則（OS の許可に従い、Option はコピー）により、コピーになる
  検索の途中で項目が元の場所に戻されると、その場所の遅れた結果も表示しなくなる（今も FSEvents では結果を足さないため、影響は小さい）（EC-236、research.md R8）

## User Scenarios & Testing *(mandatory)*

### User Story 75 - Folzio の項目を他のアプリへ渡す (Priority: P1)

ユーザーは、Folzio のツリー・リスト形式・サムネイル形式から、ファイルやフォルダを Finder のフォルダや
Web ブラウザのアップロード欄へドラッグして、移動・コピー・アップロードできる。

**Why this priority**: TAK-74 の主目的。Folzio で画像を選んでから Finder で探し直す手間をなくす。

**Independent Test**: ツリーの通常のフォルダ、リスト形式とサムネイル形式のファイル、検索結果のファイルを、Finder のウインドウ
（同じボリュームと別のボリューム）、ブラウザのファイル選択欄へドラッグし、結果と Folzio の表示を確かめる。Dock のゴミ箱へのドラッグで何も変わらないことも確かめる。

**Acceptance Scenarios**:

- **US75-AS1**: **Given** リスト形式またはサムネイル形式でファイル A・B を選択している, **When** 同じボリュームの Finder のフォルダへドラッグしてドロップする,
  **Then** A・B がそのフォルダへ移動し、Folzio の一覧から消える（EC-236）。Option を押してドロップするとコピーになり、一覧に残る
- **US75-AS2**: **Given** ツリーで通常のフォルダ F を選択している, **When** F の行を別のボリュームの Finder のフォルダへドラッグしてドロップする,
  **Then** Finder の規則どおり F が中身ごとコピーされ、ツリーの F は残る
- **US75-AS3**: **Given** 画像ファイルを選択している, **When** Web ブラウザのファイルのアップロード欄へドラッグしてドロップする,
  **Then** ブラウザがそのファイルを受け取り、Folzio の元のファイルは変わらない
- **US75-AS4**: **Given** zip の中の項目、`..`、ホーム・ボリュームの最上位、お気に入りの項目を指している, **When** そこからドラッグを始める,
  **Then** ドラッグは始まらない（FR-162（file-operations.md）と同じ）
- **US75-AS5**: **Given** ファイルまたはツリーのフォルダを選択している, **When** Dock のゴミ箱へドラッグしてドロップする,
  **Then** 項目は元の場所に残り、Folzio の表示も変わらない（Dock のゴミ箱には対応しない。FR-344）。ゴミ箱へは ⌘⌫ と「ゴミ箱に入れる」で入れる

### User Story 76 - Finder の項目を Folzio のフォルダへ受け取る (Priority: P1)

ユーザーは、Finder などのアプリからファイルやフォルダを、Folzio のツリーのフォルダ・リスト形式のフォルダの行・
サムネイル形式のフォルダのアイコンへドラッグして、移動・コピーできる。

**Why this priority**: TAK-74 の主目的。Folzio を整理の受け皿にする。今はツリーだけが受け付ける。

**Independent Test**: Finder から、同じボリュームと別のボリュームのファイルを、ツリーのフォルダ・利用可能なお気に入り・リスト形式の
フォルダの行・サムネイル形式のフォルダのアイコン・検索結果のフォルダへドロップし、修飾キーなし・Option・⌘ の各場合の結果を確かめる。

**Acceptance Scenarios**:

- **US76-AS1**: **Given** Finder で、宛先と同じボリュームのファイル A を選択している, **When** リスト形式のフォルダの行へドラッグしてドロップし、確認モーダルで確定する,
  **Then** A がそのフォルダへ移動する。Option を押してドロップするとコピーになる
- **US76-AS2**: **Given** Finder で、別のボリュームのファイル B を選択している, **When** サムネイル形式のフォルダのアイコンへドラッグしてドロップする,
  **Then** B がそのフォルダへコピーされる（確認モーダルは FR-024（file-operations.md）の省略設定に従う）。⌘ を押してドロップすると移動になる
- **US76-AS3**: **Given** 宛先に同じ名前の項目がある, **When** Finder の項目をドロップする,
  **Then** 設定に関わらず「置き換える / 両方残す / 中止」を選ぶダイアログが表示される（FR-025（file-operations.md））
- **US76-AS4**: **Given** Finder の項目をドラッグしている, **When** リストの背景・`..`・ファイル・zip ファイル・zip の中・お気に入りの見出し・
  見つからないお気に入りの上へ来る, **Then** 宛先は強調されず、ドロップしても何も変わらない
- **US76-AS5**: **Given** Finder で、Folzio のツリーのフォルダ P を選択している, **When** P を P 自身または配下のフォルダへ、または P の親へ移動しようとする,
  **Then** 宛先は有効にならない（EC-16・EC-121（file-operations.md））
- **US76-AS6**: **Given** ブラウザに表示中の画像・リンク・文字列のうち file URL を持たないものをドラッグしている, **When** Folzio のフォルダの上へ来る,
  **Then** 宛先は強調されず、ドロップしても何も変わらない（FR-348）。file URL を持つ場合（ローカルのファイルを表示中など）は、そのファイルの移動・コピーとして扱う

### Edge Cases

- **EC-236**: アプリ外へドラッグした項目が、ドロップ先のアプリによって移動・削除された場合、システムは EC-13（overview.md）と同じく
  ツリー・ファイルリスト・プレビューに反映しなければならない。
  - ファイルリストに表示中のフォルダ（または祖先）がツリーから外へ移動された場合は、アプリ外で削除された場合の既存の扱いに従う
  - 検索結果の表示中は、移動・削除された項目を、アプリ内の移動と同じく検索結果から外す（FR-087（search.md））
  - 検索中に遅れて届く、移動・削除された項目の古い場所の結果も表示しない（アプリ内の移動と同じ）
  - この記録は、Folzio からのドラッグに限らず、アプリ外で移動・削除された項目を検索結果から外すとき（EC-13）に行う
  - フォルダごと移動・削除された場合は、そのフォルダの配下で、まだ届いていない別の項目の古い場所の結果も表示しない
- **EC-237**: アプリ外から受け取る項目に、宛先と同じボリュームのものと別のボリュームのものが混在する場合、修飾キーがなければコピーとする。
  - 元の項目を消す移動は、すべてが同じボリュームのときだけにする
- **EC-238**: ドラッグ元のアプリが、決めた操作（移動またはコピー）を許可していない場合、システムはもう一方の操作が許可されていれば
  それに切り替え、どちらも許可されていなければ宛先を有効にしない。
  - 修飾キーを押しているときは OS がドラッグ元の許可を絞るため（Option はコピー（`.copy`）、⌘ は移動（`.generic`））、切り替えは主に修飾キーなしのときに起こる
- アプリ内のドラッグ（ツリー・ファイルリストの間）の規則（FR-020・FR-162〜FR-165（file-operations.md））は変えない。
  Folzio のビューから始めたドラッグは、Folzio の中へドロップしたときは常にアプリ内のドラッグとして扱う
- ドラッグ中またはドロップ後の確認中に、受け取る項目や宛先が消えた・アクセスできなくなった場合は EC-122（file-operations.md）に従う

## Requirements *(mandatory)*

### Functional Requirements

- **FR-344**: Folzio のビューから始めたドラッグをアプリ外へドロップするとき、システムはドロップ先にコピーと移動を許可しなければならない。
  - ドラッグ元の範囲は FR-162（file-operations.md）と同じ（ツリー・リスト形式・サムネイル形式・検索結果）
  - どちらの操作にするか（修飾キー、同じボリュームかどうか）はドロップ先のアプリが決め、Folzio は確認モーダルを表示しない
  - Dock のゴミ箱へのドラッグには対応しない。Dock はドラッグ元に削除を任せるため（T005 で確認）、削除の操作を許可しない。Folzio はドラッグ元として項目を削除しない
  - FR-024 の移動の確認は、アプリ外のドロップ先が実行する移動には適用しない（FR-024（変更））
- **FR-345**: システムは、アプリ外からのドラッグを、FR-163（file-operations.md）のアプリ内のドラッグと同じ宛先で受け付けなければならない。
  - 宛先: ツリーの実在するフォルダ行（ホーム・ボリュームの最上位を含む）、利用可能なお気に入りの項目（登録したフォルダ）、
    リスト形式のフォルダの行、サムネイル形式のフォルダのアイコン、検索結果のフォルダ
  - お気に入りの見出し、見つからないお気に入り、`..`、ファイル、zip ファイル、zip の中、リストと検索結果の背景、行間にはドロップできない
  - 有効な宛先は FR-164（file-operations.md）と同じく視覚的に強調し、修飾キーの変更に追従して操作の種類と有効性を更新し、ドロップ時にも再検証する
- **FR-346**: アプリ外から file URL を受け取ったとき、システムは Finder と同じ規則で移動かコピーかを決めなければならない。
  - 修飾キーがなければ、受け取るすべての項目が宛先と同じボリュームにあるときは移動、それ以外はコピー（EC-237）
  - ドロップ時に Option を押していればコピー、⌘ を押していれば移動とする
  - Option と ⌘ を同時に押したとき（Finder ではエイリアスの操作）は、OS が絞ったドラッグ元の許可に従い、
    コピーも移動も許可されていなければ宛先を有効にしない（A-206）
  - ドラッグ元のアプリが許可しない操作は EC-238 に従う
  - 自分自身・配下への転送、親と同じ場所への移動、フォルダと配下の同時の転送は、EC-16・EC-121（file-operations.md）と同じく全体を拒否する
- **FR-347**: アプリ外から受け取る移動・コピーは、既存のファイル操作の確認（FR-022〜FR-024）、衝突（FR-025）、
  失敗の表示（FR-026）、結果の反映（FR-027・FR-165）に従わなければならない。
  - 移動は確認モーダルの省略設定に関わらず確認し、コピーは省略設定に従う（FR-024）
  - 受け取った項目の元の場所が Folzio に表示中のフォルダにある場合、移動の結果は EC-13（overview.md）と同じく反映する
- **FR-348**: システムは、アプリ外からのドラッグのうち、file URL を持つものだけを受け付けなければならない。
  - file URL を持たないドラッグ（ブラウザの画像のデータ・ファイルの書き出しの約束、URL、文字列）は宛先を有効にしない（A-204）
  - アプリ外からのドラッグを受け取るために、ネットワークへ通信しない

### Key Entities *(include if feature involves data)*

- **アプリ外からのドラッグ**: Folzio 以外のアプリ（または Folzio に登録していないビュー）から始まったドラッグ。受け付けるデータは file URL だけ（FR-348）
- **受け取りの操作**: 移動かコピー。宛先、対象の項目のボリューム、修飾キー、ドラッグ元が許可する操作で決まる（FR-346）
- **ドロップ先のアプリ**: Folzio からアプリ外へのドラッグを受け取るアプリ（Finder、ブラウザ、Dock など）。移動とコピーのどちらにするかを決める

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-180**: ツリー・リスト形式・サムネイル形式・検索結果の各ドラッグ元から、Finder（同じボリュームと別のボリューム）・
  Safari と Chrome のファイルのアップロード欄へのドラッグを試し、受け取りを拒否される・操作の種類が Finder の規則と食い違う組み合わせが0件。
  Dock のゴミ箱へのドラッグで、項目が移動・削除される場合が0件。
- **SC-181**: Finder から、ツリーのフォルダ・利用可能なお気に入り・リスト形式のフォルダの行・サムネイル形式のフォルダのアイコン・
  検索結果のフォルダの各宛先へ、修飾キーなし・Option・⌘ の各場合を試し、移動とコピーの結果が FR-346 と食い違う組み合わせが0件。
- **SC-182**: 無効な宛先・確認のキャンセルの各場合で、宛先のフォルダと元の項目に変更が残るものが0件。
  衝突の中止では、中止した項目とその後の項目に変更が残るものが0件（それまでに完了した項目は残る。既存の動作で、
  `Tests/FolzioAppTests/FileTransferCancellationTests.swift` が確かめている）。
- **SC-183**: file URL を持たないブラウザの画像・リンク・文字列のドラッグで、宛先が有効になる、または Folzio がネットワークへ通信する場合が0件。
- **SC-184**: アプリ内のドラッグ（SC-074・SC-075（file-operations.md）の確認の組み合わせ）で、この変更の前と結果が変わるものが0件。

## Assumptions

- **A-202**: アプリ外へのドラッグの移動は、ドロップ先のアプリ（Finder）が実行し、取り消しもそのアプリ（Finder の「取り消す」）で行う。
  - ユーザーがドロップ先と修飾キーを明示的に選ぶ操作であり、Finder 同士のドラッグと同じ扱いにする（憲章 原則 I の「確認または取り消し可能性」は、
    Finder の取り消しで満たすと解釈した）
- **A-203**: アプリ外から受け取る操作の決め方は、Folzio の中でのドラッグ（FR-020（file-operations.md）。常に移動、Option でコピー）と違い、
  Finder の規則に合わせた。
  - ドラッグ元が Finder なので、Finder の中でドラッグしたときと同じ結果にするため
  - 今のツリーでのアプリ外からのドロップ（常に移動、Option でコピー）は、この規則に変わる
- **A-204**: Web ブラウザに表示中の画像の取り込み（画像のデータ・ファイルの書き出しの約束の受け取り）は、この feature の範囲外とする。
  - 憲章 原則 III の「新しい操作にはキーボードの手段を同時に提供する」を満たすため、キーボードの手段（ブラウザの「画像をコピー」の後の ⌘V など）と合わせて別の Issue で扱う
  - FR-344〜FR-347 のキーボードの手段は既存の ⌘C・⌘V・⌥⌘V（FR-019）で、Folzio と Finder の間で file URL のコピー・ペーストとして使える
  - ツリーのフォルダには ⌘C がないため、ファイルリストで親フォルダの一覧を表示し、そのフォルダを選んで ⌘C する（014 と同じ手段）
  - お気に入りはペースト先にならない（A-20）ため、お気に入りのフォルダをファイルリストに表示し、ファイルリストで ⌘V・⌥⌘V する
- **A-205**: Folzio から始めたドラッグをほかのアプリへ渡すデータは、今と同じ file URL だけとする（画像データやファイルの書き出しの約束は加えない）。
- **A-206**: エイリアスの作成（Finder の ⌥⌘ ドラッグ）は対象外とする。
- **A-20（変更）**: お気に入りの見出しはドロップ先・ペースト先にしない。
  - 利用可能なお気に入りの項目は、アプリ内とアプリ外からのドラッグのドロップ先として、登録先の実フォルダを使える
  - 見つからない項目はドロップ先にしない
  - お気に入りの項目をペースト先にはしない
- **A-129（変更）**: ツリーの一括削除はドラッグでは行わない。
  - ⌘⌫ とメニュー・右クリックの「ゴミ箱に入れる」で行い、ファイルリストの一括削除と同じ操作経路にする
  - Dock のゴミ箱などアプリの外へのドラッグでも削除しない（FR-344。Dock のゴミ箱には対応しない）

## 変更する既存の要件

- **FR-024（変更）**: 確認モーダルの省略は、コピー（ツリーのフォルダへのペースト・ドロップによるコピーを含む）と、
  ファイルリストからの削除（ゴミ箱へ入れる）と、お気に入りの削除（FR-064）にだけ適用されなければならない。
  - 名前の変更（ツリーのフォルダの名前の変更（FR-103）を含む）と移動、
    およびツリーのフォルダをゴミ箱に入れる操作（FR-079）は、設定に関わらず常に確認モーダルを表示しなければならない。
  - 設定ウインドウの確認の項目には、名前の変更・移動・ツリーのフォルダをゴミ箱に入れる操作を、
    設定に関わらず常に確認する操作として示す（FR-223（window-layout.md））。
  - 複製（FR-018）とフォルダの新規作成（FR-209）、および作成直後のフォルダの名前の編集（FR-211）
    は確認モーダルの対象外とし、設定にも影響されない。
  - Folzio からアプリ外へドラッグし、ドロップ先のアプリが実行する移動（FR-344）は、確認モーダルの対象外とする。
  - 省略時の安全性は、削除が必ずゴミ箱経由で元に戻せること（FR-021）、コピーが元のファイルを変更しないこと、
    同名ファイルの上書きが常に確認されること（FR-025）で担保する。
  - この方針は憲章 v1.1.0 原則 I の「確認または取り消し可能性」に従う

- **FR-163（変更）**: 宛先はツリーの実在するフォルダ行（ホーム・ボリュームのルート、利用可能なお気に入りを含む）
  または通常一覧・検索結果の実フォルダ項目とする。
  - お気に入り見出し、見つからないお気に入り、`..`、ファイル、zip ファイル、zip 内、検索結果の背景、リストの背景、
    行間にはドロップできない。
  - アプリ外からのドラッグも同じ宛先で受け付ける（FR-345）。
  - アプリ外へのドラッグは FR-344 に従う。
