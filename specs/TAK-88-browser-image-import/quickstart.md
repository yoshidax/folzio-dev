（`docs_private/cloud-agent-workflow.md` の 5 章）。結果は `checklists/validation.md` に記録する。

```bash
scripts/make-app.sh
```

- Safari と Chrome で、JPEG・PNG・GIF・WebP の画像のあるページを開く

## 先に行う確認（R1）

```bash
swift scripts/dev/pasteboard-probe.swift
```

- スクリプトのウインドウへ、Safari・Chrome の画像、写真アプリの写真・動画をドラッグし、表示された型・約束の種類・マスク・書き出された名前と時間を記録する
- 各アプリで「コピー」した後に、スクリプトのクリップボードの表示を記録する
- 200 MB 程度の TIFF をクリップボードに置いたときの、読み出しの時間を記録する

### 確認スクリプトの使い方

- 「確認するケース」にアプリ・形式・操作を書く（例: `Safari / JPEG / ドラッグ`）。ログを保存するときは次で起動する

```bash
swift scripts/dev/pasteboard-probe.swift | tee /tmp/folzio-pasteboard-probe.log
```

- ドロップすると型・マスクと、選んだ画像の型の `bytes`・`readSeconds` が出る。
  型は「自動」または PNG・JPEG・HEIC・TIFF から選べる。PNG と TIFF の両方があるときは、型を切り替えて同じ操作を繰り返す
- コピーを調べるときは、まず「クリップボードを調べる」を押す。各項目の各型について容量と UI スレッドでの読み出し時間が出る。
  約束の有無と書き出しは、別の「クリップボードの約束を書き出す」ボタンで確かめる
- 約束の `fileNames(before)` は空でも失敗としない。`fileNames(requested)`・`fileNames(after)` と、
  `readerCount`・`seconds`・書き出された名前と大きさ、またはエラーを記録する。複数ファイルの約束では `readerCount` が増える
- 「200 MB TIFF をコピー」「256 MB TIFF をコピー」は、非圧縮 TIFF をバックグラウンドで作り、一般のクリップボードを置き換える。
  実際の容量は `generatedTIFF bytes` を記録し、生成後に「クリップボードを調べる」で読む。実アプリからの遅延提供とは別の測定として記録する
- 下の2つの「ここからドラッグ」は、ともに PNG の約束を渡す。`cat.png` の中身は JPEG、`logo.svg` の中身は PNG。
  この段階ではこのスクリプト自身のドロップ欄へドラッグし、受け取りとファイルの名前を確かめる。Folzio への保存は T031 で確かめる
- 約束はログの `destination` の一時フォルダへ書き出す。同じドラッグの約束には共通の宛先を渡す。
  受け取りごとのフォルダは終了後も残すので、確認後に Finder で削除する
- 結果は `checklists/validation.md` の「T006 の実測結果」にまとめる。GUI を使わない確認用画像の自己検査は次で実行できる

```bash
swift -swift-version 6 scripts/dev/pasteboard-probe.swift --self-test
```

## 安全性（SC-190・SC-196）

- 自動テスト（`Tests/FolzioCoreTests/ImportedFileNameTests.swift`・`ImportInspectorTests.swift`・`ImportCleanupRecordTests.swift`）で、
  細工した名前・種類・大きさ・構造・起動時の記録の各場合を確かめる。CI で実行する
- 保守者は、動作の確認として次を行う
  - 中身が JPEG で名前が `.png` のファイルを書き出すアプリ（R1 のスクリプトの書き出しの機能）からドラッグし、`.jpg` で保存されること
  - 書き出しの途中で Folzio を強制終了し、次の起動の後に一時的なフォルダが残らないこと（SC-188）

## 受け取りの流れと性能（EC-245・EC-246・SC-188・SC-189）

- 自動テストは `ImportBudgetTests.swift`・`ImportReceptionStateTests.swift` で、実時間を待たずに 60 秒・600 秒と容量の境界、
  状態の移り変わりを確かめる。`Tests/FolzioAppTests/ImportSessionTests.swift` で、遅い結果の拒否と掃除、宛先の失敗、複数の操作と確認の直列化を確かめる
- 保守者は、長くかかる動画の書き出しなどで次を確かめる。時間を制御する確認は上記の自動テストでも行う
  - 受け取りを待つ間と確認モーダルを開いている間のそれぞれで、別のアプリから宛先を削除、または書き込み不可にする。
    失敗の表示があり、宛先に保存されず、一時的なファイルが残らない（EC-245）
  - 別の宛先へ2つの受け取りを始め、パネルに2行が出ること、片方の行の「取り消す」が他方に影響しないこと、
    ⌘. は最後に始めた操作を取り消すこと、確認モーダルと衝突のダイアログが1つずつ表示されることを確かめる（EC-246）
  - 受け取りを待つ間にフォルダの切り替えとプレビューを繰り返し、入力から表示が変わり始めるまでを画面収録などで測る。
    1 秒を超える場合がないこと、2 秒を超えた受け取りにはパネルが出て取り消せることを確かめる（SC-189）
- T006 の画像データの読み出し時間（R5 の 0.2 秒の判断）と、変更前後で同じ画像を同じ宛先へドラッグしたときの
  宛先の強調までの時間も記録する。macOS・機種・データの型と大きさ・両コミット・測定方法・結果を `checklists/validation.md` に残し、T040 で PR に記載する
