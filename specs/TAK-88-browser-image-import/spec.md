# Feature Specification: ブラウザの画像をフォルダへ保存する

**Feature Branch**: `claude/clever-knuth-udimb8`

**Created**: 2026-11-08

**Status**: Draft

**Input**: TAK-88 https://linear.app/takyoshida/issue/TAK-88 — Web ブラウザに表示中の画像を、ドラッグとキーボードで Folzio のフォルダへ
ファイルとして保存できるようにする。TAK-74 で範囲外にした A-204（file-operations.md）を、キーボードの手段と合わせて扱う。

## Clarifications

### Session 2026-11-08

- Q: キーボードの手段の形は？ → A: 既存のペースト（ファイルリストの ⌘V・右クリックの「ペースト」、ツリーの ⌘V・「ここにペースト」）で受ける。
  クリップボードに file URL がなく画像データがあるとき、画像を保存する。移動ペースト（⌥⌘V・「移動ペースト」・「ここに移動ペースト」）は、
  画像データだけのときは無効にする（FR-354）
- Q: 画像データを保存する形式は？ → A: 常に PNG。データが PNG ならそのまま書き、ほかの形式は PNG に変換する（FR-351）
- Q: ブラウザの書き出し（file promise）が終わらない・失敗したときは？ → A: 60 秒で打ち切り、失敗として表示する。宛先には何も作らず、
  一時ファイルを残さない（FR-355・EC-239）
- Q: 1回のドロップで複数の画像を受け取るとき、Folzio の対応形式にない画像のときは？ → A: TAK-74 の旧設計どおり。
  まとめて1回の操作として確認し、一部の失敗は成功した分と区別して伝える。対応形式にない画像もファイルとして保存する（EC-240・EC-242）
- 保守者の指示: セキュリティの観点を含める。攻撃目的のページ・リンクによって危害を加えられる穴を作らない（FR-353・FR-357〜FR-360）
- Q: file promise で受け取るファイル（名前と中身をページ側が決められる）の範囲は？ → A: 画像の通常ファイルだけ。
  画像の種類には Folzio の非対応形式の画像も含む。フォルダ・パッケージ・シンボリックリンク・エイリアス・画像以外の種類は保存せず、理由を示す（FR-357）
- Q: 「インターネットから入手した」印（quarantine 属性）は？ → A: 受け取ったファイルの印を引き継ぎ、印がないものと Folzio が画像データから書くファイルには、
  Folzio が付ける（FR-358）
- Q: 巨大な画像への上限は？ → A: 画像データは 1 件 256 MB まで。PNG 以外を PNG へ変換するのは 1 億画素以下の画像だけ。
  超えたものは保存せず、理由を示す。PNG のデータは展開せずにそのまま書く（FR-359）
- Q: 拡張子の偽装（中身と拡張子が食い違う、中身が画像でない）は？ → A: 保存の前に中身を画像として判別する（展開はせず、形式と画像の数だけを調べる）。
  判別できなければ保存しない。判別した形式と拡張子が食い違うときは、拡張子を中身の形式のものに直して保存する（FR-357・FR-360）
- Q: 画像に分類されていてもスクリプトを持てる形式（SVG・EPS・PostScript・PDF）は？ → A: 保存しない。画素を持つ画像の形式だけを保存する（FR-357）

### Session 2026-11-08（spec のレビュー）

- 名前の条件に名前の変更の検証をそのまま使うと、宛先に同じ名前がある名前も不正となり、衝突のダイアログ（FR-025）を出さずに日時の名前へ変わる。
  名前の条件は文字と長さの規則だけとし、同じ名前の項目の有無は FR-025 で扱う（FR-357）
- 拡張子で先に拒否すると、拡張子のない・変わった拡張子の正しい画像（`download`、`photo.jpg_large`）を FR-360 で直せない。
  種類の判定は中身だけで行い、拡張子は FR-360 で中身の形式のものに直す（FR-357・FR-360）
- 宛先と同じボリュームの一時的なフォルダから、宛先へはファイルを移す（複製しない）。ディスクを 2 倍使わないため（FR-350）
- Q: quarantine の印を付けられない宛先（拡張属性を保存できない共有など）は？ → A: 印なしで保存する。安全性は FR-357 で保ち、印は補助の守りとする（FR-358・A-211）
- Q: 表計算のセル・Keynote の図形など、画像でないもののコピーに含まれる絵（TIFF・PNG）は？ → A: 画像データとして保存する。コピー元を問わない（FR-354・A-214）
- Q: 複数の画像を含むデータ・ファイル（アニメーション GIF、複数ページの TIFF）は？ → A: 書き出されたファイルと PNG のデータは、変換しないのですべての画像を残す。
  PNG 以外のデータを PNG に変換するときは 1 枚目だけを使い、1 億画素の上限も 1 枚目で数える（FR-351・FR-359）
- Q: 書き出されたファイルの大きさの上限は？ → A: 画像データと同じく 1 件 256 MB（FR-359）
- ドロップの間にペーストボードの画像データを UI スレッドで読むと、大きなデータで UI が止まる。読み出しも UI を待たせない形にし、方法は plan で決める（FR-355）

### Session 2026-11-08（spec の2回目のレビュー）

- SVG・EPS・PostScript・PDF の拒否も中身だけで判定する。拡張子が `.svg` でも中身が PNG なら、FR-360 で `.png` に直して保存する（FR-357）
- 名前の長さの規則は既存の名前の検証にないため、FR-357 で定める（拡張子を含めて UTF-8 で 200 バイト以下。連番を付けても 255 バイトに収める）
- 1回の操作の約束どうしの名前の重なりは、約束ごとに一時的なフォルダの中の別のフォルダへ書き出させ、宛先の名前は EC-243 の連番で重ならないようにする（FR-350・EC-243）
- 1つの項目に複数の画像データの種類があるときは、PNG を選び、なければほかの画素を持つ画像の種類を選ぶ（FR-351）
- Q: クリップボードの file promise（写真アプリのコピーなど）は？ → A: ペーストでもドラッグと同じく、file URL、file promise、画像データの順に使う（FR-354・EC-241）
- Q: Folzio が付ける quarantine の印に記録するものは？ → A: アプリ名と日時だけ。URL は記録しない。引き継ぐ印は変えない（FR-358）
- Q: 強制終了で残る一時的なフォルダは？ → A: 作った場所を記録し、次の起動で、記録に残る場所だけを消す（EC-247・FR-361）
- Q: 書き出し中に大きさが上限を超えたら？ → A: 待つ間も 1 秒ごとに大きさを調べ、操作全体で 256 MB × 約束の件数を超えたら失敗として打ち切り、一時的なフォルダを消す（FR-359）
- ページは非同期のクリップボード API で、クリック1回で画像をクリップボードへ書ける。A-211 の脅威に加える（保存の規則は変えない）

## User Scenarios & Testing *(mandatory)*

### User Story 77 - ブラウザの画像をドラッグしてフォルダへ保存する (Priority: P1)

ユーザーは、Web ブラウザに表示中の画像を、Folzio のツリーのフォルダ・お気に入り・リスト形式のフォルダの行・
サムネイル形式のフォルダのアイコン・ファイルリストの背景へドラッグして、ファイルとして保存できる。
ブラウザの「名前を付けて保存」と保存先の選択を省き、閲覧中の画像を整理先のフォルダへ直接入れる。

**Why this priority**: TAK-88 の主目的。TAK-74 で Finder とのドラッグに対応したが、ブラウザの画像は受け付けていない（FR-348（file-operations.md））。

**Independent Test**: Safari と Chrome で Web の画像を表示し、FR-345（file-operations.md）の各宛先へドラッグしてドロップし、
作られたファイルの名前・形式・内容と、確認・衝突・失敗の表示を確かめる。リンクや文字列だけのドラッグで宛先が有効にならないことも確かめる。

**Acceptance Scenarios**:

- **US77-AS1**: **Given** ブラウザに画像を表示している, **When** その画像をツリーのフォルダへドラッグしてドロップする,
  **Then** ブラウザが付けた名前と形式で、画像がそのフォルダに保存される。保存はコピーとして扱い、確認モーダルは FR-024（file-operations.md）の省略設定に従う
- **US77-AS2**: **Given** ブラウザがファイルの書き出しの約束を渡さず、画像データだけを渡す, **When** その画像をフォルダへドロップする,
  **Then** 画像は PNG 形式で、FR-352 の名前で保存される
- **US77-AS3**: **Given** ブラウザのリンクや文字列（file URL・ファイルの書き出しの約束・画像データのどれもない）をドラッグしている, **When** フォルダの上へ来る,
  **Then** 宛先は強調されず、ドロップしても何も変わらない。Folzio はその URL へ通信しない（FR-348（変更）・FR-353）
- **US77-AS4**: **Given** 宛先に同じ名前のファイルがある, **When** 画像をドロップする,
  **Then** 設定に関わらず「置き換える / 両方残す / 中止」を選ぶダイアログが表示される（FR-025（file-operations.md））
- **US77-AS5**: **Given** 確認モーダルまたは衝突のダイアログが表示されている, **When** キャンセル・中止する,
  **Then** 宛先のフォルダには何も作られず、取り込みのために作った一時的なファイルも残らない（FR-350）
- **US77-AS6**: **Given** 画像をドラッグしている, **When** Option または ⌘ を押しながらフォルダの上へ来てドロップする,
  **Then** 修飾キーに関わらず、コピーとして示され、コピーとして保存される（FR-356）
- **US77-AS7**: **Given** ファイルリストに通常のフォルダ F の一覧を表示している, **When** ブラウザの画像を一覧の背景へドロップする,
  **Then** 一覧全体が宛先として強調され、画像は F に保存される（FR-349（file-operations.md））

### User Story 78 - コピーした画像をペーストしてフォルダへ保存する (Priority: P1)

ユーザーは、ブラウザの「画像をコピー」でクリップボードに入れた画像を、Folzio のファイルリストの ⌘V・「ペースト」、
ツリーの ⌘V・「ここにペースト」で、表示中のフォルダ・選択したフォルダへファイルとして保存できる。
ドラッグと同じ操作をキーボードで行えるようにする（憲章 原則 III）。

**Why this priority**: 憲章 原則 III は、新しい操作にキーボードで到達できる手段を同時に提供することを求める（MUST）。US77 と同時に提供しなければならない。

**Independent Test**: Safari と Chrome で Web の画像を「画像をコピー」し、ファイルリストとツリーでペーストして、作られたファイルを確かめる。
移動ペーストが無効であること、リンクや文字列だけのクリップボードでペーストが無効であることも確かめる。

**Acceptance Scenarios**:

- **US78-AS1**: **Given** ブラウザで画像を「画像をコピー」し、ファイルリストに通常のフォルダ F の一覧を表示している, **When** ⌘V を押す,
  **Then** 画像が PNG 形式で、FR-352 の名前で F に保存される。確認・衝突・失敗は FR-347（変更）に従う
- **US78-AS2**: **Given** 同じクリップボードで、ツリーの通常のフォルダ G を選択している, **When** ⌘V を押す、または G の右クリックの「ここにペースト」を選ぶ,
  **Then** 画像が G に保存される
- **US78-AS3**: **Given** クリップボードに画像データだけがある（file URL がない）, **When** 編集メニューと右クリックメニューを開く,
  **Then** 「ペースト」「ここにペースト」は有効、「移動ペースト」「ここに移動ペースト」は淡色で選べない（⌥⌘V も何もしない）
- **US78-AS4**: **Given** クリップボードにリンクや文字列だけがある, **When** ファイルリストとツリーのメニューを開く,
  **Then** ペーストと移動ペーストはどちらも淡色で選べない（今と同じ）
- **US78-AS5**: **Given** クリップボードに file URL と画像データの両方がある（Finder でファイルをコピーした場合など）, **When** ⌘V を押す,
  **Then** 今と同じく、file URL の項目がコピーされ、画像データは使わない（EC-241）
- **US78-AS6**: **Given** 画像をコピーし、zip の中または検索結果を表示している, **When** ⌘V を押す,
  **Then** 何も起きない（今と同じく、ペーストは無効。FR-073（zip.md）・search.md の検索結果へのペースト）
- **US78-AS7**: **Given** 画像をコピーし、名前の変更の編集欄で入力している, **When** ⌘V を押す,
  **Then** 今と同じく、編集欄への文字列の貼り付けとして扱い、画像は保存しない
- **US78-AS8**: **Given** 写真アプリで写真をコピーした（クリップボードにファイルの書き出しの約束と縮小した画像データがある）, **When** ファイルリストで ⌘V を押す,
  **Then** 写真アプリが書き出した元のファイル（名前と形式）が保存される。縮小した画像データは使わない（EC-241）

### Edge Cases

- **EC-239**: ブラウザがファイルの書き出しに失敗した場合（画像の取得に失敗した、60 秒で書き出しが終わらない（FR-355）など）、
  システムは FR-026（file-operations.md）と同じく対象の名前と失敗の理由を表示し、宛先には何も作らない。
  - 書き出しを待つ間も、Folzio の操作（ほかのフォルダの表示、プレビュー、ほかのファイル操作）は止まらない
  - 名前が分からない約束は、FR-352 の日時の名前（拡張子を付けない）で示す
- **EC-240**: 1回のドロップ・ペーストに複数の画像（ファイルの書き出しの約束・画像データ）がある場合、まとめて1回の操作として確認し、
  一部が失敗したときは FR-026 に従って成功した分と失敗した分を区別して伝える。
- **EC-241**: アプリ外から受け取るドラッグ・クリップボードに、複数の種類のデータがある場合は、file URL、ファイルの書き出しの約束、画像データの順に1つを選ぶ。
  - file URL があれば、今と同じく file URL の項目の移動・コピー（FR-346（file-operations.md））として扱い、ほかのデータは使わない
  - ペーストも同じ順にする（写真アプリなどは、コピーでもクリップボードにファイルの書き出しの約束と縮小した画像データを入れる。FR-354）
- **EC-242**: 受け取った画像が Folzio の対応形式（overview.md）にない画像の形式（AVIF など）の場合も、FR-357 を満たせばファイルとして保存する。
  - 保存した後の表示は、既存の非対応形式の規則に従う
- **EC-243**: 1回の操作で宛先に作る名前が重なる場合（同じ秒の日時の名前、同じ URL の末尾の名前、同じ名前の約束、FR-360 で直した後に同じになる名前）、
  2つ目以降の名前には FR-018（file-operations.md）の連番の規則で番号を付け、操作の中で重ならないようにする。
  - 宛先の既存の項目との衝突は FR-025 に従う
- **EC-244**: 画像データを画像として読めない場合（壊れたデータ、画像でないデータ）、システムはそれを保存せず、FR-026 と同じく理由を表示する。
- **EC-245**: 書き出しを待つ間・確認の間に宛先のフォルダが消えた・書き込めなくなった場合、システムは FR-026 と同じく失敗を表示し、一時的なファイルを残さない。
- **EC-246**: 書き出しを待つ間に、ユーザーが別の画像を別の宛先へドロップ・ペーストした場合、それぞれを別の操作として扱う。
  - 確認モーダルとダイアログは、既存のファイル操作と同じく1つずつ表示する
- **EC-247**: Folzio が強制終了するなど、一時的なフォルダを消す前に終わった場合に残るファイルは、宛先のフォルダには現れず、次の起動で消す（FR-361）。
  - 一時的なフォルダは、宛先と同じボリュームの、OS が一時ファイルのために用意する場所に作る（FR-350）
- アプリ内のドラッグ（FR-020・FR-162〜FR-165（file-operations.md））と、file URL の受け取り（FR-344〜FR-347・FR-349（file-operations.md））の規則は変えない。
  Folzio のビューから始めたドラッグは画像データもファイルの書き出しの約束も持たない（A-205（file-operations.md））

## Requirements *(mandatory)*

### Functional Requirements

#### 受け付けるデータ

- **FR-348**（変更）: システムは、アプリ外からのドラッグのうち、file URL、ファイルの書き出しの約束、画像データのどれかを持つものだけを受け付けなければならない。
  - どれも持たないドラッグ（URL・文字列・HTML だけのもの）は宛先を有効にしない
  - 複数を持つときは EC-241 の順に1つを選ぶ
  - アプリ外からのドラッグを受け取るために、ネットワークへ通信しない（FR-353）
- **FR-350**: アプリ外から file URL がなく、ファイルの書き出しの約束（ドラッグ元のアプリがドロップ後にファイルを書き出す仕組み）を受け取ったとき、
  システムはドラッグ元のアプリに、宛先と同じボリュームの一時的なフォルダへファイルを書き出させ、書き出されたファイルを宛先へ保存しなければならない。
  - 操作の種類はコピーとして扱う（確認の省略設定・確認モーダルの表示・元の項目を消さないこと）
  - 一時的なフォルダから宛先へは、ファイルを移す（同じボリュームなので、内容を複製せず、ディスクを 2 倍使わない）
  - 約束ごとに、一時的なフォルダの中の別のフォルダへ書き出させる（同じ名前の約束が互いに上書きしないため。宛先の名前は EC-243）
  - ファイル名と形式は、ドラッグ元のアプリが書き出したものを使う（FR-360 で名前を直す場合を除く）
  - 確認・衝突でキャンセル・中止した場合、書き出しが失敗した場合、保存が終わった場合のどれでも、一時的なフォルダとその中身を消す
  - 宛先へ直接書き出させない（確認のキャンセルと衝突の「両方残す」を守るため）
- **FR-351**: アプリ外から file URL もファイルの書き出しの約束もなく、画像データを受け取ったとき、システムは画像を PNG 形式のファイルとして宛先へ保存しなければならない。
  - 1つの項目に複数の画像データの種類があるときは、PNG を選び、なければほかの画素を持つ画像の種類（TIFF など）を選ぶ
  - データが PNG のときは、変換せずにそのまま書く（複数の画像を含む PNG も、すべての画像を残す）
  - ほかの形式（TIFF など）のときは、PNG に変換して書く
  - 複数の画像を含むデータ（複数ページの TIFF など）を変換するときは、1 枚目の画像だけを使う
  - 保存は FR-350 と同じく、一時的なフォルダに書いてから宛先へ移す、コピーの操作として扱う
- **FR-352**: FR-351 で保存するファイルの名前は、同じドラッグ・クリップボードにある画像の URL（file URL でないもの）の末尾の名前とし、拡張子を `.png` にしなければならない。
  - 末尾の名前は、パーセントエンコードを解き、元の拡張子を除いて `.png` を付ける（`https://example.com/a/cat.jpg?w=1` → `cat.png`）
  - URL がない、または末尾の名前が FR-357 の名前の条件を満たさない場合は、「画像 2026-11-08 13.45.12.png」（英語: `Image 2026-11-08 13.45.12.png`）の形で、
    ドロップ・ペーストした日時から名前を付ける
  - 日時はローカルのタイムゾーンで、数字は ASCII にする
  - 名前の接頭辞（「画像」・`Image`）は表示言語に従う
  - URL から名前を取るために、その URL へ通信しない（FR-353）
  - 操作の中で名前が重なる場合は EC-243、宛先に同じ名前がある場合は FR-025（file-operations.md）に従う
- **FR-353**: システムは、画像の受け取り（ドラッグ・ペースト）のために、ネットワークへ通信してはならない。
  - ドラッグ・クリップボードにある URL は、名前を取るための文字列としてだけ扱い、開かない・取得しない・解決しない
  - HTML・リッチテキストなどの書式付きのデータは読まない
  - ファイルの書き出しの約束で、ドラッグ元のアプリ（ブラウザ）が画像を取得するために通信する場合は、そのアプリの動作であり、Folzio は通信しない

#### キーボードの手段

- **FR-354**: ユーザーは、クリップボードに file URL がなく、ファイルの書き出しの約束または画像データがあるとき、既存のペーストで、
  画像をドラッグと同じ規則（FR-350〜FR-353・FR-357〜FR-360）でファイルとして保存できなければならない。
  - 使うデータの順は、ドラッグと同じく file URL、ファイルの書き出しの約束、画像データとする（EC-241）
  - 対象のペーストは、ファイルリストの ⌘V・右クリックの「ペースト」（表示中のフォルダへ）、ツリーの ⌘V（選択した通常のフォルダへ）・右クリックの「ここにペースト」とする
  - ペーストできる場所と条件（zip の中・検索結果・お気に入りの項目・複数の行の選択中・名前の編集中は無効）は、file URL のペーストと同じにする
  - 移動ペースト（⌥⌘V・「移動ペースト」・「ここに移動ペースト」）は、file URL がないときは無効にする（Folzio が消す元の項目がないため）
  - 「ペースト」「ここにペースト」のメニュー項目は、クリップボードに file URL、ファイルの書き出しの約束、画像データのどれかがあるときに有効にする
  - 画像データは、コピー元のアプリと、ほかに文字列などがあるかを問わない（表計算のセルのコピーに含まれる絵も保存する。A-214）
  - メニューの有効・無効を決めるときは、クリップボードにあるデータの種類だけを調べ、データの中身を読まない
  - クリップボードの中身は、ユーザーがペーストを実行したときだけ読む
- **FR-355**: システムは、ファイルの書き出しの約束の書き出しを、ドロップ・ペーストから 60 秒で打ち切らなければならない。
  - 60 秒までに書き出されなかった約束は失敗として扱い、EC-239 に従う
  - 打ち切った後に書き出されたファイルは、宛先へ入れず、一時的なフォルダごと消す
  - 書き出し・変換・一時的なフォルダへの書き込みは UI スレッドで行わない
  - ドラッグ・クリップボードの画像データの読み出しも、UI の応答を待たせない形で行う（OS がドロップの間に読むことを求める場合の方法は plan で決め、
    A-212 の確認で 256 MB のデータにかかる時間を測る）
- **FR-356**: アプリ外から受け取る画像の保存（ファイルの書き出しの約束・画像データ）は、修飾キーに関わらず、コピーとして示し、コピーとして行わなければならない。
  - ドラッグ元のアプリがコピーを許可しない場合は、宛先を有効にしない
  - 宛先は FR-345（file-operations.md）と同じ範囲とし、強調と再検証も FR-345 に従う

#### 安全性

- **FR-357**: システムは、アプリ外から受け取る画像のファイル（書き出されたファイルと、画像データから作るファイル）を、次の条件を満たすものだけ宛先へ保存しなければならない。
  - 書き出されたファイルは、一時的なフォルダの直下にある通常のファイルであること（フォルダ・パッケージ・シンボリックリンク・エイリアスでないこと）
  - 一時的なフォルダの外を指すファイルは受け取らない
  - 中身を画像として判別できること（拡張子の偽装への対策。拡張子ではなく中身で判定する。中身の先頭の形式の情報と、含む画像の数だけを調べ、画像を展開しない）
  - 中身から判別した形式が、画素を持つ画像（JPEG・PNG・GIF・WebP・HEIC・AVIF・TIFF・BMP など。Folzio の非対応形式の画像を含む）であること
  - SVG・EPS・PostScript・PDF など、スクリプトや命令を含められる形式は、中身がそう判別されたら保存しない（拡張子だけが `.svg` で中身が PNG のものは、FR-360 で `.png` に直して保存する）
  - 名前の条件: 名前の変更の検証の文字の規則（空でない、`/` と `:` を含まない、`.` で始まらない）を満たし、制御文字と文字の向きを変える書式の文字を含まず、
    拡張子を含めて UTF-8 で 200 バイト以下であること
  - 200 バイトは、EC-243 と FR-025 の「両方残す」で連番を付けても、ファイル名の上限の 255 バイトに収めるための値である
  - 名前の条件は、宛先に同じ名前の項目があるかを含まない（同じ名前は FR-025 の衝突として扱う）
  - 拡張子は条件にしない。拡張子は FR-360 で中身の形式のものに直す（`photo.jpg.command` も、中身が JPEG なら JPEG の拡張子で保存され、中身が画像でなければ保存しない）
  - 名前の条件だけを満たさないファイルは、FR-360 の名前を付けて保存する
  - ほかの条件を満たさないファイル・データは保存せず、FR-026 と同じく名前と理由を表示する（「画像として読めません」「この形式の画像は保存できません」など）
- **FR-360**: システムは、書き出されたファイルの拡張子が、FR-357 で中身から判別した形式のものでない場合、拡張子を中身の形式のものに直して保存しなければならない。
  - 最後の拡張子を中身の形式の拡張子に置き換え、拡張子がなければ付ける
  - 例: 中身が JPEG のとき、`cat.png` → `cat.jpg`、`photo.jpg_large` → `photo.jpg`、`download` → `download.jpg`、`photo.jpg.command` → `photo.jpg.jpg`
  - 拡張子の大文字と小文字の違いだけのとき（`cat.JPG` と JPEG）、同じ形式の別の拡張子のとき（`.jpeg` と `.jpg`）は直さない
  - 書き出されたファイルの名前が FR-357 の名前の条件を満たさない場合は、中身の形式の拡張子で FR-352 の日時の名前を付けて保存する
  - FR-351 の画像データも同じく中身で判別し、PNG と判別できたものだけを変換せずに書き、ほかの画素を持つ画像は PNG に変換し、判別できないものは保存しない（EC-244）
  - 直した名前・付けた名前は、確認モーダルと衝突のダイアログに、宛先に作る名前として示す
- **FR-358**: システムは、アプリ外から受け取って保存した画像のファイルに、インターネットから入手したことを示す印（quarantine 属性）を付けなければならない。
  - 書き出されたファイルに印があれば、それを引き継ぐ
  - 印がない書き出されたファイルと、画像データから作るファイルには、Folzio が印を付ける
  - Folzio が付ける印には、アプリ名（Folzio）と保存した日時だけを記録し、URL（ページ・画像の場所）は記録しない
  - 印は、宛先へ移す前に、一時的なフォルダの中で付ける（印のないファイルが宛先に現れないため）
  - file URL の移動・コピー（FR-346）は、今と同じく元の項目の属性を変えない
  - 宛先のボリュームが拡張属性を保存できない場合は、印なしで保存し、失敗にしない（安全性は FR-357 で保つ。A-211）
- **FR-359**: システムは、アプリ外から受け取る画像データと書き出されたファイルの大きさを制限しなければならない。
  - 1件の画像データ、または1件の書き出されたファイルが 256 MB を超える場合は保存しない
  - 書き出しを待つ間も、一時的なフォルダの大きさを 1 秒ごとに調べ、256 MB × 約束の件数を超えたら、その操作の約束をすべて失敗として打ち切り、一時的なフォルダを消す
  - PNG 以外のデータを PNG に変換するのは、1 枚目の画像の画素数が 1 億以下のときだけとし、超える場合は保存しない
  - 画素数は、画像を展開する前に、画像の情報から調べる
  - 書き出されたファイルと PNG のデータは展開しないので、画素数の上限を適用しない
  - 保存しなかったデータ・ファイルは、FR-026 と同じく理由を表示する
- **FR-361**: システムは、作った一時的なフォルダの場所を記録し、操作が終わって消したら記録から外し、起動したときに記録に残る一時的なフォルダを消さなければならない。
  - 消すのは記録した場所だけとし、ほかの場所は探さない
  - 記録した場所のボリュームがつながっていないときは、記録を次の起動へ持ち越す
  - 記録は設定ではない（設定の書き出し・初期化の対象にしない）。保存先は plan で決める

#### 既存の規則への接続

- **FR-347**（変更）: アプリ外から受け取る移動・コピー・画像の保存（ドラッグとペースト）は、既存のファイル操作の確認（FR-022〜FR-024）、衝突（FR-025）、
  失敗の表示（FR-026）、結果の反映（FR-027・FR-165）に従わなければならない。
  - 移動は確認モーダルの省略設定に関わらず確認し、コピーと画像の保存は省略設定に従う（FR-024）
  - 受け取った項目の元の場所が Folzio に表示中のフォルダにある場合、移動の結果は EC-13（overview.md）と同じく反映する
  - 画像の保存の確認モーダルと衝突のダイアログには、宛先に作るファイルの名前を示す（一時的なフォルダの場所は示さない）

### Key Entities *(include if feature involves data)*

- **アプリ外からのドラッグ**（変更）: Folzio 以外のアプリ（または Folzio に登録していないビュー）から始まったドラッグ。
  受け付けるデータは file URL、ファイルの書き出しの約束、画像データの3種類で、この順に優先する（EC-241）
- **受け取りの操作**（変更）: 移動・コピー・画像の保存のどれか。file URL では宛先、対象の項目のボリューム、修飾キー、ドラッグ元が許可する操作で決まり（FR-346）、
  画像の保存は常にコピー（FR-356）
- **ファイルの書き出しの約束**: ドラッグ元のアプリが、ドロップされた後に、受け取り側が指定した場所へファイルを書き出す仕組み。ファイルの名前と中身はドラッグ元が決める
- **画像データ**: ドラッグ・クリップボードにある、ファイルになっていない画像（PNG・TIFF など）。同じドラッグ・クリップボードに画像の URL があることがある
- **一時的なフォルダ**: 受け取りのために、宛先と同じボリュームに操作ごとに作るフォルダ。保存するファイルは、ここから宛先へ移す。操作の終わりに必ず消す

## Assumptions

- **A-204**（変更）: Web ブラウザに表示中の画像の取り込みは、ドラッグ（FR-350・FR-351）とペースト（FR-354）の両方で行う。
  - 憲章 原則 III の「新しい操作にはキーボードの手段を同時に提供する」は、ブラウザの「画像をコピー」の後のペースト（FR-354）で満たす
  - FR-344〜FR-347 のキーボードの手段は既存の ⌘C・⌘V・⌥⌘V（FR-019）で、Folzio と Finder の間で file URL のコピー・ペーストとして使える
  - ツリーのフォルダには ⌘C がないため、ファイルリストで親フォルダの一覧を表示し、そのフォルダを選んで ⌘C する
  - お気に入りはペースト先にならない（A-20（directory-tree.md））ため、お気に入りのフォルダをファイルリストに表示し、ファイルリストで ⌘V・⌥⌘V する
- **A-208**: ブラウザ以外のアプリ（写真、Mail など）が渡すファイルの書き出しの約束と画像データも、同じ規則（FR-350〜FR-361）で受け取る。
  - FR-357 により、画像でないもの（Mail の PDF の添付など）は保存しない
- **A-209**: 画像の保存は常にコピーとする（FR-356）。元の画像はブラウザの中にあり、Folzio が消す元の項目がないため。
- **A-210**: 書き出しを待つ間に、専用の進み具合の表示は出さない。書き出しは通常すぐに終わり、終わらない場合は 60 秒で失敗として示す（FR-355）。
- **A-211**: 安全性の規則（FR-357〜FR-360）の脅威は、ユーザーが閲覧した攻撃目的のページが、画像の URL・ファイルの書き出しの約束の名前と中身・画像データ・クリップボードを細工することとする。
  - ページは、ユーザーのドラッグ、ブラウザの「画像をコピー」、ページ上のクリック1回で使える非同期のクリップボード API（画像の書き込み）でデータを Folzio に渡せる
  - クリップボードは、ユーザーが選んでいない画像に置き換えられていることがある。それでも保存されるのは FR-357 を満たす画素を持つ画像だけで、
    名前は日時の名前か、ページが決めた URL の末尾から FR-357 の名前の条件で作る名前になる
  - Folzio は、受け取ったファイルを開かず、実行しない。保存した画像の表示は既存のプレビュー（表示サイズに縮小して読み込む）で行う
  - 守りの中心は FR-357（画素を持つ画像だけを、中身の形式の拡張子で保存する）である。保存されたファイルを既定のアプリ（⌘O）で開くと、画像のアプリで開かれる
  - FR-358 の印は補助の守りである。画像の書類を開くときに OS の確認は出ないが、ファイルを後でほかの場所へ移したときにも、インターネットから入手したことが残る
  - 印を保存できない宛先では印を失う（Finder のコピーと同じ）。そのため、FR-357 を緩めて画像以外を受け取る変更は、この前提を見直してから行う
- **A-212**: Safari と Chrome が画像のドラッグ・コピーで何を渡すか（ファイルの書き出しの約束か画像データか、ファイル名、ドラッグ元が許可する操作）は未検証である。
  - 実装の最初に、保守者が macOS で確かめ、その結果で仕様を確定してから残りを実装する（TAK-74 の T005 と同じ進め方）
- **A-213**: 新しい文言（日時の名前の接頭辞、失敗の理由）は、既存の翻訳の仕組み（contracts/localization.md）で両言語に追加する。
  - 訳は下の「反映する本文 / contracts/localization.md」の表に示す
- **A-214**: クリップボードの画像データは、コピー元のアプリを問わず保存の対象にする（FR-354）。
  - 表計算のセル・プレゼンテーションの図形などのコピーにも、OS が絵を添えるため、⌘V でその絵が PNG として保存される
  - コピー元を見分ける確かな方法がなく、プレビューや画面収録の絵も保存できるようにするため、規則を単純にした
  - 意図しない保存は、確認モーダル（FR-024 の設定に従う）で名前を見て取りやめるか、⌘Delete でゴミ箱へ入れて戻せる

### 主なエンティティ（変更）（file-operations.md）

- **アプリ外からのドラッグ**: Folzio 以外のアプリ（または Folzio に登録していないビュー）から始まったドラッグ。
  - 受け付けるデータは file URL、ファイルの書き出しの約束、画像データの3種類で、この順に1つを選ぶ（FR-348・EC-241）
- **受け取りの操作**: 移動・コピー・画像の保存のどれか。
  - file URL は、宛先、対象の項目のボリューム、修飾キー、ドラッグ元が許可する操作で決まる（FR-346）
  - 画像の保存は、常にコピーとして扱う（FR-356）
- **ファイルの書き出しの約束**: ドラッグ元のアプリが、ドロップ・ペーストの後に、
  受け取り側が指定した場所へファイルを書き出す仕組み。
  - ファイルの名前と中身はドラッグ元が決めるため、FR-357〜FR-360 で検査する
- **画像データ**: ドラッグ・クリップボードにある、ファイルになっていない画像（PNG・TIFF など）。
  - 同じドラッグ・クリップボードに画像の URL があることがある（FR-352）
- **一時的なフォルダ**: 受け取りのために、宛先と同じボリュームに操作ごとに作るフォルダ。
  - 保存するファイルは、ここから宛先へ移し、操作の終わりに必ず消す（FR-350）

### ペーストの有効条件（変更）（contracts/keyboard-and-menus.md）

「3 選択とファイル操作」の表の `paste` の行（説明・条件は「表の詳細」へ移す）:

| paste | ⌘V / ⌥⌘V | 下記 |

同じ表の「表の詳細」に加える項目:

- **paste**（説明・条件）: コピー / 移動ペースト。ツリーの通常フォルダにも可。
  - zip内・検索結果リストは無効。編集中の⌘Vは文字列の貼り付け
  - クリップボードに file URL がなく、ファイルの書き出しの約束か画像データがあるときは、⌘Vで画像を保存する（FR-354）
  - file URL がないときは、⌥⌘Vは無効（FR-354）

ツリーのキーボード操作の表の ⌘V / ⌥⌘V の行（動作は「表の詳細」へ移す）:

| ⌘V / ⌥⌘V | 下記 |

同じ表の「表の詳細」に加える項目:

- **⌘V / ⌥⌘V**（動作）: 選択したフォルダへペースト（コピー / 移動）。
  - お気に入りの見出し・項目では無効。複数の行の選択中は無効（FR-218）
  - クリップボードに file URL がなく、ファイルの書き出しの約束か画像データがあるときは、⌘Vで画像を保存し、
    ⌥⌘Vは無効（FR-354）

ファイルリストの右クリックメニュー（項目）の 10 番目と、その後に加える子項目:

- 10. ペースト（⌘V）／ 移動ペースト（⌥⌘V）
  - 「ペースト」は、クリップボードにファイル・ファイルの書き出しの約束・画像データのどれかがある場合のみ有効
    （FR-354）
  - 「移動ペースト」は、クリップボードにファイルがある場合のみ有効

ファイルリストの右クリックメニュー（背景）の 3 番目と、その後に加える子項目:

- 3. ペースト（⌘V）／ 移動ペースト（⌥⌘V）（表示中のフォルダへ）
  - 「ペースト」は、クリップボードにファイル・ファイルの書き出しの約束・画像データのどれかがある場合のみ有効
    （FR-354）
  - 「移動ペースト」は、クリップボードにファイルがある場合のみ有効

ツリーの右クリックメニュー（通常のフォルダ）の 7 番目と、その後に加える子項目:

- 7. ここにペースト / ここに移動ペースト
  - 「ここにペースト」は、クリップボードにファイル・ファイルの書き出しの約束・画像データのどれかがある場合のみ有効
    （FR-354）
  - 「ここに移動ペースト」は、クリップボードにファイルがある場合のみ有効

- 番号付きのメニューの一覧に子項目を加えるとき、番号の振り方が崩れる場合は、
  一覧の直後に「ペーストの有効条件」として同じ子項目を置く
