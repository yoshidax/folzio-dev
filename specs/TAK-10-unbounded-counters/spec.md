# Feature Specification: 大きな連番のファイル操作

**Feature Branch**: `bugfix/tak-10-unbounded-counters`
**Created**: 2026-11-01
**Status**: Draft
**Input**: [TAK-10](https://linear.app/takyoshida/issue/TAK-10/連番が-intmax-のファイルを複製すると整数オーバーフローでクラッシュする)

## User Scenarios & Testing

### User Story 1 - 大きい連番でも複製する (Priority: P1)

利用者は大きな連番を持つファイルを、クラッシュや既存ファイルの上書きなしに複製できる。同名衝突時の「両方残す」も同じ連番規則を使う。

**Independent Test**: 上限の連番を持つファイルの複製と、同名のコピー先での「両方残す」を確認する。

**Acceptance Scenarios**:

1. **Given** `photo 9223372036854775807.jpg`、**When** 複製する、**Then** `photo 9223372036854775808.jpg` を作り、元を変更しない。
2. **Given** 同じ名前がコピー先に存在し次の連番も存在する、**When** 「両方残す」を選ぶ、**Then** 次の空き連番を使い、既存項目を変更しない。
3. **Given** 通常の連番のファイル、**When** 複製する、**Then** 従来どおり次の空き連番を使う。

### Edge Cases

- 連番が `9223372036854775806` で次の候補が存在する場合も、その先に進む。
- 先頭ゼロを含む数字は数値として扱い、生成する連番の先頭ゼロを除く（ゼロ自体は `0`）。
- ファイルシステムの名前長などの制限により作成できない場合は FR-026 に従って失敗を知らせ、既存項目を変更しない。
- 拡張子なし、大文字小文字のみが異なる衝突も従来の規則に従う。

## Requirements

### Functional Requirements

- **FR-018（変更）**: ユーザーは、選択したファイルとフォルダ（FR-076）に対して「コピー」「名前の変更」「削除」「移動」「複製」を実行できなければならない。フォルダの操作はその中身を含めて行い、FR-019〜FR-027 をファイルと同じく適用する（削除はフォルダごとゴミ箱へ入れる）。「複製」は対象と同じフォルダに「名前 2」という名前で作成し（既にその名前がある場合は空いている連番まで進める）、既存のファイルを変更しないため確認モーダル（FR-022）の対象外とする。名前の末尾にスペースと半角十進数字の連番がある場合はその数の次から採番し、桁数による整数上限を設けない。生成する連番の先頭ゼロは除く。
- **FR-025（変更）**: コピーまたは移動の操作先に同名ファイルが存在する場合、システムは確認モーダル設定に関わらず「置き換える / 両方残す / 中止」を選ばせなければならない。ただしコピー元と衝突先が同一の項目である場合は「置き換える」を選べないようにし、「両方残す / 中止」を選ばせる。この例外はドラッグ以外のコピーにも適用する。「両方残す」の採番は FR-018 の連番規則に従い、既存項目を変更しない。名前の変更で同じ親フォルダにある別の項目の名前（大文字小文字の違いのみを含む）を指定した場合は、衝突ダイアログを出さず、名前の検証エラーとして拒否しなければならない。複製は FR-018 の連番の規則に従い、この対象外とする。元項目自身の名前の大文字小文字だけを変える変更は、ボリュームが大文字小文字を区別するかに関わらず許可し、入力した表記を保存する。別のディレクトリエントリは、同じ実体を指すリンクであっても別項目として扱う。

## Success Criteria

- 上記 3 シナリオと上限手前の衝突を含む回帰検証で、生成名と既存データがすべて期待どおりである。

## Assumptions

- この変更は半角数字の末尾連番を対象とし、数字以外を含む末尾は従来どおり名前の一部とする。
- ファイルシステムが受け入れない名前の作成は、既存の操作エラー経路で報告する。
