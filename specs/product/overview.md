# 概要と横断要件

この領域の現在の仕様（Living spec）。ID は各 feature から引き継いだもの。ほかの領域は [README.md](README.md) を参照。

## 出発点となった要望

**Input**: User description: 「縦に3分割されたペイン（左: ディレクトリツリービュー / 中央: ファイルリストビュー /
右: プレビュービュー）を持つメディアビューア。ペインは仕切りのドラッグでリサイズ可能。ツリーは Windows
Explorer 風。ファイルリストは Finder 風にリスト形式とサムネイル形式を切り替えでき、リスト形式では
ファイル名・作成日・種類の列を持つ。コピー・リネーム・削除・移動（ツリーへのドラッグ&ドロップ）が可能で、
実行前に確認モーダルを出すがオプションで出さないこともできる。操作は Finder に寄せる（右クリックメニュー・
キーボード操作）。扱えるファイルのみフィルタ表示。サムネイルサイズは Finder のように可変で、ペイン内に
自動レイアウトし横スクロールは出さない。プレビューはペイン内に収まるよう表示し、動画はデフォルトで
自動ループ再生、オプションで自動再生・ループをオフにできる。プレビューのダブルクリックでフルスクリーン、
再度ダブルクリックで解除。最低限 JPEG / PNG / GIF / WebP / mp4 / mov に対応する。」

## ユーザーストーリー

各ストーリーの受け入れシナリオは、関係する領域のファイルに振り分けている。

### US1 フォルダを辿って画像をプレビューする（P1）

ユーザーはアプリを起動し、左のディレクトリツリーでフォルダを展開・選択する。中央のファイルリストに
そのフォルダ内の対応メディアファイルだけが表示され、ファイルを選ぶと右のプレビューにその画像が
ペイン内の最大サイズで表示される（ペインより小さい画像は拡大される）。キーボードの上下キーで
選択を移すと、プレビューも追従する。

**Why this priority**: 「フォルダを選んで画像を見る」はこのアプリの存在理由そのもの。これだけで
画像ビューアとして成立する最小の価値（MVP）になる。

**Independent Test**: JPEG / PNG / GIF / WebP と非対応ファイルが混在するフォルダを用意し、ツリーで
選択 → リストにサブフォルダと対応ファイルのみ並ぶこと → 各ファイルを選ぶとプレビューに表示されることを確認する。

受け入れシナリオ: [directory-tree.md](directory-tree.md)（AS1・7〜14）、[file-list.md](file-list.md)（AS2・4・21・22）、[zip.md](zip.md)（AS15〜20・29）、[file-operations.md](file-operations.md)（AS23・24）、[search.md](search.md)（AS25〜28）、[preview.md](preview.md)（AS3・5・6）

### US2 動画をプレビューで再生する（P2）

ユーザーがリストで mp4 / mov を選ぶと、プレビューで自動的にループ再生が始まる。設定で自動再生や
ループをオフにすることもできる。

**Why this priority**: 対応形式に動画が含まれており、画像と並ぶ主要な閲覧対象であるため。

**Independent Test**: mp4 と mov を含むフォルダで動画を選択し、デフォルトで自動ループ再生されること、
設定変更後は自動再生しない／ループしないことを確認する。

受け入れシナリオ: [preview.md](preview.md)（AS1〜5）

### US3 リスト形式とサムネイル形式を切り替えて一覧する（P2）

ユーザーはファイルリストを Finder のようにリスト形式とサムネイル形式で切り替える。リスト形式では
ファイル名・作成日・種類の列で並べ替えでき、サムネイル形式ではスライダー等でサムネイルの大きさを
自由に変えられる。サムネイルはペインの幅に合わせて自動で折り返され、横スクロールは発生しない。

**Why this priority**: 大量の画像から目的の1枚を探す効率を大きく左右するが、US1 のリスト形式だけでも
閲覧自体は可能なため P2。

**Independent Test**: 多数の画像を含むフォルダで表示形式を切り替え、列による並べ替え、サムネイルの
拡大縮小、ペイン幅変更時の再レイアウトを確認する。

受け入れシナリオ: [window-layout.md](window-layout.md)（AS7〜10）、[file-list.md](file-list.md)（AS1〜6・11〜18）、[zip.md](zip.md)（AS19〜22）

### US4 Finder と同じ感覚でファイルを整理する（P3）

ユーザーはリスト上のファイルを右クリックメニューやキーボードショートカットでコピー・リネーム・削除し、
ファイルをツリー上のフォルダへドラッグ&ドロップして移動する。実行前には確認モーダルが出るが、
設定でコピーと削除の確認を省略できる（名前の変更と移動は常に確認し、複製は確認しない）。

**Why this priority**: 閲覧しながら整理できると便利だが、閲覧機能（US1〜3）が先に成立している必要があり、
かつファイルを変更する操作のため慎重な検証を要する。

**Independent Test**: テスト用フォルダで各操作を実行し、ファイルシステム上の結果、確認モーダルの有無、
キャンセル時に何も変わらないことを確認する。

受け入れシナリオ: [file-operations.md](file-operations.md)（AS1〜8）

### US5 プレビューをフルスクリーンで見る（P3）

ユーザーはプレビューをダブルクリックしてフルスクリーン表示に切り替え、メディアを画面いっぱいに見る。
もう一度ダブルクリックすると元の3ペイン表示に戻る。動画の場合はダブルクリックにこだわらず、
キーボードやメニューなど macOS 標準の手段で切り替え・解除できればよい。

**Why this priority**: 鑑賞体験を高めるが、通常表示で閲覧は完結しているため P3。

**Independent Test**: 画像と動画それぞれでダブルクリックによるフルスクリーン化と解除、キーボードによる
同等操作、フルスクリーン中の矢印キーによる選択移動とプレビュー更新を確認する。

受け入れシナリオ: [preview.md](preview.md)（AS1〜6）

### US6 ペインの幅を調整する（P3）

ユーザーはペイン間の仕切りをドラッグして、ツリー・リスト・プレビューの幅を好みに調整する。
また、ツールバーのボタン・「表示」メニュー・ショートカットで、ファイルリストだけ・プレビューだけを表示する状態に切り替える（FR-088〜094）。

**Why this priority**: 快適さに関わるが、既定幅でも全機能が使えるため P3。

**Independent Test**: 2本の仕切りをそれぞれドラッグして幅が変わること、最小幅で止まること、再起動後に
復元されることを確認する。続けて、ツールバーのボタンと ⌃⌘2・⌃⌘3 でファイルリストのみ表示・プレビューのみ表示に切り替わり、
もう一度押すと3ペイン表示に戻って各ペインの幅が切り替え前と同じになることを確認する。

受け入れシナリオ: [window-layout.md](window-layout.md)（AS1〜10）

### US7 移動したフォルダを戻る・進む（P2）

ユーザーは、ツリーやファイルリストでフォルダを次々に移りながら画像を探す。目的の画像が前に見ていたフォルダにあったと
気づいたとき、今はツリーを辿り直すか、⌘↑ で親へ戻ってから開き直すしかない。ユーザーは Finder と同じく、ツールバーの `<`・`>` と
⌘[・⌘] で、直前に見ていたフォルダへ戻り、また先へ進みたい。途中で消えた・名前が変わったフォルダは、エラーを見せずに飛ばしてほしい。

**Why this priority**: フォルダを辿る主要な流れ（US1）の効率を上げるが、ツリーと ⌘↑ でも同じ場所へは行けるため P2。

**Independent Test**: 3つのフォルダ A → B → C を順に選び、⌘[ を2回押して A に戻ること、⌘] で B に進むこと、ツールバーの
`<`・`>` でも同じに動くことを確かめる。続けて B を Finder で削除してから A で ⌘] を押し、B を飛ばして C に進むこと、
もう一度 ⌘[ を押すと A に戻る（B が履歴から消えている）ことを確かめる。アプリを再起動すると、`<`・`>` がどちらも淡色であることを確かめる。

受け入れシナリオ: [navigation-history.md](navigation-history.md)（AS1〜13）

### US8 表示の変更を戻す・やり直す（P3）

ユーザーは、フォルダを見ながら表示形式・サムネイルの大きさ・種類フィルタ・ペインの表示を切り替える。試しに変えた表示を
元に戻したいとき、どの操作でどう変えたかを思い出さずに、フォルダの移動と同じ `<`・⌘[ で1つ前の表示に戻したい。

**Why this priority**: 表示の変更はそれぞれのショートカットで戻せるため、フォルダの移動の履歴（US7）より優先度が低い。

**Independent Test**: フォルダを表示した状態で、⌘1 でサムネイル形式にし、⇧⌘I で画像のみ表示にする。⌘[ を押すと画像のみ表示が
解除され、もう一度押すとリスト形式に戻ること、⌘] で順にやり直せることを確かめる。

受け入れシナリオ: [navigation-history.md](navigation-history.md)（AS1〜7）

### User Story 17 - 英語環境のユーザーが英語の UI で操作する (Priority: P1)

英語の表示言語を使うユーザーは、メニュー・右クリックメニュー・ツールバーのツールチップ・
設定ウインドウ・列見出し・検索モーダル・空状態・確認モーダル・衝突ダイアログ・エラーを英語で読む。操作の内容・ショートカット・有効条件は日本語のときと同じである。

**Why this priority**: 英語で使えることがこの変更の中心的な価値であり、日本語を読めない利用者がアプリを使い始める前提になる。

**Independent Test**: 表示言語を英語にして配布用 `.app` を起動する。メニューバーの全メニュー、ツリーとファイルリストの右クリックメニュー、ツールバー、
設定ウインドウ、検索モーダル（検証エラーを含む）、ファイル操作の確認モーダルと衝突ダイアログ、空のフォルダ・種類フィルタで0件の一覧、
表示できないファイルのプレビュー、壊れた zip を順に表示し、日本語・内部キー・置換されていないプレースホルダが出ないことを確かめる。

**Acceptance Scenarios**:

1. **US17-AS1**: **Given** 表示言語が英語, **When** アプリを起動してメニューバーの各メニューを開く,
   **Then** アプリが管理する項目名はすべて英語で表示される。項目の並び・区切り線・ショートカット・チェックマーク・有効／無効は日本語のときと同じである。
2. **US17-AS2**: **Given** 英語で起動している, **When** ファイルを1つ選んで右クリックし、続けて3つ選んで右クリックする,
   **Then** コピーの項目はファイル名を含む1件用の文（例: Copy "photo.jpg"）と、件数を含む複数件用の文（例: Copy 3 Items）で表示される。
   ファイル名は翻訳・変形されない。
3. **US17-AS3**: **Given** 英語で起動している, **When** 複数のファイルをゴミ箱に入れる操作を確認モーダル付きで行い、続けて同名のファイルがある場所へコピーする,
   **Then** 確認モーダルの見出し・件数・フォルダを中身ごと操作する旨・ボタン・「今後この確認を表示しない」と、衝突ダイアログの
   「置き換える」「両方残す」「中止」「残りすべてに適用」に当たる文言が英語で表示される。既定ボタン・Esc の動作・操作結果は日本語のときと同じである。
4. **US17-AS4**: **Given** 英語で起動している, **When** ⌘F で検索モーダルを開き、存在しない起点パスで検索し、次に有効な起点で検索する,
   **Then** 入力欄のラベル・ボタン・検証エラーの理由・検索中の表示・検索バーの文（キーワード・起点のフォルダ名・件数を含む）が英語で表示される。
   キーワードとフォルダ名はユーザーが入力・作成したとおりに表示される。
5. **US17-AS5**: **Given** 英語で起動している, **When** ⌘, で設定ウインドウを開く,
   **Then** 区分の見出し・チェックボックス・切り替え間隔の単位・切り替え効果の選択肢が英語で表示され、変更の保存と反映は日本語のときと同じに行われる。
6. **US17-AS6**: **Given** 英語で起動している, **When** 空のフォルダ、種類フィルタで0件になるフォルダ、壊れた画像、暗号化された zip の中の画像を順に表示する,
   **Then** 空状態のメッセージ、プレビューのエラー、zip のエラーの理由がすべて英語で表示される。
7. **US17-AS7**: **Given** 日本語で起動して設定・お気に入り（表示名付き）を変更した, **When** アプリの設定で表示言語を英語に変更する,
   **Then** 保存した設定・お気に入りの登録と表示名・最後のフォルダ・ツールバーの表示状態はすべてそのまま復元される。お気に入りの表示名は翻訳されない。


### User Story 18 - 設定で表示言語を切り替える (Priority: P1)

利用者は、既定の英語からアプリの設定で日本語へ切り替え、再起動せずに日本語の UI を使う。選択は次回起動にも引き継がれる。
配布用 `.app` をどこに置いても、翻訳が失われない。

**Why this priority**: 国際化によって既存の日本語の利用者の体験を壊さないこと、対応外の言語で文言が欠けないことは、英語対応と同じく必須である。

**Independent Test**: 新規設定で英語が表示され、設定で日本語・英語を切り替えると各画面に即時反映されること、再起動後も選択が復元されることを確かめる。

**Acceptance Scenarios**:

1. **US18-AS1**: **Given** 表示言語に日本語を選んだ, **When** アプリの画面を見る,
   **Then** アプリが管理する文言は日本語で表示され、既存仕様（contracts/keyboard-and-menus.md・contracts/settings.md ほか）に書かれた日本語の表示名と一致する。
2. **US18-AS2**: **Given** 保存された表示言語がない, **When** アプリを起動する,
   **Then** アプリが管理する文言は英語で表示され、内部キーや日本語との混在はない（OS が提供する文言の言語は EC-111 に従う）。
3. **US18-AS3**: **Given** 英語で表示中, **When** 設定で日本語を選ぶ, **Then** 再起動せずアプリの文言が日本語に変わる。
4. **US18-AS4**: **Given** 日本語で表示中, **When** 設定で英語を選ぶ, **Then** 再起動せずアプリの文言が英語に変わる。
5. **US18-AS5**: **Given** 配布用 `.app` を作った後、ビルドディレクトリの外へコピーし、元のビルドディレクトリを移動または削除した,
   **When** コピーした `.app` を英語・日本語のそれぞれで起動する, **Then** どちらも翻訳された文言で表示され、内部キーは表示されない。
6. **US18-AS6**: **Given** 設定で言語を選択した, **When** アプリを終了して起動し直す,
   **Then** 選択した言語が復元される。OS の優先言語やアプリごとの言語指定では選択が変わらない。


### User Story 19 - 表示言語とは別の地域設定で日時と数値を読む (Priority: P2)

日本に住み英語の UI を好むユーザーは、英語の UI のまま、作成日・件数・倍率を日本の地域設定の書式で読む。逆の組み合わせも同じに扱う。

**Why this priority**: 言語と地域を分けて扱えることは macOS の標準的な期待だが、文言の翻訳（US17・US18）が先に成立している必要があるため P2。

**Independent Test**: 表示言語を英語、地域を日本にして起動し、リスト形式の「作成日」列・検索結果の件数（1,000件以上）・倍率の読み上げを確かめる。
次に表示言語を日本語、地域を米国・ドイツにして同じ箇所を確かめる。24時間表示の設定を切り替えて起動し直したときの時刻の表示も確かめる。

**Acceptance Scenarios**:

1. **US19-AS1**: **Given** 表示言語が英語で地域が日本, **When** リスト形式で作成日の列を見る,
   **Then** 列見出しは英語で、日付と時刻は日本の地域設定の並び・区切り・時刻表記で表示される。
2. **US19-AS2**: **Given** 表示言語が日本語で地域が米国, **When** リスト形式で作成日の列を見る,
   **Then** 列見出しは日本語で、日付と時刻は米国の地域設定の並び・区切り・12時間表記で表示される。
3. **US19-AS3**: **Given** 地域がドイツ, **When** 1,000件以上の一致がある検索を行い、画像を125%に拡大する,
   **Then** 検索バーの件数はドイツの桁区切りで表示され、倍率のアクセシビリティ値と読み上げはドイツの割合の書式に従う。
4. **US19-AS4**: **Given** システム設定で24時間表示を切り替えた, **When** アプリを起動し直す, **Then** 作成日の時刻はその設定に従う。
5. **US19-AS5**: **Given** 地域が日本以外（桁区切りを使う地域を含む）, **When** 設定ウインドウで切り替え間隔を表示・入力する,
   **Then** 値は桁区切りなしの整数で表示され、入力の解釈（半角・全角の数字、1〜3600）は地域によらず従来と同じである（contracts/settings.md）。


### User Story 20 - VoiceOver の利用者が両言語で操作する (Priority: P2)

VoiceOver を使うユーザーは、表示言語に合わせた言語で、ツールバーのボタン・入力欄・ペイン・設定項目のラベル、倍率などの値、エラーや倍率変更の読み上げを聞く。

**Why this priority**: アクセシビリティは憲章 原則 III の必須事項だが、画面の文言（US17・US18）と同じ翻訳の上に成り立つため P2。

**Independent Test**: 英語と日本語のそれぞれで VoiceOver をオンにし、ツールバーの各ボタン、検索モーダルの入力欄と「選択…」、設定ウインドウの切り替え間隔・繰り返し・効果、
お気に入りとフォルダの名前の編集欄、プレビューの倍率を順に読み上げさせ、検索起点の検証エラーと倍率の変更の読み上げを確かめる。

**Acceptance Scenarios**:

1. **US20-AS1**: **Given** 英語で起動して VoiceOver がオン, **When** ツールバーの各ボタンとスライダーへ移る,
   **Then** 各項目のラベルとヘルプが英語で読み上げられ、ショートカットの表記はツールチップと同じである。
2. **US20-AS2**: **Given** 英語で起動して VoiceOver がオン, **When** 検索起点に存在しないパスを入れて検索する,
   **Then** 検証エラーの理由が英語で読み上げられる。日本語で起動した場合は日本語で読み上げられる。
3. **US20-AS3**: **Given** 画像を表示中で VoiceOver がオン, **When** 拡大する,
   **Then** 新しい倍率が地域設定の割合の書式で読み上げられ、プレビューのアクセシビリティ値も同じ書式になる（FR-138（preview.md））。

## 機能要件

### 保存と復元

- **FR-003**: システムは、ペイン幅・ファイルリストの表示形式・サムネイルサイズ・並び順・ツールバーの表示状態・
  zip ファイルの表示設定（FR-095）・各種オプション・最後に選択していたフォルダ・お気に入りの登録内容を保存し、次回起動時に復元しなければならない。
