# Feature Specification: 同一パスのファイルの内容更新をサムネイルとプレビューに反映する

**Feature Branch**: `claude/admiring-allen-cf97f7`

**Created**: 2026-11-01

**Status**: Draft

**Input**: [TAK-14](https://linear.app/takyoshida/issue/TAK-14)「同一パスの画像の内容更新をプレビューとサムネイルに反映する」

## 背景

同じパスの画像を別の内容で上書きしても、変更の通知を処理した後の再選択で、上書き前の内容が表示され続けると報告された
（folzio-oss main c22eee6 の AI レビューの指摘4。8×8 の画像を同じパスの 16×16 の画像で上書きした例）。
現行の仕様は、外部の追加・削除・名前変更の反映（FR-042（overview.md）、EC-13（overview.md））と、操作結果の即時反映
（FR-027（file-operations.md））を定めるが、同じパスのファイルの内容が置き換わった場合の扱いを定めていない。
コピーで同名のファイルを「置き換える」（FR-025（file-operations.md））と、同じ症状が出るという報告もある
（[TAK-43](https://linear.app/takyoshida/issue/TAK-43)。本 feature の完了後に、本 feature で解消するかを確かめる）。

この feature は、同じパスのファイルの内容の置き換えを、サムネイル（FR-013（file-list.md））とプレビュー（FR-017（file-list.md）・
FR-028（preview.md））に反映する規則を追加する。

## Clarifications

### Session 2026-11-01

- Q: プレビュー中のファイルが同じパスで上書きされたとき、いつ新しい内容を表示するか → A: 検知時に自動で読み込み直す（再選択を待たない）。
  FR-027（file-operations.md）の即時反映と揃え、TAK-43 の症状もこれで解消を狙う（FR-229）
- Q: zip の中の画像も対象にするか → A: 対象にする。置き換わった zip を開き直したとき、置き換え前の内容を表示しない（FR-231）
- Q: 検索結果の一覧の表示中に、結果のファイルが上書きされた場合も対象にするか → A: 対象にする。通知のあったフォルダの下の結果について、
  フォルダの一覧と同じに扱う（FR-232）

## User Scenarios & Testing *(mandatory)*

### User Story 1（US41） - 上書きした画像をそのまま見直す (Priority: P1)

ユーザーは、Folzio で表示しているフォルダの画像を、別のアプリで編集して同じ名前で保存する。Folzio に戻ると、選択し直さなくても、
プレビューとサムネイルが保存後の内容になっている。

**Why this priority**: 報告された不具合そのもの。古い内容が表示され続けると、編集の結果を確かめられず、アプリの再起動が要る。

**Independent Test**: 画像を表示中のフォルダで、同じパスの画像を寸法の違う画像で上書きし、プレビューとサムネイルが上書き後の内容に
変わることを確かめる。

**Acceptance Scenarios**:

1. **US41-AS1**: **Given** 画像 A をプレビュー中、**When** アプリの外で A を同じパスの別の内容の画像で上書きする、
   **Then** 選択し直さなくても、プレビューが上書き後の内容に変わる。選択とフォーカスは A のまま変わらない
2. **US41-AS2**: **Given** サムネイル形式（またはリスト形式）で画像 B の縮小画像が表示されている、**When** アプリの外で B を同じパスの
   別の内容の画像で上書きする、**Then** B の縮小画像が上書き後の内容に変わる。内容が変わっていないほかのファイルの縮小画像は、
   作り直されず、そのまま表示される
3. **US41-AS3**: **Given** 画像 A をプレビュー中で、隣の画像 C を表示したことがある、**When** アプリの外で C を上書きしてから C を選択する、
   **Then** C の上書き後の内容が表示される（上書き前に読み込んだ内容は表示されない）
4. **US41-AS4**: **Given** 別のフォルダに同じ名前で内容の違う画像がある、**When** それを Folzio でコピーし、表示中のフォルダに貼り付けて
   「置き換える」を選ぶ、**Then** 置き換えた画像のサムネイルとプレビューが、再起動せずに置き換え後の内容になる

---

### User Story 2（US42） - zip を置き換えた後に開き直す (Priority: P2)

ユーザーは、zip ファイルを同じ名前の別の zip で置き換えた後に、その zip を開き直す。中の画像のサムネイルとプレビューは、
置き換え後の zip の内容になっている。

**Why this priority**: zip の中の画像も同じ方法で一時的に保持されるため、同じ症状が起こり得る（静的な確認のみで、再現はしていない）。

**Independent Test**: zip を開いて中の画像を表示した後、zip を、同じパスの中のファイルの名前が同じで内容の違う zip で置き換え、
開き直して内容を確かめる。

**Acceptance Scenarios**:

1. **US42-AS1**: **Given** zip Z の中の画像 P を表示したことがある、**When** Z を、同じ名前の P を含む内容の違う zip で置き換えてから、
   Z を開いて P を選択する、**Then** P のサムネイルとプレビューが置き換え後の zip の内容になる
2. **US42-AS2**: **Given** zip Z の中の画像 P をプレビュー中、**When** アプリの外で Z を置き換える、**Then** 既存の EC-26（zip.md）のとおり
   zip を含むフォルダの一覧に戻り、プレビューを空にする（この挙動は変えない）

---

### User Story 3（US43） - 検索結果でも置き換え後の内容を見る (Priority: P3)

ユーザーは、検索結果の一覧を表示中に、結果に含まれる画像を別のアプリで上書きする。検索結果の一覧のサムネイルとプレビューも、
フォルダの一覧と同じく上書き後の内容になる。

**Why this priority**: 検索結果は変更の通知で一覧を作り直さないため、フォルダの一覧とは別に規則が要る。利用の頻度は低い。

**Independent Test**: 検索結果の一覧を表示中に、結果の画像を上書きし、サムネイルとプレビューが上書き後の内容に変わることを確かめる。

**Acceptance Scenarios**:

1. **US43-AS1**: **Given** 検索結果の一覧で画像 D をプレビュー中、**When** アプリの外で D を同じパスの別の内容の画像で上書きする、
   **Then** 選択し直さなくても、D のプレビューとサムネイルが上書き後の内容に変わる。検索結果の並びと選択は変わらない

---

### Edge Cases

- **EC-159**: 置き換えでファイルの種類の扱いが変わった場合（静止画をアニメーション画像で置き換えた場合など）、置き換え後の内容に
  従って表示する。置き換え後のファイルが表示できない場合は、FR-038（preview.md）のとおり、ファイル名と表示できない旨を示す
- **EC-160**: 書き込みの途中で変更が通知された場合、書き込み途中の内容を一時的に表示してもよいが、書き込みが終わった後の通知で
  最終的な内容に更新する。書き込み途中の内容を、書き込みが終わった後も表示し続けてはならない
- **EC-161**: 置き換えの前に始めた読み込みが、置き換えの後に終わった場合、その結果（置き換え前の内容）は表示せず、後で再利用もしない
- **EC-162**: プレビュー中の画像を拡大していた場合、FR-229 による読み込み直しでは、同じファイルの表示の続きとして倍率（FR-133（preview.md））を
  保つ（別のファイルを選んだときのようにフィット表示へ戻さない）。はみ出す方向の位置は FR-158・FR-159（preview.md）に従う。
  静止画では、置き換え後の内容が読み込めるまで、置き換え前の表示を続ける（読み込み中の表示に切り替えない）
- **EC-163**: 再生中・プレビュー中の動画が置き換わった場合、プレビューは自動では読み込み直さない（A-142）。動画の縮小画像（代表フレーム）は
  FR-228 に従って更新する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-228**: システムは、表示中のフォルダの一覧にあるメディアファイルについて、同じパスのまま内容が置き換わったこと
  （アプリの外での上書き、およびアプリでのコピー・移動の「置き換える」（FR-025（file-operations.md））を含む）を、外部の変更の反映
  （FR-042（overview.md））と同じ契機で検出し、そのファイルの縮小画像（FR-013（file-list.md））を置き換え後の内容で作り直さなければ
  ならない。内容が変わっていないファイルの縮小画像は、作り直してはならない
- **FR-229**: 置き換えを検出したファイルが、静止画またはアニメーション画像としてプレビュー中であれば、システムは、ユーザーが選択し直さなくても、
  プレビューを置き換え後の内容で読み込み直さなければならない。選択・フォーカス・一覧のスクロール位置は変えない
- **FR-230**: 置き換えの後にファイルを選択したとき、システムは、置き換え前の内容から作った縮小画像・プレビューの画像を表示しては
  ならない。置き換えの前に始めた読み込みの結果も、置き換え後に表示・再利用してはならない（EC-161）
- **FR-231**: zip ファイルが同じパスのまま別の内容に置き換わった後にその zip を開いた場合、システムは、中のファイルの縮小画像と
  プレビューに、置き換え後の zip の内容を表示しなければならない。置き換え前の zip から作った縮小画像・プレビューの画像を表示しては
  ならない。表示中の zip が置き換わった場合の一覧の扱いは、EC-26（zip.md）のとおりとする
- **FR-232**: 検索結果の一覧を表示中に変更が通知された場合、システムは、通知のあったフォルダの下にある検索結果について内容の置き換えを確かめ、
  FR-228〜FR-230 をフォルダの一覧と同じく適用しなければならない。消えた結果を外す規則（FR-087（search.md））と、結果の並びと選択は変えない

### Key Entities *(include if feature involves data)*

- **ファイルの内容の識別情報**: 同じパスのファイルの内容が置き換わったかを判断するための値。ファイルの大きさ・更新日時・
  ファイルシステム上の実体の番号などからなる。一覧を作るとき、またはプレビューを読み込むときに得る。zip の中のファイルでは、
  zip ファイル自体の識別情報を使う
- **縮小画像・プレビュー画像の保持**: 表示を速くするために保持している、作成済みの縮小画像とデコード済みの画像。
  パスと、作ったときの内容の識別情報の組で区別する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-115**: 外部での上書き・アプリでの置き換え・zip の置き換え・検索結果の表示中の上書きの各確認項目で、再起動も選択し直しもせずに、
  変更の通知が届いてから 1 秒以内に、縮小画像とプレビューが置き換え後の内容（寸法の違いで判別できる画像）になる
- **SC-116**: 10,000 ファイルを含むフォルダで 1 ファイルだけを上書きした場合、作り直す縮小画像はそのファイルの分だけで、一覧の再読み込みの間に
  スクロールと選択の操作が 100ms 以上止まらない

## Assumptions

- **A-141**: 内容の置き換えは、ファイルの大きさ・更新日時・ファイルシステム上の実体の番号のいずれかの変化で判断する。
  これらがすべて同じまま内容だけが変わった場合（更新日時を保ったまま同じ大きさで上書きした場合など）は、検出の対象外とする。
  ファイルの内容を読んで比較することはしない
- **A-142**: プレビュー中の動画の自動の読み込み直しは対象外とする（再生位置の扱いなど別の判断が要るため）。動画は、選択し直したときに
  置き換え後のファイルを再生する
- **A-143**: 変更の検知は、既存の外部変更の検知（FR-042（overview.md））の範囲（表示中のフォルダ、検索結果の一覧ではその結果のあるフォルダ）
  と時機に従う。表示していないフォルダのファイルは、そのフォルダを表示したとき、または選択したときに、置き換え後の内容を表示する
- 表示の確認（GUI）は保守者がローカルで行う。Cloud では Swift のビルドとテストを CI で確認する
- 新しい設定・保存キー・メニュー・ショートカットは追加しない
- 現行の最大値（origin/master 4ec25c0 時点）FR-227・SC-114・EC-158・A-140・US40 の次から採番した。`specs/product/` への反映の前に再照合する
