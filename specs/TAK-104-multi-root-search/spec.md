# Feature Specification: 複数の検索起点

**Feature Branch**: `claude/wizardly-volta-ie6ncn`（Cloud が指定した作業ブランチ）

**Created**: 2026-11-27

**Status**: Draft

**Input**: [TAK-104](https://linear.app/takyoshida/issue/TAK-104)「検索ダイアログで複数の検索起点を指定できるようにする」。
検索のモーダルで複数の検索起点パスを指定し、複数の場所をまとめて検索できるようにする。
あわせて、検索キーワードがワイルドカードに対応していることを、モーダルの UI で分かるようにする。
起点の指定方法と、複数起点での性能・起点の重複や重なりの扱いは、仕様の策定時に決める（Issue の「検討事項」）。

## Clarifications

### Session 2026-11-27（clarify_mode: auto。推奨回答を採用）

- Q: 複数の起点をどう指定するか？ → A: 起点の行を追加・削除できる一覧にする。各行は従来の起点欄（1行の入力）と
  「選択…」と「削除」ボタンを持ち、一覧の下に「起点を追加」ボタンを置く（FR-081（変更）・FR-435）。
  - 理由: 区切り文字（`;`・`,`・改行）で1つの欄に並べる方式は、名前に区切り文字を含むフォルダを表せず、
    GUI 選択の「名前の末尾の空白を保つ」規則（FR-081・US16-AS10（search.md））を保てない。
    行ごとに従来の欄を使えば、直接入力の解釈・GUI 選択・検証・キーボード操作（FR-141〜FR-144（search.md））
    をそのまま行単位で使える
  - 標準パネルの複数選択で一度に複数の起点を加える方式は採らない。行と選択結果の対応が分かりにくくなり、
    FR-141 の「パネルは1つのフォルダを選ぶ用途」を変えずに済むため
- Q: 起点の数に上限を設けるか？ → A: 10 行までとする（FR-435・A-264）。
  - 理由: シートの高さを画面に収め、同時に辿る場所の数を抑えて性能の基準（SC-249）を守るため
- Q: 同じ起点や、ある起点が別の起点の配下にある場合は？ → A: 検証後の同じフォルダは1つにまとめ、
  別の起点の検索で辿られる配下の起点は除いて検索する。結果に同じ項目が2回現れない（FR-437）。
  - 配下の起点でも、外側の起点の検索で辿られない場所（間に隠しフォルダ・パッケージがある）なら、両方を検索する
    （FR-083（search.md）の「明示的に指定した起点が隠しフォルダの配下にある場合」と同じ考え方）
- Q: 複数の起点をどの順に辿るか？性能の基準は？ → A: 一覧の上の起点から1つずつ順に辿り、結果は1つの一覧にまとめる。
  合計 10,000 ファイルを複数の起点に分けても、単一の起点の基準（SC-016・SC-054（search.md））と同じ3秒以内とする
  （FR-438・SC-249）。
  - 理由: 同じディスク上の場所を並行して辿ると読み取りが競合し、合計の時間が単一の起点の場合より悪くなり得るため
- Q: 起点の一部が無効なときは？ → A: 1つでも無効なら検索を始めず、どの行が無効かと理由を示して、その行の起点欄に
  フォーカスを移す。無効な起点を飛ばして残りだけで検索することはしない（FR-436）。
  - 理由: 入力した場所の一部が黙って検索されないと、見つからない理由を利用者が誤解するため
- Q: 空の行は？ → A: 空白だけの行は無視する。すべての行が空なら、従来の「検索起点ディレクトリを入力してください」
  の理由を示す（FR-436）。
- Q: 検索バーと「場所」列はどう表示するか？ → A: 検索バーは、起点が1つなら従来どおり起点のフォルダ名、2つ以上なら
  「{最初の起点のフォルダ名} ほか {n} か所」とし、ツールチップに全起点の絶対パスを示す（FR-439）。
  「場所」列は、その項目を含む起点のフォルダ名から始める。ほかの起点と同じフォルダ名の起点では、起点の絶対パスから始める
  （FR-084（変更））。
- Q: モーダルを開いたときの起点の行は？ → A: 従来どおり既定値（FR-081）の1行だけとし、前回の起点の一覧は復元しない
  （A-265。検索条件を保存しない規則（FR-086・contracts/settings.md）に合わせる）。
- Q: ワイルドカードの説明をどこにどう示すか？ → A: 検索キーワード欄の直下に、補足説明（FR-394（search.md））と同じ
  小さく淡い文字で、`*` と `?` の意味と「含むときは名前全体と一致する」ことを1文で示す。
  キーワード欄のアクセシビリティの説明にも加える（FR-441）。
  - プレースホルダには書かない。前回のキーワードが入って開くと（FR-081）見えなくなるため
- Q: ツールバーの検索欄の虫眼鏡から開く場合（FR-390（file-list.md））は？ → A: ⌥⌘F と同じモーダルを開くので、同じく
  起点の追加ができる。ツールバーの検索欄の絞り込み（FR-381（file-list.md））は変えない。

## User Scenarios & Testing *(mandatory)*

### User Story 99 - 複数の場所をまとめて検索する (Priority: P1)

ユーザーは、検索のモーダルで検索起点を2つ以上指定し、1回の検索でそれらすべての場所から名前が一致する項目を探せる。
写真を複数のディスクやフォルダに分けて保存していても、場所ごとに検索し直さずに済む。

**Why this priority**: TAK-104 の主目的。

**Independent Test**: 別々のフォルダ A と B に、名前に同じ語を含むファイルを置く。検索のモーダルで起点を2行にして
A と B を指定し、検索結果に両方のファイルが1つの一覧で現れ、検索バーと「場所」列で場所を見分けられることを確かめる。

**Acceptance Scenarios**:

- **US99-AS1**: **Given** 一覧にフォルダ A を表示中, **When** ⌥⌘F で検索のモーダルを開く,
  **Then** 起点の行は A の絶対パスが入った1行だけで、その行の「削除」は無効になっている。行の下に「起点を追加」ボタンがある
- **US99-AS2**: **Given** 検索のモーダルで起点が1行, **When** 「起点を追加」を押す,
  **Then** 空の起点の行が一覧の末尾に加わり、その行の起点欄にフォーカスが移る。すべての行の「削除」が有効になる
- **US99-AS3**: **Given** 起点の行が A と B の2行で、キーワードが `kyoto`, **When** 「検索」を押す,
  **Then** A 以下と B 以下の両方で名前が一致したファイルとフォルダが、1つの一覧として現在の並べ替え順で表示される。
  検索バーには「A ほか 1 か所」と両方の合計の件数が出て、ツールチップで A と B の絶対パスを確かめられる
- **US99-AS4**: **Given** US99-AS3 の検索結果をリスト形式で表示中, **When** 「場所」列を見る,
  **Then** A の配下の項目は A のフォルダ名から、B の配下の項目は B のフォルダ名から始まるパスで表示される
- **US99-AS5**: **Given** 起点の行が3行, **When** 2行目の「削除」を押す,
  **Then** 2行目が消え、残りの行の値はそのまま保たれ、フォーカスは新しい2行目（元の3行目）の起点欄に移る
- **US99-AS6**: **Given** 起点の行が2行, **When** 2行目の「選択…」から標準パネルでフォルダ C を選んで確定する,
  **Then** 2行目の起点欄だけが C の絶対パスになり、1行目とキーワードは変わらない。フォーカスは2行目の「選択…」に戻る
- **US99-AS7**: **Given** 起点の行が10行, **When** 一覧を見る, **Then** 「起点を追加」は無効になっている
- **US99-AS8**: **Given** 2行目の起点欄に存在しないパスを入力した, **When** 「検索」を押す,
  **Then** モーダルは閉じず、2行目の起点が無効であることと理由が表示・読み上げられ、2行目の起点欄にフォーカスが移る。
  検索は始まらず、ファイルリストは変わらない
- **US99-AS9**: **Given** 起点の行が A と、空白だけの行, **When** 「検索」を押す, **Then** 空白だけの行は無視され、A だけを起点に検索する。
  検索バーは「A」と表示され、「ほか」は付かない
- **US99-AS10**: **Given** A と B を起点に検索中, **When** B のフォルダがアプリの外で削除される,
  **Then** B の配下の結果だけが一覧から外れ、A の配下の結果と検索は続く
- **US99-AS11**: **Given** A と B を起点に検索した結果を表示中, **When** ツリーで B のフォルダの名前を B2 に変える,
  **Then** 検索バーのツールチップの B の絶対パスと、B の配下の結果の「場所」列が B2 の名前になる。結果は外れない

### User Story 100 - 重なった起点を指定しても同じ項目が重複しない (Priority: P1)

ユーザーは、同じフォルダを2回指定したり、親フォルダとその中のフォルダを両方指定したりしても、
同じ項目が2回表示されない検索結果を得られる。

**Why this priority**: 起点を複数にしたことで新たに起こる誤り（重複した行・件数の水増し・余分な読み取り）を防ぐため。
US99 と同じく、複数起点を使える状態にするための前提である。

**Independent Test**: 親フォルダ P とその中のフォルダ P/C を両方起点に指定して検索し、P だけを起点にした検索と同じ行と
件数になることを確かめる。

**Acceptance Scenarios**:

- **US100-AS1**: **Given** 起点の行に同じフォルダ A を2回（片方は末尾に `/` を付けて、または `~` で始めて）入力した,
  **When** 検索する, **Then** A を1回だけ起点にした検索と同じ行と件数になる。検索バーは「A」と表示され、「ほか」は付かない
- **US100-AS2**: **Given** 起点の行に P と、その配下のフォルダ P/C を入力した, **When** キーワード `C` で検索する,
  **Then** P だけを起点にした検索と同じ行と件数になる。P/C は P の配下のフォルダとして、名前が一致すれば行になる
- **US100-AS3**: **Given** 起点の行に P と、P の配下の隠しフォルダの中のフォルダ P/.hidden/D を入力した, **When** 検索する,
  **Then** P の配下（隠しフォルダの中を除く）と D の配下の両方の結果が表示される。同じ項目は1回だけ現れる
- **US100-AS4**: **Given** 起点の行に A と、A を指すシンボリックリンク L を入力した, **When** 検索する,
  **Then** A を1回だけ起点にした検索と同じ行と件数になる
- **US100-AS5**: **Given** 名前が同じ `Photos` のフォルダ `/Volumes/X/Photos` と `~/Photos` を起点にした, **When** 検索結果をリスト形式で見る,
  **Then** 「場所」列は `/Volumes/X/Photos/…` と `/Users/<ユーザー>/Photos/…` のように起点の絶対パスから始まり、どちらの場所の項目かを見分けられる

### User Story 101 - ワイルドカードを使えることを知る (Priority: P2)

ユーザーは、検索のモーダルを開いたときに、キーワードで `*` と `?` のワイルドカードを使えることと、その意味を知れる。

**Why this priority**: Issue の副次的な要望。検索の機能そのものは変えずに、既存の機能（FR-082（search.md））を見つけやすくする。

**Independent Test**: 日英の両方の表示言語で検索のモーダルを開き、キーワード欄の下にワイルドカードの説明が切れずに表示されることと、
VoiceOver がキーワード欄の説明として読み上げることを確かめる。

**Acceptance Scenarios**:

- **US101-AS1**: **Given** 一覧を表示中, **When** ⌥⌘F（または「ファイル」メニューの「検索…」、ツールバーの検索欄の虫眼鏡）でモーダルを開く,
  **Then** 検索キーワード欄の直下に、小さく淡い文字で
  「* は0文字以上の任意の文字、? は任意の1文字に一致します。* か ? を含むときは、名前全体と一致するものを探します。」が表示される
- **US101-AS2**: **Given** 前回のキーワード `cat` が入った状態でモーダルを開いた, **When** 画面を見る,
  **Then** ワイルドカードの説明は表示されたままである（プレースホルダのように隠れない）
- **US101-AS3**: **Given** モーダルを開いて VoiceOver を使っている, **When** 検索キーワード欄に移る,
  **Then** キーワード欄の説明として、モーダルの補足説明（FR-394（search.md））に続けてワイルドカードの説明が読み上げられる。
  説明の文が独立した項目として二重に読まれることはない
- **US101-AS4**: **Given** 表示言語が英語, **When** モーダルを開く,
  **Then** ワイルドカードの説明は `* matches any number of characters and ? matches one character. With * or ?, the whole name must match.`
  で表示され、ウインドウの幅に収まって切れない

### Edge Cases

- **EC-300**: 起点の行に同じフォルダを指す入力が複数ある場合（表記の違い・`~`・末尾の `/`・シンボリックリンク・
  GUI 選択と直接入力の違いを含む）は、検証後のフォルダが同じなら1つの起点として扱う（FR-437）
- **EC-301**: ある起点 C が別の起点 P の配下にあり、P から C までの間に隠しフォルダ・パッケージがない場合は、
  C を起点から除き、P の検索で C とその配下を辿る（FR-437）。
  - C の名前がキーワードに一致すれば、C は P の配下のフォルダとして行になる（FR-083 の「起点そのものは一致の対象にしない」は
    P に対して適用する）
- **EC-302**: 起点 C が P の配下でも、P から C までの間に隠しフォルダまたはパッケージがある場合は、P と C の両方を起点にする。
  - P の検索はその隠しフォルダ・パッケージの中を辿らないため、同じ項目が重複しない（FR-083・FR-437）
- **EC-303**: 起点の行のうち1つでも無効（FR-081 の検証に失敗）なら、検索を始めない。
  - 最も上の無効な行について、行の番号と理由を示し、その行の起点欄にフォーカスを移す（FR-436）
- **EC-304**: 空白だけの起点の行は無視する。すべての行が空白だけなら、従来の「検索起点ディレクトリを入力してください」
  を示す（FR-436・EC-34（search.md））
- **EC-305**: 2つ以上の起点のフォルダ名が同じ場合、それらの起点の配下の項目の「場所」列（サムネイル形式のツールチップ）は、
  起点の絶対パスから始める（FR-084（変更））
  - フォルダ名は大文字小文字の違いを区別せずに比べる（`Photos` と `photos` も同じとみなす）
- **EC-306**: 検索中または検索結果の表示中に、起点の1つが削除・移動された（ボリュームが外された）場合は、
  その起点の配下の結果だけを外し、ほかの起点の結果・検索は続ける。
  - すべての起点が消えた場合は EC-36（search.md）と同じく、結果が0件になった旨を表示する（FR-440）
- **EC-307**: ルート `/` とほかの起点を指定した場合、ほかの起点は `/` の検索で辿られる限り除く（EC-301）。
  - 隠しフォルダ（`/private` など OS が隠すものを含む）の配下の起点は EC-302 に従う
- **EC-308**: 起点の行を削除しても、残った行の入力の由来（直接入力か GUI 選択か。FR-081）と値は変えない
- **EC-309**: 起点の行を追加・削除しても、進行中の検索・検索結果・ツリー・プレビューは変えない（FR-142（search.md）の
  「選択操作を理由に変えない」と同じ）

## Requirements *(mandatory)*

### Functional Requirements

#### 変更する項目

- **FR-081（変更）**: 検索のモーダルは、冒頭の見出しとその補足説明（FR-394）、「検索キーワード」（標準の検索フィールド）と
  その直下のワイルドカードの説明（FR-441）、「検索起点ディレクトリ」の見出しと1行以上10行以下の起点の行（各行は1行のテキスト入力・
  「選択…」ボタン・「削除」ボタン。FR-435）、「起点を追加」ボタン、「検索」ボタン、「キャンセル」ボタンで構成しなければならない。
  - モーダルを開いたときの起点の行は1行とし、その既定値は、ファイルリストに表示中のフォルダの絶対パスとする。
  - 検索結果の表示中は検索前のフォルダ、zip の中を表示中は FR-069 により zip ファイルを含むフォルダとする。
  - お気に入りの見出しを選択しても一覧のフォルダを使う。
  - EC-102で一覧に F、ツリーに祖先 V を表示している場合は F を使い、V へ置き換えない。
  - 「検索」で検索を始めてモーダルを閉じる。
  - 「キャンセル」（Esc を含む）ではモーダルを閉じるだけで、ファイルリスト・ツリー・
    プレビューを取消操作によって変えてはならない。
  - モーダルを開いたときは検索キーワード欄にフォーカスを置き、
    同じ起動中に前回検索したキーワードがあれば全選択した状態で入れておく（起点の行は毎回上の既定値の1行とする）。
  - 標準パネルを開いていないときは、Return で「検索」（キーワードが空のときは何もしない）、Esc で「キャンセル」
    とする。
  - Tab は検索キーワード → 各起点の行（上の行から順に、起点欄 → 「選択…」 → 「削除」） → 「起点を追加」 → キャンセル →
    検索の順、⇧Tab は逆順に移動し、システムのキーボードナビゲーションの設定に関わらずボタンにも止まる。
  - 無効な「削除」「起点を追加」には止まらない。
  - 各起点欄は直接入力・編集を引き続き可能とし、入力手段によらず「検索」を押したときに確かめる（FR-436）。
  - 直接入力では前後の空白を除き、先頭の `~` はホームフォルダ、末尾の `/` は無視して解釈する。
  - GUI 選択で反映してから起点欄を編集していない間だけは、名前の末尾の空白も含む選択した絶対パスを文字どおり使い、
    空白除去は行わない。
  - 起点欄を編集した時点で従来の直接入力の解釈へ戻す。
  - キーワードの編集・ほかの行の編集・行の追加と削除・標準パネルの取消では、この区別を変えない。
  - `/` と `~` のどちらでも始まらないパス、存在しないパス、フォルダでないパス（zip ファイルを含む）、
    読み取り権限のないフォルダの場合は、モーダルを閉じずに理由を起点の行の近くに表示し、

- **FR-083（変更）**: 検索は、各検索起点ディレクトリ以下のすべての階層のサブフォルダを辿って行わなければならない。

- **FR-084（変更）**: システムは、検索結果（一致したファイルとフォルダ）を、

  - サムネイル形式は名前だけを表示し、場所はポインタを重ねたときの説明で示す。

#### 追加する項目

- **FR-435**: ユーザーは、検索のモーダルで、起点の行を「起点を追加」で一覧の末尾に加え、各行の「削除」でその行を取り除けなければならない。
  - 加えた行の起点欄は空とし、その起点欄にフォーカスを移す。
  - 行が10行のときは「起点を追加」を無効にする。
  - 行が1行のときはその行の「削除」を無効にする。
  - 行を削除したときは、同じ位置に繰り上がった行の起点欄にフォーカスを移し、最後の行を削除したときは新しい最後の行の起点欄に移す。
  - 行の追加と削除では、ほかの行の値と入力の由来（FR-081）・キーワード・表示中の検証の理由のうちほかの行に対するものを変えない。
  - 削除した行に対する検証の理由は消す。
  - 標準パネルの表示中と、標準パネルの初期位置の解決中・選択の検証中・起点の検証中（FR-436）は、行の追加と削除を受け付けない。
  - 行の追加と削除では検索を開始せず、進行中の検索・検索結果・ツリー・ファイルリスト・プレビューを変えない（EC-309）。
  - 各行の起点欄・「選択…」・「削除」は、スクリーンリーダーで行の番号を含む名前で識別できる
    （例:「検索起点ディレクトリ 2」「検索起点 2 を選択」「検索起点 2 を削除」）
- **FR-436**: システムは、「検索」を押したとき、空白だけの行を除いたすべての起点の行を FR-081 の規則で解釈・検証し、
  すべてが有効なときだけ検索を始めなければならない。
  - 空白だけの行は無視し、残った行がなければ従来の「検索起点ディレクトリを入力してください」の理由を示す（EC-304）。
  - 無効な行が1つでもあれば検索を始めず、モーダルを開いたままにする（EC-303）。
  - そのとき、最も上の無効な行について、行の番号と理由を起点の行の近くに表示・読み上げ、その行の起点欄にフォーカスを移す。
  - 理由の表示は、起点が1行だけのときは従来の文言とし、行の番号を付けない。
  - 検証はすべて UI スレッドの外で行い、検証中は従来どおり重ねて「検索」を受け付けない（FR-143 の保留中の選択の扱いを含む）。
  - 検証の途中で起点欄・キーワード・行の数が変わったときは、その検証の結果で検索を始めず、理由も表示しない
- **FR-437**: システムは、検証した起点を、検索の前に次のとおり整理しなければならない。
  - シンボリックリンクを解決したパスが同じ起点は1つにまとめ、一覧の上の行の位置に置く（EC-300）。
  - ある起点が別の起点の配下にあり、その間の階層に隠しフォルダもパッケージもない場合は、配下の起点を除く（EC-301）。
  - 間に隠しフォルダまたはパッケージがある場合は、両方を起点に残す（EC-302）。
  - 整理の後の起点が、検索バー（FR-439）・「場所」列（FR-084）・変更への追随（FR-440）で使う起点となる。
  - 整理は UI スレッドの外で行い、整理によって同じ項目が検索結果に2回以上現れてはならない
- **FR-438**: システムは、整理した起点（FR-437）を一覧の上から1つずつ順に辿り、すべての起点の結果を1つの検索結果として扱わなければならない。
  - 見つかった項目から順に一覧へ加え（FR-085）、件数はすべての起点の合計とする。
  - すべての起点を辿り終えたときに検索を完了とする。
  - 検索を止める操作（FR-085・FR-086・FR-140）は、残りの起点も含めて検索全体を止める
- **FR-439**: 検索バー（FR-084）は、整理した起点の数に応じて、次のとおり起点を示さなければならない。
  - 1つのときは、従来どおり起点のフォルダ名（ルートは `/`）を示す。
  - 2つ以上のときは、最初の起点のフォルダ名と残りの数を「{フォルダ名} ほか {n} か所」（英語: `{folder} and {n} more`）で示す。
  - ツールチップには、すべての起点の絶対パスを上の順に1行ずつ示す。
  - 検索中・完了・種類フィルタによる件数の表示は従来どおりとする
- **FR-440**: 検索起点に関する既存の規則は、整理した起点のそれぞれに適用しなければならない。
  - 起点そのもの・祖先の名前の変更（FR-105）は、その起点の検索バーの表示・ツールチップ・配下の結果の「場所」列に反映する。
  - 起点そのものの削除・移動・ボリュームの取り外し（EC-36）は、その起点の配下の結果だけを外し、ほかの起点の結果と検索は続ける（EC-306）。
  - 変更通知（FR-232）は、すべての起点の配下を対象にする。
  - 検索中のフォルダの名前の変更（FR-105・EC-52・EC-94）は、そのフォルダを含む起点について従来の規則で扱う
- **FR-441**: 検索のモーダルは、検索キーワード欄の直下に、ワイルドカードの説明を表示しなければならない。
  - 説明は「* は0文字以上の任意の文字、? は任意の1文字に一致します。* か ? を含むときは、名前全体と一致するものを探します。」
    （英語: `* matches any number of characters and ? matches one character. With * or ?, the whole name must match.`）とする。
  - 補足説明（FR-394）と同じく、見出しより小さい文字と OS の標準の淡い（二次的な）文字色で表示し、選択・編集できず、Tab の移動先にならない。
  - キーワードの有無に関わらず表示し続ける。
  - 検索キーワード欄のアクセシビリティの説明（ヘルプ）は、補足説明（FR-394）に続けてこの説明を加えたものとし、
    読み上げで独立した項目として二重に読ませない。
  - 表示言語を切り替えたときは新しい言語にし、開き方（⌥⌘F・メニュー・虫眼鏡）によらず同じに表示する。
  - 照合の規則（FR-082）は変えない

### Key Entities

- **検索条件（変更）**: 検索キーワード（ワイルドカード `*`・`?` を含められる）と、1つ以上10以下の検索起点ディレクトリの並び。保存しない
- **起点の行**: 検索のモーダルの中だけにある、1つの起点の入力。起点欄の値と入力の由来（直接入力か GUI 選択か。FR-081）を持つ。
  モーダルを閉じると破棄する
- **整理した起点**: 検証と整理（FR-437）の後の、重複と重なりのない起点の並び。検索の間と検索結果の表示中だけ保つ

## Assumptions

- **A-263**: 「複数の検索起点パスに対応する」は、1回の検索で複数のフォルダの配下を探し、結果を1つの一覧にまとめる意味と解釈した。
  - 起点ごとに結果を分けて表示する（タブ・グループ見出し）ことは範囲外とする。「場所」列と並べ替えで見分ける
- **A-264**: 起点の行の上限は10行とする。
  - シートの高さを画面に収め、1回の検索で辿る場所の数を抑えるためである
- **A-265**: モーダルを開いたときの起点の行は既定値の1行とし、前回の検索の起点の並びは復元しない。
  - 検索条件を保存しない規則（FR-086）と、毎回既定値で開く従来の動作（FR-081）に合わせる
- **A-266**: 起点は一覧の上から1つずつ順に辿り、並行しては辿らない。
  - 同じディスク上の場所を並行して辿ると読み取りが競合し、合計の時間が単一の起点より悪くなり得るためである。
  - 別のボリュームにある起点を並行して辿る最適化は範囲外とし、必要なら性能の測定に基づいて別の Issue で扱う
- **A-267**: ツールバーの検索欄の絞り込み（FR-381（file-list.md））と、虫眼鏡からの引き継ぎ（FR-390（file-list.md））は変えない。
  - 虫眼鏡から開いたモーダルでも、⌥⌘F と同じく起点の行を追加できる
