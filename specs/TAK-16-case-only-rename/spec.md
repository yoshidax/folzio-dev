## User Scenarios & Testing *(mandatory)*

### User Story 1 - ファイルの表記を整える (Priority: P1)

ユーザーは一覧のファイルを選び、大文字小文字だけを変えて保存できる。

**Why this priority**: TAK-16 の主目的で、一般的なボリュームでも名前を整えられる。

**Independent Test**: 大文字小文字を区別する・しない両ボリュームで、photo.png → Photo.png と photo.png → photo.PNG を実行する。

**Acceptance Scenarios**:

1. **Given** photo.png と競合する別項目がない, **When** Photo.png へ変更して確認する, **Then** 入力した表記で保存され、内容は同一、一覧とプレビューが結果に追従する。
2. **Given** 確認モーダルの省略設定がオン, **When** photo.PNG に変更する, **Then** 名前の変更の確認を必ず表示し、拡張子の大文字小文字だけの変更では拡張子変更の追加確認は出さない（EC-15 の既存規則）。
3. **Given** 大文字小文字を区別するボリュームに photo.png と Photo.png の別項目がある, **When** 前者を Photo.png または PHOTO.PNG へ変更する, **Then** 検証エラーで拒否し、両者の名前・内容を保つ。別項目が同じ実体のハードリンクやシンボリックリンクでも同様。
4. **Given** 名前の編集中, **When** Esc または確認のキャンセルを選ぶ, **Then** 名前も内容も変えない。元と完全に同じ表記で確定した場合も変更しない（EC-48）。

### User Story 2 - フォルダの表記を整える (Priority: P1)

ユーザーはファイルリストとツリーで通常フォルダの大文字小文字だけを変えられる。

**Why this priority**: ファイルとフォルダで一貫した操作を提供する。

**Independent Test**: 中にファイルを含む Album を一覧とツリーから album に変更し、実際の名前と中身、表示中の子ファイルの継続を確認する。

**Acceptance Scenarios**:

1. **Given** Album の内容を表示中, **When** ツリーで album に変更し確認する, **Then** 実際の表記が変わり、FR-104 の選択・展開・スクロール・プレビュー・履歴の反映規則を維持する。
2. **Given** リスト形式またはサムネイル形式のフォルダ, **When** 大文字小文字だけを変更する, **Then** 常に確認後に変更し、子ファイルの名前・内容を保つ。
3. **Given** 同じ親に別項目 ALBUM がある, **When** Album を album に変更する, **Then** 検証エラーとし、両項目・中身を保つ。ファイルとフォルダの組み合わせでも同様。
4. **Given** フォルダの編集中, **When** 確認をキャンセルするか別項目との競合が起きる, **Then** 名前・中身・表示先を変更しない。

### Edge Cases

- 大文字小文字を区別するボリュームでも別項目との比較では違いを無視する。元項目の除外は表記が完全一致するエントリだけとする。
- 非表示の項目・別の種類の項目・リンクも兄弟の競合に含める。実体の一致だけで元項目と判定しない。
- 親の読み取り不可、元項目の消失、書き込み権限不足、操作中の外部変更は成功扱いせず FR-026 に従う。外部変更との完全なトランザクション制御は追加しない。
- 大文字小文字を区別しない環境で旧パスにアクセスできても、保存された表記が変わっていれば成功とする。
- 検索結果・表示中フォルダ配下・zip の閲覧中のパス反映は FR-027・FR-087・FR-104・FR-105 と同じ規則を適用する。

## Requirements *(mandatory)*

### Functional Requirements（変更）

- **FR-025**: コピーまたは移動の操作先に同名ファイルが存在する場合、システムは確認モーダル設定に関わらず「置き換える / 両方残す / 中止」を選ばせなければならない。ただしコピー元と衝突先が同一の項目である場合は「置き換える」を選べないようにし、「両方残す / 中止」を選ばせる。この例外はドラッグ以外のコピーにも適用する。名前の変更で同じ親フォルダにある別の項目の名前（大文字小文字の違いのみを含む）を指定した場合は、衝突ダイアログを出さず、名前の検証エラーとして拒否しなければならない。複製は FR-018 の連番の規則に従い、この対象外とする。 元項目自身の名前の大文字小文字だけを変える変更は、ボリュームが大文字小文字を区別するかに関わらず許可し、入力した表記を保存する。別のディレクトリエントリは、同じ実体を指すリンクであっても別項目として扱う。

- **FR-103**: ユーザーは、ツリーの通常のフォルダ（ホーム・マウント中のボリュームの最上位の下にある実際のフォルダ。FR-079 と
  同じ範囲）の名前を、次のどの手段でも変更できなければならない。
  （1）そのフォルダをツリーで選択し、ツリーにキーボードフォーカスがあるときに Return を押す。
  （2）そのフォルダの行の右クリックメニューの「名前を変更」を選ぶ（右クリックした行を対象にし、選択中の行でなくてもよい。
  A-21）。
  （3）ツリーにキーボードフォーカスがあり、そのフォルダを選択しているときに「編集」メニューの「名前を変更」を選ぶ。
  名前の編集はその行の中で行い、編集の始め方と終え方、名前の検証、確認はファイルリストのフォルダの名前の変更と同じとする。
  すなわち、編集を始めたときは現在の名前を入れ、ファイルリストと同じ範囲（最後の「.」より前。「.」がなければ全体）を選択した
  状態にする。Return またはほかの場所のクリックなどで確定し、Esc で取り消す（名前を変えず、確認モーダルも出さない）。確定した名前は
  前後の空白（改行を含む）を取り除き、空、または編集前と同じ名前なら何もしない。「/」または「:」を含む名前、先頭が「.」の名前、
  同じ場所にある別の項目（ツリーやファイルリストに表示していない隠し項目やファイルを含む）と大文字小文字の違いだけを含めて同じ名前、
  システムがパッケージとして扱う名前（EC-53）は、検証エラーを表示して拒否する（EC-14・FR-025）。元フォルダ自身の大文字小文字だけの変更は FR-025 に従い許可する。検証を通った名前は、確認モーダル（FR-022）を設定に
  関わらず表示してから変更し（FR-024）、キャンセルした場合は変更しない。この確認モーダルには、ファイルリストの
  名前の変更の確認モーダルの内容に加えて、対象のフォルダの絶対パスを示す（同じ名前の別のフォルダと見分けられるようにする）。
  名前の編集欄には「フォルダの名前」というアクセシビリティラベルを付ける（お気に入りの表示名の編集欄の「お気に入りの名前」
  （FR-101）と区別する）。失敗した場合は FR-026 に従って
  表示する。編集を始めても、ツリーの選択・ファイルリスト・プレビュー・最後に選択していたフォルダ（FR-003）は
  変えない。ホーム・ボリュームの最上位・「お気に入り」の見出しを選択中の Return は何もせず、それらの右クリックメニューに
  「名前を変更」は出さず、それらを選択中は「編集」メニューの「名前を変更」を無効にする。お気に入りの項目の Return・
  「名前を変更」は、従来どおり表示名の変更（FR-099）とする。ファイルリストに zip の中または検索結果を表示中でも、
  ツリーにフォーカスがあれば（1）〜（3）は使える（zip の中の読み取り専用と検索結果の制限はファイルリストの操作にだけ適用する）。
  ファイルリストにフォーカスがあるときの Return と「名前を変更」は、従来どおりファイル名の変更（FR-019）とする

- **EC-14**: リネームで使用できない文字、同じ親フォルダにある別項目と同名（大文字小文字の違いのみを含む）を指定した場合、または
  フォルダの名前をシステムがパッケージとして扱う名前（EC-53）に変えようとした場合はエラーを表示し確定しない。空の名前
  （前後の空白だけを含む）と編集前と同じ名前は、エラーを出さずに何もしない（EC-48）

- **US1-AS39**: **Given** ツリーのフォルダの名前を編集している, **When** 「/」「:」を含む名前、先頭が「.」の名前、
  同じ場所にある別の項目と同じ名前（大文字小文字の違いだけのものを含む）、またはパッケージとして扱われる名前（例: `Photos.app`）で
  確定する, **Then** ファイルリストの
  名前の変更と同じ検証エラーが表示され、フォルダの名前は変わらない

### Key Entities

- **改名元項目**: 親、保存されている名前、ファイルまたはフォルダ、中身。
- **兄弟項目**: 同じ親にある別エントリ。表示の有無やリンク先に依存せず競合判定に含める。
- **改名結果**: 入力表記の新しい場所、または失敗理由。既存の結果通知を使う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-100**: 両ボリューム種別で、ファイル・フォルダの大文字小文字だけの改名が受け入れシナリオの全ケースで入力表記どおりに保存され、中身の変更が 0 件。
- **SC-101**: 別項目との競合・キャンセルの全ケースで、元項目と別項目の名前・内容の変更が 0 件。成功時の表示は FR-027・FR-104 と一致する。

## Assumptions

- **A-39**: ホームフォルダとマウント中のボリュームの最上位の名前の変更は範囲外とする。通常フォルダ自身の大文字小文字だけの変更（`Album` → `album`）は FR-025・FR-103 に従って許可する。
- 新しい設定・確認モーダル・一括改名は追加しない。既存の Return とメニューを使う（FR-019・FR-103）。
- ファイルの一覧・サムネイル・既存の検索結果の改名に適用する。zip 内の項目は引き続き読み取り専用（FR-073）。お気に入りの表示名は変更しない。
- Core の判断・操作・異常系は自動テストを追加する。GUI と両ボリューム種別の実操作の確認をマージ前の条件にする。
- 新規 ID は master 取り込み時に再確認する。採番時の既存 SC 最大値は 099。SC-100/101 を使用する。
