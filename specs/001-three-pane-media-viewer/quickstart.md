# Quickstart: 3ペイン型メディアビューアの検証手順

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

機能が端から端まで動くことを確かめるための、実行と検証の手順。操作の割り当ては
[contracts/keyboard-and-menus.md](./contracts/keyboard-and-menus.md)、設定キーは
[contracts/settings.md](./contracts/settings.md)、バンドルとアイコンは
[contracts/app-bundle.md](./contracts/app-bundle.md) を参照。

## 前提条件

- macOS 15 以降、Apple Silicon または Intel の Mac
- Xcode（Swift 6 ツールチェーン付き）。`swift --version` で 6.0 以上であること
- ネットワーク接続は不要（原則 I）

## ビルドと自動テスト

```bash
swift build                                      # Core と App をビルド
swift test --filter MediaViewerCoreTests         # 単体・異常系テスト（原則 IV）
swift test --filter MediaViewerPerformanceTests  # 性能基準の計測（原則 II）。結果は PR に記載する
scripts/check-no-archive-writes.sh              # zip の読み取りのコードに書き込み系の API がないこと（FR-072）
```

**期待結果**: すべてのテストが通る。性能テストは基準値（下の「性能の検証」）を超えると失敗する。

## 起動

```bash
swift run MediaViewerApp            # 開発中の起動（TCC の許可はターミナルに紐づく）
scripts/make-app.sh                 # .build/MediaViewer.app を組み立てて ad-hoc 署名する
open .build/MediaViewer.app
```

## アプリアイコンの検証（FR-043〜045、SC-011）

`swift run` はバンドルを持たないため標準アイコンになる。アイコンの確認は必ず `.app` で行う。

```bash
scripts/make-app.sh
test -f .build/MediaViewer.app/Contents/Resources/AppIcon.icns
plutil -extract CFBundleIconFile raw .build/MediaViewer.app/Contents/Info.plist
iconutil -c iconset .build/MediaViewer.app/Contents/Resources/AppIcon.icns -o /tmp/MediaViewer.iconset
sips -g pixelWidth -g pixelHeight /tmp/MediaViewer.iconset/icon_16x16.png
open .build/MediaViewer.app
```

**期待結果**:

- `plutil` が `AppIcon` を返し、`iconutil` が全スロットを展開できる（[contracts/app-bundle.md](./contracts/app-bundle.md)）
- `icon_16x16.png` が 16×16、`icon_512x512@2x.png` が 1024×1024 である
- Finder・Dock・⌘Tab・About に、汎用アイコンではなく3ペインをモチーフにした同じアイコンが出る
- 16px と 32px でも3ペインの図案が判別でき、ライト・ダークの両方の外観で同じアイコンが表示される
- アイコン生成に失敗した場合、`scripts/make-app.sh` は `.app` を残さず非ゼロで終了する

## 検証用フォルダの準備

```bash
scripts/make-fixtures.sh ~/MediaViewerFixtures
```

次のフォルダを生成する（自動テストのフィクスチャ生成と同じ処理を使う）。

| フォルダ | 内容 |
|----------|------|
| `mixed/` | JPEG・PNG・GIF（アニメーション）・WebP（静止とアニメーション）・mp4・mov・.txt・.pdf・サブフォルダ・隠しファイル |
| `broken/` | 破損 JPEG、中身が PNG の .jpg、0 バイトの .mp4 |
| `huge/` | 10,000 個の小さな JPEG |
| `bigimage/` | 1億画素級の PNG |
| `ops/` | ファイル操作の検証用。毎回作り直してよい。フォルダの操作用に `album/`（中に JPEG 2 枚と `inner/`）を含む |
| `folders/` | ファイルリストのフォルダの検証用（FR-076〜078）。下の表を参照 |
| `zip/` | zip 対応の検証用（FR-068〜075）。下の表を参照 |
| `search/` | ファイル名の検索の検証用（FR-080〜087）。下の表を参照 |

`zip/` の内容（`FixtureKit` の `ZipFixtureWriter` で生成する。外部の `zip` コマンドは使わない。research.md R28）:

| ファイル | 内容 |
|----------|------|
| `cover.jpg` | 通常の画像（zip と並んで一覧に出ることの確認用） |
| `photos.zip` | deflate。ディレクトリの項目なしで `sub/deep/` まで階層を持つ。JPEG・PNG・アニメーション GIF・WebP・.txt・`.hidden.jpg`・`__MACOSX/._01.jpg`・入れ子の `inner.zip` |
| `videos-stored.zip` | 無圧縮で格納した 640×360 の mp4 と mov、1080p の mp4（10 秒、faststart。SC-014 の再生開始の計測用） |
| `videos-deflated.zip` | deflate で格納した mp4（faststart: `VideoFixtures` の `fastStart: true`）と mov（再生用の情報が末尾: 既定） |
| `names-sjis.zip` | UTF-8 フラグなし・CP932 の名前（`写真①.jpg`、`フォルダ/画像.png`） |
| `names-utf8.zip` | UTF-8 フラグありの日本語の名前 |
| `locked.zip` | 暗号化フラグの JPEG、格納方式 12（bzip2）の PNG、通常の JPEG |
| `no-media.zip` | .txt だけ |
| `empty.zip` | 項目なし |
| `broken.zip` | 途中で切れた zip |
| `not-a-zip.zip` | 中身がテキストのファイル |
| `huge.zip` | 10,000 個の小さな JPEG（SC-015） |

`folders/` の内容（`FixtureSets.folders(in:)`）:

| 項目 | 内容 |
|------|------|
| `cover.jpg` | 通常の画像 |
| `trip/` | `day1/`（JPEG 3 枚）と `day2/`（PNG 1 枚）を持つ。`day1/` の中にさらに `best/`（JPEG 1 枚） |
| `only-subfolders/` | メディアはなく、サブフォルダ `inner/` だけを持つ |
| `empty-folder/` | 空 |
| `.hidden-folder/` | 隠しフォルダ（一覧にもツリーにも出ない） |
| `Viewer.app/` | パッケージ（一覧にもツリーにも出ない） |
| `dir.zip/` | 名前が .zip のフォルダ（フォルダとして出る。zip としては開かない） |

`search/` の内容（`FixtureSets.search(in:)`。名前に `cat` を含むかどうかで、一致するもの・しないものを分けてある）:

| 項目 | 内容 | `cat` で見つかるか |
|------|------|--------------------|
| `Cat01.jpg` | 起点の直下の画像 | 見つかる（大文字小文字を区別しない） |
| `a/my_cat.mov`・`a/dog.png` | サブフォルダの動画と画像 | `my_cat.mov` だけ |
| `a/b/deep/cat-deep.png` | 3 階層下 | 見つかる |
| `b/Cat01.jpg` | 起点の直下と同じ名前 | 見つかる（「場所」列で見分ける） |
| `kana/が.png` | 名前を NFD（`か` + 結合用濁点）で書いた画像 | キーワード `が`（NFC）で見つかる |
| `numbers/IMG_0001.jpg`・`numbers/IMG_12.jpg` | `?` の確認用 | `IMG_????.jpg` で `IMG_0001.jpg` だけ |
| `cat.txt`・`cats.zip`（中に `cat.jpg`） | 対応メディアでないファイルと zip | 見つからない（zip の中も見ない） |
| `cat-folder/x.jpg` | 名前に `cat` を含むフォルダ | 見つからない（フォルダ名は照合しない） |
| `.hidden/cat-hidden.jpg`・`.cat-dot.jpg` | 隠しフォルダの中と隠しファイル | 見つからない |
| `Viewer.app/Contents/cat-pkg.jpg` | パッケージの中 | 見つからない |
| `link`（`a/` へのシンボリックリンク） | シンボリックリンクのフォルダ | リンク経由では見つからない（`a/` 経由の1件だけ） |
| `linked.jpg`（`Cat01.jpg` へのシンボリックリンク） | ファイルへのシンボリックリンク | `cat` では見つからない。キーワード `linked` で見つかる（通常の一覧と同じく対象にする。FR-083） |

SC-014 のメモリの確認用に、大きな動画の zip を別に作れる。生成に時間とディスク（約 2.3GB）を使うため、既定では作らない。

```bash
scripts/make-fixtures.sh ~/MediaViewerFixtures --big   # zip-big/ を追加で作る
```

| ファイル | 内容 |
|----------|------|
| `zip-big/big-video-stored.zip` | 1080p・約 1.1GB の mp4 を無圧縮で格納 |
| `zip-big/big-video-deflated.zip` | 同じ mp4 を deflate で格納 |

## 手動の検証シナリオ

各シナリオは spec のユーザーストーリーに対応する。

### US1: フォルダを辿って画像をプレビューする
1. ツリーでホーム → `MediaViewerFixtures` → `mixed` を展開して選択する
2. **期待結果**: ツリーの各フォルダ名の先頭にアイコンがあり、ホーム（`house`）・マウント中の
   ボリューム（`externaldrive`）・通常フォルダ（`folder`）が互いに区別できる。展開・折りたたみや
   選択をしてもアイコンは変わらず、操作を妨げない（FR-047、SC-013）
3. **期待結果**: リストの先頭行に `..`、続いてサブフォルダ `sub` と画像4種・動画2種が並び、.txt・.pdf・隠しファイルは出ない（FR-008・076・077）
4. ↓ キーで順に選択を移す。**期待結果**: プレビューが追従し、画像は縦横比を保ってペイン内の
   最大サイズで表示される。ペインより小さい画像（例: 400×300 の `02-image.png`）は拡大される。
   アニメーション GIF は動く。アニメーション WebP は動くか、先頭フレームの
   静止画で表示される（どちらでも合格。エラー表示や空白になれば不合格）

### ツリーのダブルクリック開閉と開閉の三角（FR-053〜055）

準備（`MediaViewerFixtures` の中に、ツリー確認用のフォルダを作る）:

```bash
mkdir -p ~/MediaViewerFixtures/tree/has-sub/child ~/MediaViewerFixtures/tree/hidden-only/.secret \
  ~/MediaViewerFixtures/tree/package-only/Sample.app ~/MediaViewerFixtures/tree/empty \
  ~/MediaViewerFixtures/tree/denied/inner
chmod 000 ~/MediaViewerFixtures/tree/denied
# 確認後に戻す: chmod 755 ~/MediaViewerFixtures/tree/denied
```

1. ツリーでホーム → `MediaViewerFixtures` → `tree` を展開する。**期待結果**: `has-sub` にだけ開閉の三角があり、
   `hidden-only`・`package-only`・`empty`・`denied` には三角がない。`denied` は「アクセスできません」の表示に
   なる。三角のある行とない行でアイコンとフォルダ名の位置が揃っている（FR-054・055）
2. `has-sub` のフォルダ名をダブルクリックする。**期待結果**: `has-sub` が選択されてファイルリストが
   切り替わり、展開されて `child` が表示される。`child` には三角がない。もう一度ダブルクリックすると
   折りたたまれる。アイコンの上でダブルクリックしても同じ（FR-053）
3. `empty` と `hidden-only` をダブルクリックする。**期待結果**: 選択とファイルリストの切り替えだけが起き、
   展開されない。→ キーでも展開しない
4. `has-sub` の三角を素早く2回クリックする。**期待結果**: 三角を2回クリックしたときと同じく
   展開してから折りたたまれ、ダブルクリックによる開閉が追加で起きない
5. Finder またはターミナルで `mkdir ~/MediaViewerFixtures/tree/empty/new` を実行する。**期待結果**: 数秒以内に
   `empty` に三角が現れる。`rmdir` で消すと三角も消える（FR-042・054）
6. `huge/`（10,000 ファイル・サブフォルダなし）を含む `MediaViewerFixtures` を展開する。**期待結果**: 展開直後から
   ツリーを上下キーでスクロール・選択でき、移動を続けても表示が 100ms 以上止まらない。`huge` には三角が出ない（FR-055）
7. 外付けドライブまたはディスクイメージをマウントする。**期待結果**: ツリーにボリュームが現れ、
   サブフォルダがあれば三角が付く。ボリュームの中までは確認しない（展開するまで孫の三角は確認されない）

### お気に入り（FR-061〜067）

準備: 前回の検証で残ったお気に入りがあれば、各項目を ⌘Delete で削除しておく。確認モーダルの設定（⌘,）は ON にする。

1. 起動する。**期待結果**: ツリーの最上部（ホームより上）に、スターのアイコンと「お気に入り」のラベルの行があり、
   開閉の三角付きで折りたたまれている。▶ をクリックすると展開でき、登録が0件でも見出しは消えない（FR-061）
2. `mixed` を右クリックし、「お気に入りに追加」を選ぶ。**期待結果**: 見出しの下に `mixed` が追加される。項目には三角がない。
   もう一度 `mixed` を右クリックすると「お気に入りに追加」は無効になっている（FR-062・063）
3. ツリーで `huge` を選び、ファイルリストにフォーカスを移して（⌥⌘2）⌃⌘T を押す。**期待結果**: `huge` が `mixed` の後ろに
   追加される。続けてホームのルートを選んで ⌃⌘T を押すと、ホームも追加され、`house` のアイコンで表示される
4. 見出しの下の `mixed` をクリックする。**期待結果**: ファイルリストが `mixed` の内容に切り替わる。ツリー下側の
   `MediaViewerFixtures` の展開状態と表示位置は変わらない（FR-063）
5. ファイルリストで動画を選んで再生し、⇧⌘F を押す。**期待結果**: ツリーにフォーカスが移って「お気に入り」の見出しが
   選択される（折りたたまれていた場合は展開される）。ファイルリスト・プレビューはそのまま変わらず、動画も止まらない。
   続けて ↓ キーを押すと、先頭の項目が選ばれて、ファイルリストがそのフォルダの内容に切り替わる（FR-065）
6. フルスクリーン（⌃⌘F）にして ⇧⌘F を押す。**期待結果**: 何も起きない。解除後に「表示」メニューを開くと
   「お気に入りへ移動（⇧⌘F）」がある
7. 見出しの下の `huge` を右クリックする。**期待結果**: メニューには「お気に入りから削除」だけがある。見出しを
   右クリックしてもメニューは出ない。お気に入りの項目のメニューには「ゴミ箱に入れる」がない（FR-064）
8. 「お気に入りから削除」を選び、確認モーダルで「キャンセル」（Esc）を押す。**期待結果**: `huge` は残る。もう一度選んで
   「削除」を押すと `huge` が消え、Finder で `~/MediaViewerFixtures/huge` が残っていてゴミ箱にも入っていない
9. 見出しの下の `mixed` を選び、⌘Delete を押す。**期待結果**: 「ファイル」メニューの項目名が「お気に入りから削除」に
   なっており、確認モーダルの後に `mixed` がお気に入りから消える。`mixed` のファイルはゴミ箱に入らない。見出しの行が
   選択され、ファイルリストは `mixed` の内容のまま残る
10. ツリーでホームのルートを選び、⌘Delete を押す。**期待結果**: 何も起きない。メニューの項目は
    「ゴミ箱に入れる」で無効になっている。ファイルリストへフォーカスを移して ⌘Delete を押すと、従来どおり
    選択中のファイルをゴミ箱に入れる確認が出る（通常のフォルダの ⌘Delete は「ツリーのフォルダのゴミ箱」で確かめる）
11. 設定（⌘,）で確認を OFF にし、残っているお気に入りの項目で ⌘Delete を押す。**期待結果**: 確認なしで削除される。
    確認を ON に戻す
12. `mixed` と `ops` を登録して終了し、再起動する。**期待結果**: 見出しは折りたたまれて始まり、展開すると `mixed`・`ops` が
    登録順に並んでいる（FR-066）
13. アプリを前面にしたまま、ターミナルで `mv ~/MediaViewerFixtures/ops ~/MediaViewerFixtures/ops-moved` を実行する。
    **期待結果**: 数秒以内に `ops` の項目が淡色になり、ツールチップは「見つかりません」。項目は消えない。選ぶと
    ファイルリストに「フォルダが見つかりません」が出る。`mv` で元に戻すと、数秒以内に通常の表示に戻る。名前を変えた
    フォルダへの追従はしない（FR-067）
14. Finder で `ops` を別の名前に変えてからアプリに戻る。**期待結果**: アプリがアクティブになった時点で、`ops` の項目が
    淡色になる。名前を戻してアプリに戻ると通常の表示に戻る
15. 外付けドライブまたはディスクイメージ上のフォルダを登録し、ボリュームを取り外す。**期待結果**: その項目は淡色で残る。
    再びマウントすると通常の表示に戻る
16. 見つからない項目を選んだまま ⌘Delete を押す。**期待結果**: 確認モーダルの後に削除できる
17. リストのファイルを見出しや項目の上へドラッグする。**期待結果**: ドロップ先として強調されず、ドロップしても何も起きない
18. ツリーでお気に入りの項目を選び、⌘Delete を押さずにプレビューへフォーカスを移して（⌥⌘3）「ファイル」メニューと「編集」メニューを開く。
    **期待結果**: 項目名はどちらも「ゴミ箱に入れる」で、無効になっている。ツリーへ戻って（⌥⌘1）開き直すと「お気に入りから削除」になる
19. 「お気に入り」を展開した状態で、外付けドライブまたはディスクイメージをマウント・取り外しする。**期待結果**: ボリュームの行が
    増減しても、「お気に入り」の見出しは最上部のまま動かず、展開状態と項目の並びも変わらない（FR-061）

### zip ファイル（FR-068〜075）

準備: zip ファイルの表示は既定でオフのため、先にツールバーの「zipファイルを表示」をオンにする（または「表示」メニューの
「zipファイルを表示」、⌃⌘Z）。この節の手順は、zip ファイルの行が見えている状態を前提とする（FR-095）。

1. `zip/` を開く。**期待結果**: 一覧の先頭行の `..` に続いて `cover.jpg` と各 zip ファイルが並び、zip の行頭には zip のアイコンが出る。ツリーの `zip` の下に
   zip ファイルは出ず、`zip` フォルダに開閉の三角も出ない（FR-068）
2. `photos.zip` の行を選ぶ。**期待結果**: プレビューは空になる（FR-075）。⌘C → 別フォルダで ⌘V、Return での名前の変更、⌘Delete が
   通常のファイルと同じに使える（`ops/` にコピーした zip で確かめる。FR-073 の最後の文）
3. `photos.zip` をダブルクリックする。**期待結果**: 一覧の先頭行が `..`、続いて `sub` ディレクトリと JPEG・PNG・GIF・WebP が並ぶ。
   .txt・`.hidden.jpg`・`__MACOSX`・`inner.zip` は出ない。ツリーの選択は `zip` のまま変わらない（FR-069・070）
4. ↓ で画像を順に選ぶ。**期待結果**: プレビューが追従し、GIF は動く。⌘2 / ⌘1 で表示形式を切り替えると、サムネイルとリストの行頭アイコンに
   内容の縮小画像が出る。列見出しで並べ替えると、ディレクトリと画像が区別なく並び替わり、`..` は先頭のまま（FR-071、spec Assumptions）
5. `sub` を選んで ⌘↓、続けて `deep` をダブルクリックする。**期待結果**: それぞれの中の一覧に切り替わる。⌘↑ を押すと `sub` の一覧に戻り、
   `deep` の行が選択されて見える位置にある。`..` をダブルクリックすると最上位に戻り `sub` が選択されている。最上位で ⌘↑ を押すと
   `zip/` の一覧に戻り、`photos.zip` の行が選択されている（FR-070）

### zip ファイルの表示の切り替え（FR-095〜098）

### os_signpost による起動・動画再生の計測（SC-002・SC-010）

起動から一覧表示までの時間と、動画の再生要求から再生開始までの時間を os_signpost の
インターバルとして記録する。Instruments の「Points of Interest」で確認できる。

- subsystem: `local.my-img-viewer.MediaViewer`
- category: `Performance`
- インターバル名:
  - `LaunchToList`: `applicationDidFinishLaunching` の開始から、最初のフォルダ一覧が
    `.loaded` / `.empty` / `.denied` / `.failed` のいずれかになって表示されるまで（SC-002）
  - `VideoPlaybackStart`: 動画の再生要求から、プレイヤーが最初に `.playing` になるまで（SC-010）

Instruments（Points of Interest）で計測する手順:

1. Instruments を開き、「Points of Interest」テンプレートを選ぶ
2. 対象に `.build/MediaViewer.app` を指定して記録を開始し、アプリを起動する
3. タイムラインを subsystem `local.my-img-viewer.MediaViewer` / category `Performance` で絞り込み、
   `LaunchToList` の長さを読む。目標は 2 秒以内
4. `mixed/` の mp4 を選び、`VideoPlaybackStart` の長さを読む。自動再生がオフの場合は Space で
   再生を開始してから読む。目標は 1 秒以内

コマンドラインで記録する場合:

```bash
xcrun xctrace record \
  --template 'Points of Interest' \
  --output launch.trace \
  --launch -- .build/MediaViewer.app

open launch.trace
```

`launch.trace` を Instruments で開き、同じ subsystem / category とインターバル名で絞り込む。
手動操作が必要な `VideoPlaybackStart` は、記録中に動画を選んで再生を開始する。
