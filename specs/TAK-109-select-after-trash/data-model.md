# Data Model: 削除後の選択

新規の永続データ・設定キーはない。URL は既存の一覧の同一性と同じ方法で比較する。

## PostTrashSelection — 操作中だけの記録

FolzioCore/Model/PostTrashSelection.swift の小さな値型で、次を保持する。

| フィールド | 内容 | 制約 |
|---|---|---|
| orderedURLs | 削除前に表示していた行の URL 配列 | 表示順を固定し、後から届いた行を足さない |
| targets | 実際にゴミ箱へ入れる元 URL 集合 | 空でなく、全対象が元の選択に含まれる |
| selection | 元の selected と focused | `..` を含む元の選択も保持する |
| context | 場所・検索世代と利用者操作世代 | 世代が変わった記録は適用しない |

取得できなければ記録なしとする。ツリー起点・選択外の右クリック・zip の中では記録しない。
世代の具体的な格納場所は BrowserModel とし、UI が解釈しない。

## Result — 既存の操作結果

FileOperationResult.failed の元 URL を使い、対象から失敗を引いた集合を成功元 URL とする。
成功元 URL が空なら選択判断を適用しない。ゴミ箱内の URL は候補照合に使わない。
成功したフォルダの配下も検索結果から除外する。

## Decision — 選択の遷移

1. 記録なし、成功なし、世代不一致、退避、更新失敗なら noChange。
2. 元の選択と更新後の表示行の積が非空なら、その集合を選択として保つ。
3. 元フォーカスがその集合に残れば維持し、消えた場合は表示順で最後の残存選択をフォーカスにする。
4. 元の選択が空になった場合は、orderedURLs の targets の最大位置より後を順に見る。
5. 更新後に存在し、成功削除・削除フォルダの配下でない最初の候補を単一選択する。
6. 候補がなければ selected=[] / focused=nil とする。

候補集合と URL の索引を1回作り、判断全体を O(n + m) とする。
noChange と空選択の適用は区別し、前者では preview の再読込も行わない。

## BrowserModel の利用者操作世代

場所の移動・検索の開始終了・実際の選択変更・表示条件変更で無効化する。
変えて元へ戻しても以前の記録は無効なままとする。
監視イベントと検索結果追加・削除による自動の選択制限では無効化しない。

## UI の空選択の入口

selected と focused がともに空、通常ファイルリスト、修飾キーなしの上下キーだけが対象。
表示件数0は移動先なし、↑は count-1、↓は0。`..` も表示件数に含む。
通常の選択移動と full screen / hidden list の判断は既存の経路を使う。
