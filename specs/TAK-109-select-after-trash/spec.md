## Clarifications

### Session 2026-11-17

`clarify_mode=auto` として、Issue と既存仕様を根拠に次の推奨回答を採用した。

- Q: 複数削除の基準位置はどこか？ → A: 削除前の最も下の対象より後の最初の残存項目。
  - 途中の選択の穴へ戻る案より、単一削除の「一つ下」を選択集合の末尾に拡張できる。
- Q: 一部失敗した場合は何を選ぶか？ → A: 表示中に残った元の選択を保ち、元のフォーカスが消えたときだけ最後の残存選択へ。
  - 失敗した対象を確認でき、別の項目を続けて誤操作するのを避けられる。
- Q: 検索結果・サムネイル・絞り込みも対象か？ → A: すべて対象とし、その時点の表示順で決める。
  - 両表示形式の同一操作と、検索結果の通常一覧と同じファイル操作という既存仕様に揃える。
- Q: 選択外の右クリックから削除しても次を選ぶか？ → A: 選ばず現在の選択を保つ。
  - FR-397（file-list.md）の選択を変えない契約を優先する。
- Q: 削除中に利用者の表示条件や選択が変わったらどうするか？ → A: 新しい状態を優先し、自動選択は適用しない。
  - 古い操作が別の場所や新しい選択へ作用するのを防ぐ。

現行憲章と仕様を維持、実装方式は計画で扱う。品質チェックは16/16のままで変化なし。

## User Scenarios & Testing *(mandatory)*

### User Story 87 - 削除後も並び順で操作を続ける (Priority: P1)

利用者は選択した項目をゴミ箱へ入れた後、次の項目を選び直さずに閲覧・整理を続けられる。

**Why this priority**: Issue の主目的であり、削除を繰り返す際の再選択を省ける。

**Independent Test**: 表示順が A・B・C・D の一覧で B を削除し、C だけが選択されることを確認する。

**Acceptance Scenarios**:

- **US87-AS1**: **Given** A・B・C・D の順で B を単一選択しているとき、
  **When** B をゴミ箱へ入れると、**Then** C だけが選択・フォーカスされ、プレビューが C に対応する。
  - フォルダや zip ファイルが C なら中には入らず、プレビューを空にする。
- **US87-AS2**: **Given** A・B・C・D・E の順で B・D を選択しているとき、
  **When** 両方の削除に成功すると、**Then** 最も下の対象 D より後の E だけが選択される。
  - B・C の連続選択なら D を選択する。
- **US87-AS3**: **Given** B・D を選択しているとき、**When** B だけ削除に成功し D が失敗すると、
  **Then** D の選択を保ち、失敗理由を示して、別の項目を自動選択しない。
- **US87-AS4**: **Given** A を選択したまま選択外の B の右クリックメニューを開いたとき、
  **When** B を削除すると、**Then** A の選択・フォーカス・プレビューを保つ。
  - 選択外の項目の操作対象は FR-397（file-list.md）に従う。
- **US87-AS5**: **Given** 絞り込んだ一覧または検索結果の一覧を表示しているとき、
  **When** 選択した項目の削除に成功すると、**Then** 削除前に表示していた順序の次の残存項目を選択する。
  - リスト形式・サムネイル形式、昇順・降順で同じ規則を使う。

### User Story 88 - 末尾の削除後に矢印キーで選択を再開する (Priority: P1)

利用者は最下部の項目を削除した後、選択がない状態から上下の矢印キーで一覧操作に戻れる。

**Why this priority**: Issue が維持を求める境界でのキーボード操作を保証する。

**Independent Test**: 最下部を削除した直後に ↑ で残った最下部を、選択なしに戻して ↓ で最上部を選択する。

**Acceptance Scenarios**:

- **US88-AS1**: **Given** 最下部の項目だけを選択しているとき、**When** 削除に成功すると、
  **Then** 前の項目を選択せず、選択・フォーカスがなくなり、プレビューが空になる。
- **US88-AS2**: **Given** 削除後に選択・フォーカスがないとき、**When** ファイルリストで修飾キーなしの ↑ を押すと、
  **Then** 表示中の最下部の行だけを選択・フォーカスする。
- **US88-AS3**: **Given** 削除後に選択・フォーカスがないとき、**When** ファイルリストで修飾キーなしの ↓ を押すと、
  **Then** 表示中の最上部の行だけを選択・フォーカスする。
  - `..` があれば最上部は `..` とする。
- **US88-AS4**: **Given** 最後の実項目を削除したとき、**When** 表示行がなくなった状態で ↑ または ↓ を押しても、
  **Then** 選択なしのままで、エラーにならない。
  - `..` だけ残る場合は、削除直後は選択なしで、↑・↓ のどちらでも `..` を選択する。

### Edge Cases

- **EC-268**: 削除中にフォルダ・検索・並び順・絞り込み・選択を利用者が変更した場合、
  削除完了による自動選択でその新しい状態を上書きしてはならない。
  - 削除された項目を一覧・選択から外す既存の処理は続ける。
- **EC-269**: 検索結果のフォルダを削除して配下の結果も消える場合、
  次の選択候補からその配下の項目も除かなければならない。
  - 削除前の次の候補が外部変更で消えた場合も、その後の残存候補へ進める。
  - 削除開始後に届いた検索結果や新しく現れた行は、今回の自動選択候補には加えない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-399**: ファイルリストで選択した項目をゴミ箱へ入れる操作の完了後、
  選択項目がすべて削除された場合は、削除前の表示順で最も下の削除対象より後にある最初の残存項目だけを
  選択・フォーカスしなければならない。
  - 単一選択では削除対象の一つ下を選ぶ。
  - 連続・非連続の複数選択でも同じ規則を適用する。
  - 後続の残存項目がなければ選択・フォーカスを空にし、前の行への繰り上げや先頭への循環は行わない。
- **FR-400**: ファイルリストで選択・フォーカスがない場合、修飾キーなしの ↑ は表示中の最下部の行を、
  ↓ は最上部の行を単一選択・フォーカスしなければならない。
  - リスト形式・サムネイル形式の両方に適用する。
  - `..` は表示行として含め、行がなければ何もしない。
  - 選択がある状態の移動、Shift による範囲選択、左右キー、プレビューでの移動は従来どおりとする。
- **FR-401**: 削除のキャンセルまたは全件失敗では、削除操作を理由に選択・フォーカス・プレビューを変えてはならない。
  - 一部失敗で元の選択項目が表示中に残る場合は、残存する選択を保って後続の項目を自動選択しない。
  - 元のフォーカスが消えた場合は、残った選択のうち表示順で最後の項目をフォーカスにする。
  - 失敗理由と成功・失敗の区別は FR-026（file-operations.md）に従う。
- **FR-402**: 削除後の自動選択は、通常のフォルダの一覧・検索結果の一覧について、
  リスト形式とサムネイル形式の両方で、並べ替えと種類・名前の絞り込みを反映した表示順に従わなければならない。
  - 選択・プレビュー・動画停止は FR-017・FR-076（file-list.md）と FR-034（preview.md）に従う。
  - 選択先が見えるように必要最小限スクロールし、キーボードフォーカスのペインは移さない。
  - 選択外の項目の右クリックからの削除では FR-397（file-list.md）の選択を保つ扱いを優先する。
  - ツリーからの削除、アプリ外での削除、移動・名前の変更・複製では今回の自動選択を行わない。

### 検索結果のファイル操作（変更）

- **FR-087**: 検索結果の一覧で選択したファイルとフォルダには、コピー・名前の変更・ゴミ箱に入れる・移動・複製・
  ドラッグ&ドロップ（FR-018〜FR-027）を通常のフォルダの一覧と同じに行えなければならない（フォルダの行は FR-076
  と同じく操作の対象にする）。
  - 貼り付け先のフォルダがないため、検索結果へのペースト（⌘V・⌥⌘V）は、
    フォルダの行を選択中も含めて右クリックメニューで淡色にして選べないようにし、ショートカットも何もしない。
  - ゴミ箱に入れた・移動したファイルとフォルダ、およびアプリの外で削除・移動された（元の場所から消えた）
    ファイルとフォルダは一覧から外す。
  - フォルダが消えた場合は、その中にあった検索結果（ファイルとフォルダ）もすべて外す。
  - 外したファイルがプレビュー中だった場合は、プレビューを空にする。
    - ただしファイルリストからのゴミ箱に入れる操作で FR-399・FR-401 により別の項目をフォーカスした場合は、
      その項目に対応するプレビューを表示する。
  - 検索前のフォルダやその祖先のフォルダの行をゴミ箱に入れた・移動した場合も、検索結果の表示を続ける（EC-101）。
  - 名前を変更したファイルとフォルダは、キーワードに一致しなくなっても新しい名前で一覧に残し、
    名前を変えたフォルダの中にある検索結果は FR-105 のとおり新しい場所で表示する。
  - ただし、ファイルを対応メディアファイルの拡張子でない名前に変えた場合は、FR-083
    の対象外になるため一覧から外す（プレビュー中だった場合はプレビューを空にする）。
  - 複製で作ったファイルとフォルダや、検索の後に新しく現れたファイルとフォルダは一覧に加えない。

### Key Entities

- **削除前の一覧**: 操作対象、表示順、選択・フォーカス、および表示していた場所と条件。
- **削除結果**: 成功して消えた元の項目と失敗した項目の区別。
- **削除後の選択**: 残存する元の選択、後続候補1件、または選択なし。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-221**: 単一・連続複数・非連続複数の削除について、両表示形式・昇順と降順・通常一覧と検索結果で、
  再クリックなしで期待する次の項目を選択できる割合が 100% となる。
- **SC-222**: 末尾・全実項目の削除後の選択なしの状態から、両表示形式で ↑・↓ による選択再開の確認がすべて成功する。
- **SC-223**: キャンセル・全件失敗・一部失敗・選択外の右クリック・削除中の状態変更の確認で、
  この仕様に反して選択やプレビューを上書きする件数が 0 件となる。

## Assumptions

- **A-240**: 本変更の削除は利用者がファイルリストから明示的に行うゴミ箱への移動に限り、
  zip の中の項目や `..` を操作できる範囲は広げない。
  - 通常一覧・検索結果に表示される zip ファイル自体は、従来の実ファイルと同じ対象とする。
  - 新しい設定・ショートカット・翻訳文言は追加しない。
