# Feature Specification: 通常表示でも動画を < / > で5秒戻す・送る

**Feature Branch**: `claude/gallant-hawking-vyx9ta`

**Created**: 2026-11-02

**Status**: Approved — 実装済み、CI・実機確認待ち

**Input**: [TAK-49](https://linear.app/takyoshida/issue/TAK-49)「通常表示のファイルリストとプレビューの表示中も、動画を < / > で5秒戻す・送れるようにする」。
TAK-48 の PR（yoshidax/folzio-dev#37）の実機確認で、通常表示では `<` / `>` が効かないことが見つかった。現行の仕様（FR-033・FR-093）が
プレビューのみ表示とフルスクリーンに限っているため、不具合ではなく仕様変更として扱う。

  （保守者が選択。FR-269。Space の FR-248 とは条件が異なる）
- Q: 進め方 → A: 仕様書・計画・タスク・analyze まで作って設計レビューを受け、承認後に実装する（保守者が選択）

## User Scenarios & Testing *(mandatory)*

変更点だけを定める。フルスクリーンとプレビューのみ表示での `<` / `>`（FR-033・FR-093）、スライドショー中のシーク（FR-121 付近）は変えない。
`US5-AS13`〜`US5-AS15` は、既存の US5（preview.md）に追加する受け入れシナリオ。

### User Story 1 - 通常表示でキーボードだけで動画をシークする (Priority: P1)

利用者は、3ペイン表示（ファイルリスト・プレビューが見える非フルスクリーンの状態）で動画を見ながら、`<` / `>` で5秒戻す・送る。

**Why this priority**: 要望の中心。表示の切り替えやマウス操作なしで、通常表示でも他の表示と同じキーでシークできる。

**Independent Test**: 3ペイン表示で動画を選び、ファイルリストにフォーカスがある状態と、プレビューの動画にフォーカスがある状態のそれぞれで `<` / `>` を押す。

**Acceptance Scenarios**:

- **US5-AS13**: **Given** 3ペイン表示でプレビューに動画を表示中、フォーカスはプレビューの動画にある, **When** `>` / `<` を押す,
  **Then** 再生位置が5秒進む / 戻る。再生中か一時停止中かは変わらず、動画の先頭・末尾を越えるときは先頭・末尾で止まる
- **US5-AS14**: **Given** 3ペイン表示でプレビューに動画を表示中、フォーカスはファイルリストにある, **When** `>` / `<` を押す,
  **Then** US5-AS13 と同じくシークし、ファイルリストの選択・スクロール位置・検索欄の内容は変わらない
- **US5-AS15**: **Given** 3ペイン表示で、プレビューに動画以外（画像・読み込み中・表示できない旨・空）を表示中, **When** `<` / `>` を押す,
  **Then** 何も起きない。ファイルリストにフォーカスがあるときの文字入力としての扱い（先頭一致の移動など、FR-016 付近の既存の規則）も変えない

### User Story 2 - 文字入力と衝突しない (Priority: P1)

利用者は、名前の変更・検索などの文字入力中に `<` / `>` を打っても、動画のシークは起きず、入力が従来どおり行われる。

**Why this priority**: 動画がプレビューに出ている間に、文字入力が妨げられてはならない。

**Independent Test**: 3ペイン表示で動画を表示したまま、検索欄・名前の変更のフィールドに `<` を入力する。

**Acceptance Scenarios**:

- **US5-AS16**: **Given** 3ペイン表示で動画を表示中、検索欄・名前の変更・新規フォルダ名などの文字入力にフォーカスがある, **When** `<` / `>` を入力する,
  **Then** 文字が入力され、動画はシークしない
- **US5-AS17**: **Given** 3ペイン表示で動画を表示中、設定・ショートカット一覧・Quick Look などのモーダルまたは別ウインドウが前面にある, **When** `<` / `>` を押す,
  **Then** 動画はシークしない

### Edge Cases

- **EC-188**: 修飾キー（⌘・⌥・⌃）付きの `<` / `>` はシークしない。Shift は `<` / `>` の入力に必要なため許す（現行のプレビューのみ表示と同じ）
- **EC-189**: 通常表示に戻した直後・フルスクリーンを解除した直後も、動画を表示中ならシークできる。表示の遷移中に二重に処理しない（1回の押下で5秒だけ動く）
- **EC-190**: プレビューが非表示の表示（ファイルリストのみ・ツリーのみなど）では、見えない動画をシークしない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-269**: 3ペイン表示（プレビューが見える非フルスクリーン）でも、プレビューに動画を表示している間、`<` で5秒戻し `>` で5秒送れなければならない。
  フォーカスがファイルリスト・プレビューのどちらにあっても有効とする（動画の再生／一時停止の Space は FR-248 のとおりプレビューのフォーカス時に限る）。
  文字入力（検索・名前の変更など）中、モーダルまたは別ウインドウが前面のとき、修飾キー（⌘・⌥・⌃）付きのとき、動画以外を表示中のときは動かさない。
  シークで再生中・一時停止中の状態は変わらない。FR-033 の `<` / `>` の記述（フルスクリーン中）と FR-093 の記述（プレビューのみ表示）は、
  「動画を表示中はどの表示でも `<` / `>` でシークできる」に改める

### Key Entities

なし（状態を永続化しない）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-133**: 3ペイン表示で動画を表示中、ファイルリストにフォーカスがある場合とプレビューにフォーカスがある場合の両方で、`<` / `>` を1回押すごとに
  再生位置が5秒（先頭・末尾の手前では端まで）動く。10回の操作すべてで、再生・一時停止の状態が変わらず、文字入力中の `<` / `>` ではシークが0回起きる

## Assumptions

- **A-164**: 動画のシークは既存の処理（フルスクリーン・プレビューのみ表示で使うもの）を再利用し、5秒の幅・端での止まり方は変えない
- ショートカットの割り当て（TAK-24）の一覧にある videoSeek は表示専用のキー（`< / >`）で、割り当て可能な項目は増やさない。
  一覧の条件の文言（「全画面・プレビューのみ表示中の動画で使えます。」）は新しい条件に合わせて更新する（日本語・英語）
- 契約（contracts/keyboard-and-menus.md）の videoSeek 行、プレビューの表の「< / >」2行、ユーザーガイド（docs/usage.ja.md と英語版）の記述を更新する
- スライドショー中の `<` / `>`（期限を変えない）は変えない
