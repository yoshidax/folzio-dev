## Clarifications

### Session 2026-11-26

- Q: アプリが行う更新の範囲は？ → A: 新しい公開版の有無の確認と通知まで。ダウンロードと入れ替えは、今と同じく利用者が
  GitHub Releases の Release ページから行う（保守者の回答）。
- Q: 更新の確認の通信をいつ行うか？ → A: アプリメニューの項目を利用者が選んだときだけ。起動時や定期的な自動の確認は
  行わず、そのための設定も置かない（保守者の回答。設計レビューで次の回答に改めた）。
- Q: ネットワーク機能の追加に必要な憲章（原則 I）の改定をどう扱うか？ → A: この feature の中で改定し、許す通信を
  更新の確認に限って明記する（保守者の回答）。
- Q: 確認の対象にする Release は？ → A: 公開用リポジトリで公開済みの最新の Release。ドラフトとプレリリースは対象外
  （推奨回答を採用。ドラフトは公開前で利用者が取得できず、プレリリースは現在の配布手順（FR-173（overview.md））で作らないため）。
- Q: 新しい版があると知らせた後、利用者は何をできるか？ → A: その版の Release ページを既定の Web ブラウザで開くか、
  閉じるかを選べる。アプリはファイルを取得しない（推奨回答を採用。About のリンクと同じく、URL を OS に渡すだけの既存の
  扱い（FR-242（window-layout.md））に合わせる）。
- Q: 実行中のアプリの版が分からないとき（`swift run` など）はどうするか？ → A: メニュー項目を無効にし、通信しない
  （推奨回答を採用。比べる対象がなく、通信しても結果を示せないため。FR-241（window-layout.md）と同じ値を使う）。
- Q: ダイアログはどう出すか？ → A: メインウィンドウのシートではなく、アプリ全体のダイアログとして前面に出す（推奨回答を採用。
  設定ウインドウや About と同じく、メインウィンドウの状態に関わらず選べる項目のため（FR-238（window-layout.md））。

### Session 2026-11-26（設計レビュー）

- Q: 起動時の自動の確認を入れるか？ → A: 入れる。メニューの確認だけでは、利用者が新しい版に気付きにくいため（保守者の回答。
  前のセッションの「メニューの操作でだけ」を改める）。
- Q: 自動の確認と利用者の同意をどう結び付けるか？ → A: 初めて起動したときに自動で確認するかを尋ね、「自動で確認する」を
  選んだときだけ自動で確認する。尋ねる前と「確認しない」を選んだ後は通信しない。設定でいつでも切り替えられる（保守者の回答）。
- Q: 自動の確認の頻度は？ → A: 起動時に、前回の自動の確認から 24 時間以上たっているときだけ（保守者の回答）。
- Q: 自動の確認で新しい版があったときの知らせ方は？ → A: メニューの確認と同じダイアログを、各版につき1回だけ出す
  （保守者の回答）。
- Q: 自動の確認で最新だったとき・確認できなかったときは？ → A: 何も表示しない（保守者の回答）。
- Q: 自動の結果が出たときに利用者が名前の変更・シート・全画面・スライドショーの途中だったら？ → A: その回は知らせず、
  記録も残さず、次の起動で確かめ直す（推奨回答を採用。作業を妨げず、状態を後で見張る仕組みが要らないため。判定はショートカット
  一覧を開ける条件（FR-200（window-layout.md）の EC-136〜138）と同じものを使う）。

## User Scenarios & Testing *(mandatory)*

変更点だけを定める。About ダイアログの動作は FR-238〜FR-245（window-layout.md）に従い、配布の方式は
FR-169〜FR-176（overview.md）に従う。

### User Story 1 - 新しい公開版があることを知り、入手先を開く (Priority: P1)

利用者はアプリメニューの「アップデートを確認…」を選び、新しい公開版があれば、その版と今の版を知らされ、
Release ページを開いて ZIP を入手する。

**Why this priority**: TAK-95 の目的（継続利用時の更新を容易にする）の中心である。

**Independent Test**: 公開用リポジトリの最新の Release より古い版のアプリで項目を選び、通知から Release ページを開ける。

**Acceptance Scenarios**:

- **US96-AS1**: **Given** 公開済みの最新の Release の版が実行中のアプリの版より新しい、**When** 「アップデートを確認…」
  を選ぶ、**Then** 新しい版の番号と今の版の番号を示し、「ダウンロードページを開く」と「閉じる」を選べるダイアログを出す。
- **US96-AS2**: **Given** US96-AS1 のダイアログを表示中、**When** 「ダウンロードページを開く」を選ぶ、**Then** その版の
  Release ページを既定の Web ブラウザで開き、ダイアログを閉じる。
- **US96-AS3**: **Given** US96-AS1 のダイアログを表示中、**When** 「閉じる」を選ぶか Esc を押す、**Then** 何も開かずに
  ダイアログを閉じる。
- **US45-AS3**（変更）: **Given** メニューバーを開く、**When** アプリメニューを見る、**Then** 先頭に「Folzio について」、
  「アップデートを確認…」、区切り線、「設定…」、区切り線、「終了」の順で並び、「Folzio について」にショートカットは割り当てない。
- **US96-AS4**: **Given** 自動の確認を有効にしていない、**When** 「アップデートを確認…」を選ばずにアプリを使い続ける、
  **Then** アプリは外部と一切通信しない。

---

### User Story 2 - 最新であること・確認できなかったことを知る (Priority: P2)

利用者は、メニューから確認したときに、今の版が最新であることや、オフラインなどで確認できなかったことを知り、作業を続けられる。

**Why this priority**: 結果が何も示されないと、確認できたのか分からないため。

**Independent Test**: 最新の版のアプリと、ネットワークを切った状態で項目を選び、それぞれの結果のダイアログを確認する。

**Acceptance Scenarios**:

- **US97-AS1**: **Given** 実行中のアプリの版が公開済みの最新の Release の版と同じかそれより新しい、**When**
  「アップデートを確認…」を選ぶ、**Then** 今の版が最新であることと今の版の番号を示し、「OK」で閉じるダイアログを出す。
- **US97-AS2**: **Given** ネットワークに接続していない、または応答が得られない、**When** 「アップデートを確認…」を選ぶ、
  **Then** 確認できなかったことを示すダイアログを出し、アプリのほかの機能はそのまま使える。
- **US97-AS3**: **Given** 確認の結果を待っている、**When** ファイルリストやプレビューを操作する、**Then** 操作は待たされない。

---

### User Story 3 - 起動時に自動で新しい版に気付く (Priority: P1)

利用者は初めて起動したときに自動の確認を有効にしておけば、メニューを開かなくても、新しい公開版が出た後の起動で知らされる。

**Why this priority**: メニューの確認だけでは、利用者が新しい版に気付きにくい（保守者の判断）。

**Independent Test**: 設定を消した状態で起動して同意し、最新の公開版より古い版のアプリで新しい版のダイアログが出る。
次の起動では同じ版について出ない。

**Acceptance Scenarios**:

- **US98-AS1**: **Given** 自動の確認についてまだ答えていない、**When** アプリを起動する、**Then** メインウィンドウを表示した後に、
  自動で確認するかを尋ねるダイアログを出し、答えるまで通信しない。
- **US98-AS2**: **Given** US98-AS1 のダイアログを表示中、**When** 「自動で確認する」を選ぶ、**Then** 答えを保存し、すぐに自動の
  確認を行う。
- **US98-AS3**: **Given** US98-AS1 のダイアログを表示中、**When** 「確認しない」を選ぶか Esc を押す、**Then** 答えを保存し、
  以後の起動で尋ねず、自動の確認を行わない。
- **US98-AS4**: **Given** 自動の確認を有効にしていて、前回の自動の確認から 24 時間以上たっている、**When** アプリを起動する、
  **Then** 自動の確認を行い、まだ知らせていない新しい版があれば US96-AS1 と同じダイアログを出す。
- **US98-AS5**: **Given** 自動の確認で版 X を一度知らせた、**When** 後の起動の自動の確認でも最新の公開版が X である、
  **Then** ダイアログを出さない。
- **US98-AS6**: **Given** 自動の確認を有効にしている、**When** 自動の確認の結果が最新、または確認できなかった、
  **Then** 何も表示しない。
- **US98-AS7**: **Given** 設定ウインドウを開いている、**When** 「アップデートを自動で確認する」を切り替える、
  **Then** すぐに保存し、次の起動からその設定に従う。

### Edge Cases

- **EC-291**: 確認の結果を待っている間にもう一度「アップデートを確認…」を選ぶ場合は、2つ目の確認を始めない。
  - 自動の確認を待っている間も同じ。
- **EC-292**: 公開用リポジトリに公開済みの Release が1つもない、または最新の Release のタグが `v<数>.<数>.<数>` の形でない場合は、
  確認できなかったとして扱う。
- **EC-293**: 版の比較は、各部分を数として比べる（1.10.0 は 1.9.0 より新しい）。
- **EC-294**: GitHub が回数の制限や障害で応答を拒んだ場合は、確認できなかったとして扱う。
- **EC-295**: メニューから確認したとき、結果のダイアログを表示する前にメインウィンドウがスライドショー・全画面・シートの表示中でも、
  ダイアログはメインウィンドウの状態を変えずに前面に出る。
- **EC-296**: 自動の確認の結果が出たときに、メインウィンドウでショートカット一覧を開けない状態（文字の編集中・シート・
  モーダル・全画面・スライドショー）なら、新しい版があっても知らせず、前回の自動の確認の時刻と知らせた版を更新しない。
  - 初回の問い合わせ（US98-AS1）を出す時点で同じ状態なら、その起動では尋ねない。
- **EC-297**: 前回の自動の確認の時刻が今より後（時計が戻された）なら、24 時間たったものとして扱う。
- **EC-298**: 自動の確認が確認できなかった場合は、前回の自動の確認の時刻を更新しない（次の起動で確かめ直す）。
- **EC-299**: 実行中のアプリの版を取得できない場合は、初回の問い合わせも自動の確認も行わない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-238**（変更）: アプリメニューの先頭に「Folzio について」（英語: About Folzio）を追加し、その直後に
  「アップデートを確認…」（FR-422）、区切り線を置いて、「設定…」の前に並べる。
  - ショートカットは割り当てない。
  - 選ぶと FR-239（window-layout.md）のダイアログを開く。
  - メインウィンドウの状態（スライドショー・全画面・名前の変更・シート・設定ウインドウの表示中）
    に関わらず選べる（設定と同じ。US47-AS5）。
- **FR-041**（変更）: システムは、閲覧・操作に関する情報を外部に送信してはならず、更新の確認（FR-423・FR-431）を除く
  全機能がオフラインで動作しなければならない（憲章 原則 I）。
- **FR-422**: アプリメニューの「Folzio について」の直後に「アップデートを確認…」（英語: Check for Updates…）を置かなければならない。
  - ショートカットは割り当てず、メニューバーからキーボードで到達できる。
  - メインウィンドウの状態（スライドショー・全画面・名前の変更・シート・設定ウインドウの表示中）に関わらず選べる
    （FR-238（window-layout.md）と同じ）。
  - 実行中のアプリの版を取得できない場合（FR-241（window-layout.md）でバージョン行を出さない場合）と、
    版が `<数>.<数>.<数>` の形でない場合は、無効にする。
  - 確認の結果を待っている間は、無効にする（EC-291）。
- **FR-423**: 「アップデートを確認…」を選ぶと、公開用リポジトリ `yoshidax/folzio` で公開済みの最新の Release（ドラフトと
  プレリリースを除く）の版を GitHub に問い合わせなければならない。
  - この問い合わせと FR-431 の問い合わせが、アプリが行う唯一の通信である。
- **FR-424**: 問い合わせには、Folzio を識別する名前と、GitHub が求める最小限の情報だけを含めなければならない。
  - 画像・動画のファイル、そのメタデータ、ファイルパス、設定の値、利用者や端末を識別する値を送らない。
- **FR-425**: 最新の Release のタグ `v<版>` の版を実行中のアプリの `CFBundleShortVersionString` と比べ、結果に応じて
  US96-AS1・US97-AS1・US97-AS2 のいずれかのダイアログを出さなければならない。
- **FR-426**: 「ダウンロードページを開く」は、比べた版の Release ページ `https://github.com/yoshidax/folzio/releases/tag/v<版>`
  を既定の Web ブラウザで開かなければならない。
  - URL は確かめた版の番号から組み立て、応答に含まれる URL をそのまま開かない。
  - アプリはファイルをダウンロードせず、アプリ自身を置き換えない。
- **FR-427**: 問い合わせは UI のスレッドを止めずに行い、一定時間（15 秒）で応答がなければ確認できなかったとして扱わなければならない。
- **FR-428**: 結果のダイアログは、メインウィンドウから独立して前面に出し、メインウィンドウの状態を変えてはならない。
  - 文言は表示言語（英語・日本語）に従う。
  - ボタンはキーボードで操作でき、OS のアクセシビリティ API から識別できる。
- **FR-430**: 自動の確認について利用者がまだ答えていないとき、起動してメインウィンドウを表示した後に、自動で確認するかを
  尋ねるダイアログを出さなければならない（US98-AS1〜AS3）。
  - ダイアログは、起動時に1日1回まで GitHub に問い合わせること、ファイルやその情報を送らないこと、設定で変えられることを示す。
  - ボタンは「自動で確認する」（既定）と「確認しない」（Esc）とする。
  - 答えずにアプリを終了した場合は、次の起動でもう一度尋ねる。
- **FR-431**: 自動の確認が有効なとき、起動してメインウィンドウを表示した後に、前回の自動の確認から 24 時間以上たっていれば、
  FR-423 と同じ問い合わせを1回行わなければならない。
  - 起動中に定期的には問い合わせない。
  - 結果が新しい版か最新のときに、その時刻を前回の自動の確認の時刻として保存する（EC-298）。
- **FR-432**: 自動の確認で新しい版が見つかり、その版をまだ知らせていなければ、US96-AS1 と同じダイアログを出し、その版を
  知らせた版として保存しなければならない。
  - 知らせた版と同じか古い版は、自動の確認では知らせない（US98-AS5）。
  - メニューの確認で新しい版のダイアログを出したときも、その版を知らせた版として保存する。
- **FR-433**: 自動の確認の結果が最新か確認できなかったときは、何も表示してはならない。
- **FR-434**: 設定ウインドウの「一般」の最後に区分「アップデート」を置き、「アップデートを自動で確認する」（英語: Automatically
  check for updates）のチェックボックスを置かなければならない。
  - 変更はすぐに保存する。
  - まだ答えていない状態では、チェックを外して表示する。チェックボックスを操作した時点で答えたものとして扱う。
- **FR-176**（変更）: 開発専用のファイルや履歴を配布物へ含めず、アプリのネットワーク機能は更新の確認（FR-423・FR-431）の
  問い合わせだけとしなければならない。
  - 既存の公開時の除外・テストを維持する。
  - ソースにネットワーク API の使用を検査する仕組みを保ち、許す箇所を更新の確認に限る。
- **FR-429**: README と利用ガイドの英語版と日本語版は、メニューと自動の更新の確認の使い方と、それが利用者の操作か同意した
  自動の確認でだけ GitHub と通信し、送る情報を最小限にすることを、それぞれ同じ内容で案内しなければならない。
  - README の「ネットワーク通信なしでローカルで動作」の表記を、更新の確認のときだけ通信する旨に改める。

### Key Entities

- **今の版**: 実行中のアプリの `CFBundleShortVersionString`。`<数>.<数>.<数>` の形。
- **最新の公開版**: 公開用リポジトリで公開済みの最新の Release のタグから `v` を除いた版。
- **確認の結果**: 新しい版がある（その版）・最新である・確認できなかった、のいずれか。
- **自動の確認の設定**: 未回答・有効・無効のいずれか。保存する。
- **前回の自動の確認の時刻**: 自動の確認で結果を得た最後の時刻。保存する。
- **知らせた版**: 新しい版のダイアログで最後に知らせた版。保存する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-243**: 新しい公開版があるとき、利用者はアプリメニューから2回の選択（項目とダイアログのボタン）でその版の Release ページを開ける。
- **SC-244**: 自動の確認を有効にしていない利用者が「アップデートを確認…」を選ばずにアプリを起動・操作・終了したとき、
  アプリが外部と行う通信は0件である。
- **SC-245**: ネットワークに接続していない状態で項目を選んでから、確認できなかったことを示すまでの時間は 15 秒以内であり、
  その間もほかの操作が待たされない。
- **SC-246**: ソースのネットワーク API の使用箇所は、更新の確認の部分に限られ、それ以外への追加は自動の検査で失敗する。
- **SC-247**: 自動の確認を有効にした利用者は、新しい版の公開後、前回の自動の確認から 24 時間以上たった最初の起動で、
  操作なしにその版を知らされる。
- **SC-248**: 自動の確認を有効にした利用者が1日に何度起動しても、自動の確認の問い合わせは 24 時間に1回以下である
  （確認できなかった回を除く）。

## Assumptions

- **A-257**: 更新の適用（ダウンロード・展開・アプリの置き換え・再起動）と、起動中の定期的な確認は対象外とする。
  - ad hoc 署名・未公証の配布（FR-172（overview.md））のままでは、アプリ内で取得した更新の正当性を OS の署名で
    保証できないため。
- **A-258**: Release の内容（リリースノート）はダイアログに表示せず、Release ページで読む。
- **A-259**: 版の情報源は GitHub の公開用リポジトリの Release に限り、別の配信用ファイル（appcast など）を作らない。
  - そのため、配布の手順（FR-169〜FR-175（overview.md））は変えない。
- **A-260**: GitHub への問い合わせでは、利用者の IP アドレスなど通信に伴う情報が GitHub に届く。
  - 自動の確認を初回に尋ねて同意を得ること（FR-430）と README での案内（FR-429）で、利用者が通信の有無を選べるようにする。
- **A-261**: 「このバージョンをスキップ」「あとで知らせる」のボタンは置かない。

- **A-262**: 以前の版から更新した利用者も、自動の確認の設定がないため、更新後の最初の起動で尋ねられる。
- **A-95**（変更）: Intel Mac、Universal Binary、アプリ内での更新の適用、Mac App Store、Developer ID 署名・公証は対象外。
