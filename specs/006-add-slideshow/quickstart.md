# Quickstart: スライドショーの検証

**Date**: 2026-10-25 | **Branch**: `006-add-slideshow`

本書は実装後の検証ガイド。計画時点では機能・追加フィクスチャ・計測イベントは未実装であり、以下の結果は未確認。操作の正本は [contracts/slideshow.md](contracts/slideshow.md)、状態遷移は [data-model.md](data-model.md)、受け入れ条件は [spec.md](spec.md) を参照。

## 前提

- macOS 15 以降、Swift 6 対応の開発環境、Instruments（OS Signposts／Points of Interest の確認に使用）。
- 実装と自動テストが揃った `006-add-slideshow`。ネットワーク接続・外部パッケージ不要。
- GUI の起動と操作はユーザーが行う。エージェントは build・test・bundle 作成までを実施し、起動コマンドと確認点を渡す。
- フィクスチャは生成先を専用ディレクトリにする。生成を繰り返すと検証データを作り直すため、個人メディアを入れない。テスト自身の一時データは FixtureKit で生成して終了時に削除する。

## 検証データ

実装工程で `FixtureSets.slideshow(in:)` を追加し `makeAll` から生成する予定。既存セットと併せて次を用意する。

| 生成先以下 | 内容／用途 |
|---|---|
| `slideshow/mixed/` | 表示順が分かる画像3件、GIF、1秒 MP4、10秒 MOV、サブフォルダ、zip、非対応テキスト。非メディアの混在と循環 |
| `slideshow/single/` | 動画1件。tick で再生し直さないこと |
| `slideshow/empty/` | 非メディア行だけ。開始不可と対象0件 |
| `slideshow/search/left/same.jpg` と `right/same.jpg` | 同名別場所を検索して、行番号変更後も URL で辿ること |
| `slideshow/slides.zip` | mixed と同等の対応メディアと sub 階層。zip の現在階層だけを対象にすること |
| 既存 `broken/`・`zip/` | 破損・非対応・zip 異常系。必要に応じた上限超過ケースは既存 zip 検証手順を使う |

実装後の生成コマンド:

```bash
cd /Users/igachan/projects/my_img_viewer
scripts/make-fixtures.sh .build/SlideshowFixtures
```

WebP は既存の同梱フィクスチャを利用する。`cwebp` / `img2webp` が新たに必要になった場合は、導入前にユーザーへ確認する。

## 自動検証と起動ゲート

まとまった変更・実装 Phase の終わりに次の順で行う。build/test の失敗を3回修正しても解決しない場合は停止して報告する。

```bash
cd /Users/igachan/projects/my_img_viewer
swift build
swift test
scripts/check-no-network.sh
scripts/make-app.sh
```

成功後、ユーザーに次を実行してもらう。通常ウィンドウが表示され、ツリー・ファイルリスト・プレビューの3ペインが表示されることを最初に確認する。

```bash
cd /Users/igachan/projects/my_img_viewer
open .build/MediaViewer.app
```

その後、ツリーで `.build/SlideshowFixtures` 以下の検証フォルダを選ぶ。zip 混在を確認する際は既定で非表示の「zipファイルを表示」をオンにし、確認後に元へ戻す。起動しない場合は推測で修正せず、AGENTS.md の lldb による Objective-C 例外停止手順をユーザーへ依頼する。

自動テストに含める証拠:

| テスト領域 | 確認する条件 |
|---|---|
| SlideshowSequence | 空・1件・非メディア混在・昇降順・複数選択・フォーカス優先・同名別場所・zip ID・末尾循環 |
| SlideshowSession | 3秒未満0回／期限で1回、20周期、矢印反復・端・リスト左右、古い世代と終了後0回、遅延で最大1回、due と矢印／Esc の両到着順 |
| BrowserModel 統合 | 開始中の動画を再ロードしない、1件維持、選択消去と非復活、検索追加・並べ替えで期限不変、対象0件終了、置換前取消、rename 継続、古い reload／decode を拒否 |
| PaneCommands・復帰計算 | 実行中の禁止 action、開始可否、3種 layout、全画面の独立、狭幅で160/240/320ptを維持、空選択を補完しない |
| 入力受理とモーダル（U1） | 対象ウィンドウ・active・シート／アプリモーダル・編集欄／メニュー等の各条件の真理値表。受理不可の Esc／矢印を session に渡さず、due の前後でも不適格なキーを理由に期限・世代を変更しない。開閉後も元の期限、遅延時は最大1回だけ送る |
| HistoryNavigator | 一時的ペインの非記録、通常のユーザー表示変更のみ記録、検索中非記録と後日の検索解除時反映 |

個別試験を開発中に実行する場合は `swift test --filter Slideshow` 等を使えるが、Phase の最終ゲートは全 `swift test` とする。Core の仮想時刻試験だけで実機の SC-034/035 合格とはしない。

### 復帰・全画面の確認

1. 3ペイン・リストのみ・プレビューのみの各開始状態について、開始前のフォーカス先と3ペイン幅を控える。
2. 開始後、⌃⌘F／画像ダブルクリック／メニューで全画面化・解除を3回繰り返す。動画の位置と状態、選択、次の送りまでの残り時間が切替操作で初期化されず、通常解除では preview-only の実行が続く。
3. Esc 1回で終了し、必要な全画面解除と開始前の通常 layout・focus・幅へ復帰する。開始前から全画面の場合も行う。現在選択の行が最小限スクロールで見える。リストのみ復帰では音声・再生が止まる。
4. 通常ウィンドウを狭めてから終了する。window frame は戻らず、プレビュー→リスト→ツリーの順に最小幅まで詰まり、160/240/320ptを下回らない。プレビューのみへ戻る場合も消去済み選択を補完しない。

対応: US9-AS8/13、US11-AS1〜4、SC-036。

### モーダル・編集と入力受理の確認（U1）

1. mixed の複数メディアで開始し、既存の確認シートまたはアプリモーダルを実行中に表示する。モーダル開始前にスライドショーを終了する操作や閲覧先置換は、このケースの再現に使わない。両方式それぞれについて、表示方法と対象ウィンドウを「入力調停検証記録」に残す。通常操作で到達できない条件は T028 の App 接続確認で再現し、再現できなければ未実施として記録する。
2. 表示中に6秒以上待ち、選択 commit の計測で元の3秒周期の送りを確認する。モーダルに Esc を入力し、その取消だけが起きることを確認する。同じ Esc でスライドショー終了・全画面解除・検索解除が起きないこと、閉じた時点から新たな3秒を数え直さないことを確認する。due 直前の取消でも行う。
3. モーダル／編集欄が入力を受ける間の矢印は、その入力先の既存動作だけに使われることを確認する。矢印そのものによる手動選択や SlideshowArrow がなく、予定時刻が変わらないことを計測する。自動送りによる選択変更は区別する。編集取消の Esc も SlideshowStop を発生させない。別ウィンドウ（設定ウィンドウ等）への Esc／矢印でも同様に session へ通知されないことを確認する。
4. モーダル・編集を終え、対象ウィンドウがキー入力先へ戻った後、別の矢印で通常の割り込みと3秒再設定が行えることを確認する。その後の別の Esc で終了し、6秒以上送りが0回であることを確認する。
5. 通常ウィンドウと全画面の両方で繰り返す。シート／アプリモーダルによる処理遅延があった場合も、戻った直後に遅延回数分を連続して送らず最大1回となることを確認する。実際の monitor と cancelOperation fallback の両経路の確認状況を記録し、Core の真理値表だけで GUI 確認済みにしない。

## 実時間と性能の計測

既存 [性能の検証](../001-three-pane-media-viewer/quickstart.md) の基準も実行する。追加の計測イベントは既存 `OSSignposter` の `local.my-img-viewer.MediaViewer` / `Performance` に合わせ、`SlideshowStart`・`SlideshowAdvance`（実選択 commit）・`SlideshowArrow`（押下受理）・`SlideshowStop` とする。パス・名前・メディア情報は含めない。計測イベントの追加は実装タスクに含める。

1. Instruments の OS Signposts／Points of Interest で `.build/MediaViewer.app` の MediaViewer プロセスを記録する。GUI の起動・記録操作はユーザーが行う。
2. 表示可能な画像を2件以上用意し、入力／更新なしで連続20回送る。Start→最初の Advance と各 Advance 間の20区間がすべて3.0〜3.2秒で各1回か確認する。1秒／10秒動画でも選択時刻を基準に同じ範囲を確認する。
3. 1秒間隔で矢印を10回受理させ、操作中の Advance が0件、最後の Arrow→Advance が3.0〜3.2秒で1件か測る。端・反復・リスト左右・全画面でも行う。予定時刻直前の入力で二重送りがないことを別に確認する。
4. Stop 後6秒以上の Advance が0件か確認する。別の描画・動画開始の遅延は既存 SC-001/010 として分けて測る。
5. `swift test --filter MediaViewerPerformanceTests` で既存基準と新しい対象走査を確認する。10,000件一覧／大量検索中の UI 応答と既存キャッシュ上限も確認する。

記録には環境（macOS、機種、build 種別）、SC-033〜037 の結果、20区間の最小・最大・範囲外件数、矢印操作中の送り件数、Stop 後件数、既存性能結果を含める。結果欄は tasks が明示する本書への追記タスクで追加し、未実施を PASS にしない。
