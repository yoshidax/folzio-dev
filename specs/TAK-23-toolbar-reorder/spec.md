## User Scenarios & Testing *(mandatory)*

### User Story 1 - ボタンセットをドラッグして並び替える (Priority: P1)

利用者は、Finder のようにツールバーの構成要素をドラッグ&ドロップで並び替え、使いやすい順序に調整する。

**Why this priority**: Issue の中心の要望。

**Independent Test**: ツールバーを表示し、カスタマイズ操作で「ズーム」のセットを「履歴」の左へ移して、位置が変わることを確認する。

**Acceptance Scenarios**:

1. **Given** ツールバーを表示中, **When** カスタマイズ操作を始める, **Then** 各ボタンセット（履歴、ペイン表示、スライドショー、ズーム、種類フィルタ、zip 表示、表示形式、サムネイルサイズ）が並び替えの単位として現れる
2. **Given** カスタマイズ中, **When** セットをドラッグして別の位置へ落とす, **Then** セットが新しい位置へ移り、他のセットの順序は保たれる
3. **Given** 並び替えを終えた, **When** ボタンを押す・状態を変える, **Then** 並び替え前と同じ動作と表示（有効・無効、選択状態）になる

---

### User Story 2 - セット内のボタンは分離できない (Priority: P1)

利用者は、サムネイル／リスト切り替えのように関連するボタンが、常に1つのまとまりとして並ぶことを期待する。

**Why this priority**: 操作のまとまりを保つことが Issue の目的。

**Independent Test**: 表示形式のセットの片方のボタンだけを別の位置へ動かせないことを確認する。

**Acceptance Scenarios**:

1. **Given** カスタマイズ中, **When** 表示形式（サムネイル／リスト）の片方だけを動かそうとする, **Then** 動かせず、セット全体だけが動く
2. **Given** 3つのボタンを持つズームのセット, **When** 並び替える, **Then** 「拡大・表示領域に合わせる・縮小」の左右の順序とセットの見た目は変わらない

---

### User Story 3 - 並び順を次回の起動でも保つ (Priority: P2)

利用者は、調整した順序が再起動後にも残ることを期待する。

**Why this priority**: 毎回やり直しになると並び替えの価値が下がる。

**Independent Test**: 並び替えてアプリを終了・再起動し、同じ順序で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 並び替えた状態, **When** アプリを終了して再起動する, **Then** ツールバーは並び替えた順序で表示される
2. **Given** 保存済みの並び順が破損している・知らない項目を含む, **When** 起動する, **Then** 既定の順序で表示し、すべてのセットが1回ずつ現れる

---

### User Story 4 - 標準のカスタマイズ機能をそのまま使う (Priority: P3)

利用者は、Finder と同じ感覚で、使わないセットを外し、必要なら戻し、スペースを入れ、表示モードを変えられる。

**Why this priority**: 抑止の作り込みを避け、標準の挙動に任せる。

**Independent Test**: 「ズーム」のセットを外してもメニューとショートカットで拡大・縮小でき、パレットから戻せる。

**Acceptance Scenarios**:

1. **Given** カスタマイズ中, **When** セットをパレットへ戻す, **Then** ツールバーから消え、対応する機能はメニュー・ショートカットで使える
2. **Given** セットを外した状態, **When** パレットからツールバーへ戻す, **Then** 状態（有効・無効、選択）が現在の状態と一致する
3. **Given** カスタマイズ中, **When** 表示モードを「アイコンとテキスト」「テキストのみ」に変える, **Then** セットの操作とアクセシビリティが保たれる

---

### Edge Cases

- ツールバーの非表示（⇧⌘T）、フルスクリーンの自動非表示を繰り返しても、並び順と各セットの状態が変わらない
- カスタマイズ中に表示言語を切り替えても、ラベル・ツールチップ・アクセシビリティ表記が更新され、並びは保たれる
- スライドショー実行中・名前の変更中・フルスクリーン中にカスタマイズを始めた場合は、標準のまま制限しない。開いても動作が破綻せず、閉じた後も状態が正しいこと（FR-003b、quickstart Q9）
- セットを外した後に再追加したとき、項目が作り直されても状態が実際に表示しているボタンへ反映される
- 同じセットを複数回追加できるか（標準で許されるなら、状態の共有をどうするか）
- 表示モードがテキストのとき、セグメントのラベル・幅・ツールチップが破綻しない
- 並び替えの結果、サムネイルサイズのスライダー（可変幅）が極端な位置に置かれても、他のセットが隠れない（狭いウィンドウでの溢れの扱い）
- 既定の順序へ戻す手段は、標準のカスタマイズ画面の「デフォルトセット」を使う（FR-006）。専用の手段は作らない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、ツールバーのボタンセットを、ドラッグ&ドロップで並び替えられなければならない。並び替えの単位は、履歴、ペイン表示、スライドショー、ズーム、種類フィルタ、zip 表示、表示形式、サムネイルサイズの各セットとする
- **FR-002**: セット内の個々のボタンを分離して配置できてはならない。セット内のボタンの順序と見た目は並び替えで変わらない
- **FR-003**: 標準のカスタマイズ機能が備える次の操作は、抑止せず許容する: セットの削除（パレットへ戻す）と再追加、スペース・可変スペースの追加、表示モード（アイコン／テキスト）の変更。これらを抑止するための独自の作り込みは行わない
- **FR-003a**: セットを削除してもアプリの機能は失われない。すべての機能はメニューとショートカットから使え（FR-040）、削除したセットはカスタマイズ操作で再追加できる
- **FR-003b**: 削除・再追加・表示モード変更の前後でも、各セットの動作・有効条件・選択状態は FR-004 のとおり保たれる
- **FR-003c**: 表示モードの変更を有効にする（`allowsDisplayModeCustomization = true`）。現行の `.iconOnly` は既定の表示モードとして残す（保守者の要望、2026-11-02）
- **FR-009**: カスタマイズ画面とテキスト表示で使うラベルを、Finder に倣って次のとおり改める（日本語。英語は `contracts/toolbar-labels.md` の承認済みの案）。ツールチップとアクセシビリティの読み上げは、この feature では変えない

  | セット | 現行 | 新 |
  |---|---|---|
  | 履歴 | 履歴 | 戻る / 進む |
  | ペイン | ペイン | 表示 |
  | スライドショー | スライドショーを開始 | スライドショー |
  | ズーム | 拡大・縮小 | プレビューサイズ |
  | 種類フィルタ | 種類 | メディアタイプ |
  | zip 表示 | zipファイルを表示 | zipファイル |
  | 表示形式 | 表示形式 | ファイルリスト表示形式（案。「サムネイル/リスト表示形式」はレイアウト上長すぎるため採らない） |
  | サムネイルサイズ | サイズ | サムネイルサイズ |

- **FR-010**: ツールチップは「ラベル = セット名（名詞）、ツールチップ = そのボタンを押したときの動作（動詞句）＋ショートカット」に揃える。
  現行はショートカットの有無と語尾がそろっていない（スライドショー・ズーム・サイズだけ付く）。案（日本語）:

  | ボタン | 現行 | 案 |
  |---|---|---|
  | 戻る | 戻る | 戻る（⌘[） |
  | 進む | 進む | 進む（⌘]） |
  | ファイルリストのみ表示 | ファイルリストのみ表示 | ファイルリストのみ表示（⌃⌘2） |
  | プレビューのみ表示 | プレビューのみ表示 | プレビューのみ表示（⌃⌘3） |
  | スライドショー | スライドショーを開始（⇧⌘S） | 変更なし（ラベルだけ「スライドショー」） |
  | 拡大・表示領域に合わせる・縮小 | 拡大（⌘+）／表示領域に合わせる（⌘0）／縮小（⌘-） | 変更なし |
  | 画像のみ・動画のみ | 画像のみ表示／動画のみ表示 | 画像のみ表示（⇧⌘I）／動画のみ表示（⇧⌘M） |
  | zipファイル | zipファイルを表示 | zipファイルを表示（⌃⌘Z） |
  | サムネイル・リスト | サムネイル／リスト | サムネイル（⌘1）／リスト（⌘2） |
  | サムネイルサイズ | サムネイルのサイズ（⌃⌘. / ⌃⌘,） | サムネイルサイズ（⌃⌘. / ⌃⌘,） |

  アクセシビリティの読み上げ（ラベルとヘルプ）も同じ文言に揃える。ショートカットは `contracts/keyboard-and-menus.md` の定義と一致させ、
  メニュー側の表記と食い違わせない。英語は `contracts/toolbar-labels.md` の承認済みの案

- **FR-004**: 並び替え・削除・再追加は、セットの動作・有効条件・選択状態の共有（メニュー・ショートカットとの共有）に影響してはならない（FR-051・089・114・134 の既存の動作を維持する）
- **FR-005**: 並び順と構成（削除したセット、スペース、表示モード）は再起動後も復元しなければならない。保存した内容が不正なときは既定の構成で表示する
- **FR-006**: 既定の構成は、利用者が既定へ戻す操作（標準のカスタマイズにある「デフォルトのセット」）でも復元できる。既定の順序は現行の並び（履歴 → ペイン表示 → スライドショー → ズーム → 種類フィルタ → zip 表示 → 表示形式 → サムネイルサイズ → 末尾の可変スペース）とする
- **FR-007**: 現行仕様の「項目順は固定」「ツールバー構成は保存しない」を、本 feature の実施が決まった時点で改める。実施しない場合は仕様を変えない
- **FR-008**: 標準部品だけで FR-001・002 を満たせない場合、または改修規模が大きい場合は、実施を見送る（見送り基準は下記）

### 現行仕様との整合（実施する場合に改める箇所）

| 箇所 | 現行 | 必要な変更 |
|---|---|---|
| `contracts/keyboard-and-menus.md` のツールバー | 項目順を固定 | 既定順と、並び替え可能であることを定める |
| `contracts/settings.md` | ツールバー構成を保存しない（表示状態 `view.showsToolbar` だけ保存） | 並び順を保存すること、その保存先（標準の構成保存）と不正値の扱いを定める |
| FR-114・FR-134 | 「…の右隣」「…の左」と位置を規定 | 「既定では」を付け、並び替え後は位置が変わり得ることを明記 |
| FR-051・FR-089 | セットの構成と動作 | 変更不要（セット内の構成は不変）。「項目の並びと位置は変わらない」は表示形式の切り替えに限る旨を保つ |

### Key Entities

- **ボタンセット**: 並び替えの最小単位。1つ以上のボタン（またはスライダー）からなり、分割できない
- **並び順**: セットの並びの保存値。既定の順序と、利用者が変えた順序

## 技術検証の記録（静的確認・2026-11-01）

根拠は `Sources/FolzioApp/App/MainToolbarController.swift`（master `e7c8413` 時点）と現行仕様。AppKit の挙動は私（Agent）の知識に基づく見込みで、**実機とドキュメントでの確認が未了**である。

| 観点 | 確認結果 | 確度 |
|---|---|---|
| セットが1つの項目か | 履歴・ペイン・ズーム・種類フィルタ・zip・表示形式は、それぞれ `NSSegmentedControl` を1つの `NSToolbarItem` の `view` にしている（`makeGroupItem`）。標準のカスタマイズは項目単位で動くため、セットは自動的に分離されない見込み | コードで確認／挙動は見込み |
| 有効化の入口 | `allowsUserCustomization` と `autosavesConfiguration` が両方 `false`（`init`）。標準の構成保存を使えば並び順の保存も同時に得られる見込み | コードで確認／挙動は見込み |
| 並び替え以外の操作 | 標準のカスタマイズは、許可項目の追加・削除、スペースの追加、表示モードの変更を含む。**方針を改め、抑止せず許容する**（FR-003）。抑止の可否は不要になり、不確実性は「項目が作り直される前提で状態を正しく保てるか」へ移る | 方針変更済み |
| delegate の参照上書き（**重要度が上がった**） | 削除・再追加で項目が作り直されることを許容するため、参照の管理を直す必要がほぼ確実に生じる。`toolbar(_:itemForItemIdentifier:willBeInsertedIntoToolbar:)` は `flag` を使わず、呼ばれるたびに `historyControl` 等のプロパティを新しい control で上書きする。カスタマイズ用パレットの複製のためにも呼ばれる場合、実際に表示している control から参照が外れ、有効・無効や選択状態が反映されなくなる恐れがある | 懸念として確認（`flag == false` で呼ばれるかは実機で要確認） |
| 言語切替時の更新 | `displayLanguageDidChange` は `toolbar.items` を走査してラベルを更新する。並び替えの影響は小さい見込み | コードで確認 |
| 可変幅の項目 | サムネイルサイズのスライダーは幅 120pt の制約を持つ。並び替え時に項目の最小・最大サイズが必要になる可能性がある | 未確認 |
| 自作の要否 | 並び替え・分離不可は標準機能で満たせた。自作のドラッグ処理は不要 | 実機で確認済み |

## 実機検証の結果（保守者、2026-11-02、`allowsUserCustomization = true`）

| 項目 | 結果 | 意味 |
|---|---|---|
| 1. 並び替え・セットの分離 | 問題なし | セットが項目単位で動き、分離できない。FR-001・002 は標準機能で満たせる |
| 2. 表示モード | カスタマイズ画面に出ない | `allowsDisplayModeCustomization = false` のため（現行コード）。許容に変更（FR-003c） |
| 3. 参照の上書き | **壊れる** | カスタマイズ画面を開いて閉じただけで、履歴の有効・無効が逆になる（A→B と進み ⌘[ で A に戻ると、「<」でなく「>」が淡色）。外して戻す・「デフォルトセット」の入れ直しで、履歴が操作できなくなった。カスタマイズしなければ正常 |
| 4. 構成の復元 | 復元されない | `autosavesConfiguration = true` にしても、再起動後に既定へ戻る（原因は未調査） |
| 5. 状態の追従 | 特におかしな挙動なし（外して戻す・入れ直しの確認が不足していた可能性。3 の結果と矛盾するため、plan の実装後に再確認する） | |

**検証4の追加調査（2026-11-02）**: 再起動前に `defaults read local.folzio.Folzio "NSToolbar Configuration MainToolbar"` を実行すると、
`TB Item Identifiers` が並び替え後の順序（履歴 → サムネイルサイズ → ズーム → …）で**保存されていた**。したがって、書き込みは行われており、
問題は**起動時に読み込まれない**ことにある。コードに構成の読み書きの明示的な処理はない（`insertItem`・`setConfiguration` なし）。
`MainToolbarController.init` は、`toolbar.delegate = self` の後で `autosavesConfiguration` を設定し、`MainWindowController` は
`toolbar.isVisible` を設定してから `window.toolbar` を割り当てている。`autosavesConfiguration` を
delegate の設定より前に移す実験（保守者、2026-11-02）では**直らなかった**。次の仮説「初期化の設定が起動時に保存済みの構成を既定へ上書きする」も**棄却**した（保守者、2026-11-02）:
カスタマイズ後、何も触らずに起動・終了しても、`TB Item Identifiers` はカスタマイズした順序のままだった。元のコードも
`autosavesConfiguration` を `displayMode`・`allowsUserCustomization` の設定より後に置いていたため、設定順の実験は不要だった。
結論として、**書き込みは正常で、起動時の読み込みだけが効かない**（原因は未特定）。静的な確認では特定できないため、plan では
次の順で進める: (1) 起動直後に `toolbar.items` の識別子を、`init` 後・`window.toolbar` 割り当て後・次の run loop の3点でログに出し、
どの時点で既定の並びになるかを確認する（保守者の実機）、(2) 原因が AppKit の仕様で回避できない場合は、標準の構成保存を使わず、
並び順を自前で保存・復元する（設定キーを1つ追加し、終了時に `toolbar.items` の識別子を保存、起動時に `insertItem` で並べ直す）。
この自前の保存は規模が小さく、見送り基準には当たらない見込みである。

**判断への影響**: 3 により、参照の管理（delegate の状態保持）の作り直しが必須と確定した。セットごとの参照を、項目が作り直されても
実際に表示しているボタンへ向け直す設計が要る。独自のカスタマイズ画面は不要のため、見送り基準には当たらない。4 の原因次第では、
標準の構成保存に頼らず、並び順を自前で保存する作り込みが要る可能性がある（その場合は規模を再評価する）。

## 保守者への検証依頼（実機が必要・初回の依頼。結果は上の表）

実装前に、次を macOS 上の最小のプロトタイプ（または現行コードの `allowsUserCustomization = true` への一時変更）で確かめる。

1. ツールバー上で右クリックまたはメニューから開くカスタマイズで、セットがドラッグで並び替えられるか。セット内の片方だけが動くことがないか
2. 項目の削除・再追加・スペース追加・表示モード変更（アイコンのみ／テキストのみ／両方）で、見た目と操作が破綻しないか。特にテキスト表示のときのセグメントの幅とラベル、同じセットの重複追加の可否
3. パレット用の項目生成で delegate が `willBeInsertedIntoToolbar == false` で呼ばれるか。呼ばれる場合、参照の上書きが状態表示を壊すか
4. 並び替え・削除後に再起動して構成が復元されるか。保存値が壊れたときに起動できるか
5. 並び替え・削除・再追加の後に履歴・ペイン・ズームの有効条件と選択状態が正しく更新されるか

## 見送り基準

次のいずれかに当てはまる場合は、実装せずに Issue へ結果を残して終える。

- 独自のカスタマイズ画面や入力処理が必要になる（標準機能の挙動を許容しても、FR-001・002 が満たせない場合）
- セットを分離できてしまう（FR-002 を満たせない）
- 参照の上書きなどを避けるために、ツールバーの生成・状態管理を作り直す必要がある（改修規模が大きい）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 8つのセットのそれぞれを、ドラッグ操作で任意の位置へ移せる
- **SC-002**: 3つ以上のボタンを持つセットを含め、セット内のボタンを別の位置へ分離できる操作が0件である
- **SC-002a**: すべてのセットを外した状態でも、各機能をメニューとショートカットで実行でき、パレットから全セットを戻せる
- **SC-003**: 並び替えの前後で、各セットのボタンの有効・無効と選択状態が、メニュー・ショートカットと食い違う場面が0件である
- **SC-004**: 並び替え後に再起動した場合に、同じ順序が復元される。不正な保存値では、既定の順序のツールバーで起動できる
- **SC-005**: 「保守者への検証依頼」の5項目の結果が記録され、実施か見送りかの判断を根拠付きで説明できる

## Assumptions

- 対象は macOS 15 以降の標準 `NSToolbar` のみ。ネットワーク API・外部パッケージは使わない（AGENTS.md）
- 削除・スペース追加・表示モード変更は標準の挙動のまま許容し、独自の制限や専用の画面は作らない
- 並び替えの操作は標準のカスタマイズ UI（Finder と同等）を第一候補とし、独自の操作画面は作らない
- 並び順の保存は標準の構成保存を第一候補とする。保存先は UserDefaults のドメイン（`.app` と `swift run` で別）に依存するため、検証は `.app` で行う
- ツールバーの表示・非表示（`view.showsToolbar`）、フルスクリーンの自動非表示の既存の扱いは変えない
- 本 feature は仕様案の段階であり、`specs/product/` への反映は、実装と検証が終わった後に行う（AGENTS.md）
