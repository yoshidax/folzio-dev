## User Scenarios & Testing *(mandatory)*

### User Story 1 - ボタンセットをドラッグして並び替える (Priority: P1)

利用者は、Finder のようにツールバーの構成要素をドラッグ&ドロップで並び替え、使いやすい順序に調整する。

**Why this priority**: Issue の中心の要望。

**Independent Test**: ツールバーを表示し、カスタマイズ操作で「ズーム」のセットを「履歴」の左へ移して、位置が変わることを確認する。

**Acceptance Scenarios**:

1. **Given** ツールバーを表示中, **When** カスタマイズ操作を始める, **Then** 各ボタンセット（履歴、ペイン表示、スライドショー、ズーム、種類フィルタ、zip 表示、表示形式、サムネイルサイズ）が並び替えの単位として現れる
2. **Given** カスタマイズ中, **When** セットをドラッグして別の位置へ落とす, **Then** セットが新しい位置へ移り、他のセットの順序は保たれる
3. **Given** 並び替えを終えた, **When** ボタンを押す・状態を変える, **Then** 並び替え前と同じ動作と表示（有効・無効、選択状態）になる

---

### User Story 2 - セット内のボタンは分離できない (Priority: P1)

利用者は、サムネイル／リスト切り替えのように関連するボタンが、常に1つのまとまりとして並ぶことを期待する。

**Why this priority**: 操作のまとまりを保つことが Issue の目的。

**Independent Test**: 表示形式のセットの片方のボタンだけを別の位置へ動かせないことを確認する。

**Acceptance Scenarios**:

1. **Given** カスタマイズ中, **When** 表示形式（サムネイル／リスト）の片方だけを動かそうとする, **Then** 動かせず、セット全体だけが動く
2. **Given** 3つのボタンを持つズームのセット, **When** 並び替える, **Then** 「拡大・表示領域に合わせる・縮小」の左右の順序とセットの見た目は変わらない

---

### User Story 3 - 並び順を次回の起動でも保つ (Priority: P2)

利用者は、調整した順序が再起動後にも残ることを期待する。

**Why this priority**: 毎回やり直しになると並び替えの価値が下がる。

**Independent Test**: 並び替えてアプリを終了・再起動し、同じ順序で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 並び替えた状態, **When** アプリを終了して再起動する, **Then** ツールバーは並び替えた順序で表示される
2. **Given** 保存済みの並び順が破損している・知らない項目を含む, **When** 起動する, **Then** 既定の順序で表示し、すべてのセットが1回ずつ現れる

---

### Edge Cases

- ツールバーの非表示（⇧⌘T）、フルスクリーンの自動非表示を繰り返しても、並び順と各セットの状態が変わらない
- カスタマイズ中に表示言語を切り替えても、ラベル・ツールチップ・アクセシビリティ表記が更新され、並びは保たれる
- スライドショー実行中・名前の変更中・フルスクリーン中にカスタマイズを始めようとした場合の扱い（開始を許すか）を決める
- 並び替えの結果、サムネイルサイズのスライダー（可変幅）が極端な位置に置かれても、他のセットが隠れない（狭いウィンドウでの溢れの扱い）
- 既定の順序に戻す手段を用意するか（Finder の「デフォルトのセット」に相当）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は、ツールバーのボタンセットを、ドラッグ&ドロップで並び替えられなければならない。並び替えの単位は、履歴、ペイン表示、スライドショー、ズーム、種類フィルタ、zip 表示、表示形式、サムネイルサイズの各セットとする
- **FR-002**: セット内の個々のボタンを分離して配置できてはならない。セット内のボタンの順序と見た目は並び替えで変わらない
- **FR-003**: 利用者ができる変更は並び替えだけとする。セットの削除、非表示化、スペースや区切りの追加、表示モード（アイコン／テキスト）の変更はできない
- **FR-004**: 並び替えは、セットの動作・有効条件・選択状態の共有（メニュー・ショートカットとの共有）に影響してはならない（FR-051・089・114・134 の既存の動作を維持する）
- **FR-005**: 並び順は再起動後も復元しなければならない。保存した順序が不正なときは既定の順序で表示する
- **FR-006**: 既定の順序は現行の並び（履歴 → ペイン表示 → スライドショー → ズーム → 種類フィルタ → zip 表示 → 表示形式 → サムネイルサイズ → 末尾の可変スペース）とする
- **FR-007**: 現行仕様の「項目順は固定」「ツールバー構成は保存しない」を、本 feature の実施が決まった時点で改める。実施しない場合は仕様を変えない
- **FR-008**: 標準部品だけで FR-001〜003 を満たせない場合、または改修規模が大きい場合は、実施を見送る（見送り基準は下記）

### 現行仕様との整合（実施する場合に改める箇所）

| 箇所 | 現行 | 必要な変更 |
|---|---|---|
| `contracts/keyboard-and-menus.md` のツールバー | 項目順を固定 | 既定順と、並び替え可能であることを定める |
| `contracts/settings.md` | ツールバー構成を保存しない（表示状態 `view.showsToolbar` だけ保存） | 並び順を保存すること、その保存先（標準の構成保存）と不正値の扱いを定める |
| FR-114・FR-134 | 「…の右隣」「…の左」と位置を規定 | 「既定では」を付け、並び替え後は位置が変わり得ることを明記 |
| FR-051・FR-089 | セットの構成と動作 | 変更不要（セット内の構成は不変）。「項目の並びと位置は変わらない」は表示形式の切り替えに限る旨を保つ |

### Key Entities

- **ボタンセット**: 並び替えの最小単位。1つ以上のボタン（またはスライダー）からなり、分割できない
- **並び順**: セットの並びの保存値。既定の順序と、利用者が変えた順序

## 保守者への検証依頼（実機が必要）

実装前に、次を macOS 上の最小のプロトタイプ（または現行コードの `allowsUserCustomization = true` への一時変更）で確かめる。

1. ツールバー上で右クリックまたはメニューから開くカスタマイズで、セットがドラッグで並び替えられるか。セット内の片方だけが動くことがないか
2. 項目の削除・スペース追加・表示モード変更を、標準の設定（例: `allowsDisplayModeCustomization = false`、許可項目の一覧の絞り込み）で抑止できるか。抑止できない場合、その挙動を仕様として許容するか
3. パレット用の項目生成で delegate が `willBeInsertedIntoToolbar == false` で呼ばれるか。呼ばれる場合、参照の上書きが状態表示を壊すか
4. 並び替え後に再起動して順序が復元されるか。保存値が壊れたときに起動できるか
5. 並び替えの後に履歴・ペイン・ズームの有効条件と選択状態が正しく更新されるか

## 見送り基準

次のいずれかに当てはまる場合は、実装せずに Issue へ結果を残して終える。

- 標準の設定だけで FR-003（並び替え以外を許さない）を満たせず、独自のカスタマイズ画面や入力処理が必要になる
- セットを分離できてしまう（FR-002 を満たせない）
- 参照の上書きなどを避けるために、ツールバーの生成・状態管理を作り直す必要がある（改修規模が大きい）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 8つのセットのそれぞれを、ドラッグ操作で任意の位置へ移せる
- **SC-002**: 3つ以上のボタンを持つセットを含め、セット内のボタンを別の位置へ分離できる操作が0件である
- **SC-003**: 並び替えの前後で、各セットのボタンの有効・無効と選択状態が、メニュー・ショートカットと食い違う場面が0件である
- **SC-004**: 並び替え後に再起動した場合に、同じ順序が復元される。不正な保存値では、既定の順序のツールバーで起動できる
- **SC-005**: 「保守者への検証依頼」の5項目の結果が記録され、実施か見送りかの判断を根拠付きで説明できる

## Assumptions

- 対象は macOS 15 以降の標準 `NSToolbar` のみ。ネットワーク API・外部パッケージは使わない（AGENTS.md）
- 並び替えの操作は標準のカスタマイズ UI（Finder と同等）を第一候補とし、独自の操作画面は作らない
- 並び順の保存は標準の構成保存を第一候補とする。保存先は UserDefaults のドメイン（`.app` と `swift run` で別）に依存するため、検証は `.app` で行う
- ツールバーの表示・非表示（`view.showsToolbar`）、フルスクリーンの自動非表示の既存の扱いは変えない
- 本 feature は仕様案の段階であり、`specs/product/` への反映は、実装と検証が終わった後に行う（AGENTS.md）
