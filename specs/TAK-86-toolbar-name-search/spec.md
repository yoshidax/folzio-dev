# Feature Specification: ツールバーの名前検索欄

**Feature Branch**: `claude/peaceful-bell-dj1h3u`

**Created**: 2026-11-12

**Status**: Draft

**Input**: TAK-86 https://linear.app/takyoshida/issue/TAK-86 — ツールバーの右端に、ファイル名・フォルダ名を検索するテキストフィールドを追加する。
フィールドで Return を押すと、ツリーで選択中のフォルダを起点に名前を検索し、結果をファイルリストに表示する。
フィールド内の虫眼鏡アイコンを押すと、⌘F の検索のモーダルを開き、フィールドの文字をキーワードとして引き継ぐ。

## Clarifications

### Session 2026-11-12

- Q: Return で検索するときの起点を、ツリーの複数選択・フォルダ未選択などの状態ごとにどう決めるか？ → A: 保守者の指示は「使い勝手を最大限に考えた案を提案する」。
  提案: 起点は、ツリーの選択に対応してファイルリストが表示しているフォルダとする（FR-383・A-223）。
  - 単一選択はそのフォルダ、複数選択は主の行のフォルダ（FR-216（directory-tree.md））になる
  - ツリーの選択と一覧のフォルダが食い違う状態（「お気に入り」の見出しだけを選択、EC-102（search.md））では、一覧のフォルダを使う
  - 結果として、検索のモーダルの既定の起点（FR-081（search.md））と常に同じフォルダになる
  - この提案は設計のレビューで保守者が確認する
- Q: すでにツールバーを並び替えて保存している利用者に、新しい検索欄をどう扱うか？ → A: 自動では追加しない。
  現行の規則（FR-235（window-layout.md）・EC-165）のまま、カスタマイズ画面から追加する（FR-390・A-225）
- Q: ツールバーの検索欄の文字と、検索のモーダル・検索結果との連動は？ → A: 片方向とし、検索欄の文字は自動で変えない。
  虫眼鏡から開くときに検索欄の文字をモーダルへ引き継ぐだけとする（FR-386・FR-387・A-224）

## User Scenarios & Testing *(mandatory)*

### User Story 81 - ツールバーから名前で検索する (Priority: P1)

ユーザーは、ツールバーの検索欄にキーワードを入力して Return を押すだけで、いま見ているフォルダ以下を名前で検索できる。
検索のモーダルを開いて起点を確かめる手間がなく、結果は検索のモーダルから検索した場合と同じ一覧に表示される。

**Why this priority**: TAK-86 の主目的。ツールバーから直接検索を始められるようにする。

**Independent Test**: ツールバーを表示し、ツリーでフォルダを選択して、検索欄にキーワードを入力して Return を押す。
同じキーワードと起点で検索のモーダルから検索した結果と、一覧・件数・検索バーの表示が同じであることを確かめる。

**Acceptance Scenarios**:

- **US81-AS1**: **Given** ツールバーを表示し、ツリーでフォルダ A を選択して A の一覧を表示中, **When** 検索欄に `cat` と入力して Return を押す,
  **Then** A を起点に検索が始まり、ファイルリストに検索結果が表示される。検索バーにはキーワード `cat` と起点 A が示される。
  キーボードフォーカスはファイルリストへ移り、検索欄には `cat` が残る
- **US81-AS2**: **Given** 検索欄が空, **When** 文字を入力する, **Then** 検索欄の右端にクリア（×）ボタンが現れる。
  入力しただけでは検索は始まらず、ファイルリストは変わらない
- **US81-AS3**: **Given** 検索欄に文字があり、検索結果を表示中, **When** ×ボタンを押す,
  **Then** 検索欄が空になり、×ボタンが消える。検索結果の表示は変わらない
- **US81-AS4**: **Given** ツリーで複数のフォルダを選択し、一覧には主の行のフォルダ B を表示中, **When** 検索欄で Return を押す,
  **Then** B を起点に検索する
- **US81-AS5**: **Given** A を起点にした検索結果を表示中（ツリーの選択は検索前の A のまま）, **When** 検索欄のキーワードを変えて Return を押す,
  **Then** 前の検索は止まり、同じ A を起点にした新しい検索の結果で置き換わる
- **US81-AS6**: **Given** 検索欄が空、または空白だけ, **When** Return を押す, **Then** 何も起きない
- **US81-AS7**: **Given** 検索欄で日本語を変換中, **When** Return で変換を確定する, **Then** 検索は始まらない。
  確定した後にもう一度 Return を押すと検索が始まる
- **US81-AS8**: **Given** 検索欄から `cat` で検索した後, **When** ⌘F で検索のモーダルを開く,
  **Then** 検索キーワード欄に `cat` が全選択の状態で入っている（FR-081（search.md）の前回のキーワード）

### User Story 82 - 入力したキーワードを持って検索のモーダルへ移る (Priority: P2)

ユーザーは、検索欄にキーワードを入力した後で起点を変えたくなったとき、虫眼鏡アイコンを押して検索のモーダルを開ける。
入力済みのキーワードはモーダルへ引き継がれ、入力し直さずに起点だけを指定して検索できる。

**Why this priority**: 起点を指定する検索への橋渡し。US81 だけでも検索はできるため P2 とする。

**Independent Test**: 検索欄に文字を入れて虫眼鏡を押し、モーダルのキーワード欄に同じ文字が入ることを確かめる。
検索欄が空のときは ⌘F と同じ内容で開くことを確かめる。

**Acceptance Scenarios**:

- **US82-AS1**: **Given** 検索欄に `kyoto` と入力済み, **When** 検索欄の虫眼鏡アイコンを押す,
  **Then** 検索のモーダルが開き、検索キーワード欄に `kyoto` が全選択の状態で入っている。
  検索起点ディレクトリは ⌘F で開いた場合と同じ既定値（FR-081（search.md））である
- **US82-AS2**: **Given** 検索欄が空で、同じ起動中に `cat` で検索したことがある, **When** 虫眼鏡アイコンを押す,
  **Then** ⌘F で開いた場合と同じく、検索キーワード欄に `cat` が全選択の状態で入っている
- **US82-AS3**: **Given** 虫眼鏡から開いたモーダルでキーワードを `kyoto*` に書き換えた, **When** 「検索」または「キャンセル」を押す,
  **Then** モーダルの動作は ⌘F で開いた場合と同じで、ツールバーの検索欄の文字は `kyoto` のまま変わらない
- **US82-AS5**: **Given** 検索欄に `kyoto` と入力済みで、検索欄にフォーカスがある, **When** ⌘F を押す,
  **Then** 虫眼鏡を押した場合と同じく、検索キーワード欄に `kyoto` が入った検索のモーダルが開く
- **US82-AS4**: **Given** プレビューのみ表示中（⌘F が無効の状態）, **When** ツールバーの検索欄を見る・押そうとする,
  **Then** 検索欄は無効の表示で、入力も虫眼鏡の押下もできない

### User Story 83 - 検索欄を含むツールバーを自分の並びにする (Priority: P3)

ユーザーは、検索欄をほかのセットと同じく、ツールバーのカスタマイズで並び替え・削除・再追加できる。
一度もカスタマイズしていないユーザーには、検索欄が既定で右端に現れる。

**Why this priority**: 既存のカスタマイズ（FR-233〜FR-235（window-layout.md））との整合。検索の機能そのものではないため P3 とする。

**Independent Test**: 保存した並びがない状態で起動し、検索欄が右端にあることを確かめる。
カスタマイズ画面で検索欄を動かし、再起動後に位置が復元されることを確かめる。

**Acceptance Scenarios**:

- **US83-AS1**: **Given** ツールバーを一度もカスタマイズしていない, **When** この変更を含む版を起動してツールバーを表示する,
  **Then** 検索欄がツールバーの右端に表示される
- **US83-AS2**: **Given** この変更より前にツールバーを並び替えて保存した, **When** この変更を含む版を起動する,
  **Then** 保存した並びのまま表示され、検索欄は自動では加わらない。カスタマイズ画面には検索欄が候補として表示され、ドラッグで追加できる
- **US83-AS3**: **Given** カスタマイズ画面で検索欄を左端へ移した, **When** アプリを再起動する, **Then** 検索欄は左端に復元される
- **US83-AS4**: **Given** ツールバーを文字だけで表示する形式にした、またはウインドウが狭く検索欄があふれた, **When** 「検索」の項目を選ぶ,
  **Then** 検索のモーダルが開く

### Edge Cases

- **EC-250**: zip の中を表示中に検索欄で Return を押した場合は、検索のモーダルの既定の起点と同じく、zip ファイルを含むフォルダを起点にする。
  - 検索を始めると zip の中の表示は終わる（FR-069（zip.md）・FR-081（search.md））
- **EC-251**: 一覧のフォルダ F がツリーに表示されず、ツリーでは祖先 V を選択している状態（EC-102（search.md））で Return を押した場合は、F を起点にする。
  - V へ広げない
- **EC-252**: Return を押した時点で、起点のフォルダが存在しない・読み取り権限がないなどで FR-081（search.md）の検証に通らない場合は、検索を始めない。
  - 検索のモーダルを、検索欄のキーワードと起点のパスを入れ、理由を表示した状態で開く（モーダルで「検索」を押して検証に失敗した場合と同じ状態）
  - ファイルリストの表示は変えない
- **EC-253**: 検索中に検索欄で別のキーワードを入れて Return を押した場合は、実行中の検索を止め、新しい検索の結果で置き換える（FR-085（search.md））
- **EC-254**: 検索欄の文字は保存しない。再起動後と、カスタマイズで検索欄を外して再び追加した後は、空で始まる
- **EC-255**: 表示言語を切り替えた場合、検索欄のプレースホルダ・ラベル・ツールチップは新しい言語に変わり、入力済みの文字は保つ
- **EC-256**: カスタマイズ画面のパレットの見本の検索欄には入力できず、Return と虫眼鏡も働かない（標準の動作）
- **EC-257**: 検索欄で Esc を押した場合は、標準の検索フィールドと同じく検索欄の文字を消すだけで、表示中の検索結果は解除しない。
  - 検索結果の解除は、従来どおりファイルリストでの Esc とツリーでの選択で行う（FR-086（search.md））
- **EC-258**: 検索欄にフォーカスがある間、ファイル操作のショートカット（⌘⌫・⌘C・⌘V・⌘D など）は、検索欄の文字の編集として働くか、何もしない。
  - ファイルリストとツリーで選択中の項目を対象にしない（検索欄で文字を消そうとして、ファイルをゴミ箱に入れることがない）
- フルスクリーン表示中・プレビューのみ表示中に ⌘F が無効であること（FR-080（search.md））は変えない。検索欄も同じ条件で無効にする（FR-388）
- 検索欄から始めた検索の結果の操作（解除・フォルダを開く・履歴・ファイル操作）は、検索のモーダルから始めた検索と同じ（FR-084〜FR-087・FR-140（search.md））

## Requirements *(mandatory)*

### Functional Requirements

- **FR-380**: ツールバーに、名前（ファイル名とフォルダ名）を検索するための検索欄（標準の検索フィールド）を1つのセットとして追加しなければならない。
  - 既定の並びでは、ツールバーの右端に置く（FR-233（変更））
  - 検索欄の中の左端に虫眼鏡アイコンを表示する
  - 検索欄が空のときは、名前で検索する欄であることを示すプレースホルダを表示する
- **FR-381**: 検索欄に1文字以上が入っている間、検索欄の中の右端にクリア（×）ボタンを表示しなければならない。
  - ×ボタンを押すと、検索欄の文字を消し、×ボタンを隠す
  - ×ボタンの操作で、ファイルリスト・検索結果・ツリー・プレビューを変えてはならない
- **FR-382**: 検索欄にフォーカスがある状態で Return を押すと、システムは、検索欄の文字をキーワードとし、FR-383 の起点で名前の検索を始めなければならない。
  - キーワードの照合は FR-082（search.md）、検索の対象と進め方は FR-083・FR-085・FR-278（search.md）、結果の表示は FR-084（search.md）に従い、
    同じキーワードと起点で検索のモーダルから検索した場合と同じ結果になる
  - 前後の空白を除いたキーワードが空のときは、何もしない
  - 検索を始めたら、キーボードフォーカスをファイルリストへ移す（検索のモーダルから検索した場合と同じ）
  - 検索を始めても、検索欄の文字は変えない
  - 文字の入力だけでは検索を始めない（Return を押したときだけ始める）
  - 日本語入力の変換を確定する Return では検索を始めない
- **FR-383**: 検索欄からの検索の起点は、ツリーの選択に対応してファイルリストが表示しているフォルダとしなければならない。
  - ツリーで1つのフォルダ（お気に入りの項目を含む）を選択しているときは、そのフォルダになる
  - ツリーで複数の行を選択しているときは、主の行のフォルダになる（FR-216（directory-tree.md））
  - 検索結果の表示中は、検索前のフォルダとする（ツリーの選択は検索前のまま変わらない。FR-086（search.md））
  - zip の中を表示中は zip ファイルを含むフォルダ、「お気に入り」の見出しだけを選択しているときと EC-102（search.md）の状態では一覧のフォルダとする
  - この起点は、検索のモーダルの検索起点ディレクトリの既定値（FR-081（search.md））と常に同じフォルダである
- **FR-384**: システムは、検索欄からの検索を始める前に、起点を FR-081（search.md）と同じ規則で UI を止めずに検証しなければならない。
  - 検証に通らない場合は検索を始めず、ファイルリストの表示を変えない
  - その場合は、検索のモーダルを、検索欄のキーワードと起点のパスを入れ、検証の理由を表示した状態で開く（EC-252）
- **FR-385**: 検索欄から検索したキーワードは、検索のモーダルが引き継ぐ「同じ起動中に前回検索したキーワード」（FR-081（search.md））として扱わなければならない
- **FR-386**: 検索欄の虫眼鏡アイコンを押すと、システムは検索のモーダル（FR-080（search.md））を開かなければならない。
  - 検索欄に前後の空白を除いて1文字以上が入っているときは、検索キーワード欄に検索欄の文字（前後の空白を除く）を全選択の状態で入れる
  - 検索欄が空（空白だけを含む）のときは、⌘F で開いた場合と同じく、前回検索したキーワードがあればそれを入れる
  - 上の2点を除き、モーダルの構成・既定の起点・検証・キーボード操作・「検索」「キャンセル」の動作は、⌘F で開いた場合（FR-081・FR-141〜FR-144（search.md））と同じとする
  - 検索欄にフォーカスがある状態で ⌘F（「ファイル」メニューの「検索…」を含む）を実行した場合も、虫眼鏡を押した場合と同じに扱う
- **FR-387**: 検索のモーダルでの操作（キーワードの編集・検索・キャンセル）と、検索結果の解除（FR-086（search.md））は、ツールバーの検索欄の文字を変えてはならない
- **FR-388**: 検索欄（入力・Return・虫眼鏡・×ボタン）は、検索のモーダルを開ける条件（FR-080（search.md））を満たすときだけ有効にしなければならない。
  - フルスクリーン表示中とプレビューのみ表示中（FR-092（window-layout.md））は、無効の表示にする
  - 無効の間も、入力済みの文字は保つ
  - 名前の変更中に検索欄を押した場合の名前の変更の扱いは、ほかの場所を押した場合と同じとする
- **FR-389**: 検索欄のセットのラベル（カスタマイズ画面とテキスト表示で使う名前）は「検索」（英語: `Search`）としなければならない（FR-236（変更））。
  - プレースホルダとアクセシビリティのラベルは「名前で検索」（英語: `Search by Name`）とする
  - 虫眼鏡アイコンのツールチップとアクセシビリティのラベルは「検索…（⌘F）」（英語: `Find… (⌘F)`）とし、キーは現在の割り当てに従う（FR-237（window-layout.md））
  - ツールバーを文字だけで表示する形式と、あふれたときのメニューでは、項目「検索」を選ぶと検索のモーダルを開く（有効の条件は FR-388）
- **FR-390**: 検索欄のセットは、ほかのセットと同じくツールバーのカスタマイズ（並び替え・削除・再追加）の対象とし、保存した並びに識別子 `search` で記録しなければならない。
  - この変更より前に保存した並び（検索欄を含まない）は、そのまま復元し、検索欄を自動では追加しない（FR-235（window-layout.md））
  - 検索欄を外しても、検索は ⌘F とメニューで使える（FR-234（window-layout.md））

### Key Entities *(include if feature involves data)*

- **ツールバーの検索欄の入力**: ユーザーが検索欄に入力した文字。検索欄からの検索のキーワードと、虫眼鏡から開くモーダルへ引き継ぐキーワードになる。保存しない
- **検索条件**（search.md の既存のエンティティ）: 検索欄からの検索では、キーワードは検索欄の文字、起点は FR-383 のフォルダになる

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-208**: ツリーの単一選択・複数選択・お気に入りの項目の選択・検索結果の表示中・zip の中の表示中の5つの状態で、
  検索欄から検索した結果（一覧・件数・検索バーの起点）が、検索のモーダルを既定の起点のまま使って同じキーワードで検索した結果と食い違う場合が0件
- **SC-209**: 検索欄に文字がある・空で前回のキーワードがある・空で前回のキーワードがないの3つの状態で、
  虫眼鏡から開いたモーダルのキーワード欄の内容が FR-386 と食い違う場合が0件
- **SC-210**: 文字の入力・×ボタン・日本語入力の変換の確定・空の Return のいずれかで、検索が始まる、またはファイルリストの表示が変わる場合が0件
- **SC-211**: 保存した並びがない状態では検索欄が右端に表示され、この変更より前に保存した並びで起動したときに並びが変わる場合が0件
- **SC-212**: 検索欄にフォーカスがある間に ⌘⌫・⌘C・⌘V・⌘D を押して、ファイルリストまたはツリーで選択中の項目が変更・コピー・移動される場合が0件

## Assumptions

- **A-223**: 検索欄からの検索の起点を「一覧が表示しているフォルダ」と定めるのは、ユーザーが見ている内容から起点を予測できるようにするため。
  - 通常はツリーで選択したフォルダと一覧のフォルダが同じなので、Issue の「ツリーで選択されているフォルダ」と一致する
  - 食い違う状態（EC-102（search.md）・「お気に入り」の見出しの選択）では、ツリーの選択をそのまま使うと、見ている一覧より広い範囲を検索する、または起点がなくなる
  - 検索のモーダルの既定の起点と同じにすると、「検索欄の Return は、⌘F を開いてそのまま『検索』を押すのと同じ」と1つの規則で説明できる
  - 起点は検索バー（FR-084（search.md））に表示されるので、検索の後に確かめられる
  - 2026-11-12 に保守者が「使い勝手を最大限に考えた案」を求めたことへの提案で、設計のレビューで確認する
- **A-224**: 検索欄と検索のモーダルの連動は、検索欄からモーダルへの片方向とする（2026-11-12 の保守者の決定）。
  - モーダルで検索したキーワードを検索欄へ書き戻さず、検索結果を解除しても検索欄を消さない
  - 検索欄は入力の場所であり、現在の検索の状態は従来どおり検索バー（FR-084（search.md））が示す
- **A-225**: 保存した並びへ検索欄を自動で追加しない（2026-11-12 の保守者の決定）。
  - 「利用者が外した」と「保存した時点で存在しなかった」を区別する仕組みを持たず、FR-235（window-layout.md）・EC-165（window-layout.md）の規則を変えない
  - この変更より前の版へ戻した場合、`search` を含む保存した並びは未知の識別子を含む値として既定の並びになる（EC-165）
- **A-226**: 入力のたびに検索する方式（逐次検索）にはしない。
  - 検索は起点以下のすべての階層を辿るため（FR-083（search.md））、入力のたびに始めると負荷が大きく、Issue も Return での検索を指定している
- **A-227**: 虫眼鏡アイコン・×ボタン・Esc での消去は、標準の検索フィールドの機能を使う。
  - 標準の検索フィールドで、虫眼鏡の押下にモーダルを開く動作を割り当てられることは、計画の段階で確かめる
- **A-228**: 検索欄へフォーカスを移す専用のショートカットとメニュー項目は追加しない。
  - ⌘F は従来どおり検索のモーダルを開く（FR-080（search.md））。キーボードだけの検索は、従来どおり ⌘F で行える（憲章のキーボード操作の原則はこれで満たす）
- **A-229**: 検索欄の幅は固定の幅を基本とし、ウインドウが狭いときの扱いは標準のツールバーのあふれ処理に従う

## 変更する既存の要件

- **FR-233（変更）**: ツールバーのボタンセット（履歴、ペイン表示、スライドショー、ズーム、種類フィルタ、zip 表示、表示形式、
  サムネイルサイズ、検索）を、標準のカスタマイズ画面のドラッグ&ドロップで並び替えられなければならない。
