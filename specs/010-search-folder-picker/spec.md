# Feature Specification: 検索起点フォルダの GUI 選択

**Feature Branch**: `010-search-folder-picker`

**Created**: 2026-10-27

**Status**: Draft

**Input**: User description: "検索モーダルで検索起点フォルダパスをGUIベースで入力できるようにする。現状の検索起点パス入力を残しつつ、NSOpenPanel、もしくはそれ相当のGUIを使ってパスを設定することができるようにする"

本仕様は `specs/product/` に対する差分である。基準は FR-081・FR-082・EC-34（search.md）、FR-040・FR-041（overview.md）、
検索モーダルのキー操作（contracts/keyboard-and-menus.md）、検索条件を保存しない契約（contracts/settings.md）とする。
検索の対象・照合・結果表示は既存仕様を参照する。本変更は検索起点の入力手段だけを追加する。
既定起点は既存のキー契約と実装に合わせ「一覧に表示中のフォルダ」に統一する。FR-081・US1-AS25 の「ツリーで選択中」という旧記述を改め、
EC-102 で一覧の F とツリーの V が異なる場合も F を使う。ツリー同期・保存・履歴の EC-102 自体は変更しない。
新規 ID は正本全領域と既存 feature の使用済み ID を確認し、未反映の `009-folder-search` とも重複させない。

既存仕様との照合では、FR-081・EC-34（search.md）の直接入力の規則を保ち、未編集の GUI 選択パスの空白保持だけを FR-081 の明示的な例外とする。
EC-19・A-09（overview.md）との初期表示の衝突は FR-141・FR-143 で解消する。FR-085・FR-086（search.md）の検索の継続・置換・非保存、
FR-003（overview.md）と contracts/settings.md の最後のフォルダの保存契約は維持し、GUI 選択だけでは保存値を変えない。
FR-040（overview.md）を満たすため、contracts/keyboard-and-menus.md にはボタンの Tab 順序・Space・選択画面での Return／Esc の扱いを追加する。
`009-folder-search` の FR-082〜FR-087 の変更と EC-102 は検索対象・結果の扱いの差分であり、本変更で上書きしない。

## Clarifications

### Session 2026-10-27

- Q: GUI で選んだフォルダ名の末尾に空白がある場合も、既存の FR-081（search.md）の空白除去を適用するか? → A: 適用しない。GUI 選択で反映してから起点欄を編集していない間は、選択した絶対パスを文字どおり使う。起点欄を編集したら従来の直接入力の解釈へ戻し、入力手段によらず検索時の存在・種類・読み取り可否の検証は行う。

- Q: 起点欄が隠しフォルダやパッケージを指す場合、FR-143 の初期表示と EC-19・A-09（overview.md）の非表示規則のどちらを優先するか? → A: 非表示規則を優先する。GUI では隠しフォルダ・パッケージの表示切替、選択、内部への移動を提供せず、初期表示の各候補にも同じ制限を適用して次候補へ進む。元の起点欄は保持し、直接入力の既存の検証規則は変えない。

- Q: フォルダ選択画面で確定する時点で、選択先が削除されているか読み取れない場合は、いつ拒否するか? → A: 確定時に拒否し、選択画面で理由を表示・読み上げて選び直しまたは取消を可能にする。起点欄・キーワード・既存の検証エラーは保持する。確定できた場合も検索開始時には再検証する。

- Q: FR-085（search.md）の検索が進行中にフォルダ選択画面を開いた場合、既存の検索の進行や結果の更新を止めるか? → A: 止めない。選択画面の開閉・確定・取消だけでは既存の検索を停止・再開始・置換しない。「一覧等を変えない」は選択操作による変更を禁じる意味で、既存検索の進行と外部変更の反映は継続する。新しい検索が有効な条件で開始された時点で、FR-085 に従い既存検索を置き換える。

## User Scenarios & Testing *(mandatory)*

### User Story 16 - フォルダを画面で選んで検索起点を設定する (Priority: P1)

ユーザーは長いパスを手入力せず、検索モーダルからフォルダを辿って選択し、その場所を検索起点にできる。
必要なら選択後のパスを直接編集でき、選択を取り消しても入力中の条件を失わない。

**Why this priority**: パスを正確に覚えたり別の画面からコピーしたりせずに検索起点を設定できることが、この追加機能の中心的な価値である。

**Independent Test**: 検索モーダルで任意の別フォルダを選択し、パス欄の反映後に「検索」を押す。
選択だけでは検索が始まらず、確定した起点で検索できることを確認する。取消・直接編集・キーボード操作も同じモーダルで確認できる。

**Acceptance Scenarios**:

1. **US16-AS1**: **Given** 検索モーダルでキーワードと起点パスを入力済み, **When** 「フォルダを選択…」を押して別の読み取り可能なフォルダを1つ選び確定する,
   **Then** 検索起点欄の全体が選択したフォルダの絶対パスになり、キーワードは保たれる。検索モーダルは開いたままで、選択操作による検索開始・
   ツリーの選択・ファイルリスト・プレビューの変更は起きない。その後「検索」を押すと、その起点で既存の検索を開始する。
2. **US16-AS2**: **Given** 検索モーダルでキーワードと起点パスを編集中, **When** フォルダ選択画面を開き「キャンセル」または Esc で取り消す,
   **Then** 選択画面だけが閉じ、検索モーダルと両入力欄の値が保持される。新たな検索は始まらず、取消操作によってツリー・ファイルリスト・プレビューは変わらない。
3. **US16-AS3**: **Given** フォルダ選択で起点を設定済み, **When** 起点欄を別の有効なパスに直接書き換えて「検索」を押す,
   **Then** 選択時のパスではなく欄にある最新のパスを使う。直接入力だけで検索する従来の操作も利用できる。
4. **US16-AS4**: **Given** 起点欄が GUI で表示・選択できる読み取り可能なフォルダを表す（直接入力の前後の空白・先頭の `~`・末尾の `/` は FR-081 に従う）,
   **When** フォルダ選択画面を開く, **Then** 解釈後のフォルダを最初に表示する。選択を確定するまでは入力欄の文字列を変更しない。
5. **US16-AS5**: **Given** 起点欄が空または無効なパス, **When** フォルダ選択画面を開く,
   **Then** 検索モーダルを開いた時点の既定フォルダを、そこも利用できなければホームフォルダを最初に表示する。
   取消では無効な入力もそのまま保ち、有効なフォルダを選び確定すればその絶対パスへ置き換えられる。
6. **US16-AS6**: **Given** 検索モーダルが開いている, **When** キーボードだけで「フォルダを選択…」へ移り、フォルダ選択・確定または取消を行う,
   **Then** 検索モーダルへ戻り「フォルダを選択…」にフォーカスが戻る。選択画面での Return・Esc はその画面だけに作用し、検索を開始したり
   検索モーダルを閉じたりしない。操作名はスクリーンリーダーでも識別できる。
7. **US16-AS7**: **Given** フォルダを選択して確定した後、そのフォルダが削除されたか読み取り権限を失った,
   **When** 「検索」を押す, **Then** FR-081（search.md）の検証で拒否し、モーダルを閉じずに理由を表示する。新たな検索は始めず、検証失敗を理由に一覧は変えない。
8. **US16-AS8**: **Given** フォルダ選択画面が開いている, **When** 通常のファイルや zip ファイルを選ぼうとする,
   **Then** 検索起点として確定できない。複数のフォルダを同時に検索起点へ設定することもできない。
9. **US16-AS9**: **Given** 起点の検証エラーを表示中, **When** フォルダ選択で読み取り可能なフォルダを確定する,
   **Then** 新しい絶対パスが入り、古いパスに対するエラー表示が消える。検索モーダルは開いたままで、実際の検索時には最新のパスを再検証する。

10. **US16-AS10**: **Given** 同じ親の下に `Photos` と末尾に空白がある `Photos ` の両フォルダが存在する,
    **When** GUI で `Photos ` を選び、起点欄を編集せずに検索する, **Then** `Photos ` が起点となり、`Photos` へ置き換わらない。
    選択画面を開き直すと同じフォルダから始まり、取消やキーワードの編集後もこの扱いを保つ。起点欄を直接編集した場合は従来の空白除去を適用する。

11. **US16-AS11**: **Given** 起点欄が隠しフォルダまたはパッケージを指し、検索モーダルを開いた時点の既定フォルダは GUI で利用できる,
    **When** フォルダ選択画面を開く, **Then** 既定フォルダから始まり、取消後も元の起点欄を保持する。GUI 内で隠しフォルダやパッケージを
    直接指定しても選択・内部への移動はできず、直接入力からの検索の可否は従来の検証に従う。

12. **US16-AS12**: **Given** フォルダ選択画面で確定しようとしたフォルダが削除済み、または読み取り不能である,
    **When** 確定を試みる, **Then** 選択画面に理由が表示・読み上げられ、検索起点欄・キーワード・既存の検証エラーは変わらない。
    別の有効なフォルダを選び直せ、取消した場合は元の検索モーダルへ戻れる。

13. **US16-AS13**: **Given** 検索 A が進行中で、検索モーダルからフォルダ選択画面を開く, **When** フォルダを確定または取り消す,
    **Then** 検索 A は継続し、発見された結果と途中の件数は更新される。選択操作による停止・再開始・結果の置換は起きない。
    新しい検索 B を有効な条件で開始したときだけ、検索 A を停止し、その結果を B の結果で置き換える。

### 既存の受け入れシナリオの変更

- **US1-AS25（変更）**: **Given** 一覧にフォルダを表示中（EC-102 で一覧の F とツリーの V が異なる場合を含む）, **When** ⌘F を押す
  （または「ファイル」メニューの「検索…」を選ぶ）, **Then** 検索キーワードと検索起点ディレクトリの入力欄、「フォルダを選択…」「検索」
  「キャンセル」ボタンを持つ検索モーダルが表示され、検索起点にはモーダルを開いた時点で一覧に表示中のフォルダの絶対パスが入る。
  検索結果の表示中は検索前のフォルダ、zip の中を表示中は zip ファイルを含むフォルダとし、EC-102 では V でなく F を使う（FR-081）。
  「キャンセル」を押すと、取消操作によってファイルリスト・ツリー・プレビューは変わらない。

### Edge Cases

- **EC-103**: 起点欄が空・相対パス・存在しないパス・ファイルのパス・読み取り不能なフォルダでも、フォルダ選択は開ける。
  初期表示は FR-143 に従い、取消では元の入力を変更しない。選択画面の初期位置への切り替えだけでパス欄を補正しない。
- **EC-104**: 選択後から検索開始までにフォルダが削除・移動された、ボリュームが外された、読み取り権限を失った場合は、
  直接入力と同じく FR-081（search.md）・EC-34（search.md）で扱う。GUI で選択したことを理由に検証を省略しない。
- **EC-105**: フォルダ選択中の Esc は選択画面の取消だけを行い、Return は選択画面の操作だけを行う。
  検索モーダルへ入力を伝播させない。復帰後に検索モーダルで Esc を押した場合は従来どおり検索モーダルを閉じる。既存の検索は停止しない。
- **EC-106**: 日本語・空白を含むフォルダ、ルート `/`、読み取り可能な外部ボリュームのフォルダを選んだ場合も、選択した場所を表す
  絶対パスを欄へ反映する。名前の末尾の空白も保持し、引用符やエスケープ記号を付け加えず、起点欄を編集しなければ再入力せずに検索できる。

## Requirements *(mandatory)*

### Functional Requirements

#### FR-081 検索モーダルの構成と入力（変更）

- **FR-081**: 検索のモーダルは、「検索キーワード」（1行のテキスト入力）、「検索起点ディレクトリ」（1行のテキスト入力）、
  その近くの「フォルダを選択…」ボタン、「検索」ボタン、「キャンセル」ボタンで構成しなければならない。
  検索起点ディレクトリの既定値は、検索モーダルを開いた時点で一覧に表示中のフォルダの絶対パスとする。検索結果の表示中は検索前のフォルダ、
  zip の中を表示中は FR-069（zip.md）により zip ファイルを含むフォルダとする。お気に入りの見出しを選択しても一覧のフォルダを使う。
  EC-102（009-folder-search）で一覧に F、ツリーに祖先 V を表示している場合は F を使い、V へ置き換えない。
  「検索」で検索を始めてモーダルを閉じる。「キャンセル」（Esc を含む）ではモーダルを閉じるだけで、ファイルリスト・
  ツリー・プレビューを取消操作によって変えてはならない。モーダルを開いたときは検索キーワード欄にフォーカスを置き、同じ起動中に前回検索した
  キーワードがあれば全選択した状態で入れておく（検索起点ディレクトリは毎回上の既定値とする）。フォルダ選択画面を開いていないときは、
  Return で「検索」（キーワードが空のときは何もしない）、Esc で「キャンセル」とする。Tab は検索キーワード → 検索起点ディレクトリ →
  フォルダを選択… → キャンセル → 検索の順、⇧Tab は逆順に移動し、システムのキーボードナビゲーションの設定に関わらずボタンにも止まる。
  検索起点欄は直接入力・編集を引き続き可能とする。検索起点ディレクトリは入力手段によらず「検索」を押したときに確かめる。
  直接入力では前後の空白を除き、先頭の `~` はホームフォルダ、末尾の `/` は無視して解釈する。GUI 選択で反映してから起点欄を
  編集していない間だけは、名前の末尾の空白も含む選択した絶対パスを文字どおり使い、空白除去は行わない。起点欄を編集した時点で
  従来の直接入力の解釈へ戻す。キーワードの編集や選択画面の取消では、この区別を変えない。`/` と `~` のどちらでも始まらないパス、
  存在しないパス、フォルダでないパス（zip ファイルを含む）、読み取り権限のないフォルダの場合は、モーダルを閉じずに理由を入力欄の
  近くに表示し、検索を始めてはならない（検証失敗を理由にファイルリストの表示は変えない）。フォルダ選択画面の動作は FR-141〜FR-144 に従う。

#### 追加: フォルダ選択による入力

- **FR-141**: 「フォルダを選択…」を押すと、検索モーダルからフォルダ階層を辿って1つの既存フォルダを選べる GUI を開かなければならない。
  起点欄やキーワードが空・無効でも利用できる。通常のファイル・zip ファイルは確定対象にせず、複数選択と新規フォルダ作成は提供しない。
  確定時に選択先の存在・フォルダであること・読み取り可否を確認し、満たさない場合は確定せず、選択画面で理由を表示・読み上げる。
  選択画面を保って選び直し・取消を可能にし、検索モーダルの入力値と既存の検証エラーは保持する。確定後も検索時の再検証は省略しない。
  隠し項目・パッケージは EC-19・A-09（overview.md）に従い表示せず、表示切替も提供しない。GUI 内でパスを指定する操作でも、
  隠しフォルダ・パッケージの選択や内部への移動はできない。この制限を直接入力の検索起点の検証へ追加してはならない。
- **FR-142**: 選択の確定時は、検索起点欄の全体を選択したフォルダの絶対パスで置き換え、以前の起点に対する検証エラーを消さなければならない。
  キーワードを保ち、選択画面だけを閉じる。取消（Esc を含む）では選択画面を開く直前の起点欄・キーワード・検証エラーを保つ。
  開く・確定・取消のいずれでも検索を開始せず、選択操作を理由にツリーの選択・ファイルリスト・プレビューを変更しない。
  既存の検索が進行中でも、この操作だけでは停止・再開始・置換しない。「変えない」は選択操作による変更を指し、既存検索の進行と結果の更新
  （FR-085（search.md））、外部変更の反映（FR-042（overview.md））は継続する。新しい検索を有効な条件で開始した時点で FR-085 に従い置き換える。
  選択後も起点欄を直接編集でき、検索には最新の欄の値を FR-081 の規則で解釈して使う。
  GUI 選択後に起点欄を編集したかどうかは検索モーダル内だけで扱い、モーダルを閉じたら破棄する（検索条件の非保存は FR-086（search.md）・contracts/settings.md に従う）。
- **FR-143**: 選択画面の初期表示フォルダは、次の優先順で決めなければならない。
  （1）現在の起点欄を FR-081 と同じ規則（未編集の GUI 選択パスは文字どおり、それ以外は空白・`~`・末尾 `/` の解釈）で解釈した、存在し読み取り可能なフォルダ、
  （2）検索モーダルを開いた時点の既定フォルダ（存在し読み取り可能な場合）、（3）ユーザーのホームフォルダ。
  どの候補も FR-141 に従い GUI で表示・選択できるフォルダであることを条件とし、隠しフォルダ・パッケージやその内部など、
  GUI で移動できない候補は飛ばして次へ進む。初期表示のために起点欄を書き換えず、選択画面を再度開くときも現在の起点欄を優先する。
  （2）は FR-081 の既定値を開いた時点で捕捉し、後からツリーの選択や一覧の変化で置き換えない。EC-102 の F が非表示対象の内部なら、
  （1）と（2）の F を飛ばしてホームへ進み、ツリーの V を追加候補にはしない。取消では起点欄の F を保持する。
  いずれの候補も利用できない場合は検索モーダルを保ち、起点欄の近くに理由を表示して直接入力・再試行を可能にする。
  初期位置の解決中も親の「検索」は利用できる。空キーワードの無操作を除き検索操作を受理した時点で保留中の選択画面提示を失効させ、
  その後で検索条件を検証する。失効した解決の成功・失敗は、検索検証との完了順によらず子の提示や親のエラー変更に使わない。
  検索検証に失敗しても旧依頼を復活させず、親で理由を示して選択操作の再試行を可能にする。先に子を提示済みなら FR-144 に従い親の検索を受理しない。
- **FR-144**: 新しいフォルダ選択操作はキーボードだけで利用でき、「フォルダを選択…」にフォーカスがあるとき Space で開けなければならない。
  選択画面ではキーボードで階層移動・単一フォルダの選択・確定・取消ができる。表示中は検索モーダルを操作できず、Return・Esc は
  選択画面だけで処理する。確定・取消の後は「フォルダを選択…」へフォーカスを戻す。
  ボタンと選択画面は、検索起点フォルダを選ぶ操作であると分かるラベルでスクリーンリーダーから識別できなければならない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

## Assumptions

- **A-83**: 要望の GUI は、OS 標準のフォルダ選択と同等に階層を辿って確定・取消できる画面と解釈する。

  入力手段の追加に範囲を絞るための推奨回答として採用した。
- **A-85**: 選択画面の初期表示には、現在の有効な入力のうち GUI で利用できるフォルダを優先し、候補が利用できなければ

  入力を修正せずに選び直せ、繰り返し選ぶときも現在の条件から辿れるための推奨回答として採用した。
- **A-86**: 専用のグローバルショートカットは増やさず、Tab・⇧Tab とボタンの Space 操作を入口とする。
  選択画面から戻ったときは入口のボタンへフォーカスを戻す。既存ショートカットとの衝突を避け、操作の続きが分かる推奨回答として採用した。
