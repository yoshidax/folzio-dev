# Quickstart: 検索起点フォルダの GUI 選択

これは実装後の検証ガイドである。現時点の検証結果ではない。動作の詳細は [UI 契約](contracts/search-folder-picker.md)、状態・可否は [data-model.md](data-model.md) を参照する。

## 前提と検証データ

- macOS 15 以降、Swift 6、Xcode / Command Line Tools。
- GUI の起動はユーザーが行う。通常権限のユーザーで検証する。
- 外部ボリュームのケースには、読み取り可能なローカルの外部ボリュームを用意する。未実施を合格に含めない。
- VoiceOver と、キーボードナビゲーション設定のオン・オフを確認できること。
- フィクスチャを作る際に WebP ツールの導入が必要になった場合はユーザーに確認する。本 feature 固有のデータは JPEG・ディレクトリ・既存の zip 生成で足りる。

実装では `FixtureSets.searchFolderPicker(in:)` を追加し、makeAll から呼ぶ。既存の生成コマンドで次の構成を作れるようにする。以下の新規データは実装前には存在しない。

```bash
cd /Users/igachan/projects/my_img_viewer
scripts/make-fixtures.sh ~/MediaViewerFixtures
```

| `search-folder-picker/` 内 | 用途・内容 |
|---|---|
| `default/` | 検索シートを開く既定フォルダ。`default-hit.jpg` |
| `other/child/` | 別の起点と階層移動。`other/other-hit.jpg` と `child/child-hit.jpg` |
| `日本語/`・`Space Folder/` | 文字種のケース。各 `hit.jpg` |
| `Photos/`・`Photos ` | 同じ親に末尾空白なし・ありを併存。各 `plain-hit.jpg`・`space-hit.jpg` と異なる名前のサブフォルダを置き、行でも見分けられるようにする |
| `empty/` | 空フォルダ自体の選択 |
| `.hidden/inside/`・`flag-hidden/inside/` | 名前由来と isHidden 属性由来の非表示。後者は生成時に隠し属性を付ける |
| `Picker.app/Contents/inside/` | パッケージ自身と内部の禁止 |
| `visible-link`・`hidden-link`・`package-link` | それぞれ other、.hidden/inside、Picker.app/Contents/inside を指すリンク。禁止先への迂回がないこと |
| `locked/`・`vanishing/` | 読取不能・削除・移動の再現。生成直後は通常の読取可能フォルダ |
| `file.jpg`・`archive.zip` | 非フォルダを選択できないこと |
| `many-folders/` | 直下 10,000 フォルダ。各1個の小さな JPEG を置き、検索更新と選択画面の大量件数を同じデータで確認 |

自動テストのフィクスチャは一時ディレクトリへ生成して defer で削除する。GUI 用は上の専用領域だけを使い、実データの権限を変更しない。

## 手動シナリオ

### 1. 基本の確定と検索（AS1・AS8、SC-058）

1. ツリーで default を選び、⌘F。キーワード `hit` を入れ、現在のツリー・一覧・プレビューを記録する。
2. 「フォルダを選択…」から other へ移動して確定。起点欄全体が other の絶対パスとなり、キーワードと検索シートが残る。検索は始まらず、選択操作によるツリー・一覧・プレビューの変更はない。
3. 検索ボタンで初めて検索が始まり、other 以下の結果だけになる。
4. 通常フォルダ、日本語、空白を含む名前、`/`、外部ボリュームの5ケースを記録する。各起点配下の既知の `hit` 一致画像（`/` では上で生成した専用フィクスチャ、外部ボリュームは検証用の一致画像を用意）を使い、有効な検索開始・検索バーの起点パス・一致結果で場所を照合する。合格には全走査の完了を要求せず、`/` を含め照合後は既存の解除操作で終了してよい。起点・結果を照合する前に終了した場合は未確認とし、5/5件の成功に含めない。開始成立・起点一致・照合結果と、走査完了/照合後解除/未確認を別々に記録する。
5. 空フォルダと `/` では行を選択せず現在位置を選べる。ファイル・zip・複数フォルダは選択対象にならず、新規作成はない。

### 2. 取消とエラー保持（AS2・AS9、SC-059）

1. キーワードと無効な起点を入力して検索し、起点エラーを出す。
2. 子で他フォルダへ移動後、キャンセルボタンを5回、Esc を5回、毎回開き直して試す。
3. 毎回、子だけが閉じ、キーワード・無効な起点文字列・元の起点エラーが保たれ、親の選択ボタンへフォーカスが戻ること。親の終了・入力変更・選択操作による一覧等の変更は各0回。
4. 次に有効なフォルダを確定すると、起点だけが置換され古いエラーが消える。検索ボタンまで検索は始まらない。

### 3. 初期位置と直接入力（AS3〜AS5、US1-AS25、EC-103）

1. 起点に有効なパスを直接入力し、前後空白・先頭 `~`・末尾 `/` の各形で子を開く。解釈後のフォルダから始まり、取消で元の文字列を保持する。
2. 空、相対、存在しない、ファイル、zip、読取不能の各入力は既定フォルダへ戻る。既定も削除済みならホームへ戻る（既定の削除は専用フィクスチャだけで行う）。
3. 全候補不可は注入した結果で自動検証する。親の欄を変えず理由を出し、直接入力と再試行が可能なことを確認する。
4. GUI で other を選んでから起点を日本語フォルダへ直接編集して検索する。最新の直接入力を使い、直接入力だけの検索も従来どおり使える。
5. EC-102（009-folder-search）の状態を再現する。親の起点に `~/MediaViewerFixtures/search-folder-picker/.hidden` を直接入力し、キーワード `inside` で検索する。結果から `.hidden/inside` のフォルダ F を開き、一覧には F、ツリーには表示可能な祖先 V があることを記録する。⌘F と「ファイル」メニューの「検索…」の双方で起点欄が V でなく F となり、親の「キャンセル」によって一覧・ツリー・プレビューが変わらないことを確認する（変更後の US1-AS25）。再度親を開いて子を開くと F は GUI 対象外なのでホームから始まり、V は追加の候補にならない。子の取消後も親の F を保持する。起点欄を無効値に変えて開き直しても、捕捉済み既定の F が対象外ならホームとなり、取消で無効値を保持する。ホームが利用可能な環境で行い、利用不可なら未実施理由を残す。

初期位置解決と親検索の競合は、上の自動検証で完了順を制御して固定する。実機で解決待ちの間に検索を操作できた場合は、検索成功後の子の遅延表示がないこと、検索失敗後も旧依頼が開かず改めて選択できることを補助記録する。競合を実機で観測できなくても自動検証の完了順確認を省略しない。

### 4. 末尾空白の保持（AS10・EC-106、SC-058）

1. `Photos` と `Photos ` が併存することを確認。GUI で `Photos ` を確定し、起点欄を編集せず検索する。`space-hit.jpg` が一致し、`plain-hit.jpg` が起点直下の結果として出ない。
2. 再度同じ選択を行い、子の開き直しで `Photos ` から始まることを中の異なるサブフォルダで確認。子の取消とキーワード編集の後も同じ場所を使う。
3. 起点欄をユーザー操作で編集し、末尾空白を含む同じ表示文字列へ戻して検索。今度は従来の trim で `Photos` を使う。文字列の一致だけで picked に戻さない。

### 5. 非表示規則（AS11）

1. `.hidden`、flag-hidden、Picker.app およびそれぞれの内部を親の起点へ直接入力して子を開く。GUI で利用可能な既定フォルダから始まり、取消では入力を保持する。
2. 親フォルダから辿っても禁止対象は表示されず、⌘⇧. や⌘⇧G で禁止対象を表示・指定する機能も開かない。hidden-link・package-link 経由でも内部へ入れない。
3. 直接入力での検索可否は既存 SearchRoot の規則のまま。隠し祖先という理由だけで新たに拒否しない。パッケージ自身の既存の拒否は維持する。

### 6. 確定時と検索時の再検証（AS7・AS12、EC-104）

1. 子で vanishing を選び、別のターミナルからその専用フォルダを移動して確定する。子は閉じず、理由が表示・読み上げられ、親の入力と既存エラーは変わらない。別の場所を選び直せ、取消でも親へ戻れる。
2. locked を選び、別のターミナルで次を実行して確定する。同じ拒否と復帰を確認後、必ず権限を戻す。

```bash
chmod 000 ~/MediaViewerFixtures/search-folder-picker/locked
# 確認直後に戻す
chmod 755 ~/MediaViewerFixtures/search-folder-picker/locked
```

3. 正常に確定した後、検索ボタンを押す前に同じ削除・権限変更を行う。今度は親の検証で拒否し、親を閉じず、新規検索を始めない。
4. 列挙・確定中の Esc で即座に子へ取消を指示でき、遅い完了で欄が変わったり子が再表示されたりしない。ボリュームを取り外したケースも記録する。

### 7. キーボードと VoiceOver（AS6・EC-105、SC-060）

1. マウスを使わず ⌘F、契約の Tab 順序、選択ボタンの Space、子の矢印・⌘↓・⌘↑、Return、親の検索まで5回完了する。⇧Tab も逆順に辿る。
2. システムのキーボードナビゲーションをオフにしても全ボタンへ止まる。空一覧でも取消・現在位置の確定へ到達できる。
3. 子での Return は選択だけ、Esc は子だけを閉じる。親へ戻った後の Esc は親を閉じ、既存検索は止めない。
4. VoiceOver で親ボタン、子の操作名、現在位置、フォルダ名、処理中、エラーを識別できる。確定・取消後は親の選択ボタンへ戻る。

### 8. 既存検索の継続と保存（AS13・FR-085・086）

1. many-folders で検索 A を開始し、検索中に ⌘F から子を開く。背後の途中件数・結果更新が続き、選択の確定・取消で停止・再開始・結果置換がないことを確認する。
2. 外部から専用フィクスチャの結果を移動し、子の表示中も既存の外部更新が反映されることを確認する。
3. 検索 B の無効条件では A が続き、有効条件で検索を開始したときだけ A が止まり B へ置換される。
4. 選択のみで子と親を閉じ、開き直すと起点が既存の既定値へ戻る。`defaults read local.my-img-viewer.MediaViewer` の最後のフォルダが選択操作で変わらない。アプリ再起動で選択起点・入力元・検索結果が復元されない。

### 9. 大量件数と処理中の操作

1. many-folders を子で開き、読み込み中表示・取消・別の入口への移動が応答することを確認する。
2. Instruments の Hangs 等で UI の 100ms 以上の停止がないか測り、端末・OS・件数・操作・最大停止時間を記録する。主スレッドでアプリの列挙・祖先検査・権限確認が走っていないことも確認する。
3. 既存の 10,000 件検索が3秒以内の性能テストを維持し、子を表示中の検索更新も観測する。検索が速く終わり AS13 を観測できなければ件数を増やした専用データで再試行し、観測できないまま合格にしない。
