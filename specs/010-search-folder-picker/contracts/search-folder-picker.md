# UI Contract: 検索起点フォルダの選択

本 feature の差分契約。既存は `specs/product/contracts/keyboard-and-menus.md`・`settings.md`、検索内容は product の search.md と `009-folder-search` を参照する。

## 親の検索シート（FR-081・142・144、US1-AS25）

- 「検索キーワード」は標準の検索フィールド（`NSSearchField`）、「検索起点ディレクトリ」は編集可能な1行のテキスト入力とし、その近くに「選択…」を置く。キーワード・起点の有効性に関わらず「選択…」は利用可能。初期位置の解決中・確定後の検証中・標準パネル表示中だけ無効にする。
- 起点の既定値は開いた時点で一覧に表示中のフォルダ。検索結果中は検索前、zip 内は zip を含むフォルダとする。EC-102 の一覧 F・ツリー V では F を使う。⌘F と「ファイル」メニューの「検索…」の双方で同じ規則を適用する（変更後の US1-AS25）。
- Tab は キーワード → 起点 → 選択… → キャンセル → 検索 → キーワード。⇧Tab は逆順。システムのキーボードナビゲーション設定によらずボタンへ止まる。
- 「選択…」は Space で開く。シートだけが表示中の Return は従来どおり検索、Esc は検索シートを閉じる。
- 開いたときのキーワードへのフォーカスと前回値の全選択は初回だけ。標準パネルから戻ると「選択…」へフォーカスする。
- 標準パネルの表示中は親を操作できない。パネルの Return・Esc はパネルだけに作用し、親の検索・取消を起動しない。
- 初期位置解決中も親の検索と Return は利用できる。空キーワードは無操作とし、それ以外の検索操作を受理した時点で保留中のパネル提示を失効させてから検索条件を検証する。確定後の検証中も検索を受理でき、その場合は選択結果を採用しない。
- 失効した初期位置の成功・失敗は、検索検証より先に返っても後に返ってもパネルを提示せず、親のエラーも変えない。検索失敗時は親を保ち理由を示す。旧依頼は復活せず、選択ボタンの再操作で新しい依頼を開始する。
- 確定後の検証中は「選択…」を無効にし、重複した選択操作を受け付けない。パネル表示中は検索・選択を拒否する。

## 標準フォルダ選択パネル（FR-141）

検索コントローラ自身が `NSOpenPanel` を親ウインドウのシートとして開く。`runModal` は使わない。

| 設定 | 値 |
|---|---|
| `canChooseFiles` | false |
| `canChooseDirectories` | true |
| `allowsMultipleSelection` | false |
| `canCreateDirectories` | false |
| `resolvesAliases` | true |
| `treatsFilePackagesAsDirectories` | false |
| `showsHiddenFiles` | false |
| `directoryURL` | 初期位置（下記） |
| `message` | 「検索起点にするフォルダを選択してください。」 |
| `prompt` | 「選択」 |

- 通常ファイル・zip・パッケージはフォルダとして選択できず、パッケージの内部へも移動できない。複数選択・新規作成・パス直接入力・ドロップ・最近の場所は提供しない。
- 隠し項目は標準パネルに従う。既定では非表示だが、ユーザーが ⌘⇧. で表示でき、隠しフォルダも選択できる。独自の表示切替・迂回防止は追加しない。
- サイドバー・アイコン・検索・表示切替・キーボード・VoiceOver・ダークモードは OS 標準のパネルに任せる。

## 初期位置（FR-143）

1. 現在の起点入力を FR-081 の入力元別規則で解釈した候補。
2. 検索シートを開いた時点に捕捉した、FR-081 の一覧基準の既定フォルダ。
3. ホーム。

各候補へ存在・フォルダ・読取り・パッケージ拒否を適用する。隠しフォルダは許可し、パッケージ・読み取り不能なフォルダは飛ばして次へ進む。
ルートと各ボリュームは標準パネルのサイドバーから選べるが、初期位置の追加フォールバックにはしない。
全滅ならパネルを開かず親に理由を表示・読み上げ、欄は保持する。EC-102 の F が無効なら現在入力と既定の F を飛ばし、ホームへ進む。
ツリーの V を追加候補にせず、取消でも親の F を保持する。

初期位置の解決中も親の検索は利用できる。空キーワードの無操作を除き検索操作を受理したら、パネル提示の依頼を失効させる。
検索検証に失敗しても旧依頼は復活させない。

## 確定・取消の境界（FR-142・EC-103〜106）

| 結果 | パネル | 親の起点・入力元 | キーワード・親の理由 |
|---|---|---|---|
| 確定検証成功 | 閉じる | 選択 URL の絶対パスで全体置換、picked にする | キーワード保持、古い起点理由だけ消す |
| 確定検証失敗 | 閉じる | 不変。無効な URL は反映しない | キーワード保持、失敗理由を新しく表示・読み上げる |
| 取消 | 閉じる | 不変 | すべて保持 |

確定時に対象が消失・非フォルダ・読取不能・パッケージなら拒否する。検証は UI スレッド外で行う。処理中は重複確定を防ぎ、取消はいつでも可能にする。
パネルを閉じた後に検証が終わるため、失敗時は親シートで理由を示して選び直させる。以前の起点理由は新しい失敗理由に置き換わる。

確定パスへ引用符やエスケープを加えない。`Photos ` の末尾空白は起点欄を編集しない間保持する。キーワード編集・パネルの再表示・取消では typed に戻さない。
起点を直接編集すると従来の trim・ホーム展開等へ戻る。検索開始時には入力元によらず再検証する。失敗は親へ表示し、新規検索を始めず、親を閉じない。

SC-058 の5ケースは、有効な検索開始が成立し、検索バーの起点と配下の既知の一致結果で選択場所を照合できれば合格とする。全走査の完了は要求せず、ルートを含め照合後の解除を許す。照合前に終了したケースは未確認とする。

## 既存検索・保存との関係

開く・確定・取消で検索・ツリー・一覧・プレビューを操作しない。既存検索の進行・途中件数・外部変更の反映は続ける。新しい検索の有効な開始時だけ FR-085 で置換する。

選択による設定保存・履歴記録・最後のフォルダ更新はない。入力元は検索シート内だけの状態。画面を閉じて開き直すと既存の起点既定値へ戻る。

## アクセシビリティと表示

親のボタンは「選択…」と読み上げ、検索シートは標準の検索フィールド・テキストフィールド・ボタンを使う。
標準パネルは OS のアクセシビリティ（画面名・場所・フォルダ名・処理中の表示・キーボード操作）に従う。
エラーは表示だけでなく announcementRequested で通知する。標準色・標準コントロールでダークモードと OS の設定を尊重する。
