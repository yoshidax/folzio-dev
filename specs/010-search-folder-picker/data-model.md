# Data Model: 検索起点フォルダの GUI 選択

本書の型・メソッドは実装予定の契約を示す。保存形式・外部 API は追加しない。

## 1. SearchRootInput（Core、値型）

| 状態 | 値 | 表示 | 解釈 |
|---|---|---|---|
| typed | 入力文字列 | 文字列そのもの | `SearchRoot.parse(text, home:)` の既存規則 |
| picked | フォルダ選択で確定した絶対 file URL | `url.path`、引用符・エスケープなし | 選択 URL をそのまま返す。trim しない |

- 初期状態は typed。picked は選択画面の検証成功からのみ作る。
- 起点欄のユーザー編集は常に typed にする。同じ文字列へ戻しても picked には戻さない。
- キーワード編集、子の取消・失敗・再表示は状態を変えない。
- `displayText` と `resolvedInput(home:)` 相当の読み出しを設ける。検索と初期表示の両方が同じ解釈を使う。
- 検索シートを閉じたら破棄。次に開くときは既存の既定値で初期化する。
- picked が持つ「選択した URL」と、検索検証が返す「リンク解決後の URL」は区別する。前者を欄へ表示し、後者を検索へ渡す。

## 2. SearchFolderAccess（Core、非同期の読取り処理）

アプリ独自の列挙・存在・種類・読取り・メタデータ確認を UI スレッド外で行う。操作は次の4つに絞る。具体的な関数の分割は実装で同じ責務を保つ。

| 操作 | 入力 | 出力 |
|---|---|---|
| 入口取得 | ユーザーのホーム | `/`・ホーム・表示可能なマウント済みボリュームの一覧 |
| 初期位置 | SearchRootInput、開始時既定パス、ホーム、入口 | 優先順で最初の利用可能 URL、または利用不可の理由 |
| フォルダ表示 | 現在位置、入口 | 表示可能な直下のフォルダ URL の配列、または列挙失敗 |
| 確定検証 | 選択 URL、入口 | 成功（選択 URL を保持）/ 理由 |

初期位置の検証失敗は次候補へ進む。全滅だけを親へ返す。候補を試す途中では欄・エラーを変更しない。入口の取得は位置の候補順を変えず、ルートを追加の初期位置候補にはしない。

### GUI 到達可否

- 対象は存在する読取り可能なフォルダである。通常ファイル・zip・パッケージは確定対象外。
- 対象と GUI の入口までの経路に隠し項目・パッケージを含まない。名前の `.` だけでなく `isHidden` と `isPackage` を用いる。
- ホームは隠し祖先を迂回する入口にしない。マウント済みの非隠しボリュームは独立した入口として扱い、マウント用ディレクトリの属性でボリューム自体を誤拒否しない。
- シンボリックリンクは表示経路と解決先の両方を調べ、禁止対象への迂回を拒否する。到達可能性を確定できない経路は拒否する。
- `DirectoryLister.subfolders` の結果へこの表示制限を適用する。通常の一覧や直接入力の `SearchRoot.validate` の意味は変えない。
- 同じ一覧取得内では共通祖先の検査結果を共有し、各行について同じ祖先をディスクから読み直さない。確定・別の移動では新しく検査する。永続的な可否キャッシュは作らない。

### 理由

既存の `SearchRootError`（notFound・notAFolder・accessDenied 等）を再利用し、GUI の対象外、初期位置なし、列挙失敗を区別できる小さな理由型を加える。すべて表示・読み上げ用のメッセージを持つ。

| 発生箇所 | 表示先 | 影響 |
|---|---|---|
| 初期位置が全滅 | 親の起点欄付近 | 子は開かない。入力元・文字列を保持し、直接入力・再試行可能 |
| 移動・一覧取得失敗 | 子 | 親は不変。別の場所・親への移動と取消を残す |
| 確定失敗 | 子 | 子を閉じない。親の入力・既存エラーを保持 |
| 検索開始時の再検証失敗 | 親の起点欄付近 | 親を閉じず、新規検索を始めない |

## 3. SearchFolderPickerState（Core、値型）

| フィールド | 内容 |
|---|---|
| locations | 利用可能な入口の値（URL・表示名・種類）。永続化しない |
| currentDirectory | 現在表示している場所。入力欄とは独立 |
| children | 直下の表示可能なフォルダだけ。名前順、単一選択 |
| selectedDirectory | 行で選択中の URL、未選択なら nil |
| phase | loading / ready / validating / failed / closed |
| generation | 非同期処理の世代。対象 URL と組にして結果を照合 |
| reason | 子で表示する理由、なければ nil |

確定対象は `selectedDirectory ?? currentDirectory`。行を選んだだけでは内部移動・確定しない。新しい現在位置へ移ったら行選択を解除する。`/` と空フォルダは未選択状態の現在位置として確定できる。

### 遷移

| イベント | 状態変更 | 完了時の条件 |
|---|---|---|
| 開く・移動 | 世代を進め loading、古い行・選択・理由を除く | 同じ世代・現在位置なら children を採用して ready |
| 行選択 | selectedDirectory を更新。古い確定を失効して ready へ戻す | 表示対象に含まれる1行だけ。旧検証の終了を待たず再確定できる |
| 確定 | 対象・世代を捕捉して validating | 同じ世代・対象・開いている状態の成功だけを返す |
| 確定失敗 | ready に戻し reason を設定 | 行・現在位置を保ち、再試行・移動・取消を許可 |
| 列挙失敗 | failed、理由を設定 | 古い行を使わず、移動・取消は残す |
| 取消 | 世代を失効して closed | 遅い成功・失敗はすべて無視。選択結果を返さない |
| 確定成功 | closed | 成功を一度だけ親へ返す |

Task の cancel は補助とし、世代照合を省かない。処理中の二重確定・二重提示を拒否する。確定検証中でも行選択の変更・移動・取消は可能にし、変更時は ready、移動時は loading に遷移させる。古い完了を無視した結果 validating に取り残されないことをテストする。列挙の完了順を変えたテスト、取消後の成功、移動後の旧確定、同じ URL へ再移動した後の旧結果も検証する。

## 4. 親の入力と表示の一時状態

`SearchPanelInputState` は SearchRootInput.swift 内に置く小さな Core の値型とする。rootInput、keyword、revision、isActive に加え、pendingOperation（idle / resolvingPicker / validatingSearch）と requestGeneration を持つ。編集・選択成功で revision を進め、終了で失効させる。処理開始・失効で requestGeneration を進め、完了は捕捉した revision・requestGeneration・処理種別と isActive がすべて一致した場合だけ採用する。判断を App の通知ハンドラだけへ埋め込まず、自動テストする。

App は次を保持し、編集通知と操作を Core へ渡して表示へ反映する。

| 値 | 役割 |
|---|---|
| initialRootPath | 開いた時点で一覧に表示中のフォルダの既定パス。変更しない。検索結果中は検索前、zip 内は zip を含むフォルダ。EC-102 では一覧の F |
| inputState | Core の親入力状態。欄と同時に更新 |
| pickerRequestGeneration | Core が発行した初期位置解決の依頼世代を捕捉する。重複・取消後・検索受理後の提示を防ぐ |
| childPresented | 子が開いている間の親アクションを防御 |
| initialFocusApplied | 初回だけキーワードへフォーカスし全選択する |

initialRootPath は後からツリーの選択へ問い合わせない。EC-102 の F が隠し・パッケージの内部なら、現在入力と既定の F は GUI 到達可否で落とし、次のホームへ進む。ツリーの V は追加候補にしない。取消後も親の F は変えない。
FR-081 と変更後の US1-AS25 は、この initialRootPath と親の起点欄が一覧基準で初期化されることを共通の受け入れ条件とする。

親の処理と子の提示は、MainActor 上で次の順序で受理・反映する。App は childPresented を親アクションの受理判定の入力として Core へ渡し、Core の判定に従って提示と検索を防御する。これにより子が先に提示済みの順序も AppKit なしでテストできる。

| イベント | 先に行う遷移 | 完了・後続操作の扱い |
|---|---|---|
| 選択要求（idle） | requestGeneration を進め resolvingPicker、入力と依頼世代を捕捉 | 一致する成功だけを提示し idle に戻して childPresented を立てる。全滅なら親に理由を示して idle |
| 初期位置解決中の検索受理 | 旧提示依頼を失効させ requestGeneration を進め validatingSearch、その後に検索条件の検証を開始 | 旧解決の成功・失敗は無視。Task.cancel は補助とする。空キーワードは従来どおり無操作で失効もしない |
| 検索検証完了 | 有効な成功なら親を終了して onSearch を一度だけ呼ぶ。失敗なら理由を示して idle | 失敗でも旧提示依頼は復活させない。選択の再試行には新しい依頼世代を発行する |
| 検索検証中の選択・重複検索 | 受理しない | 選択ボタンを無効とし、アクション側も防御 |
| 子を提示済みの親検索・取消 | 受理しない | childPresented を確認する。子のキーを親へ伝播しない |
| 親の起点・キーワード編集、終了 | 入力/依頼世代を失効させ idle、終了では isActive も false | 古い成功・失敗を表示に使わない |

検索受理後について、初期位置解決→検索検証、検索検証→初期位置解決の両完了順を検索成功・失敗、初期位置解決成功・失敗それぞれでテストする。子提示0回、旧解決による理由上書き0回、有効な検索成功だけ onSearch 1回（失敗は0回）を期待する。Core テストでは提示・理由・検索成功の採用回数を数え、App が採用成功だけを onSearch へ接続する境界も確認する。検索失敗後の再試行へ旧完了を混ぜても採用しない。逆に初期位置解決の採用と子提示が検索アクションより先なら、親検索が拒否されることも固定する。

子の取消は rootInput・キーワード・親の理由を変更しない。子の確定成功は rootInput を picked にし、欄の全体を置換して古い起点理由だけを消す。

## 5. 既存状態との関係

子は `BrowserModel` を参照しない。親も選択の開閉では startSearch・検索解除・ツリー同期・履歴記録・設定保存を呼ばない。既存検索と外部変更の更新は独立して続く。新しい検索の再検証が成功したときだけ既存 onSearch に渡し、FR-085 の置換を行う。
