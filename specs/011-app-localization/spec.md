# Feature Specification: 日本語・英語への国際化

**Feature Branch**: `011-app-localization`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "MediaViewerを、Apple標準の仕組みに沿って国際化し、日本語・英語に対応させたい。目的: macOSの言語・地域設定に自然に従うアプリにする。今後の言語追加を、主に翻訳リソースの追加で行える構造にする。（以下、言語と地域・翻訳対象・文字列と表示形式・ビルドとリソース・UIと既存動作・検証と文書・受け入れ条件の各要望。全文は `/speckit-specify` の入力のとおり）"

本仕様は `specs/product/` に対する差分である。基準は FR-040・FR-041（overview.md）、メニュー・ツールバー・確認モーダル・衝突ダイアログ・
検索モーダルの表示名とキー操作（contracts/keyboard-and-menus.md）、設定ウインドウの項目と保存キー（contracts/settings.md）、
アプリバンドルの構成（contracts/app-bundle.md）、倍率のアクセシビリティ値（FR-138（preview.md））、検索結果の表示（FR-084（search.md））とする。

現在のアプリは、UI の文言をすべて日本語で持つ。Core（`MediaViewerCore`）も、エラーの理由・種類名のフォールバック（「フォルダ」「ZIP アーカイブ」）・
種類フィルタの空状態・名前と検索起点の検証メッセージ・zip の読み込みエラーを日本語の文字列として UI へ渡している。
本変更では、アプリが管理する表示文言を日本語・英語の2言語で持つ。表示言語はアプリの設定で選び、初期値は英語とし、変更を即時反映する。日時と数値の書式は地域設定に従わせる。
既存の操作・有効条件・ショートカット・保存内容・ファイル操作の結果は変えない。既存仕様に書かれた日本語の表示名は、日本語の表示名として
そのまま有効とする。英語の表示名は、新しい契約 `contracts/localization.md` の用語対応表で定める（FR-152）。

新規 ID は正本全領域と既存 feature の使用済み ID（FR-144・SC-060・EC-106・A-86・US16 まで）の次から振る。

## Clarifications

### Session 2026-10-28（ユーザーによる仕様変更）

- Q: 表示言語は何で決め、いつ反映するか? → A: アプリの設定で対応言語を選ぶ。初期値は英語とし、選択を保存して即時反映する。macOS の言語設定や優先言語で選ばない。
- Q: 選択した言語の翻訳が一部欠けた場合はどう表示するか? → A: 英語で表示し、翻訳の欠けは出荷前の自動テストで検出する。

### Session 2026-10-28（非対話の実行。推奨回答を採用）

- Q: 英語の表示名は何を基準に決めるか? → A: macOS の Finder・標準アプリの英語表記に合わせる（例: 「ゴミ箱に入れる」→ Move to Trash、
  「移動ペースト」→ Move Item Here）。README.md の英語版で使っている英訳と異なる場合は、アプリ側に合わせて README.md を直す。
  日本語の表示名は現行の文言を変えない（件数の桁区切りなど、書式の要件で変わる部分を除く）。
- Q: 表示言語と地域設定が異なる場合（英語 UI と日本の地域など）、日時の書式はどうするか? → A: macOS 標準の組み合わせに従う。
  日付と時刻の並び・区切り・12／24時間表示・数値の桁区切りと小数点は地域設定（と「日付と時刻」の書式設定）に、月名などの語は表示言語に従う。
- Q: 「複製」の「名前 2」と衝突時の「両方残す」で作るファイル名は、表示言語で変えるか? → A: 変えない。どの言語でも現行と同じ名前を作る
  （FR-018（file-operations.md））。ファイル名はユーザーデータであり、言語を変えて起動し直しても同じ結果にする。
- Q: OS が返す文言（種類名・ファイル操作の失敗理由など）はどう扱うか? → A: OS の翻訳をそのまま使い、アプリでは訳し直さない。
  それを埋め込むアプリ側の文（例:「既存の項目をゴミ箱へ移動できませんでした: <理由>」）は表示言語で出す。
- Q: 長いキーワード・パス・フォルダ名を含む文が最小幅に収まらない場合は? → A: ユーザーデータを含む動的な文は省略記号で切り詰めてよい。
  全文はツールチップとアクセシビリティで得られるようにする。固定の操作文言（メニュー項目・ボタン・チェックボックス・列見出し・設定のラベル）は欠けてはならない。
- Q: 起動中に地域設定（日付の書式・24時間表示など）を変えた場合は? → A: 起動中の即時追従は求めない。遅くとも次回起動から反映する。
- Q: バンドルを持たない開発時の起動（`swift run`）でも翻訳されるべきか? → A: 翻訳の保証対象は配布用 `.app` とする。`swift run` では、少なくとも
  内部キーを表示せず、クラッシュせず、いずれかの対応言語の文言で表示する。
- Q: 名前・場所の並べ替え（FR-012（file-list.md）の Finder と同じ自然順）は、表示言語・地域によって順が変わってよいか? → A: 変わってよい。
  Finder と同じく macOS 標準の比較に従い、一部の文字の前後は言語・地域で変わりうる。数字を数値として比べる自然順はどの言語・地域でも保つ。
  検索の一致判定（FR-082（search.md））と zip の中の名前の文字コードの判定（FR-074（zip.md））は表示言語・地域によって変えない。
- Q: OS が提供する文言（標準パネル・テキスト編集のメニュー・種類名など）はどう扱うか? → A: OS の決定に従い、「混在0件」などの判定はアプリが管理する文言だけを対象にする。
- Q: 訳の欠け・値の数の不一致などを見つける自動検証は、Phase の検証ゲートのどこで実行するか? → A: `swift test` で実行するテストに含める。
  ゲートの手順（AGENTS.md）は増やさず、`swift test` が通れば訳の欠けが0件であることを示す。

## User Scenarios & Testing *(mandatory)*

### User Story 17 - 英語環境のユーザーが英語の UI で操作する (Priority: P1)

英語の表示言語を使うユーザーは、メニュー・右クリックメニュー・ツールバーのツールチップ・
設定ウインドウ・列見出し・検索モーダル・空状態・確認モーダル・衝突ダイアログ・エラーを英語で読む。操作の内容・ショートカット・有効条件は日本語のときと同じである。

**Why this priority**: 英語で使えることがこの変更の中心的な価値であり、日本語を読めない利用者がアプリを使い始める前提になる。

**Independent Test**: 表示言語を英語にして配布用 `.app` を起動する。メニューバーの全メニュー、ツリーとファイルリストの右クリックメニュー、ツールバー、
設定ウインドウ、検索モーダル（検証エラーを含む）、ファイル操作の確認モーダルと衝突ダイアログ、空のフォルダ・種類フィルタで0件の一覧、
表示できないファイルのプレビュー、壊れた zip を順に表示し、日本語・内部キー・置換されていないプレースホルダが出ないことを確かめる。

**Acceptance Scenarios**:

1. **US17-AS1**: **Given** 表示言語が英語, **When** アプリを起動してメニューバーの各メニューを開く,
   **Then** アプリが管理する項目名はすべて英語で表示される。項目の並び・区切り線・ショートカット・チェックマーク・有効／無効は日本語のときと同じである。
2. **US17-AS2**: **Given** 英語で起動している, **When** ファイルを1つ選んで右クリックし、続けて3つ選んで右クリックする,
   **Then** コピーの項目はファイル名を含む1件用の文（例: Copy "photo.jpg"）と、件数を含む複数件用の文（例: Copy 3 Items）で表示される。
   ファイル名は翻訳・変形されない。
3. **US17-AS3**: **Given** 英語で起動している, **When** 複数のファイルをゴミ箱に入れる操作を確認モーダル付きで行い、続けて同名のファイルがある場所へコピーする,
   **Then** 確認モーダルの見出し・件数・フォルダを中身ごと操作する旨・ボタン・「今後この確認を表示しない」と、衝突ダイアログの
   「置き換える」「両方残す」「中止」「残りすべてに適用」に当たる文言が英語で表示される。既定ボタン・Esc の動作・操作結果は日本語のときと同じである。
4. **US17-AS4**: **Given** 英語で起動している, **When** ⌘F で検索モーダルを開き、存在しない起点パスで検索し、次に有効な起点で検索する,
   **Then** 入力欄のラベル・ボタン・検証エラーの理由・検索中の表示・検索バーの文（キーワード・起点のフォルダ名・件数を含む）が英語で表示される。
   キーワードとフォルダ名はユーザーが入力・作成したとおりに表示される。
5. **US17-AS5**: **Given** 英語で起動している, **When** ⌘, で設定ウインドウを開く,
   **Then** 区分の見出し・チェックボックス・切り替え間隔の単位・切り替え効果の選択肢が英語で表示され、変更の保存と反映は日本語のときと同じに行われる。
6. **US17-AS6**: **Given** 英語で起動している, **When** 空のフォルダ、種類フィルタで0件になるフォルダ、壊れた画像、暗号化された zip の中の画像を順に表示する,
   **Then** 空状態のメッセージ、プレビューのエラー、zip のエラーの理由がすべて英語で表示される。
7. **US17-AS7**: **Given** 日本語で起動して設定・お気に入り（表示名付き）を変更した, **When** アプリの設定で表示言語を英語に変更する,
   **Then** 保存した設定・お気に入りの登録と表示名・最後のフォルダ・ツールバーの表示状態はすべてそのまま復元される。お気に入りの表示名は翻訳されない。

### User Story 18 - 設定で表示言語を切り替える (Priority: P1)

利用者は、既定の英語からアプリの設定で日本語へ切り替え、再起動せずに日本語の UI を使う。選択は次回起動にも引き継がれる。
配布用 `.app` をどこに置いても、翻訳が失われない。

**Why this priority**: 国際化によって既存の日本語の利用者の体験を壊さないこと、対応外の言語で文言が欠けないことは、英語対応と同じく必須である。

**Independent Test**: 新規設定で英語が表示され、設定で日本語・英語を切り替えると各画面に即時反映されること、再起動後も選択が復元されることを確かめる。

**Acceptance Scenarios**:

1. **US18-AS1**: **Given** 表示言語に日本語を選んだ, **When** アプリの画面を見る,
   **Then** アプリが管理する文言は日本語で表示され、既存仕様（contracts/keyboard-and-menus.md・contracts/settings.md ほか）に書かれた日本語の表示名と一致する。
2. **US18-AS2**: **Given** 保存された表示言語がない, **When** アプリを起動する,
   **Then** アプリが管理する文言は英語で表示され、内部キーや日本語との混在はない（OS が提供する文言の言語は EC-111 に従う）。
3. **US18-AS3**: **Given** 英語で表示中, **When** 設定で日本語を選ぶ, **Then** 再起動せずアプリの文言が日本語に変わる。
4. **US18-AS4**: **Given** 日本語で表示中, **When** 設定で英語を選ぶ, **Then** 再起動せずアプリの文言が英語に変わる。
5. **US18-AS5**: **Given** 配布用 `.app` を作った後、ビルドディレクトリの外へコピーし、元のビルドディレクトリを移動または削除した,
   **When** コピーした `.app` を英語・日本語のそれぞれで起動する, **Then** どちらも翻訳された文言で表示され、内部キーは表示されない。
6. **US18-AS6**: **Given** 設定で言語を選択した, **When** アプリを終了して起動し直す,
   **Then** 選択した言語が復元される。OS の優先言語やアプリごとの言語指定では選択が変わらない。

### User Story 19 - 表示言語とは別の地域設定で日時と数値を読む (Priority: P2)

日本に住み英語の UI を好むユーザーは、英語の UI のまま、作成日・件数・倍率を日本の地域設定の書式で読む。逆の組み合わせも同じに扱う。

**Why this priority**: 言語と地域を分けて扱えることは macOS の標準的な期待だが、文言の翻訳（US17・US18）が先に成立している必要があるため P2。

**Independent Test**: 表示言語を英語、地域を日本にして起動し、リスト形式の「作成日」列・検索結果の件数（1,000件以上）・倍率の読み上げを確かめる。
次に表示言語を日本語、地域を米国・ドイツにして同じ箇所を確かめる。24時間表示の設定を切り替えて起動し直したときの時刻の表示も確かめる。

**Acceptance Scenarios**:

1. **US19-AS1**: **Given** 表示言語が英語で地域が日本, **When** リスト形式で作成日の列を見る,
   **Then** 列見出しは英語で、日付と時刻は日本の地域設定の並び・区切り・時刻表記で表示される。
2. **US19-AS2**: **Given** 表示言語が日本語で地域が米国, **When** リスト形式で作成日の列を見る,
   **Then** 列見出しは日本語で、日付と時刻は米国の地域設定の並び・区切り・12時間表記で表示される。
3. **US19-AS3**: **Given** 地域がドイツ, **When** 1,000件以上の一致がある検索を行い、画像を125%に拡大する,
   **Then** 検索バーの件数はドイツの桁区切りで表示され、倍率のアクセシビリティ値と読み上げはドイツの割合の書式に従う。
4. **US19-AS4**: **Given** システム設定で24時間表示を切り替えた, **When** アプリを起動し直す, **Then** 作成日の時刻はその設定に従う。
5. **US19-AS5**: **Given** 地域が日本以外（桁区切りを使う地域を含む）, **When** 設定ウインドウで切り替え間隔を表示・入力する,
   **Then** 値は桁区切りなしの整数で表示され、入力の解釈（半角・全角の数字、1〜3600）は地域によらず従来と同じである（contracts/settings.md）。

### User Story 20 - VoiceOver の利用者が両言語で操作する (Priority: P2)

VoiceOver を使うユーザーは、表示言語に合わせた言語で、ツールバーのボタン・入力欄・ペイン・設定項目のラベル、倍率などの値、エラーや倍率変更の読み上げを聞く。

**Why this priority**: アクセシビリティは憲章 原則 III の必須事項だが、画面の文言（US17・US18）と同じ翻訳の上に成り立つため P2。

**Independent Test**: 英語と日本語のそれぞれで VoiceOver をオンにし、ツールバーの各ボタン、検索モーダルの入力欄と「選択…」、設定ウインドウの切り替え間隔・繰り返し・効果、
お気に入りとフォルダの名前の編集欄、プレビューの倍率を順に読み上げさせ、検索起点の検証エラーと倍率の変更の読み上げを確かめる。

**Acceptance Scenarios**:

1. **US20-AS1**: **Given** 英語で起動して VoiceOver がオン, **When** ツールバーの各ボタンとスライダーへ移る,
   **Then** 各項目のラベルとヘルプが英語で読み上げられ、ショートカットの表記はツールチップと同じである。
2. **US20-AS2**: **Given** 英語で起動して VoiceOver がオン, **When** 検索起点に存在しないパスを入れて検索する,
   **Then** 検証エラーの理由が英語で読み上げられる。日本語で起動した場合は日本語で読み上げられる。
3. **US20-AS3**: **Given** 画像を表示中で VoiceOver がオン, **When** 拡大する,
   **Then** 新しい倍率が地域設定の割合の書式で読み上げられ、プレビューのアクセシビリティ値も同じ書式になる（FR-138（preview.md））。

### Edge Cases

- **EC-107**: 保存済みの表示言語がない場合や保存値が対応言語でない場合は英語を使う。OS の言語設定・優先言語は表示言語の選択に使わない。
- **EC-108**: アプリの設定で言語を変更したときは即時反映する。地域設定の変更への起動中の即時追従は求めず、遅くとも次回起動から反映する。
- **EC-109**: ファイル名・フォルダ名・パス・お気に入りの表示名・検索キーワード・zip の中の名前に、別の言語の文字・右から左へ書く文字・
  書式指定に似た文字列（`%@`・`%d`・`{0}` など）が含まれていても、文字どおりに表示する。書式として解釈したり、翻訳・置換したりしない。
- **EC-110**: 表示言語の訳が見つからない項目があっても、内部キー・識別子・空欄を表示しない。英語の訳で表示する。訳の欠けは出荷前の自動検証で検出する（FR-157）。
- **EC-111**: OS が返す種類名・エラー理由・標準パネルの文言は、OS の翻訳をそのまま表示する。アプリの文の中に埋め込む場合も、埋め込んだ部分を訳し直さない。
  OS が提供する文言の言語は OS の決定に従い、アプリの表示言語と異なる場合もある。
- **EC-112**: 言語を変えて起動し直しても、保存済みの設定・お気に入り・並べ替えの列と方向・最後のフォルダは変わらない。「種類」での並べ替えは
  表示中の種類名で行うため、言語によって並び順が変わってよい。名前・場所の並べ替え（FR-012（file-list.md）の Finder と同じ自然順）は macOS 標準の比較に従い、
  表示言語・地域によって一部の文字（アクセント付きの文字・かなと英字の前後など）の順が変わってよい。数字を数値として比べる自然順は、どの言語・地域でも保つ。
  検索の一致判定（大文字小文字・濁点の扱い、FR-082（search.md））と zip の中の名前の文字コードの判定（FR-074（zip.md））は、表示言語・地域によって変えない。
- **EC-113**: 「複製」と衝突時の「両方残す」で作るファイル名は、表示言語によらず同じになる（FR-018（file-operations.md））。
- **EC-114**: 件数が0件・1件・2件以上・1,000件以上のいずれでも、各言語の文法に合った文で表示する。0件で専用のメッセージがある箇所
  （検索の「該当する項目はありません」、種類フィルタの空状態など）は、そのメッセージを使う。
- **EC-115**: キーワード・起点のフォルダ名・ファイル名を含む文が最小幅に収まらない場合は、省略記号で切り詰めてよい。
  全文はツールチップとアクセシビリティで得られるようにする。固定の操作文言は切り詰めない。
- **EC-116**: 作成日を取得できないファイルの「作成日」列は、どの言語でも現行と同じ記号（`--`）を表示する。

## Requirements *(mandatory)*

### Functional Requirements

#### 追加: 表示言語の決定

- **FR-145**: システムは日本語と英語を対応言語とし、アプリの設定ウインドウで表示言語を選べるようにしなければならない。
  初期値は英語とする。選択は保存し、次回起動時に復元する。macOS の言語設定や優先言語から表示言語を決めない。
  設定の変更は再起動なしで、開いている設定ウインドウを含むアプリ管理の表示文言に即時反映しなければならない。
  言語を変えても現在の表示や操作状態を維持する。

#### 追加: 翻訳の範囲

- **FR-146**: システムは、アプリが管理し画面に表示するすべての文言を、表示言語で表示しなければならない。対象は次のとおりとし、実装時に棚卸しして漏れなく扱う。
  メニューバー（アプリ・ファイル・編集・表示・移動の各メニューと、状態で変わる項目名（ツールバーを表示／隠す、ゴミ箱に入れる／お気に入りから削除など））、
  ツリーとファイルリストの右クリックメニュー、ツールバーの項目名・ツールチップ、設定ウインドウ（区分・チェックボックス・単位・選択肢・ウインドウ名）、
  リスト形式の列見出し、検索モーダル（ラベル・プレースホルダ・ボタン・検証エラー）と検索バー、空状態のメッセージ、プレビューのエラー表示、
  確認モーダル・衝突ダイアログ・お気に入りの削除の確認、名前の検証エラー、ファイル操作の失敗の表示、zip のエラー、
  アクセシビリティのラベル・値・ヘルプ・読み上げ。Core から UI へ渡るエラーの理由・種類名のフォールバック（フォルダ・zip ファイル）・
  種類フィルタの空状態のメッセージ・検証メッセージも含む。切り替え後、アプリが管理する文言に表示言語以外の言語を混在させてはならない。
- **FR-147**: システムは、次のものを翻訳・変形してはならない。ファイル名・フォルダ名・パス・お気に入りの表示名・検索キーワード・zip の中の名前などのユーザーデータ、
  アプリ名「MediaViewer」、キーボードショートカットの表記。ログ・内部識別子・表示言語の選択を除く保存キーとその値（contracts/settings.md）・履歴の内容は表示言語に依存させず、翻訳の対象外とする。
  OS が提供する文言（ファイルの種類名、OS が返すエラーの理由、標準のフォルダ選択パネル・動画コントロール・テキスト編集のメニューなど）は
  OS 標準の翻訳を使い、アプリで訳し直さない。
- **FR-148**: システムは、保存・読み込み・ファイル操作・並べ替えの列の選択・有効条件の判断・履歴に、表示用の訳した文言を使ってはならない。
  表示言語を変えて起動し直しても、保存内容・作成するファイル名（FR-018（file-operations.md）の「名前 2」と衝突時の「両方残す」を含む）・
  操作の結果・検索の一致判定は変わらない。

#### 追加: 動的な文と複数形

- **FR-149**: 値（件数・ファイル名・フォルダ名・キーワード・パス・理由・倍率など）を含む文は、文全体を1つの翻訳単位とし、値の位置を訳ごとに変えられなければならない。
  文の断片をつなぎ合わせて文を作ってはならない。翻訳単位には、翻訳者が使われる場所と値の意味を判断できる文脈の説明を付ける。
- **FR-150**: 件数を含む文は、表示言語の複数形の規則に従わなければならない。英語では1件と2件以上（0件を含む）で語形を変え、日本語では語形を変えない。
  対象は少なくとも、検索バーの件数、コピーの項目名（複数選択時）、確認モーダルの対象の件数、その他件数を表示するすべての文とする。
  件数の数字は FR-151 の数値の書式で表示する。0件で専用のメッセージを持つ箇所はそれを使う（EC-114）。

#### 追加: 日時と数値の書式

- **FR-151**: システムは、日時・数値を、表示言語と区別した地域設定に従って表示しなければならない。日付と時刻の並び・区切り・12／24時間表示・
  数値の桁区切りと小数点・割合の記号の位置は地域設定（と「日付と時刻」の書式設定）に、月名などの語は表示言語に従う。対象は次のとおりとする。
  リスト形式の「作成日」（日付は中程度、時刻は短い形式という現行の詳しさを保つ）、検索バーなどの件数、プレビューの倍率のアクセシビリティ値と読み上げ（FR-138（preview.md））、
  その他、実装時の棚卸しで見つかった日時・数値・割合の表示。設定ウインドウの切り替え間隔は桁区切りなしの整数で表示し、入力の解釈は従来どおりとする（contracts/settings.md）。
  ファイルサイズは現行の UI に表示箇所がないため、本変更で表示を追加しない。地域設定の起動中の変更への即時追従は求めない（EC-108）。

#### 追加: 既存仕様の表示名

- **FR-152**: 既存仕様（`specs/product/` の各領域と契約）に書かれた日本語の表示名・文例は、日本語の表示名として扱わなければならない。
  動作・並び・有効条件・ショートカットは表示言語によらず同じとし、英語の表示名は新しい契約 `contracts/localization.md` の用語対応表で定める。
  英語の表示名は macOS の Finder・標準アプリの英語表記（メニュー項目とボタンは各語の頭文字を大文字にする書き方、ダイアログを開く項目は末尾に「…」）に合わせる。
  日本語の表示名は、FR-150・FR-151 の書式で変わる部分を除き、本変更の前と同じとする。

#### 追加: 表示の配置

- **FR-153**: 日本語・英語の両方で、ウインドウの最小サイズと各ペインの最小幅（FR-002（window-layout.md））のとき、メニュー項目・ボタン・チェックボックス・
  設定のラベル・リスト形式の既定の列幅での列見出し・空状態のメッセージは欠けずに読めなければならない。確認モーダル・衝突ダイアログ・検索モーダル・設定ウインドウは、
  文言の長さに合わせて大きさや折り返しを調整し、すべての文とボタンを読めるようにする。ユーザーデータを含む動的な文は EC-115 に従い切り詰めてよい。
  ウインドウとペインの最小サイズは変えない。本変更で追加・変更する配置は、左右の固定ではなく文字の流れの先頭側・末尾側で指定し、将来の右から左へ書く言語の対応を妨げない
  （右から左へ書く言語の翻訳と全体の動作保証は範囲外）。

#### 追加: アクセシビリティ

- **FR-154**: アクセシビリティのラベル・値・ヘルプ・読み上げは、表示言語で提供しなければならない（憲章 原則 III）。既存仕様で定めたラベル
  （例: 「切り替え間隔（秒）」「お気に入りの名前」「フォルダの名前」、ツールバーの各項目名）は日本語の表示名とし、英語の表示名は FR-152 の用語対応表に従う。
  値と読み上げに含む数値は FR-151 の書式に従う。

#### 追加: 配布と言語の追加

- **FR-155**: 配布用 `.app` は、翻訳と表示言語の決定に必要なものをすべて自分の中に含まなければならない。`.app` をビルドディレクトリの外へ移し、
  ビルドディレクトリがない状態で起動しても、両言語の文言を表示できること。開発時のバンドルを持たない起動（`swift run`）では、少なくとも内部キーを表示せず、
  クラッシュせず、いずれかの対応言語の文言で表示する。Core はウインドウやメニューの部品に依存せず（AppKit を使わず）、全機能のオフライン動作（FR-041（overview.md））を保つ。
- **FR-156**: 表示言語の決定・複数形・日時と数値の書式は、言語ごとの分岐をアプリの判断ロジックに持ってはならない。
  新しい言語の追加は、主にその言語の翻訳と対応言語の宣言を加えることで行えるようにする。
- **FR-157**: すべての翻訳単位は日本語と英語の訳を持たなければならない。訳の欠け・使われていない翻訳単位・値の数や種類が元の文と合わない訳を、
  自動検証で検出できなければならない。翻訳単位の取得・訳の欠けへの対応・値を含む文・複数形（0件・1件・2件以上）・表示言語と地域の組み合わせの書式は、
  自動テストで確かめる。これらの自動検証は `swift test` で実行するテストに含め、Phase の検証ゲート（AGENTS.md）の手順を増やさない。

### Key Entities *(include if feature involves data)*

- **表示言語**: アプリの設定で選択・保存する、アプリが管理する文言の言語（日本語または英語）。初期値は英語で、変更は即時反映する
- **地域設定**: 日時・数値・割合の書式を決める macOS の設定。表示言語とは独立して組み合わせられる
- **翻訳単位**: 画面に表示する1つの文言。識別子・翻訳者向けの文脈の説明・各言語の訳・値の位置・件数による語形の違いを持つ
- **用語対応表**: 既存仕様の日本語の表示名と英語の表示名の対応。メニュー・ボタン・設定・ダイアログ・アクセシビリティのラベルの英語名の正本とする
  （`contracts/localization.md`）

## Assumptions

- **A-87**: 初回の対応言語は日本語と英語だけとする。ほかの言語の翻訳、右から左へ書く言語の翻訳と全体の動作保証は範囲外とする。

  日本語の表示名は現行の文言を変えない。
- **A-89**: 翻訳の管理は Apple 標準の String Catalog を第一候補とする。このリポジトリの Swift Package と `swift build` での抽出・コンパイル・リソースの参照の可否は
  plan で調査し、実際に動作する手順を plan に記録する。直接扱えない場合は、`.strings`・`.stringsdict` などの標準形式を含む代替案を比べ、
  管理元と生成物の関係（どれを編集し、どれを生成し、どれをコミットするか）を plan で明確にする。Xcode プロジェクトへの移行と外部パッケージの追加は行わない。
  Package.swift・リソースの同梱・Info.plist・`scripts/make-app.sh` を一貫させ、その結果を contracts/app-bundle.md へ反映する。
- **A-90**: 地域設定の起動中の変更への即時追従は範囲外とする。アプリの表示言語の変更は即時反映する（EC-108）。

  GUI の起動と目視確認はユーザーに依頼する（AGENTS.md の Phase の検証ゲート）。未実施の GUI 確認を完了扱いにしない。
- **A-92**: README.md と README.ja.md には、対応言語（日本語・英語）、既定の英語、アプリの設定での切り替えと即時反映を同じ内容で書く。README.md の「UI は日本語のみ」という記述と、英訳の後に日本語の表示名を括弧で添える書き方は、
  英語の UI に合わせて見直す（AGENTS.md の「README の英語版と日本語版」に従い、両方を同じコミットで直す）。
- **A-93**: 現行の UI にはファイルサイズの表示がないため、本変更では追加しない（憲章 原則 V）。日時・数値・割合の表示箇所の棚卸しは plan で行う。
