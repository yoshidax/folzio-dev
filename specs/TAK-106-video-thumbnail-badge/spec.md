# Feature Specification: 動画のサムネイルに動画を示すバッジを重ねる

**Feature Branch**: `claude/awesome-franklin-05nex3`（Cloud が指定した作業ブランチ。feature ディレクトリとは独立）

**Created**: 2026-11-21

**Status**: Draft

**Input**: [TAK-106](https://linear.app/takyoshida/issue/TAK-106)「動画のサムネイルに動画を示すアイコンを重ねて表示する」。
ファイルリストのサムネイル形式で、動画ファイルのサムネイルの右下に、動画を表す透過アイコンを重ねて表示し、
代表フレーム（FR-013（file-list.md））だけでは画像と見分けにくい動画を見分けやすくする。
Issue の検討事項（小さいサムネイル（FR-014（file-list.md）の 48pt 付近）での大きさと配置）について、保守者が
2026-11-21 の会話で次のように決めた。

- 小さいサムネイルでも常に右下に置き、サムネイルの大きさに比例させる（下限・上限を設ける）
- 縦長・横長の動画では、正方形の枠の余白ではなく、実際に描かれた代表フレームの右下に置く
- 代表フレームの生成中・生成失敗で汎用アイコンを表示しているときは重ねない（代表フレームのときだけ）
- 範囲に、VoiceOver でサムネイル形式の動画を「動画」と読むことと、リスト形式の行頭の縮小画像（FR-048（file-list.md））
  にもバッジを重ねることを含める

## Clarifications

### Session 2026-11-21

- Q: バッジを表示するために、ファイルの読み込みや縮小画像のデコードを追加で行ってよいか? → A: 行わない。
  項目の種類と描かれた代表フレームの矩形だけから決める（clarify_mode auto で推奨を採用。憲章の原則 II）
- Q: プレビュー・フルスクリーン・スライドショー・ツリーにもバッジを重ねるか? → A: 重ねない。ファイルリストだけとする
  （clarify_mode auto で推奨を採用。プレビューでは動画の再生の UI が表示されるため）

### Session 2026-11-25（設計レビュー）

- Q: 公開文書の使い方（`docs/usage.md`・`docs/usage.ja.md`）に、動画にバッジが付くことを書き足すか? → A: 1 文ずつ足す（保守者）
- Q: バッジの見た目と大きさを plan.md の案で始めてよいか? → A: よい。値は GUI 確認で調整する（保守者。A-253）
- Q: リスト形式の行頭の縮小画像が縦横比を保たずに正方形へ引き伸ばされている件はどう扱うか? → A: 保守者が GUI で歪みを
  確認した。別の Issue（[TAK-127](https://linear.app/takyoshida/issue/TAK-127)）で扱い、この feature では行頭の縮小画像の
  描き方を変えない

## User Scenarios & Testing *(mandatory)*

変更点だけを定める。サムネイル形式の表示は FR-013・FR-014・FR-015（file-list.md）、リスト形式の行頭の縮小画像は FR-048、
動画の形式は FR-039（overview.md）に従う。US95 は永続シナリオ ID。

### User Story 1 - サムネイル形式で動画を見分ける (Priority: P1)

利用者は、画像と動画が混ざったフォルダをサムネイル形式で一覧したとき、動画のサムネイルの右下のバッジで、
代表フレームを見ただけでは画像と区別できない動画を見分けられる。

**Why this priority**: Issue の中心の価値。

**Independent Test**: 画像と、横長・縦長・正方形の動画を含むフォルダをサムネイル形式で開き、動画だけに右下のバッジが付くことを
目視する。

**Acceptance Scenarios**:

- **US95-AS1**: **Given** サムネイル形式で、動画の代表フレームの生成が終わっている, **When** 一覧を見る, **Then** 動画の
  サムネイルの、描かれた代表フレームの右下に、背景が透けて見えるバッジが表示される
- **US95-AS2**: **Given** 同じ一覧に画像・フォルダ・zip ファイル・`..` の項目がある, **When** 一覧を見る, **Then** それらには
  バッジが表示されない
- **US95-AS3**: **Given** 縦長（例: 9:16）の動画で正方形の枠の左右に余白ができる, **When** 一覧を見る, **Then** バッジは余白ではなく
  代表フレームの右下の角の内側に表示される
- **US95-AS4**: **Given** 動画の代表フレームの生成中、または生成に失敗して汎用アイコンを表示している, **When** 一覧を見る,
  **Then** バッジは表示されず、代表フレームに差し替わった時点で表示される
- **US95-AS5**: **Given** zip の中の一覧（FR-071（zip.md））と検索結果（FR-084（search.md））, **When** 動画の代表フレームを
  表示する, **Then** 通常のフォルダと同じくバッジが表示される

---

### User Story 2 - サムネイルの大きさを変えても見分けられる (Priority: P1)

利用者は、サムネイルの大きさを 48pt〜512pt のどこに変えても、バッジが判別できる大きさで右下に付き、代表フレームの
大部分を隠さないため、一覧の密度を変えても動画を見分けられる。

**Why this priority**: Issue の検討事項（小さいサイズでの見え方）への答え。

**Independent Test**: サムネイルの大きさを最小から最大まで動かし、バッジが比例して大きさを変え、常に代表フレームの右下に
収まることを目視する。

**Acceptance Scenarios**:

- **US95-AS6**: **Given** 動画のサムネイルが表示されている, **When** サムネイルの大きさを変える（FR-014）, **Then** バッジは
  操作に追従して代表フレームの大きさに比例して大きさを変え、右下の位置を保つ
- **US95-AS7**: **Given** サムネイルの大きさが最小（48pt）, **When** 横長（16:9）の動画を見る, **Then** バッジは判別できる大きさで
  代表フレームの内側に収まる
- **US95-AS8**: **Given** サムネイルの大きさが最大（512pt）, **When** 動画を見る, **Then** バッジは上限の大きさに留まり、
  代表フレームの右下の小さな範囲だけを覆う

---

### User Story 3 - リスト形式と読み上げでも動画が分かる (Priority: P2)

利用者は、リスト形式の行頭の縮小画像でも同じ意味のバッジで動画を見分けられる。VoiceOver の利用者は、サムネイル形式で
動画のサムネイルに移ったとき、動画であることを聞き取れる。

**Why this priority**: 保守者が範囲に含めると決めた。サムネイル形式の見た目より優先度は低い。

**Independent Test**: リスト形式で動画の行頭に小さいバッジが付くことを目視し、VoiceOver でサムネイル形式の動画と画像の
サムネイルを読み上げさせて違いを聞く。

**Acceptance Scenarios**:

- **US95-AS9**: **Given** リスト形式で、動画の行頭に代表フレームの縮小画像が表示されている, **When** 一覧を見る, **Then** 行頭の
  縮小画像の右下にバッジが重なり、画像の行には重ならない
- **US95-AS10**: **Given** サムネイル形式で VoiceOver を使っている, **When** 動画のサムネイルの画像に移る, **Then** 「動画の
  サムネイル」（英語では「Video thumbnail」）と読み上げ、画像のサムネイルは従来どおり「サムネイル」と読み上げる
- **US95-AS11**: **Given** 表示言語を切り替えた（FR-145（overview.md））, **When** 動画のサムネイルを読み上げる,
  **Then** 切り替えた言語で読み上げる

### Edge Cases

- **EC-286**: 縦横比が極端な動画（例: 1:4）で代表フレームの短い辺が小さいとき、バッジは代表フレームの内側に収め、
  短い辺の半分を超えない大きさに縮めなければならない。
- **EC-287**: 内容の置き換え（FR-228（file-list.md））で縮小画像を作り直す間、古い代表フレームを表示しているあいだは
  バッジも表示したままにしなければならない。
- **EC-288**: 選択中・右クリックの対象・ドロップ先の強調（FR-164（file-operations.md））でも、バッジは同じ見た目で重なり、
  ライト・ダークのどちらの外観でも、明るい代表フレームと暗い代表フレームの両方の上で判別できなければならない。
- **EC-289**: 動画の拡張子を持つが代表フレームを取得できないファイルでは、汎用アイコンを表示し、バッジを表示してはならない。
- **EC-290**: バッジは、クリック・ダブルクリック・ドラッグ・右クリック・名前の変更・Quick Look（FR-247（file-list.md））の
  対象と起点を変えてはならない（バッジの上の操作は、その項目のサムネイルの上の操作と同じに扱う）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-415**（FR-013 の追記）: サムネイル形式で動画（FR-039 の動画形式）の代表フレームを表示しているとき、システムは、
  描かれた代表フレームの右下に、動画であることを示す半透明のバッジを重ねて表示しなければならない。
  - 位置は、正方形の枠の中の余白を除いた、代表フレームの矩形の右下の角から内側に余白をとった位置とする
  - 通常のフォルダの一覧・zip の中の一覧（FR-071）・検索結果（FR-084）のどれでも同じに表示する
- **FR-416**: バッジの大きさは、描かれた代表フレームの大きさに比例し、下限と上限の範囲に収めなければならない。
  - サムネイルの大きさ・ペインの幅の変更（FR-014・FR-015）に追従する
  - 代表フレームの短い辺の半分を超えない（EC-286）。この制限は下限より優先する
- **FR-417**: 画像・フォルダ・zip ファイル・zip の中のディレクトリ・`..` の項目と、代表フレームの生成中・生成に失敗して
  汎用アイコンを表示している動画には、バッジを表示してはならない。
- **FR-418**（FR-048 の追記）: リスト形式で動画の行頭に代表フレームの縮小画像を表示しているとき、システムは、その右下に
  FR-415 と同じ図柄のバッジを、行頭の縮小画像の大きさに合わせて重ねなければならない。
  - 行頭の縮小画像の読み上げの扱い（読み上げの対象にしない）は変えない
- **FR-419**: サムネイル形式で、動画のサムネイルの画像のアクセシビリティの説明は「動画のサムネイル」（英語は
  「Video thumbnail」）としなければならない。
  - 画像のサムネイルの説明は従来どおり「サムネイル」とする
  - 代表フレームの生成の前後で変えない
  - 表示言語で提供し（FR-154（overview.md））、表示言語の切り替えに追従する
- **FR-420**: バッジは、項目の選択・操作・読み上げの対象として独立させてはならない（EC-290）。
- **FR-421**: システムは、バッジの表示のために、ファイルの読み込み・縮小画像の再生成・デコードを追加で行ってはならない。
  - バッジの有無・位置・大きさは、項目の種類と描かれた代表フレームの矩形だけから決める

### Key Entities

- 新しく保存するデータはない。表示する項目の種類（動画か）と、描かれた代表フレームの矩形から、バッジの有無・位置・
  大きさを決める。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-238**: 48pt・128pt・512pt のサムネイルの大きさで、横長（16:9）・縦長（9:16）・正方形の動画のすべてで、バッジが
  代表フレームの右下の内側に表示され、同じ一覧の画像・フォルダ・zip・`..` には表示されない。
- **SC-239**: どのサムネイルの大きさと縦横比でも、バッジの外形は代表フレームの内側に収まり、その面積は代表フレームの
  面積の 20% 以下である。
- **SC-240**: 縦横比が 1:2〜2:1 の動画では、サムネイル形式の画像の枠の辺が 40pt 以上のとき（ペインが 1 項目の幅以上のとき）、
  バッジの直径はどのサムネイルの大きさでも下限以上、上限以下である（下限と上限の値は plan で決める）。
- **SC-241**: VoiceOver で、サムネイル形式の動画のサムネイルが日本語と英語のどちらの表示言語でも動画であることを含めて
  読み上げられ、画像のサムネイルの読み上げは変更前と同じである。
- **SC-242**: バッジの追加の前後で、サムネイル形式の項目の選択・ダブルクリック・ドラッグ・右クリック・Quick Look の
  結果が変わらない。

## Assumptions

- **A-252**: 動画かどうかは、FR-039 の拡張子による形式で決め、ファイルの内容は調べない。
- **A-253**: Issue の「透過アイコン」は、背景の代表フレームが透けて見える半透明の円の上に再生の記号を描いたバッジとして扱う。
  - 図柄・色・透明度・大きさの下限と上限の具体値は plan で決め、保守者の GUI 確認で承認を得る
- **A-254**: リスト形式の行頭の縮小画像は小さい（16pt）ため、そのバッジは見分けの手がかりとし、サムネイル形式の下限
  （SC-240）は適用しない。
- **A-255**: リスト形式の読み上げは、行頭の縮小画像を読み上げの対象にしない現状（FR-048）を保ち、ファイル名で読み上げる。
- **A-256**: プレビュー・フルスクリーン・スライドショー・ツリーの表示は変えず、バッジを重ねない。

## 検証方針

バッジの有無（項目の種類と表示中の画像が代表フレームか）と、描かれた代表フレームの矩形からバッジの位置と大きさを決める
規則は、画面の部品に依存しない形に分けて自動テストで検証する（SC-239・SC-240 と EC-286 の境界を含む）。
実際の見え方（48pt・128pt・512pt、縦横比、ライト／ダーク、選択・強調、リスト形式の行頭）と VoiceOver の
読み上げは、保守者の GUI 確認に依頼する。macOS CI の build/test と Cloud の静的検査を分けて記録する。
