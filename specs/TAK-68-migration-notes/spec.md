# Feature Specification: 完了 feature の仕様反映と凍結注記

**Feature Branch**: `chore/tak-68-migration-notes`

**Created**: 2026-11-05

**Status**: Draft

**Input**: [TAK-68](https://linear.app/takyoshida/issue/TAK-68)、[TAK-10](https://linear.app/takyoshida/issue/TAK-10)

## User Scenarios & Testing

### User Story 1 - 大きな連番の仕様を確認する (Priority: P1)

仕様の保守者は、マージ済みの TAK-10 が実装した連番の扱いを製品仕様から確認できる。

**Why this priority**: 未反映の仕様を放置すると、マージ済みの実装と仕様の正本が食い違う。

**Independent Test**: 大きな末尾連番の複製と、同名衝突時の「両方残す」を FR-018・FR-025 と既存の回帰テストに照らして確認する。

**Acceptance Scenarios**:

1. **Given** 末尾にスペースと半角十進数字がある名前、**When** 複製する、**Then** 整数型の上限で打ち切らずに次の連番から空き名を探し、生成する連番の先頭ゼロを除く。
2. **Given** コピーまたは移動で同名の項目がある、**When** 「両方残す」を選ぶ、**Then** FR-018 の連番規則に従い、既存の項目を変更しない。
3. **Given** 作成する名前がファイルシステムの制限を超える、**When** 操作に失敗する、**Then** FR-026 の既存のエラー通知に従い、既存の項目を変更しない。

### User Story 2 - 完了済み feature を識別する (Priority: P1)

仕様の保守者は完了済みの feature を作業中の仕様と取り違えず、現在の正本をたどれる。

**Why this priority**: 凍結済みの記録の誤更新を防ぐ。

**Independent Test**: 完了済み feature の spec.md を調べ、移行先を照合してから先頭の注記と現在の正本への参照を確認する。

**Acceptance Scenarios**:

1. **Given** 005 は開発環境向けで製品仕様への反映対象外、**When** 先頭の注記を読む、**Then** 対象外であることと現在の Codex 運用文書を確認できる。
2. **Given** TAK-46・TAK-49・TAK-10 は完了済み、**When** 製品仕様への反映を確認し記録を読む、**Then** 現在の正本と凍結済みであることが分かる。
3. **Given** 移行先が確認できない feature、**When** 注記の対象を調べる、**Then** 反映を確認するまで「移行済み」と断定しない。

### Edge Cases

- 空き候補がすでに存在する場合は次の連番へ進み、既存項目を変更しない。
- 先頭ゼロだけの連番は 0 として扱い、次の番号には先頭ゼロを付けない。
- TAK-49 の既存の旧・新 ID 対応表は維持する。
- `specs/TAK-68-migration-notes/` 自身は本 feature の反映完了後に凍結する。

## Requirements

### Functional Requirements

- **FR-018（変更）**: ユーザーは、選択したファイルとフォルダ（FR-076）に対して「コピー」「名前の変更」「削除」「移動」「複製」を実行できなければならない。
  - フォルダの操作はその中身を含めて行い、FR-019〜FR-027 をファイルと同じく適用する（削除はフォルダごとゴミ箱へ入れる）。
  - 「複製」は対象と同じフォルダに「名前 2」という名前で作成し（既にその名前がある場合は空いている連番まで進める）、既存のファイルを変更しないため確認モーダル（FR-022）の対象外とする。
  - 名前の末尾にスペースと半角十進数字の連番がある場合は、その数の次から採番する。
  - 連番の桁数による整数上限を設けない。
  - 生成する連番の先頭ゼロは除く。
- **FR-025（変更）**: コピーまたは移動の操作先に同名ファイルが存在する場合、システムは確認モーダル設定に関わらず「置き換える / 両方残す / 中止」を選ばせなければならない。
  - ただしコピー元と衝突先が同一の項目である場合は「置き換える」を選べないようにし、「両方残す / 中止」を選ばせる。
  - この例外はドラッグ以外のコピーにも適用する。
  - 「両方残す」の採番は FR-018 の連番規則に従い、既存項目を変更しない。
  - 名前の変更で同じ親フォルダにある別の項目の名前（大文字小文字の違いのみを含む）を指定した場合は、衝突ダイアログを出さず、名前の検証エラーとして拒否しなければならない。
  - 複製は FR-018 の連番の規則に従い、この対象外とする。
  - 元項目自身の名前の大文字小文字だけを変える変更は、ボリュームが大文字小文字を区別するかに関わらず許可し、入力した表記を保存する。
  - 別のディレクトリエントリは、同じ実体を指すリンクであっても別項目として扱う。

### Key Entities

- **完了 feature の記録**: マージ済みの feature 文書。正本への反映確認後に凍結状態を注記する。
- **連番**: 名前の末尾にスペースを挟んだ半角十進数字。生成時は先頭ゼロを除く。

## Success Criteria

### Measurable Outcomes

- TAK-10 の FR-018・FR-025 の追加内容が製品仕様と既存の実装・テストで一致する。
- 完了・移行確認済みの対象4件（005・TAK-46・TAK-49・TAK-10）の先頭に、適切な凍結注記がある。
- 旧 ID 対応表と完了済み feature の本文が変わらず、正本へのリンクが確認できる。

## Assumptions

- 005 は開発環境のみを対象とし、当初から `specs/product/` への反映対象外である。
- マージ済み TAK-10 のアプリ実装は変更しない。未反映の仕様を記録する。
- 今回の凍結済み spec.md の先頭注記は、TAK-68 への保守者の明示的な依頼による。
