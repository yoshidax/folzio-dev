# Feature Specification: 5万件のメディアがある階層の検索を速くし、PC の負荷を下げる

**Feature Branch**: `claude/speckit-bug-assess-tak-129-fpt0ix`（Cloud が指定した作業ブランチ。feature ディレクトリとは独立）

**Created**: 2026-11-27

**Status**: Draft

**Input**: [TAK-129](https://linear.app/takyoshida/issue/TAK-129)「配下に5万件以上のメディアファイルがあるフォルダを起点にした検索を速くし、
PC の負荷を下げる」。保守者の観察では、最初に見える範囲のサムネイルが表示されるまで数分以上かかり、PC の負荷も高い。
バグ診断（`.specify/bugs/tak-129/assessment.md`）で、現在の仕様が5万件規模の基準を定めていないことから、仕様の変更として扱うと決めた。
保守者が 2026-11-27 の会話で次のように決めた。

- 検索中に操作は止まらないが、反応は遅い印象である（FR-085（search.md）に反するバグではない）
- できる限りの最適化を図る。目標は暫定で 3 秒とし、最初の画面のサムネイルがそろうまでと、検索を終えるまでの両方に当てる
- 計測の条件は SC-016（search.md）の5倍とする（ローカルディスク、500 フォルダ × 100 ファイル＝5万件、画像だけ、サムネイル形式、名前順）

## Clarifications

### Session 2026-11-27

- Q: 「先に一覧を作り、サムネイルは後で作る」案のために、見つかった順に一覧へ追加する動作（FR-085）をやめ、検索の終了時に一覧をまとめて
  出すか? → A: やめない。見つかった順に追加する動作は保ち、一覧への反映をまとめる間隔の上限（1 秒）を加える。サムネイルを後で作る案は、
  検索中は表示範囲の項目だけの縮小画像を作り、先読みを検索の終了後に回す形で取り入れる（clarify_mode auto で推奨を採用。
  検索中も結果を見て操作できる FR-085 の価値を保つため）
- Q: 「最初の画面のサムネイルがそろうまで 3 秒」は、どの時点から計るか? → A: 検索を始めた時点から計り、表示範囲のすべての項目に
  縮小画像が表示された状態に初めてなるまでとする。並べ替えで表示範囲の項目が入れ替わるため、検索の終了時の表示範囲についても、
  検索の終了から 3 秒以内にそろうことを別に求める（clarify_mode auto で推奨を採用。保守者の「3 秒」を両方に当てる）
- Q: CPU の負荷に数値の基準を設けるか? → A: 設けない。計測する機材でぶれが大きく、CI で確かめられないため。代わりに、検索中に
  表示範囲に入らなかった項目の縮小画像を作らないこと（SC-252）と、操作が止まらないこと（SC-251）で負荷を抑えたことを確かめる
  （clarify_mode auto で推奨を採用）
- Q: 通常のフォルダを開いたときの縮小画像の作り方（先読み・同時に作る数）も変えるか? → A: 変えない。変えるのは検索中の作り方だけとする
  （clarify_mode auto で推奨を採用。SC-003・SC-012（file-list.md）の通常のフォルダの基準を回帰させないため。A-269）

## User Scenarios & Testing *(mandatory)*

変更点だけを定める。検索全般は FR-080〜FR-087・FR-139・FR-140（search.md）、サムネイル形式の縮小画像は FR-013・FR-014（file-list.md）、
リスト形式の行頭の縮小画像は FR-048（file-list.md）に従う。US99 は永続シナリオ ID。

### User Story 1 - 大量のメディアがある階層を検索する (Priority: P1)

利用者は、配下に5万件のメディアがあるフォルダを起点に検索し、数秒で結果を見て操作を始める。検索中も PC 全体は重くならない。

**Why this priority**: 大量のメディアを持つ利用者には、今の検索は最初のサムネイルが出るまで数分以上かかり、実用にならない。これが本 feature の中心。

**Independent Test**: SC-249 の階層を起点に検索し、件数が確定するまでの時間と、表示範囲の縮小画像がそろうまでの時間を計る。

**Acceptance Scenarios**:

- **US99-AS1**: **Given** SC-249 の5万件の階層を起点にし、サムネイル形式・名前順で表示している, **When** 多くのファイルに一致するキーワードで検索する,
  **Then** 3 秒以内に検索が終わり、検索バーの件数が確定する
- **US99-AS2**: **Given** US99-AS1 と同じ条件, **When** 検索を始める, **Then** 3 秒以内に、表示範囲のすべての項目に縮小画像が表示された状態になる
- **US99-AS3**: **Given** US99-AS1 と同じ条件で検索が終わった, **When** 一覧を見る, **Then** 検索の終了から 3 秒以内に、表示範囲のすべての項目に縮小画像が表示される
- **US99-AS4**: **Given** 5万件の階層を検索中, **When** 一覧をスクロールし、項目を選択し、プレビューを見て、ツリーを操作する, **Then** どの操作も 100ms 以上止まらない
- **US99-AS5**: **Given** 5万件の階層を検索中, **When** 一覧を動かさずに検索の終了を待つ, **Then** 表示範囲に一度も入らなかった項目の縮小画像は作られない
- **US99-AS6**: **Given** 5万件の階層の検索が終わった, **When** 一覧をゆっくりスクロールする, **Then** 表示範囲の少し先の項目の縮小画像も前もって作られ、通常のフォルダの一覧と同じく表示される

### Edge Cases

- 検索中にスクロールして表示範囲が変わった場合は、新しく表示範囲に入った項目の縮小画像を作り、表示範囲から外れた項目の作成は取り消す
- 検索中に新しい結果が並べ替えで表示範囲に入り、それまでの項目が表示範囲の外へ押し出された場合も、押し出された項目の作成を取り消す
- 検索中に表示形式（FR-010（file-list.md））・サムネイルの大きさ（FR-014）を変えた場合も、検索が終わるまでは表示範囲の項目だけの縮小画像を作る
- 検索を止めた場合（FR-086・FR-140・新しい検索）は、検索の終了と同じく扱わず、作成中の縮小画像のうち表示しなくなった項目のものを取り消す
- 一致が少なく、検索が反映の間隔より早く終わる場合は、従来どおり見つかった時点で一覧に出す（反映を遅らせる理由がない）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-085（変更）**: 検索は UI を止めずに行い、
  見つかったファイルとフォルダから順に一覧へ追加しなければならない（並び順は現在の並べ替えに従う）。
  - 検索中は検索中であることと途中の件数（見つかったファイルとフォルダの合計）を表示し、完了したら件数を確定する。
  - 検索中もスクロール・選択・プレビュー・ツリーの操作を続けられなければならない。
  - 一覧への追加は、まとめて行ってよい。
    - 見つかってから一覧と件数に出るまでの遅れは 1 秒以内とする
  - 検索結果の表示を解除したとき（FR-086）、フォルダの行を開いたとき（FR-140）、または新しい検索を始めたときは、
    実行中の検索を止める。
  - 新しい検索の結果は前の結果を置き換える。
  - 結果の件数に上限は設けない
- **FR-435**: 検索中は、システムは表示範囲にある項目の縮小画像（FR-013・FR-048（file-list.md））だけを作らなければならない。
  - 表示範囲の外の項目を前もって作る処理（先読み）は、検索が終わってから行う
  - 表示範囲から外れた項目の作成は、作り終える前に取り消す
  - 検索が終わった後は、通常のフォルダの一覧と同じ規則で縮小画像を作る
- **FR-436**: 検索中に新しい結果を一覧へ加える1回の処理は、既にある結果の件数が増えても長くなってはならない。
  - 既にある結果の順序・絞り込みの結果・選択は、新しい結果を加えても保つ（FR-085 の並び順に従って位置だけが変わる）

### Key Entities *(include if feature involves data)*

- **表示範囲**: ファイルリストのうち、いま画面に見えている項目の範囲。スクロール・ペイン幅・サムネイルの大きさで変わる

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-249**: ローカルディスク上の 500 フォルダ × 100 ファイル（5万件、画像だけ）の階層を起点に、サムネイル形式・名前順で、
  多くのファイルに一致するキーワードで検索しても、3 秒以内に検索が終わり、件数が確定する。
  - 一覧への追加を含めて計る（列挙だけの時間ではない）
- **SC-250**: SC-249 と同じ条件で検索を始めてから、表示範囲のすべての項目に縮小画像が表示された状態に初めてなるまでが 3 秒以内となる。
  - 検索の終了時の表示範囲についても、検索の終了から 3 秒以内にすべての項目に縮小画像が表示される
- **SC-251**: SC-249 と同じ条件の検索中に、スクロール・選択・プレビュー・ツリーの操作が 100ms 以上止まらない（SC-004 と同じ基準）
- **SC-252**: SC-249 と同じ条件で、一覧を動かさずに検索の終了を待ったとき、検索中に表示範囲に一度も入らなかった項目の縮小画像を作った件数が0件となる

### 既存の項目との関係

- SC-016・SC-054（search.md）の1万件の基準は変えない。SC-249 は件数を増やした基準を加える

## Assumptions

- **A-263**: SC-249〜SC-252 の基準は、保守者の Mac（ローカルの SSD）で計る。
  - CI の性能テストは共有ランナーで計り、ぶれがあるので参考とする（既存の性能テストと同じ扱い）
- **A-264**: 計測に使う画像は、SC-016 の性能テストと同じく小さい JPEG とする。
  - 大きい写真や動画を含む階層では縮小画像の生成に時間がかかるので、SC-250 の基準の対象外とし、FR-435 の規則だけを適用する
- **A-265**: 外部ボリューム・ネットワークボリューム上の階層は、SC-249〜SC-251 の基準の対象外とする。
  - FR-435・FR-436 の規則は同じく適用する
- **A-266**: CPU の負荷には数値の基準を設けない。
  - 負荷を抑えたことは、SC-251 と SC-252 で確かめる
- **A-267**: 検索の結果の順序・件数・内容（FR-083・FR-084・FR-278）は変えない。変えるのは、一覧に出る時点と縮小画像を作る時点だけとする
- **A-268**: 検索結果の表示中のファイル操作・名前の変更・変更通知への追随（FR-087・FR-105・FR-232）の結果は変えない
- **A-269**: 通常のフォルダ・zip の中の一覧の縮小画像の作り方（先読み・同時に作る数）は変えない。
  - FR-435 は検索中だけに適用する

## 検証方針

一覧の更新の処理（FR-436）と、反映の間隔（FR-085 の変更）は、画面の部品に依存しない形に分けて自動テストで検証する（件数を増やしたときの
1回あたりの処理量、結果の順序・件数が変わらないこと）。検索から一覧の確定までの時間（SC-249）は、列挙だけでなく一覧への追加を含めた性能テストで
計る。縮小画像の要求（FR-435・SC-252）は、縮小画像を作る部品を差し替えたテストで、検索中に表示範囲の外の項目を要求しないことを確かめる。
表示範囲の縮小画像がそろうまでの時間（SC-250）と操作が止まらないこと（SC-251）は、保守者の Mac での GUI 確認に依頼する。macOS CI の build/test と
Cloud の静的検査を分けて記録する。
