# Feature Specification: 5万件のメディアがある階層の検索を速くし、PC の負荷を下げる

**Feature Branch**: `claude/speckit-bug-assess-tak-129-fpt0ix`（Cloud が指定した作業ブランチ。feature ディレクトリとは独立）

**Created**: 2026-11-27

**Status**: Draft

**Input**: [TAK-129](https://linear.app/takyoshida/issue/TAK-129)「配下に5万件以上のメディアファイルがあるフォルダを起点にした検索を速くし、
PC の負荷を下げる」。保守者の観察では、最初に見える範囲のサムネイルが表示されるまで数分以上かかり、PC の負荷も高い。
バグ診断（`.specify/bugs/tak-129/assessment.md`）で、現在の仕様が5万件規模の基準を定めていないことから、仕様の変更として扱うと決めた。
保守者が 2026-11-27 の会話で次のように決めた。

- 検索中に操作は止まらないが、反応は遅い印象である（FR-085（search.md）に反するバグではない）
- できる限りの最適化を図る。目標は暫定で 3 秒とし、最初の画面のサムネイルがそろうまでと、検索を終えるまでの両方に当てる
- 計測の条件は SC-016（search.md）の5倍とする（ローカルディスク、500 フォルダ × 100 ファイル＝5万件、画像だけ、サムネイル形式、名前順）
- 保守者は、検索中の一覧を名前順に並べていたため、並べ替えが常に起きていたことに気付いた。検索中は並べ替えずに見つかった順に
  一覧へ足し、検索が終わったときに1回だけ現在の並べ替えを適用する

  一覧への反映をまとめる間隔の上限（1 秒）を加える。サムネイルを後で作る案は、検索中は表示範囲の項目だけの縮小画像を作り、

  検索の終了時に全体を並べ替える（clarify_mode auto で推奨を採用し、
  設計レビューで保守者が確認した。操作をガードする案と、終了時にまとめて適用する案は採らない。列を選んでも何も起きない状態を避けるため）

  （clarify_mode auto で推奨を採用。並べ替えで見ていた項目が入れ替わっても、利用者が見失わないため）
- Q: 「最初の画面のサムネイルがそろうまで 3 秒」は、どの時点から計るか? → A: 検索を始めた時点から計り、表示範囲のすべての項目に

  検索の終了から 3 秒以内にそろうことを別に求める（clarify_mode auto で推奨を採用。保守者の「3 秒」を両方に当てる）
- Q: 検索中にスクロールしたとき、最初の画面より先の項目の縮小画像は作るか? → A: 作る。検索中も、スクロールで表示範囲に入った項目の

  （設計レビューで保守者が確認した。検索中に速くスクロールすると縮小画像が少し遅れて出ることを受け入れ、先読みを残す案は採らない）

- Q: 通常のフォルダを開いたときの縮小画像の作り方（先読み・同時に作る数）も変えるか? → A: 変えない。変えるのは検索中の作り方だけとする

## User Scenarios & Testing *(mandatory)*

変更点だけを定める。検索全般は FR-080〜FR-087・FR-139・FR-140（search.md）、並べ替えは FR-012（file-list.md）、
サムネイル形式の縮小画像は FR-013・FR-014（file-list.md）、リスト形式の行頭の縮小画像は FR-048（file-list.md）に従う。US99 は永続シナリオ ID。

### User Story 1 - 大量のメディアがある階層を検索する (Priority: P1)

利用者は、配下に5万件のメディアがあるフォルダを起点に検索し、数秒で結果を見て操作を始める。検索中も PC 全体は重くならない。

**Why this priority**: 大量のメディアを持つ利用者には、今の検索は最初のサムネイルが出るまで数分以上かかり、実用にならない。これが本 feature の中心。

**Independent Test**: SC-249 の階層を起点に検索し、件数が確定するまでの時間と、表示範囲の縮小画像がそろうまでの時間を計る。

**Acceptance Scenarios**:

- **US99-AS1**: **Given** SC-249 の5万件の階層を起点にし、サムネイル形式・名前順で表示している, **When** 多くのファイルに一致するキーワードで検索する,
  **Then** 3 秒以内に検索が終わり、検索バーの件数が確定し、一覧が名前順に並ぶ
- **US99-AS2**: **Given** US99-AS1 と同じ条件, **When** 検索を始める, **Then** 検索中は見つかった順に結果が一覧の末尾へ加わり、先頭の項目は入れ替わらない。
  3 秒以内に、表示範囲のすべての項目に縮小画像が表示された状態になる
- **US99-AS3**: **Given** US99-AS1 と同じ条件で、項目を選択せずに検索が終わった, **When** 一覧を見る, **Then** 一覧の先頭（名前順の最初の項目）が表示され、
  検索の終了から 3 秒以内に、表示範囲のすべての項目に縮小画像が表示される
- **US99-AS4**: **Given** 検索中に項目 X を選択している, **When** 検索が終わって一覧が並べ替わる, **Then** X は選択されたまま、見える位置に表示される
- **US99-AS5**: **Given** 5万件の階層を検索中, **When** 一覧をスクロールし、項目を選択し、プレビューを見て、ツリーを操作する, **Then** どの操作も 100ms 以上止まらない
- **US99-AS6**: **Given** 5万件の階層を検索中, **When** 一覧を動かさずに検索の終了を待つ, **Then** 検索中に表示範囲に一度も入らなかった項目の縮小画像は、
  検索の終了まで作られない
- **US99-AS7**: **Given** 5万件の階層を検索中, **When** 「名前」列の見出しを押して並べ替えの向きを変える, **Then** その時点の結果がすぐに並べ替わり、
  その後に見つかった結果は末尾に加わり、検索の終了時に全体が新しい向きで並ぶ
- **US99-AS8**: **Given** 5万件の階層の検索が終わった, **When** 一覧をゆっくりスクロールする, **Then** 表示範囲の少し先の項目の縮小画像も前もって作られ、
  通常のフォルダの一覧と同じく表示される
- **US99-AS9**: **Given** 検索の終了後に一覧の先頭の縮小画像が表示されている, **When** 数画面下へスクロールしてから先頭へ戻る,
  **Then** 先頭の項目には、種類のアイコンを挟まずに、前と同じ縮小画像がすぐに表示される（通常のフォルダの一覧とリスト形式の行頭の縮小画像でも同じ）

### Edge Cases

- **EC-300**: 検索中にスクロールして表示範囲が変わった場合は、新しく表示範囲に入った項目の縮小画像を作り、表示範囲から外れた項目の作成は取り消す
- **EC-301**: 検索中に表示形式（FR-010（file-list.md））・サムネイルの大きさ（FR-014）を変えた場合も、検索が終わるまでは表示範囲の項目だけの縮小画像を作る
- **EC-302**: 検索を止めた場合（FR-086・FR-140・新しい検索）は、検索の終了と同じには扱わず、並べ替えも先読みもしない。
  表示しなくなった項目の作成中の縮小画像は取り消す
- **EC-303**: 一致が少なく、反映の間隔より早く検索が終わる場合も、検索の終了時に並べ替えてから一覧に出す（見つかった順の一覧を一瞬だけ見せない）
- **EC-304**: 検索中に結果の名前や結果を含むフォルダの名前を変えた場合（FR-087・FR-105）は、その行を一覧の同じ位置に残し、
  検索の終了時の並べ替えで新しい位置へ移す

## Requirements *(mandatory)*

### Functional Requirements

- **FR-085（変更）**: 検索は UI を止めずに行い、
  見つかったファイルとフォルダから順に一覧へ追加しなければならない。
  - 検索中は、見つかった順に一覧の末尾へ足し、並べ替えない（FR-437）。
  - 検索中は検索中であることと途中の件数（見つかったファイルとフォルダの合計）を表示し、完了したら件数を確定する。
  - 検索中もスクロール・選択・プレビュー・ツリーの操作を続けられなければならない。
  - 一覧への追加は、まとめて行ってよい。
    - 見つかってから一覧と件数に出るまでの遅れは 1 秒以内とする
  - 検索結果の表示を解除したとき（FR-086）、フォルダの行を開いたとき（FR-140）、または新しい検索を始めたときは、
    実行中の検索を止める。
  - 新しい検索の結果は前の結果を置き換える。
  - 結果の件数に上限は設けない
- **FR-435**: 検索中は、システムは表示範囲にある項目の縮小画像（FR-013・FR-048（file-list.md））だけを作らなければならない。
  - 表示範囲の外の項目を前もって作る処理（先読み）は、検索が終わってから行う
  - 表示範囲から外れた項目の作成は、作り終える前に取り消す
  - 検索が終わった後は、通常のフォルダの一覧と同じ規則で縮小画像を作る
- **FR-436**: 検索中に新しい結果を一覧へ加える1回の処理は、操作を止めない長さに収めなければならない（SC-253）。
  - 既にある結果の位置・絞り込みの結果・選択は、新しい結果を加えても変えない
- **FR-437**: システムは、検索が終わったときに1回だけ、検索結果の全体を現在の並べ替え（FR-012（file-list.md））で並べ替えなければならない。
  - 選択とフォーカスは、並べ替えの前と同じ項目に保つ
  - フォーカス項目があれば、その項目が見える位置まで一覧をスクロールする。なければ一覧の先頭を表示する
  - 検索中に利用者が並べ替えの列や向きを変えたときは、その時点の結果をすぐに並べ替え、その後に見つかった結果は末尾へ足す
  - 検索を止めたとき（EC-302）は並べ替えない
- **FR-438**: システムは、作成済みで保持している縮小画像（FR-013・FR-048（file-list.md））がある項目を表示し直すときは、その縮小画像をすぐに表示し、
  種類のアイコンを挟んではならない。
  - サムネイル形式とリスト形式の行頭の縮小画像の両方に、検索結果と通常のフォルダ・zip の中の一覧のどれでも適用する
  - 保持している縮小画像がない項目（まだ作っていない、または保持の上限を超えて捨てた）は、従来どおり種類のアイコンを表示してから作る
  - 保持の上限は変えない

### 既存の項目の変更

- **FR-105（変更）**: 検索結果を表示中（検索中を含む）に、ツリーまたは検索結果の一覧で、
  検索結果の項目を含むフォルダ（検索起点そのもの、その祖先、または配下のフォルダ）か、
  検索結果のフォルダの行のフォルダの名前を変えた場合、システムは次のとおり一覧を同期しなければならない。
  - 該当するファイルとフォルダは一覧に残し、リスト形式の「場所」列とサムネイル形式のツールチップ（FR-084）
    を新しい名前で表示する。
  - 名前を変えたフォルダが検索結果の行であれば、
    その行もキーワードに一致しなくなったかどうかに関わらず新しい名前で表示する（FR-087）。
  - 検索起点そのものの名前を変えた場合は、
    検索バーの起点のフォルダ名とツールチップの絶対パスも新しい名前にする（アプリの外での削除・移動を扱う
    EC-36とは区別し、結果を外さない）。
  - 検索起点の祖先の名前を変えた場合は、検索バーのツールチップの絶対パスを新しい名前にする。
  - 並べ替えている列の値が変わった場合（「場所」列、またはフォルダの行の名前）は並べ直す。
    - 検索中は並べ直さず、検索の終了時の並べ替え（FR-437）で新しい位置へ移す（EC-304）
  - 選択・プレビューは保つ。
  - 新しい場所が検索の対象（FR-083）でなくなったファイルとフォルダは一覧から外し（FR-103 の検証により、
    ツリーやファイルリストでの名前の変更ではこの場合は起きない。名前の変更を検索結果へ反映する処理の規則として定める）、
    それがプレビュー中だった場合はプレビューを空にして再生中の動画を止める（FR-087と同じ）。
  - 検索中であれば検索を止めずに続け、以後に見つかったファイルとフォルダも新しい場所で加える。
  - 名前の変更を、照合済みの項目の一致を判定し直す契機にはしない。
  - 新しい名前がキーワードに一致するようになったフォルダも、検索結果の行でなければ一覧に加えない。
  - 検索中は、名前を変えた時点でまだ照合していないフォルダを、照合する時点の名前で照合する
- **US1-AS26（変更）**: **Given** 検索のモーダルで検索キーワードに `*.png` を入力した,
  - **When** 「検索」を押す,
  - **Then** 検索起点ディレクトリ以下のすべての階層にある PNG ファイルが、
    ファイルリストにフォルダの区別なく1つの一覧としてバッチで追加され、検索中は見つかった順に末尾へ加わり、
    検索が終わると現在の並べ替え順に並ぶ（FR-437）。
    リスト形式では各ファイルの「場所」列で同じ名前のファイルを見分けられる。検索中もスクロール・選択・プレビュー・
    ツリーの操作ができる

### Key Entities *(include if feature involves data)*

- **表示範囲**: ファイルリストのうち、いま画面に見えている項目の範囲。スクロール・ペイン幅・サムネイルの大きさで変わる

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-249**: ローカルディスク上の 500 フォルダ × 100 ファイル（5万件、画像だけ）の階層を起点に、サムネイル形式・名前順で、
  半数（2万5千件）に一致するキーワード（SC-016 と同じ形）で検索しても、3 秒以内に検索が終わり、件数が確定し、一覧が名前順に並ぶ。
  - 一覧への追加と終了時の並べ替えを含めて計る（列挙だけの時間ではない）
- **SC-250**: SC-249 と同じ条件で検索を始めてから、表示範囲のすべての項目に縮小画像が表示された状態に初めてなるまでが 3 秒以内となる。
  - 検索の終了時に並べ替えた後の表示範囲についても、検索の終了から 3 秒以内にすべての項目に縮小画像が表示される
- **SC-251**: SC-249 と同じ条件の検索中と終了時の並べ替えで、スクロール・選択・プレビュー・ツリーの操作が 100ms 以上止まらない（SC-004 と同じ基準）
- **SC-252**: SC-249 と同じ条件で、一覧を動かさずに検索の終了を待ったとき、検索中に表示範囲に一度も入らなかった項目の縮小画像を作った件数が0件となる
- **SC-253**: 既に5万件の結果がある検索結果の一覧へ、256 件の新しい結果を加える1回の処理が 50ms 以内に終わる
- **SC-254**: 縮小画像を表示した項目を、表示範囲の外へスクロールしてから表示範囲へ戻す操作を 20 回行い、保持している縮小画像がある項目に
  種類のアイコンが表示された回数が0回となる

### 既存の項目との関係

- SC-016・SC-054（search.md）の1万件の基準は変えない。SC-249 は件数を増やした基準を加える

## Assumptions

- **A-263**: SC-249〜SC-253 の基準は、保守者の Mac（ローカルの SSD）で計る。
  - CI の性能テストは共有ランナーで計り、ぶれがあるので参考とする（既存の性能テストと同じ扱い）
- **A-264**: 計測に使う画像は、SC-016 の性能テストと同じく小さい JPEG とする。
  - 大きい写真や動画を含む階層では縮小画像の生成に時間がかかるので、SC-250 の基準の対象外とし、FR-435 の規則だけを適用する
- **A-265**: 外部ボリューム・ネットワークボリューム上の階層は、SC-249〜SC-251 の基準の対象外とする。
  - FR-085・FR-435〜FR-437 の規則は同じく適用する
- **A-266**: CPU の負荷には数値の基準を設けない。
  - 負荷を抑えたことは、SC-251 と SC-252 で確かめる
- **A-267**: 検索の結果の件数・内容（FR-083・FR-084・FR-278）と、検索が終わった後の並び順は変えない。変えるのは、検索中の並び順と、
  一覧に出る時点と、縮小画像を作る時点だけとする
- **A-268**: 検索結果の表示中のファイル操作・名前の変更・変更通知への追随（FR-087・FR-105・FR-232）の結果は変えない。
  - 検索中の名前の変更による並び順だけは EC-304 に従う
- **A-269**: 通常のフォルダ・zip の中の一覧の縮小画像の作り方（先読み・同時に作る数・保持の上限）は変えない。
  - FR-435 は検索中だけに適用する
  - 保持している縮小画像を表示し直すときの表示（FR-438）だけは、すべての一覧に適用する

## 検証方針

検索中の追加（末尾へ足す・反映の間隔・FR-436）と、終了時の並べ替え・選択とフォーカスの保持（FR-437）は、画面の部品に依存しない形に分けて
自動テストで検証する（結果の件数・内容と、終了後の並び順が従来の並べ替えと同じであること、5万件での1回の追加の時間）。検索から一覧の確定までの時間
（SC-249）は、列挙だけでなく一覧への追加と終了時の並べ替えを含めた性能テストで計る。縮小画像の要求（FR-435・SC-252）は、縮小画像を作る部品を
差し替えたテストで、検索中に表示範囲の外の項目を要求しないことを確かめる。表示範囲の縮小画像がそろうまでの時間（SC-250）と操作が止まらないこと
（SC-251）、終了時の並べ替えの見え方（US99-AS3・AS4）は、保守者の Mac での GUI 確認に依頼する。macOS CI の build/test と Cloud の静的検査を分けて記録する。
