# Feature Specification: ツリーでのフォルダの複数選択と一括操作

**Feature Branch**: `claude/youthful-brahmagupta-ocjb0d`

**Created**: 2026-10-31

**Status**: Draft

**Input**: TAK-21 https://linear.app/takyoshida/issue/TAK-21 — ツリーでフォルダを複数選択し、移動・コピー・削除を一括操作できるようにする。
選択した複数フォルダの扱いと操作結果の表示を、ファイルリストのフォルダ操作に合わせる。

## Clarifications

### Session 2026-10-31

- Q: 複数選択中にファイルリストへ表示するフォルダは？ → A: 最後にクリック（またはキーボードで移動）した行のフォルダ（FR-209）
- Q: ツリーで複数のフォルダをゴミ箱に入れるときの確認モーダルは？ → A: 単一のときと同じく、省略設定に関わらず常に確認する（FR-079（変更）、A-33 を維持）
- Q: 右クリックメニューとドラッグの対象と選択集合の関係は？ → A: 選択中の行から始めたら選択全体、選択外の行から始めたらその行だけ（FR-210。ファイルリストの US23-AS2 と同じ）
- Q: 削除の操作経路にドラッグを含めるか？ → A: 含めない。一括削除は ⌘⌫・「ゴミ箱に入れる」（メニュー・右クリック）で行い、ドラッグは移動・コピーだけとする（A-122）

## User Scenarios & Testing *(mandatory)*

### User Story 35 - 複数のフォルダをまとめて移動・コピーする (Priority: P1)

ユーザーは、ツリーで ⌘クリック・Shift クリック・Shift+↑↓ により複数の通常のフォルダを選び、ツリーまたはファイルリストの別のフォルダへ
ドラッグして、まとめて移動（Option でコピー）できる。

**Why this priority**: TAK-21 の主目的。単一フォルダのドラッグを繰り返す負担をなくす。

**Independent Test**: 同じ親の下のフォルダ A・B と、別の親の下のフォルダ C をツリーで複数選択し、ツリーのフォルダ D とファイルリストのフォルダ E へ、
移動と Option コピーをそれぞれ行い、結果・確認・表示を確かめる。

**Acceptance Scenarios**:

- **US35-AS1**: **Given** ツリーで通常のフォルダ A・B・C を複数選択している, **When** 選択中のいずれかの行からツリーのフォルダ D へドラッグしてドロップし、
  確認モーダルで確定する, **Then** A・B・C が中身ごと D へ1回の操作として移動し、確認モーダルには3件を示す。
  Option を押してドロップするとコピーし、元の A・B・C は残る
- **US35-AS2**: **Given** A・B を複数選択している, **When** 選択外の通常のフォルダ F の行からドラッグを始める, **Then** F だけを対象にする（A・B は対象にしない）
- **US35-AS3**: **Given** フォルダ P とその配下のフォルダ P/Q を同時に選択している、または選択したフォルダ自身・配下を宛先にしている, **When** ドラッグする, **Then**
  宛先は有効にならず、ドロップしても何も変わらない（EC-121・EC-16）。一部の項目だけを黙って除いて実行しない
- **US35-AS4**: **Given** 通常のフォルダとホーム（またはボリュームの最上位・お気に入りの項目）を同時に選択している, **When** 選択中の行からドラッグを始める, **Then**
  ドラッグは始まらない（FR-211）
- **US35-AS5**: **Given** 複数選択の移動で一部が衝突・失敗した, **When** 結果が表示される, **Then** 既存の衝突の選択肢（FR-025）と結果表示（FR-026）に従い、成功した分と
  失敗した分を区別して伝える。ツリーとファイルリストには成功した分だけを反映する（FR-165）

### User Story 36 - 複数のフォルダをまとめてゴミ箱に入れる (Priority: P1)

ユーザーは、ツリーで複数選択した通常のフォルダを、⌘⌫ または「ゴミ箱に入れる」でまとめてゴミ箱に入れられる。

**Why this priority**: TAK-21 の主目的の一つ。ファイルリストの複数選択の削除と操作感を揃える。

**Independent Test**: ツリーでフォルダ A・B・C を複数選択し、⌘⌫ と右クリックの「ゴミ箱に入れる」でそれぞれ削除し、確認モーダル・結果・選択・表示を確かめる。

**Acceptance Scenarios**:

- **US36-AS1**: **Given** ツリーで通常のフォルダ A・B・C を複数選択し、確認モーダルの省略設定（FR-023）がオン, **When** ⌘⌫ を押す, **Then** 確認モーダルが必ず表示され、
  対象の件数と各フォルダの名前・絶対パスを示す。確定すると A・B・C が中身ごとゴミ箱に入り、ツリーとファイルリストから消える。キャンセルすると何も変わらない
- **US36-AS2**: **Given** A・B・C を複数選択している, **When** B の行を右クリックして「ゴミ箱に入れる」を選ぶ, **Then** A・B・C の全体を対象にする。
  選択外のフォルダ D の行を右クリックした場合は D だけを対象にし、ツリーの選択は変えない（A-21）
- **US36-AS3**: **Given** A の内容をファイルリストに表示し、A・B を複数選択している, **When** まとめてゴミ箱に入れて確定する, **Then** A の親をツリーで単一選択し、
  ファイルリストを親の一覧に切り替え、プレビューを空にする（FR-079・FR-212）
- **US36-AS4**: **Given** フォルダ P と配下の P/Q を同時に選択している, **When** ⌘⌫ を押す, **Then** 理由を示すエラーを表示して全体を拒否し、どのフォルダもゴミ箱に入れない（EC-141）

### User Story 37 - 複数選択中の表示とメニュー (Priority: P2)

ユーザーは複数選択の操作中も、どのフォルダの内容を見ているかが分かり、単一の対象を前提とする操作を誤って実行しない。

**Why this priority**: 一括操作の前提となる選択の振る舞い。P1 の操作を安全に使うために必要。

**Independent Test**: ⌘クリック・Shift クリック・Shift+↑↓ で選択を広げ、ファイルリストの表示とメニュー項目の有効・無効を確かめる。

**Acceptance Scenarios**:

- **US37-AS1**: **Given** A を選択して A の内容を表示している, **When** ⌘クリックで B を追加する, **Then** ファイルリストは B の内容に切り替わる。
  Shift+↓ で選択を広げたときは、最後に移動した行のフォルダの内容を表示する
- **US37-AS2**: **Given** A・B を選択し B の内容を表示している, **When** ⌘クリックで A を選択から外す, **Then** ファイルリストの表示は B のまま変わらない
- **US37-AS4**: **Given** A・B を選択し B の内容を表示している, **When** ファイルリストで B のサブフォルダ B1 を開く, **Then** ツリーの選択は B1 の1行になり、
  以後の Shift+↑↓ は B1 を起点にする（FR-209）
- **US37-AS3**: **Given** ツリーで2行以上を選択している, **When** Return を押す、または「編集」メニューの「名前を変更」「パス名をコピー」や
  「ファイル」メニューの「お気に入りに追加」「Finder に表示」を見る, **Then** Return は何もせず、それらのメニュー項目は淡色で選べない。
  右クリックメニューでも、複数を対象にするときは「ゴミ箱に入れる」以外の項目を淡色で選べなくする

### Edge Cases

- **EC-141**: ツリーでゴミ箱に入れる対象（FR-210）に、フォルダとその配下のフォルダが同時に含まれる場合、システムは理由を示すエラーを表示して操作全体を拒否し、
  どのフォルダもゴミ箱に入れてはならない。確認モーダルは表示しない。一部の項目だけを黙って除いて実行しない（EC-121 と同じ考え方）
- **EC-142**: 複数選択の操作の実行時に、対象の一部がアプリの外で削除・移動されていた場合は、その分を失敗として FR-026 に従って表示し、残りの結果を反映する。
  見つからない項目を黙って成功として扱わない
- **EC-143**: 選択中の行を含む親フォルダを折りたたんで行が見えなくなった場合、見えなくなった行は選択から外れる。ファイルリストの表示は変えない
- 複数選択の宛先検証は、移動・コピーとも EC-16・EC-121 をそのまま適用する（自身・配下への転送、親と同じ場所への移動、親子の同時選択は全体を拒否する）
- 複数選択中に ↑↓（Shift なし）を押した場合は、主の行の前・次の行1つだけを選択する（FR-005・FR-208）
- 名前の編集中（FR-102）に ⌘クリックや Shift クリックで選択を変えた場合は、既存のほかの場所のクリックと同じく編集を確定してから選択を変える（FR-103）
- ファイルリストに zip の中や検索結果を表示中でも、ツリーの複数選択とその一括操作は使える（FR-103 と同じ扱い）。検索結果の同期は FR-087・EC-123 に従う

## Requirements *(mandatory)*

### Functional Requirements（追加）

- **FR-208**: ユーザーは、ツリーでクリック・⌘クリック・Shift クリック、および Shift+↑↓ で複数の行を選択できなければならない。
  ⌘クリックは選択中の行を選択から外すこともできる。↑↓（Shift なし）と通常のクリックは、従来どおり1行だけを選択する（FR-005）。
  複数選択の行の種類（通常のフォルダ・ホーム・ボリュームの最上位・お気に入りの項目・見出し）は制限しない。操作の可否は FR-211 で決める
- **FR-209**: ツリーで複数の行を選択しているとき、ファイルリストには、最後にクリックした行、またはキーボードで最後に移動した行（以下「主の行」）の
  フォルダを、単一選択のときと同じ規則（FR-007・FR-063・FR-065、履歴（navigation-history.md）、最後に選択していたフォルダ（FR-003））で表示しなければならない。
  ⌘クリックで行を選択から外したときは、ファイルリストの表示を変えない。
  ファイルリスト側の操作（フォルダを開く・親に戻る（FR-078）、戻る・進む（navigation-history.md）、検索結果のフォルダを開く（FR-140）など）で
  ツリーの選択が表示中のフォルダに同期されたときは、複数選択を解き、同期した1行の選択にし、その行を主の行とする。
  検索結果の表示中に、複数選択の中の行を通常のクリックで選んだときは、選択をその1行にし、FR-086 と同じく検索結果の表示を終えてその行のフォルダの一覧を表示する
- **FR-210**: ツリーの操作の対象は次のとおりとしなければならない。
  （1）⌘⌫ と、ツリーを対象にする「ファイル」「編集」メニューの項目（ツリーにフォーカスがあるとき。どのペインからでも効く ⌃⌘T を含む）は、ツリーで選択中の行全体を対象にする。
  （2）右クリックメニューは、選択中の行を右クリックしたときは選択中の行全体を、選択外の行を右クリックしたときはその行だけを対象にし、
  ツリーの選択を変えない（A-21）。
  （3）ドラッグは、選択中の行から始めたときは選択中の行全体を、選択外の行から始めたときはその行だけを対象にする（US23-AS2 と同じ）
- **FR-211**: 対象が2行以上のとき、システムは次のとおり扱わなければならない。
  （1）ゴミ箱に入れる操作とドラッグは、対象のすべてが通常のフォルダ（FR-079 と同じ範囲）のときだけ実行できる。そうでなければ、
  「ゴミ箱に入れる」は淡色で選べず、⌘⌫ は何もせず、ドラッグは始まらない。対象の一部だけを除いて実行しない。
  （2）単一の対象を前提とする操作（名前を変更（FR-103・FR-099）・パス名をコピー（FR-182）・お気に入りに追加（FR-062）・お気に入りから削除（FR-064）・
  Finder に表示・ここにペースト・ここに移動ペースト・⌘V・⌥⌘V）は、メニュー項目を淡色で選べなくし、キーボードショートカット（Return を含む）は何もしない。
  （3）複数を対象にする右クリックメニューには、対象の行の種類に関わらず、通常のフォルダの右クリックメニューと同じ項目を同じ順で出し、
  （1）（2）に従って有効・無効を決める（「ゴミ箱に入れる」だけが有効になり得る）
- **FR-212**: ツリーからの移動とゴミ箱に入れる操作で1件以上が成功した後、ツリーは、主の行（FR-209。単一選択ならその行）1つだけを選択した状態に
  しなければならない。ただし、ファイルリストに表示中のフォルダ、またはその祖先を移動・削除した場合は、FR-079・EC-123 に従って表示を切り替えた後の
  フォルダの行1つを選択する（主の行がお気に入りの項目でも、この場合は切り替え後の行を選択する）。
  コピー・キャンセル・すべて失敗した場合は、ツリーの選択とファイルリストの表示を変えない。キーボードフォーカスは FR-079 と同じく移さない

### Functional Requirements（変更）

- **FR-020**（変更）: ユーザーはアプリ内で、ツリーで選択した通常のフォルダ（複数可。FR-210・FR-211）、またはファイルリストで選択したファイル・フォルダを、
  ツリー上またはファイルリスト上の別のフォルダへドラッグ&ドロップできなければならない。通常は移動、ドロップ時に Option を押していればコピーとする。
  ファイルリストはリスト形式・サムネイル形式の両方に対応し、ツリーとファイルリストのどちらでも複数選択はまとめて扱う。確認・衝突・エラーは FR-022〜FR-026 に従う。
- **FR-079**（変更）: ユーザーは、ツリーの通常のフォルダ（ホーム・マウント中のボリュームの下にある実際のフォルダ）を、その行の
  右クリックメニューの「ゴミ箱に入れる」と、ツリーで選択中の ⌘⌫（FR-019 と同じキー。「ファイル」「編集」メニューの
  「ゴミ箱に入れる」を含む）で、中身ごと OS の
  ゴミ箱に入れられなければならない。対象は FR-210 に従い、複数のフォルダをまとめて1回の操作として扱う（FR-211）。右クリックメニューは、
  右クリックした行が選択外ならその行を対象にし、ツリーでそのフォルダを選択していなくても（ほかのフォルダを選択中でも）使える（A-21）。
  どの手段でも、実行前に対象の件数と、各フォルダの名前とその絶対パス
  （同じ名前の別のフォルダと見分けられるようにする。6件以上のときは先頭の5件を示し、残りを件数で示す）、フォルダを
  中身ごとゴミ箱に入れる旨を示す確認モーダル（FR-022）を、確認モーダルの省略設定（FR-023）に関わらず必ず表示し、
  キャンセルした場合はファイルシステムを変更してはならない。この確認モーダルには「今後この確認を表示しない」を出さない。
  ゴミ箱経由（FR-021）・失敗の表示（FR-026）・結果の反映（FR-027）はファイルリストのゴミ箱に入れる操作と同じとする。
  ホーム・ボリュームの最上位・「お気に入り」の見出し・お気に入りの項目は対象にしない（FR-064）。ファイルリストに表示中の
  フォルダ、またはその祖先をゴミ箱に入れた場合は、削除したフォルダ（表示中のフォルダを含むもの）の親をツリーで選択し、ファイルリストを親の一覧に切り替え、
  プレビューを空にする（再生中の動画は FR-034 と同じく停止する）。キーボードフォーカスは移さない（⌘⌫ で削除したときはツリーに
  残り、右クリックメニューから削除したときは削除前にフォーカスがあったペインに残る）。選択した親は最後に選択していたフォルダ
  （FR-003）として保存する。表示中のフォルダと祖先・子孫の関係にないフォルダだけを削除した場合は、ファイルリストの
  表示を変えない。削除後のツリーの選択は FR-212 に従う
- **FR-162**（変更）: ドラッグ元はツリーの通常フォルダ（FR-079 と同じ範囲。複数選択は FR-210・FR-211 に従う）または通常一覧・検索結果の実項目とする。
  ホーム・ボリュームのルート、お気に入りの項目・見出し、`..`、zip 内の項目はドラッグ元にしない。zip ファイル自体は通常のファイルとして扱う。
  検索結果のフォルダも対象とする（FR-083・FR-087（search.md））。
- **FR-183**（変更）: システムは、次の場合に「パス名をコピー」を淡色にして選べなくしなければならない。ファイルリストで複数の行を選択している、
  ツリーで複数の行を対象にしている（FR-210）、
  `..` の行を対象にしている、zip の中の項目（メディア・ディレクトリ・`..`）を対象にしている（FR-073）、見つからないお気に入りの項目を対象にしている、
  ツリーの「お気に入り」の見出しを選択中、またはキーボード操作でツリーに選択がない、名前の変更中（FR-102）

### Acceptance Scenarios（変更）

- **US23-AS1**（変更）: 通常のツリーフォルダ（複数選択を含む）を別のツリーフォルダまたはリスト内のフォルダにドラッグすると、確認後に中身ごと移動する。
  Option を押してドロップするとコピーする。複数選択から始めたときは選択全体を一操作として扱い、選択外の行から始めたときはその行だけを対象とする。

### Key Entities

- **ツリーの選択集合**: ツリーで選択中の行の集合と主の行（FR-209）。主の行がファイルリストの表示を決める。
- **操作の対象**: FR-210 で選択集合または右クリック・ドラッグを始めた1行から決まるフォルダの集合。FR-211 の条件を満たすときだけ一括操作に使う。
- **一括操作の結果**: 既存のファイル操作の結果（成功・失敗と理由）。成功分だけを表示に反映し、FR-212 でツリーの選択を決める。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-102**: ツリーの複数選択（2件・3件以上、同じ親・異なる親）を起点に、ツリー・リスト形式・サムネイル形式の宛先へ移動・Option コピー・ゴミ箱に入れるをそれぞれ行い、
  対象・結果・確認モーダルの件数が誤る組み合わせが 0 件。
- **SC-103**: 親子の同時選択・自身や配下への転送・通常のフォルダ以外を含む対象の各ケースで、一部の項目だけが移動・コピー・ゴミ箱に入れられた件数が 0 件。
- **SC-104**: 複数選択からのツリーのゴミ箱に入れる操作のうち、確認モーダルを経ずに実行されたものが 0 件（確認モーダルの省略設定がオンでも。SC-027 と同じ基準）。

## Assumptions

- **A-119**: ツリーの全選択（⌘A）は追加しない。ツリーにフォーカスがあるときの ⌘A は従来どおりツリーの選択を変えない。ルートやお気に入りを含む全行の選択は、
  一括操作の対象にならず（FR-211）有用でないため
- **A-120**: 複数の対象の確認モーダルは、ファイルリストの確認モーダルと同じく先頭の5件と残りの件数を示し、ツリーの規則（FR-079）に合わせて各件に絶対パスを添える
- **A-121**: 移動・削除の後のツリーの選択は、残った選択や失敗した項目を保たず、主の行の単一選択に戻す（FR-212）。複数選択の行が消えた後に、
  見えている選択とファイルリストの表示の関係を単純に保つため。コピー・キャンセル・すべて失敗のときは、ファイルリストの FR-165 と同じく選択を保つ
- **A-122**: ツリーの一括削除はドラッグでは行わない（Dock のゴミ箱などアプリの外へのドラッグの変更は FR-163 のとおり対象外）。⌘⌫ とメニュー・右クリックの
  「ゴミ箱に入れる」で行い、ファイルリストの一括削除と同じ操作経路にする
- **A-123**: お気に入りの項目の一括削除（お気に入りからの登録の削除）は対象外とする。お気に入りを含む複数の対象では、⌘⌫ と「お気に入りから削除」を無効にする（FR-211）
- アプリの外からツリーへのドロップ、ツリーからアプリの外へのドラッグの振る舞いは変えない（FR-163）
- Core の判断（対象の決定・可否・親子の検出・削除後の選択の決定）は自動テストを付ける。GUI の操作（選択・ドラッグ・メニュー・確認モーダル）の確認は保守者がローカルで行う
- 新規 ID は、採番時の全領域と未マージの feature（`specs/TAK-*`）を通した最大値（FR-207・SC-101・EC-140・A-118・US34）の次から採った。反映の直前に master と突き合わせて再確認する
