# Feature Specification: 公開用と開発用スクリプトの分離

**Feature Branch**: `017-separate-script-directories`
**Created**: 2026-10-30
**Status**: Draft
**Input**: [TAK-6](https://linear.app/takyoshida/issue/TAK-6/公開用と開発用のスクリプトをディレクトリで分ける)

## Clarifications

### Session 2026-10-30

- Q: 公開用と開発用をどう配置するか？ → A: 公開用の既存パスを維持し、開発専用を `scripts/dev/` に集約する。公開利用者の手順を維持し、開発用の追加を一括除外できるため。
- Q: 既存の履歴記録の古いコマンドは変更するか？ → A: 凍結済み feature と履歴記録は保存し、現行の実行設定・手順・テストを更新する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 開発専用スクリプトを公開から除く (Priority: P1)

保守者はスクリプトを公開用と開発専用に分類し、新しい開発専用スクリプトを追加しても公開書き出しに混入しないようにする。

**Why this priority**: 個別の除外漏れによる公開を防ぐ。

**Independent Test**: 一時リポジトリに開発専用の新規ファイルと公開用スクリプトを置き、公開書き出しで前者が除かれ後者が残ることを確認する。

**Acceptance Scenarios**:

1. **US24-AS1**: **Given** 開発専用ディレクトリに既存および新規のファイルがある、**When** 公開用に書き出す、**Then** それらはすべて含まれず、公開用スクリプトは含まれる。
2. **US24-AS2**: **Given** 除外設定の不備で開発専用ディレクトリが書き出しに含まれる、**When** 公開前の混入検査を行う、**Then** 同期前に失敗する。

### User Story 2 - 整理後も操作と検証を継続する (Priority: P2)

保守者は整理後のパスで開発、検査、書き出し、配布準備を行い、公開利用者は従来の公開用操作を使える。

**Why this priority**: 分離によって既存の作業が壊れることを防ぐ。

**Independent Test**: 移動後の呼び出し・テスト・現行手順を検証し、公開対象のビルド操作と開発用の検証を実行する。

**Acceptance Scenarios**:

1. **US25-AS1**: **Given** 整理後の開発環境、**When** 現行手順と自動ワークフローを使う、**Then** 正しいスクリプトが呼び出される。
2. **US25-AS2**: **Given** 公開書き出し、**When** 公開用のビルド・検査手順を使う、**Then** 従来の公開用パスで実行できる。

### Edge Cases

- **EC-127**: 開発専用ディレクトリ内の未知の名前や入れ子のファイルも除外し、混入時は検出する。
- **EC-128**: 移動したスクリプトが作業ディレクトリに依存して誤ったルートを参照しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-177**: 保守者は公開用スクリプトと開発専用スクリプトを配置で区別でき、開発専用の追加ファイルは個別の除外設定なしに公開書き出しから除かれなければならない。
- **FR-178**: 公開前の混入検査は開発専用ディレクトリ全体を検出し、混入した場合は公開先への同期前に中止しなければならない。
- **FR-179**: 整理後の現行スクリプト、設定、ワークフロー、検査、テスト、運用手順は新しいパスと実行位置に整合し、既存の公開用コマンドを維持しなければならない。
- **FR-180**: 書き出しの回帰検証は既存・未知・入れ子の開発専用ファイルの除外、公開用ファイルの保持、除外設定不備時の同期前停止を確認しなければならない。

既存の **FR-168、FR-169、FR-176（overview.md）** と公開用アプリ生成の契約（contracts/app-bundle.md）を維持する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-083**: 検証用書き出しで開発専用ファイルの混入は 0 件、対象の公開用スクリプトはすべて残る。
- **SC-084**: 除外設定を欠いた検証で公開先の内容を変更する前に停止する。
- **SC-085**: 現行の開発用検証と公開用のビルド・検査が整理後の構成で成功する。

## Assumptions

- **A-98**: `scripts/` 直下は公開用、`scripts/dev/` は開発専用とする。公開対象か判断できない追加物は開発専用に置く。
- **A-99**: 完了済み feature、バグ記録、振り返りは当時の記録として保持し、現行の案内と実行可能な設定を更新する。アプリの動作や配布方式の変更は対象外。
