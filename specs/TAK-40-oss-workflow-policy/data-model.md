# Data Model: 開発用と公開用の workflow の管理

この feature にはアプリのデータはない。扱うのは、リポジトリの中のファイルの種類と、書き出しでの扱い。

## 開発用 workflow

| 項目 | 内容 |
|---|---|
| 場所 | 開発用リポジトリの `.github/workflows/<名前>.yml`（直下のすべてのファイル） |
| 動く場所 | 開発用リポジトリ（`yoshidax/folzio-dev`）だけ |
| 書き出し | しない。`.gitattributes` の `/.github/workflows export-ignore` で除く（FR-289） |
| 例 | `macos-swift-ci.yml`（TAK-25）、TAK-35 の検査ジョブ |

検証の規則:

- `git archive HEAD` の結果に `.github/workflows/` の項目が 1 つでもあれば、混入として同期の前に止まる（FR-293）

## 公開用 workflow の定義

| 項目 | 内容 |
|---|---|
| 管理元 | 開発用リポジトリの `scripts/dev/oss-workflows/<名前>.yml` または `.yaml`（直下だけ） |
| 動く場所 | 公開用リポジトリ（`folzio-oss` の GitHub リポジトリ）だけ |
| 書き出し | 書き出しの `.github/workflows/<名前>` に、同じ名前・同じ内容で置く（FR-291） |
| 例 | TAK-41 のビルドとリリース（この feature の時点ではない） |

定義として扱う条件（すべてを満たすもの。満たさないものは置かない）:

1. `HEAD` のツリーで、`scripts/dev/oss-workflows/` の直下にある（サブディレクトリの中は対象外。EC-205）
2. 種類が blob で、モードが通常ファイル（`100644` または `100755`）。シンボリックリンク（`120000`）は対象外
3. 名前が `.yml` または `.yaml` で終わる（`README.md` などは対象外。EC-204）

## 管理元の説明

| 項目 | 内容 |
|---|---|
| 場所 | `scripts/dev/oss-workflows/README.md` |
| 書き出し | しない（定義の条件 3 を満たさない） |
| 役割 | 管理元であることと、方針の正本（`docs_private/repository-and-release.md`）への参照。Git は空のディレクトリを管理できないため、定義がない間も管理元を残す役割も持つ |

## 書き出しの workflow の配置

| 状態 | 公開先の `.github/workflows/` |
|---|---|
| 管理元に定義が 1 つ以上ある | 管理元の定義と、名前の集合と内容が一致する（FR-292） |
| 管理元に定義がない | 存在しない。書き出しに `.github/` ができないので、`rsync --delete` で公開先の `.github/` も消える（US62-AS4） |

状態の変化（書き出しを繰り返したとき）:

| 管理元での変更 | 次の書き出しで公開先に起きること |
|---|---|
| 定義を追加 | 追加される（`git status` に `A`） |
| 定義を変更 | 上書きされる（`M`） |
| 定義を削除 | 消える（`D`） |
| 変更なし | 変わらない。公開先に直接加えた workflow があれば消える（コミット済みなら `D`。未コミットなら表示されずに消える。EC-203） |
