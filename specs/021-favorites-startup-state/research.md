# Research: 起動時のお気に入りの開閉状態

**Date**: 2026-11-17
**調査対象**: `master` a826304、関連する製品仕様・設定・ツリー・翻訳・テスト。

## 1. 既定値と起動中の設定変更

**Decision**: 復元は既定でオフとし、切り替えは次回起動から適用する。

**Rationale**: 現行の A-27 と settings 契約は常に折りたたみであり、既存ユーザーの起動動作を維持できる。
設定の切り替えで閲覧中の行や動画を動かす必要もない。

**Alternatives considered**: 復元を既定でオンにする、切り替え時に即座に見出しも開閉する。
どちらも要求に必須ではなく、既存の表示を予期せず変更するため採用しない。

## 2. 保存状態の寿命

**Decision**: オン・オフと最後の開閉状態を2つのキーに分け、最後の状態は設定にかかわらず保存する。
起動時は最終的に表示した状態を保存する。

**Rationale**: オフの間に開き、オンへ変更して終了するケースでも自然に復元できる。
古い展開状態をオフでの起動をまたいで隠して持ち越さず、「前回」の意味を最後の実際の状態に揃えられる。

**Alternatives considered**: オンのときだけ保存する、モードを3値にする。
前者はオンにした瞬間の状態の取得に追加連携が要り、後者は不要な選択肢を増やす。

## 3. 型の検証

**Decision**: 新キーでは CFBoolean の型 ID を確認し、未設定・文字列・整数・配列・辞書は false とする。

**Rationale**: 現行 `SettingsStore.storedBool` は `as? Bool` を使用している。
新仕様の「不正な型」を満たすため、新キーの読み取りは Bool と数値を明確に区別する。
既存の interval の検証にも CF の型判定があるため、新しい依存は不要。

**Alternatives considered**: `bool(forKey:)` を使う、全既存キーの読み取りも変更する。
前者は型変換を受け入れ、後者は別の設定まで影響するため採用しない。

## 4. 復元と更新イベント

**Decision**: 初回の `reloadData` の後に1回だけ復元する。
見出しの expand/collapse の通知で保存し、再構築中の保存だけを局所的に抑止する。

**Rationale**: `focusFavoritesHeader()` は既に `expandItem` を呼ぶ。
`applyRoots` は現在の見出しの開閉と選択を取り置き、reload 後に復元する。
この既存経路を使えば通常のフォルダや選択の復元に責務を広げずに済む。
登録0件でも `isItemExpandable` は見出しに true を返す。

**Alternatives considered**: 終了時だけ保存する、全 reload で起動設定を再適用する。
前者は更新や終了順に依存し、後者はユーザーが起動中に変えた状態を上書きするため採用しない。

## 5. UI と検証

**Decision**: 既存の KeyViewCheckbox と「一般」タブを使い、英日2つの翻訳キーを追加する。
Core テストに加え、注入した設定とスタブを使う AppKit 結合テストで実際の outline 通知を検証する。

**Rationale**: SettingsWindowController に保存・言語更新・Tab 順・可変高さの既存経路がある。
ExternalImageDragTests には tree controller を分離して生成する前例がある。
起動時の判断だけのテストでは、通知の拾い漏れと再構築による保存値の破壊を検出できない。

**Alternatives considered**: 新しい設定タブや汎用復元サービス、見た目のスナップショットテスト。
この変更には必要なく、見た目・読み上げはユーザーの手動確認で扱う。
