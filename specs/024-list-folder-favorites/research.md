# Research: フォルダの右クリックメニューの整理

基準: `a826304`（master、v1.5.0）。2026-11-17。

## R1: 一覧の対象と単一選択

**Decision**: FavoriteCommands に対象集合・MediaFile の一覧・zip 内の状態から URL? を返す関数を置く。
**Rationale**: 判断は Core。`.folder` だけが実フォルダで、`.directory` は zip 内、`.parent` は移動行。
`FileListViewController.operationTarget` は `..` を操作対象から取り除くため、登録の対象数に流用すると
`..` と実フォルダの2件選択を単一と誤判定する。元の選択集合で数える。
**Alternatives**: 複数フォルダの一括登録はツリーの既存契約と異なるため今回採用しない。
フォルダだけ抽出して登録する案も部分的な実行になるため採用しない。

参照: `Sources/FolzioCore/Model/MediaKind.swift`、`Sources/FolzioCore/Model/FavoriteCommands.swift`、
`Sources/FolzioApp/FileList/FileListViewController.swift` の recordContextMenuTarget / operationTarget。

## R2: 右クリックとキーボードの区別

**Decision**: 選択外の項目は記録した URL、そのほかは全選択を対象とし、キーボードは常に現在の選択を使う。
**Rationale**: 現在の ContextMenuTarget の方針と、選択・フォーカスを右クリックで変えない契約にそろえる。
メニュー検証と実行時の対象計算を共用し、消えた対象を別の行へ読み替えない。
**Alternatives**: 右クリック時に選択を変える案は既存仕様に反する。

## R3: 登録状態の所有者

**Decision**: ツリーの既存の登録処理を URL 入口として共用し、MainSplitViewController が一覧とつなぐ。
**Rationale**: 現状 favorites はツリーが所有し、保存・再描画・監視・存在確認も一緒に更新している。
FavoriteFolders は標準化したパスで重複を防ぎ、独自の表示名も保持する。
**Alternatives**: 一覧側で SettingsStore を別途読み書きする案は二重の状態管理になる。
新しい永続化サービスの導入も今回の規模に対して不要。

参照: `DirectoryTreeViewController.swift` の addFavorite / reloadFavorites、`FavoriteFolders.swift`。

## R4: フォーカス・ペイン・文字入力

**Decision**: 一覧にフォーカスがあれば一覧対象とし、ツリー非表示でも一覧が見えれば登録を許可する。
ツリーまたはプレビューのフォーカス時は既存どおりツリー対象とする。
**Rationale**: 一覧の対象外でツリーへ戻すと別のフォルダを登録してしまう。
プレビューの従来動作は維持できる。名前の絞り込み欄は `isEditingText` から意図的に除外されているため、
登録コマンドに限って別途文字入力状態を検出する。
**Alternatives**: ツリー非表示で一律に無効にする案は、一覧からの登録を不要に制限する。

参照: MainSplitViewController の focusedPane / addSelectedFolderToFavorites、PaneCommands、
FileListViewController.isRenaming、ToolbarSearchFieldEditingTests。

## R5: 変更前の右クリック操作の比較（保守者の追加依頼）

対象は通常の実フォルダ1件。ファイルリストはリスト形式・サムネイル形式で共通。
「なし」はそのフォルダの項目メニューに存在しないことを示す。

| 操作 | ツリーの通常フォルダ | ファイルリストの実フォルダ |
|---|---|---|
| 新規フォルダ | 対象フォルダの中に作成 | 項目メニューになし。背景から表示中のフォルダへ作成 |
| 中を表示 | なし | 対象フォルダを Folzio で開く |
| 上の階層へ | なし | 表示中の場所に戻り先があるときだけ表示 |
| 開く | なし | OS の既定アプリで開く |
| このアプリケーションで開く | なし | 項目はあるがフォルダでは無効 |
| ゴミ箱に入れる | あり。ホーム・ボリュームのルートには出さない | あり |
| 名前を変更 | あり。ホーム・ボリュームのルートには出さない | あり |
| 複製 | なし | あり |
| コピー | なし | あり |
| パス名をコピー | あり | あり |
| ペースト・移動ペースト | 右クリックしたフォルダの中へ | 表示中のフォルダへ |
| お気に入りに追加 | あり。登録済みは無効 | なし（元の追加要件） |
| Finder に表示 | あり | あり |

### 条件・対象・結果の差

- 複数選択: ツリーではゴミ箱だけが有効になり得る。対象にルート・お気に入り・見出しを含むとゴミ箱も無効。
  親子フォルダを同時に対象にするゴミ箱は実行時にまとめて拒否する。
- ファイルリストの複数選択では、コピー・複製・ゴミ箱・開く・Finder に表示が使える。
  名前を変更とパス名をコピーは単一対象だけ。ペーストは選択数に依存せず表示中のフォルダが対象。
  「中を表示」はフォーカスのあるコンテナを開き、複数対象をまとめて開くものではない。
- 検索結果でも実フォルダの操作は使えるが、一覧のペースト・移動ペーストは無効で「上の階層へ」は出ない。
  ツリーの右クリックは一覧の検索結果表示とは独立して使える。
- zip 内のディレクトリは実フォルダと区別する。一覧では中を表示・上の階層へ以外の操作は無効。
- 右クリック対象の規則は共通: 選択中の項目なら選択全体、選択外ならその1件。
  操作対象を決めるためだけに選択やフォーカスを移さない。
- ゴミ箱の確認は共通の設定に従うが、ツリーでは対象の絶対パスも示す。
  ツリーから表示中のフォルダやその祖先を削除した場合は、閲覧可能な親へ移る処理がある。
- ツリーの「お気に入り」の項目は別メニューで、新規フォルダ・表示名の変更・登録削除・パス名のコピーを持つ。
  実フォルダの名前変更・ゴミ箱ではない。見出し単独にはメニューを出さない。

参照: FavoriteCommands.contextMenu、TreeBatchTargets、DirectoryTreeViewController.validateMenuItem、
FileContextMenu.buildMenu、FileListViewController.validateMenuItem / paste / open、
FileOperationCoordinator.trash、`specs/product/contracts/keyboard-and-menus.md`。

## R6: 元の登録要件の検証の範囲

**Decision**: Core の対象判定とペイン条件、AppKit のメニューから登録への接続を自動テストし、表示・フォーカス・VoiceOver は手動確認する。
**Rationale**: 純粋関数だけでは、別ペインの選択に誤って登録する接続ミスやメニューの状態を検出できない。
既存の FileListContextClickTests の fixture と表示2形式の検証パターンを踏襲する。
**Alternatives**: 実装をなぞる静的な文字列テストや GUI 自動起動を合格根拠にはしない。

## R7: 目的変更と共通化の境界

**Decision**: 保守者の指示でフォルダのメニュー全体を整理する。
**Rationale**: 5つの注釈を要件として反映し、追加の質問には「ファイル操作をそろえ、表示場所固有の項目は残す」と回答された。
**Alternatives**: ナビゲーションまで同じ項目にする案は保守者が選ばなかった。

共通化する通常フォルダと、登録の削除・表示名の変更を行うお気に入りの仮想項目を区別する。
通常フォルダの新規作成は背景・メニューバー・キーへ集約する案を設計レビューへ提示する。
お気に入りの仮想項目の既存メニューには手を広げない。

## R8: Finder の確認（2026-11-17）

**観察したこと**: ローカル Finder のリスト表示で通常フォルダ1件と2件の項目メニューを開いた。
単一ではペースト・ゴミ箱・名称変更・複製・コピーが表示された。
2件でもコピーと複製は有効で、単一フォルダ向けペーストは表示されなかった。
「開く」「このアプリケーションで開く」「新規フォルダ」は単一フォルダの項目メニューに見当たらなかった。
ファイル操作は実行していない。メニュー表示の観察と実際の書き込み検証は区別する。

**公式資料**:
- [ファイルをフォルダに整理する](https://support.apple.com/ja-jp/guide/mac-help/mh26885/27/mac/27)
- [Mac のキーボードショートカット](https://support.apple.com/ja-jp/102650)

**Decision**: コピーは実 URL をコピーし、複製は元と同じ親に作る。項目メニューのペーストは対象フォルダへ、
一覧の背景・キーは現在の場所へ行う。キー割り当ては既存の ⌘C・⌘D・⌘V・⌥⌘V を共用する。
**Rationale**: 保守者の明示指示と、公式資料のコピー・複製・移動ペーストの意味に合う。
**Alternatives**: 一覧でフォルダを右クリックしても親へペーストする現行動作は変更する。
Finder の全機能・すべての表示文言・一括リネームをコピーする案は採用しない。

## R9: 共通メニューと複数対象

**Decision**: FolzioCore に通常フォルダ用の操作順と対象の可否を持つ小さな方針を置く。
TreeContextMenuItem と FileContextMenu は同じ順序から標準 NSMenuItem を作る。
**Rationale**: 別々に順序をハードコードすると再び差が出る。汎用のメニュー構築基盤は不要。
通常フォルダだけの複数対象ではコピー・複製・Finder に表示を許可し、単一先を要する操作は無効にする。
ゴミ箱・ドラッグのルート保護や親子重複判定は既存の判断を使い続ける。
**Alternatives**: 複数対象を一律無効にする案は Finder と異なり、ファイル操作をそろえる目的を満たさない。

## R10: ペースト先の決定と保存処理

**Decision**: 入力元を項目メニュー・背景・メニューバー／キーで区別し、対象 URL を先に確定する。
一覧の単一実フォルダの項目メニューは、その URL を FileOperationCoordinator.paste へ渡す。
混在・複数・消失したフォルダには代わりの貼り付け先を与えない。
**Rationale**: 現行の一覧 paste は常に model.listing.folder を使うため、ここを対象ごとの経路へ分ける必要がある。
coordinator はコピー・移動・画像受信・確認・衝突解決・失敗表示をすでに共用できる。
**Alternatives**: 一覧の表示フォルダを先に切り替える案は、選択・検索・閲覧状態を不必要に変える。

検索結果でも実フォルダ1件なら行先が特定できるため項目メニューからは許可する。
背景・キーの検索結果へのペースト禁止は維持する。FR-087・A-82・EC-35 と契約の古い一律禁止を更新する。

## R11: 検証

Core では共通順序、役割・件数・zip・ルート・混在対象の可否、ペースト先をテストする。
AppKit では両ビューの実メニューと action の接続、古い右クリック対象の隔離、クリップボード URL を検証する。
一時フォルダ内の実コピー・複製・コピー／移動ペーストを自動テストし、誤った行先に作られないことも確認する。
GUI では3ペイン・両表示形式・キー・検索・編集・言語・アクセシビリティを保守者に確認してもらう。
