## User Scenarios & Testing *(mandatory)*

変更点だけを定める。並べ替え全般は FR-012・FR-277（file-list.md）、検索結果は FR-084・FR-085（search.md）、zip の中の一覧は FR-071（zip.md）に従う。
US60 は永続シナリオ ID。

### User Story 1 - 名前順でフォルダが先頭にまとまる (Priority: P1)

利用者は、リスト形式の「ファイル名」列を昇順・降順に並べ替えたとき、Finder と同じく、フォルダの行が一覧の先頭にまとまって見える。
フォルダ同士、ファイル同士は名前の自然順で並ぶ。

**Why this priority**: フォルダとファイルが混ざると、目的のフォルダを探しにくい。Finder と同じ見え方に揃えるのが本機能の価値の全体。

**Independent Test**: フォルダ `b`・`d` とファイル `a.jpg`・`c.png` があるフォルダで「ファイル名」を昇順にすると `b`・`d`・`a.jpg`・`c.png`、降順にすると `d`・`b`・`c.png`・`a.jpg` になる。

**Acceptance Scenarios**:

- **US60-AS1**: **Given** リスト形式で、フォルダ `b`・`d`、ファイル `a.jpg`・`c.png`、zip ファイル `e.zip`（zip ファイルの表示設定がオン）がある, **When** 「ファイル名」の列見出しで昇順にする, **Then** `b`・`d`・`a.jpg`・`c.png`・`e.zip` の順に並ぶ。zip ファイルはファイルとして扱い、フォルダの後ろに置く
- **US60-AS2**: **Given** US60-AS1 と同じ一覧, **When** 「ファイル名」を降順にする, **Then** `d`・`b`・`e.zip`・`c.png`・`a.jpg` の順に並ぶ。降順でもフォルダは先頭にまとまり、各グループの中が逆順になる
- **US60-AS3**: **Given** 検索結果を表示中で、起点の配下の異なる場所にあるフォルダとファイルが一致している, **When** 「ファイル名」で昇順・降順に並べる, **Then** 一致したフォルダの行が先頭にまとまる。検索中に結果が追加されても、この順序を保つ（FR-085）
- **US60-AS4**: **Given** zip の中の一覧を表示中（`..` の行がある）, **When** 「ファイル名」で昇順・降順に並べる, **Then** `..` が先頭、その次に zip の中のディレクトリ、その次にファイルの順に並ぶ
- **US60-AS5**: **Given** フォルダとファイルが混ざった一覧, **When** 「作成日」「種類」「サイズ」「変更日」「場所」の列で並べる, **Then** 並び順は従来のまま変わらない（フォルダをまとめない。サイズ順ではフォルダを 0 バイトとして扱う（FR-277））

### Edge Cases

- `..` の行は従来どおり常に先頭に置き、並べ替えの対象にしない（A-25）
- フォルダしかない、またはファイルしかない一覧は、従来の名前順と同じ並びになる
- 名前が同じ項目（検索結果の別の場所にある同名のフォルダなど）は、従来どおり一覧に現れた順を保つ
- 「表示 > 並べ替え」メニューで「ファイル名」を選んだ場合も、列見出しのクリックと同じ並びにする（FR-277）
- 並べ替えに使っている列を非表示にして「ファイル名」の並べ替えへ切り替わったとき（FR-277）も、この規則に従う
- 並べ替えの列と方向の保存・復元（`view.sort.column`・`view.sort.ascending`）は変えない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-288**（FR-012 の追記）: 「ファイル名」の列で並べ替えるとき、システムは、フォルダの行（通常のフォルダの `folder` と zip の中の `directory`）を、昇順・降順のどちらでも、
  ファイルの行（メディアファイルと zip ファイル）より前にまとめなければならない。フォルダ同士、ファイル同士は名前の自然順（降順では逆順）で並べる。
  zip ファイルはファイルとして扱う。`..` は従来どおり常に先頭で、並べ替えの対象にしない。この規則は、通常のフォルダの一覧・検索結果（FR-084）・
  zip の中の一覧（FR-071）に同じく適用し、検索中の追加（FR-085）も同じ順序になるようにする。名前以外の列の並べ替えは変えない。
- **A-25（変更）**: 一覧の並べ替えでは、「ファイル名」の列に限り、フォルダ（通常のフォルダ・zip の中のディレクトリ）を先頭にまとめ、
  zip ファイル（zip ファイルの表示設定がオンのとき）とメディアファイルをその後ろに並べる（FR-288。Finder の名前順と同じ。`..` は常に先頭）。
  それ以外の列では、フォルダ・zip ファイル・メディアファイルを区別せず、選択した列の順に混ぜて並べる。
  フォルダの「作成日」はファイルシステムの作成日時、「種類」は「フォルダ」とする
- **FR-084（変更）**: 検索結果の並びについての一文「ファイルとフォルダは区別せず、選択した列の順に混ぜて並べる（A-25（file-list.md））」を、
  「ファイル名の列で並べるときはフォルダを先頭にまとめ、それ以外の列ではファイルとフォルダを区別せず選択した列の順に混ぜて並べる（FR-288・A-25（file-list.md））」に変更する。
  そのほかの本文は変えない

### Key Entities *(include if feature involves data)*

- **フォルダの行**: 一覧の行のうち、通常のフォルダ（`ListItemKind.folder`）と zip の中のディレクトリ（`ListItemKind.directory`）。zip ファイル（`archive`）と `..`（`parent`）は含まない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-149**: フォルダ・メディアファイル・zip ファイルが混ざった一覧を、「ファイル名」の昇順・降順で並べる操作を各10回行う。20回すべてで、フォルダの行がすべてのファイルの行より前に並び、フォルダ同士・ファイル同士が名前の自然順（降順は逆順）になる
- **SC-150**: 検索結果（段階的に追加される）・通常のフォルダの一覧・zip の中の一覧で、「ファイル名」の昇順・降順を各3回確かめる。いずれも `..`（ある場合）が先頭、フォルダがその次にまとまる
- **SC-151**: 「作成日」「種類」「サイズ」「変更日」「場所」で並べ替えた一覧の並びが、この変更の前と同じである（既存の自動テストの期待値が変わらない）
- **SC-152**: 10,000 件の一覧の並べ替えと、10,000 件への 256 件の追加（FR-085）が、SC-016（overview.md）・FR-085 の性能の基準を引き続き満たす

## Assumptions

- Issue の「検討事項」のとおり、フォルダ同士・ファイル同士の比較には従来の名前の自然順（`localizedStandardCompare`）を使う
- 「ファイル名」以外の列の扱い（サイズ順はフォルダを 0 バイト、変更日順は混ぜる）は変えない
- 設定として切り替える項目は設けない。名前順は常にフォルダ先頭になる
- サムネイル形式にも並べ替えのメニューがある場合は同じ並びになる（並び順はモデル側で一つに決まるため）
- 「表示 > 並べ替え」と列見出しで同じ `SortOrder` を使うため、UI の変更は不要と見込む（plan.md で確認する）
