# AGENTS.md に何を書くか

`AGENTS.md` に規則を足す・変えるとき、または feature の `tasks.md` で `AGENTS.md` の変更を指示するときの基準。
`AGENTS.md` はエージェントが毎回読むので、短いほどよい。不要な指示は余計な探索を招き、コストと失敗を増やす。
`scripts/dev/check-agents-md.sh`（`scripts/dev/check-all.sh` から呼ぶ）が、行数と参照先のパスを検査する。

## 置き場所の基準

新しい規則は、次の順に検討する。

| 順 | 置き場所 | 当てはまるもの |
|---|---|---|
| 1 | ツール | hook・権限設定・検査スクリプトで機械的に止められるもの |
| 2 | 既存の文書・コード | コードや設定、既存の文書を読めば分かるもの。書かない |
| 3 | `docs_private/agents/` などの別ファイル | 特定の作業でしか使わないもの |
| 4 | `AGENTS.md` | コードからは分からず、知らないとエージェントが具体的に間違えるもの |

表の詳細:

- 1: 事故への対策は、まずツールで止められないかを検討する（例: TAK-53 の CI の起動は、権限設定の `ask` でも止める）
  - ツールにしても、エージェントが書く前に知る必要がある設計の制約は、`AGENTS.md` にも 1 行残してよい
- 2: 一般的なベストプラクティスで、指示しなくてもモデルが行うことも書かない
- 3: `AGENTS.md` には「〜するとき: <ファイル>」の形で参照だけを残す
  - 参照の文言は、エージェントがその作業を始めるときに思い浮かべる言葉で書く（例: 「アプリが起動しない」）
- 4: 1 つの規則を 1 行で書く。理由が短く書けるなら括弧で添える

## 行数の上限

- 上限の行数（空行と見出しを含む）と、警告を出す行数は、`scripts/dev/check-agents-md.sh` の `MAX_LINES` と `WARN_LINES` にある
  - 警告は、`WARN_LINES` を超えていて、`origin/master` より行数が増えたときに出る
- 警告や失敗が出たら、規則を足す前に `AGENTS.md` の各行を見直す
  - 見直しは監査のスキルで行う（Claude Code と Kilo Code は `/folzio-agents-md-audit`、Codex は `$folzio-agents-md-audit`。
    手順は `shared-skills/folzio-agents-md-audit.md`）
  - 過去の事故から追加された行は、削除せずに残すか、別ファイルへ移す

## 追加の理由を残す

`AGENTS.md` に規則を足す・変える・消すときは、その理由を、後で `git log` からたどれる場所に書く。
後で見直すときに、その行が事故から追加されたものか、消してよいかを判断するため。

- PR で `master` へ入れるとき: PR の本文の「変更」に、独立した項目として理由を書く
  - PR はスカッシュマージされ、作業ブランチのコミットの本文は `master` に残らない
  - スカッシュしたコミットのタイトルには `(#<PR 番号>)` が残るので、そこから PR の本文をたどれる
- `scripts/dev/merge-to-master.sh` で `master` へ入れるとき: コミットメッセージの末尾に `Rule-Reason:` の行で書く
  - このマージは作業ブランチのコミットをそのまま残す
- 事故やレビューの指摘が理由のときは、Issue の ID と、何が起きたかを書く（例: `TAK-53: 2026-11-02 に Actions の予算が 0 になり CI が止まった`）
