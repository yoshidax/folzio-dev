# メッセージで挙げる ID のリンク

**適用範囲**: 【共通】

`AGENTS.md` の「書くときの規則」にある、エージェントがメッセージで ID を挙げるときの規則（TAK-82）の補足。
規則そのものは `AGENTS.md` にあり、この文書は、形式を選んだ根拠と、環境ごとに開けるかを確かめた結果を記録する。
エージェントは毎回この文書を読む必要はない。リンクが開けないと報告されたとき、または形式を見直すときに読む。

## 規則の範囲

- 対象: `specs/product/` の ID（`FR-xxx`・`SC-xxx`・`EC-xx`・`A-xx`・`USn-ASm`）と、Linear の Issue ID（`TAK-xx`）
- 対象外: 凍結した feature（`specs/NNN-*`・`specs/TAK-*`）の ID、憲章の原則
- リンクにするのは各メッセージの初出だけ。同じ ID の繰り返しでトークンを増やさないため
- 仕様の ID は、`scripts/dev/find-spec-id.sh <ID>…` で `ID path:line` を引き、コードスパンの `path:line` を添える
  - 例: FR-080（`specs/product/search.md:8`）
  - 行番号は文書の更新で変わるので、メッセージを書く時点で引く。会話の中で既に引いた行が古くなっていないかに注意する
- `TAK-xx` は `https://linear.app/takyoshida/issue/TAK-xx` へのリンクにする

## 環境ごとの確認結果

同じ定義（FR-080、`specs/product/search.md` の 8 行目）を指す、次の 5 つの形式で確かめる。

| 形式 | 書き方 |
|---|---|
| 1 平文の `path:line` | specs/product/search.md:8 |
| 2 コードスパンの `path:line` | `` `specs/product/search.md:8` `` |
| 3 相対パスの Markdown リンク | `[FR-080](specs/product/search.md)` |
| 4 行のアンカー付きの相対リンク | `[FR-080](specs/product/search.md#L8)` |
| 5 コミットに固定した GitHub の URL | `[FR-080](https://github.com/yoshidax/folzio-dev/blob/<commit>/specs/product/search.md#L8)` |

| 環境 | 確認日 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| Claude Code のクラウド（Claude アプリで表示） | 2026-11-12 | 開けない | 開ける（その行） | 開ける（ファイル） | 開ける（その行） | 開ける（行は指せない） |
| Claude Code のローカル（ターミナル） | 未確認 | | | | | |
| Codex のローカル | 未確認 | | | | | |
| Kilo Code（VS Code） | 未確認 | | | | | |
| Codex Cloud | 未確認 | | | | | |

表の詳細:

- Claude Code のクラウドでの各形式の結果（TAK-82 で保守者が確かめた）
  - 1: リンクにならず、平文で表示された
  - 2: ファイルビューでファイルが開き、8 行目にカーソルが合った
  - 3: ファイルが Markdown のプレビューで開いた
  - 4: 2 と同じく、ファイルビューで 8 行目が開いた
  - 5: GitHub の Web ページで、ファイルが Markdown のプレビューで表示された。行の位置は示されない
- 形式 2 を規則にした理由
  - Claude Code のクラウドで、行まで開ける
  - Claude Code のシステムの指示が `file_path:line_number` の形をクリックできる形としているため、ローカルでも開ける見込みが高い（未確認）
  - 形式 5 は push していない変更を指せず、Markdown のファイルでは行を指せなかった

## 未確認の環境を確かめる手順

1. その環境のエージェントに、上の 5 つの形式の「書き方」の列を、そのまま出力するよう頼む
   - 形式 5 の `<commit>` は、push 済みのコミット（例: `git ls-remote origin master` の値）に置き換える
2. 各形式をクリックし、開くかどうかと、何が開くか（ファイル、その行、ブラウザ）を確かめる
3. 結果を上の表に記録する
4. 形式 2 が開けない環境があれば、その環境で開ける形式を代わりに使う規則を、この文書と `AGENTS.md` の規則に足す
   - 代わりの形式は、確かめた結果から決める。確かめていない形式を規則にしない

## コンテキストの消費（TAK-82 の見積もり）

規則を `AGENTS.md` に置くか判断したときの見積もり。トークン数は実測ではない。

- `AGENTS.md` の規則 1 行: 毎セッション約 100 トークン（`AGENTS.md` 45 行が `/context` で 2.1k トークン、約 0.67 トークン/文字から計算）
- 応答に添える `path:line`: ID 1 つにつき約 10 トークン
- 行を引く `find-spec-id.sh` の呼び出し: 1 回あたり約 50 トークンと、ID 1 つにつき約 15 トークン
  - 定義の行の全文を返す Grep では、ID 1 つにつき約 50 トークンになる（定義の行は平均 57 文字）
