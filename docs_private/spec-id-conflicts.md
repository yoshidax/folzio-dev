# 仕様 ID の重複解消

**適用範囲**: 【共通】ローカルと Cloud の仕様保守

仕様 ID（`FR`・`SC`・`EC`・`A`・`US`）の重複を解消するとき、どちらを振り直すかは
[憲章の「仕様の管理」](../.specify/memory/constitution.md#仕様の管理)に従う。ID の一意性を維持し、削除した ID は再利用しない。
Cloud 固有の master の取り込みや PR の手順は [Cloud Agent の作業手順の 7 章](cloud-agent-workflow.md#7-並行する作業と競合)にある。

1. 衝突した項目とそれぞれのマージ状態を確かめ、憲章に従って振り直す側を特定する。両方がマージ済みの場合は、マージ順も確認する。
2. 新しい番号は、その時点の `specs/product/` の全領域を通じた該当する種類の ID の最大値の次から採る。
3. 仕様・契約・ソースのコメント・テスト・関連文書を旧 ID で検索し、文脈から振り直す項目への参照を特定して新 ID に追従させる。
   別の項目を指す参照は変更せず、参照先を判別できない場合は推測で置換せず保守者に確認する。
4. 凍結済み feature の記録は本文を更新しない。マージ済み ID の重複解消時には、先頭に旧 ID と新 ID の対応表を注記する。
5. `specs/product/` へ反映する前と後に `scripts/dev/check-spec-ids.sh` を実行し、定義の重複がないことを確認する。
   この検査は参照先の意味の正しさを検査しないため、手順 3 の文脈の確認も必要である。
