# AGENTS.md の監査の共通手順

この手順は Codex、Claude Code、Kilo Code の対話スキルで共有する。
呼び出すときは Codex で `$folzio-agents-md-audit`、Claude Code と Kilo Code で `/folzio-agents-md-audit` を指定する。

## 目的と範囲

- `AGENTS.md` の各行が今も必要かを保守者と確かめ、上限の行数に収まる改訂案を作る。
- 判断の基準は `docs_private/agents/README.md` を正とする。上限の行数は `scripts/dev/check-agents-md.sh` の `MAX_LINES` を正とする。
- **保守者が改訂案を承認するまで、ファイルを編集しない**。承認の前に作るのは、調査の結果と下書きだけにする。
- 過去の事故やレビューの指摘から追加された行（以下、事故由来の行）は、削除の候補にしない。残すか、別ファイルへ移す。

## 1. 監査

最初に、次を読む。

- `AGENTS.md`、`docs_private/agents/README.md`、`scripts/dev/check-agents-md.sh` の出力
- エージェントの権限と hook: `.claude/settings.json` と、そこから呼ぶスクリプト、`.codex/rules/`、`.kilo/kilo.jsonc`
- `AGENTS.md` を指す参照: `specs/product/` の要件（`grep -rn AGENTS.md specs/product`）と、他の文書・スキル・workflow
  - 凍結した feature（`specs/NNN-*`・`specs/TAK-*`）、`.specify/bugs/`、`docs_private/retrospective/`、`docs_private/release-notes/` は記録なので、直す対象から外す

次に、`AGENTS.md` の各行（または節）を、次のどれか1つに分類して表にする。

| 分類 | 当てはまるもの | 根拠に書くこと |
|---|---|---|
| 削除（コード・設定） | コードや設定、既存の文書を読めば分かる | 分かる場所のファイルパスと行 |
| 削除（一般） | 一般的なベストプラクティスで、指示しなくてもモデルが行う | そう判断した理由 |
| 移動 | 特定の作業でしか使わない | 移動先の案（`docs_private/agents/` など） |
| ツール化 | hook・権限設定・検査スクリプトで機械的に止められる | 方法と、Claude・Codex・Kilo のどれに効くか |
| 要確認 | コードの実態や他の行・仕様と食い違う、古い | 食い違っている相手のファイルパスと行 |
| 残す | コードからは分からず、消すとエージェントが具体的に間違える | 間違えたときに起こること |

- 迷う行は、`git log -S'<行の一部>' -- AGENTS.md` と `git blame` で追加された経緯を調べ、分かったことを根拠に添える。
  - コミットの本文はスカッシュマージで消えるので、コミットのタイトルの `(#<PR 番号>)` から PR の本文も読む。
  - 振り返り（`docs_private/retrospective/`）と、行が触れている Linear の Issue も読む。
- 事故由来の行には印（⚠）を付ける。
- 削除・移動するとき、その行を名前や節で参照している文書（上で読んだ参照）を、表の下に一覧にする。
- `specs/product/` の要件が `AGENTS.md` に置くことを求めている内容は、「残す」か「要確認」にする。消すには仕様の変更が要る。

**完了の条件**: `AGENTS.md` のすべての行が、表のどれか1つの行に入っている。削除とツール化の行には、すべてファイルパスかコマンドの根拠がある。

## 2. ヒアリング

保守者に、次の行について質問する。1回に3問までにし、答えを受けて次の質問に進む。

- 「要確認」の行
- 経緯が分からないまま、削除の候補にした行（事故由来かどうかを尋ねる）

答えに応じて表を更新する。事故由来と分かった行は、削除の候補から外す。

**完了の条件**: 「要確認」の行が残っていない。経緯の分からない削除の候補について、保守者の判断を得ている。

## 3. 改訂案

次の4つを示す。

1. 新しい `AGENTS.md` の全文（下書き）
   - 行数を `awk 'END { print NR }'` で数え、`MAX_LINES` 以下であることを示す
   - 見出しの適用範囲（【共通】【ローカル】【Cloud】）と、仕様が求める内容を保つ
2. 移動する内容と、その移動先の一覧
3. ツール化する内容と、その方法の一覧（どのエージェントに効くかを添える）
4. 削除する行と、その理由の一覧

あわせて、参照を直す必要のある文書と、この監査の範囲外で別の作業にすることを示す。

**完了の条件**: 元の `AGENTS.md` のすべての行が、改訂案の本文か、2〜4 の一覧のどれかに入っている。

## 4. 承認の後

保守者が承認したら、次の順に進める。

1. Linear の Issue に着手する（`docs_private/agents/linear.md`）。Issue がなければ、作るかを保守者に尋ねる
2. `AGENTS.md`、移動先の文書、参照している文書を直す
3. `scripts/dev/check-all.sh` を実行する
4. 変更の理由を残す（`docs_private/agents/README.md` の「追加の理由を残す」）

承認を得られなかった部分は編集せず、表に「保留」と書いて報告する。
